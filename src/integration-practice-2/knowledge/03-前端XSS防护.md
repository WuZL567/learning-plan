# 前端 XSS 防护

## XSS 是什么

XSS（跨站脚本攻击）是指攻击者把恶意脚本注入到页面里，让它在其他用户的浏览器上执行。一旦执行，脚本可以读取 cookie、localStorage，冒充用户发请求。

## AI 应用为什么风险更高

传统前端渲染的是自己写的、可控的模板。AI 应用的输出是外部输入，模型生成什么、用户 prompt 注入什么，前端完全不可控。用户完全可以让模型输出一段 script 标签。

所以 AI 应用的渲染必须当成"渲染用户输入"来处理，不能当成"渲染自己写的 HTML"。

## 为什么不能用 innerHTML

用 innerHTML 渲染 AI 输出有两个问题。第一，回答里的尖括号会被浏览器当成 HTML 标签解析，用户看到的文字凭空消失。第二，任何标签里的 onerror、onclick 都会被真实执行，这是一个实实在在的 XSS 入口。

## 用 textContent 还是 Markdown 渲染

如果不需要 Markdown，直接用 textContent，浏览器会把内容当纯文本处理，天然安全。

但 AI 回答通常是 Markdown 格式，带代码块、列表、表格，需要渲染成 HTML，所以必须走 marked 这类解析器，再用 DOMPurify 消毒。

DOMPurify 的原理是拿浏览器的 HTML 解析器解析一遍字符串，然后按白名单过滤标签和属性，把 script、iframe、onerror 这类危险内容全部剔除。它是目前前端最成熟的 XSS 消毒库。

## 关键原则

凡是内容来自外部，包括用户输入、AI 输出、第三方接口，渲染前必须消毒。这是前端安全的一条硬规则，和"永远不要相信客户端传来的数据"是同一个道理。

## 其他常见防护手段

CSP 内容安全策略可以从浏览器层面限制脚本来源，即使注入成功也无法执行。HttpOnly 让 cookie 无法被 JavaScript 读取，降低 XSS 得手后的损失。对用户输入做转义和长度限制属于纵深防御，不能替代输出端的消毒。
