# RAG 检索增强生成

## 为什么需要 RAG

大模型的知识在训练完成那一刻就冻结了。你问它公司内部文档里写了什么，它不知道；你问它昨天发布的新闻，它也不知道。而且它不知道的时候不会说不知道，而是会一本正经地编一个答案，这就是幻觉。

有两种解法。第一种是微调，把知识训进模型权重里。缺点是贵、慢，而且知识一更新就得重新训练一次。

第二种就是 RAG（Retrieval-Augmented Generation，检索增强生成）：不改模型，每次提问时先去外部知识库查资料，把查到的内容连同问题一起塞进 prompt，让模型基于资料回答。

一个类比：微调等于让学生背书，RAG 等于开卷考试。开卷考试的好处是资料可以随时换、答案可以溯源、成本低得多。

## RAG 的四个步骤

RAG 分两个阶段。离线阶段做索引：文档经过切块、向量化，存进向量库。在线阶段做检索和生成：用户问题先向量化，然后在向量库里找出最相似的几个文本块，把它们拼进 prompt，最后让模型基于这些资料生成回答。

## 为什么要切块

整篇文档直接塞进去有三个问题：可能超过上下文窗口、token 成本高、而且检索粒度太粗，找不准到底是哪一段在回答这个问题。

切块就是把书拆成卡片，检索的单位是卡片而不是整本书。

chunk_size 需要权衡。切得太小，单块语义不完整，出现它、这个之类的指代时无法理解；切得太大，一块里混进太多无关内容，检索精度下降，还会浪费 token。

overlap 重叠的作用是防止句子被硬切在边界上。相邻两块重叠一部分内容，即使关键句正好跨在切割点上，也能至少在一块里保持完整。

## Embedding 是什么

Embedding 是把一段文本变成一串固定长度的数字，也就是向量。比如 bge-m3 输出 1024 个浮点数。

它的神奇之处在于语义相近的文本，向量也相近。可以想象成给每段文字在一张语义地图上定位。如何重置密码和忘记密码怎么办这两个点挨得很近，而它们和今天天气不错这个点离得很远。

这样一来，找相关内容就变成了纯粹的几何问题：找最近的几个点。

## 余弦相似度

衡量两个向量有多近，用余弦相似度，也就是两个向量夹角的余弦值。

cos 等于 1 表示方向完全相同，最相似；cos 等于 0 表示垂直，毫不相关；cos 等于 -1 表示方向相反。

公式是 a 点乘 b 除以 a 的模长乘 b 的模长。分子是点积，分母是两个向量模长的乘积。

为什么用余弦而不是欧氏距离？因为余弦只看方向、不看长度。同一段话写长写短，方向基本不变，语义也没变，所以余弦能公平地比较长短不同的文本。

## 检索质量怎么优化

几种常见手段。第一是相似度阈值过滤，低于阈值的直接丢掉，避免把不相关内容硬塞给模型。第二是 Multi-Query，让大模型把一个问题改写成几个不同角度的问法分别检索，再把结果合并，提升召回率。第三是 Reranking 重排序，先用向量检索快速召回一批，再用更精确的交叉编码器模型精排，兼顾速度和准确率。第四是 MMR，在相关性和多样性之间做平衡，避免检索出来的几块内容高度重复。

## 引用来源追踪

RAG 相对于直接问模型的最大产品价值是可溯源。前端展示答案时同时列出用到了哪几段原文，用户可以点进去验证模型有没有瞎编。这在调试时也很有用：检索错了还是模型答错了，一眼就能分清。
