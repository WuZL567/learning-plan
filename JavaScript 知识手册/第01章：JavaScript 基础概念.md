# 第01章：JavaScript 基础概念

## 1.1 函数优先（Function-First）

**一句话解释：**
函数的地位特别高，跟普通数据（比如数字、文字）平起平坐，你可以把函数当"东西"传来传去。

**餐厅比喻：**
普通语言里，菜单（数据）和厨师（函数）是分开的，你只能点菜。但在 JS 这家餐厅里，你不仅可以点菜，还可以把**厨师本人**当作一道"菜"端来端去——比如你跟服务员说："把张师傅打包送到我朋友的餐厅去，让他在那边炒菜。"函数可以当参数传给别人，也可以被别人返回给你。

**代码示例：**

~~~javascript
// 把函数当"东西"传给另一个函数
function 做菜(厨师) {
  厨师();  // 调用传进来的"厨师"
}

function 炒饭() {
  console.log("正在炒蛋炒饭...");
}

function 煮面() {
  console.log("正在煮牛肉面...");
}

做菜(炒饭);  // 输出: 正在炒蛋炒饭...
做菜(煮面);  // 输出: 正在煮牛肉面...
~~~

看到了吗？`炒饭`和`煮面`这两个函数，被当成"东西"塞给了`做菜`。**函数就是一等公民，可以被传来传去。**

## 1.2 即时编译（JIT = Just In Time）

**一句话解释：**
先一句一句跑着，发现哪段代码老是反复用，就**临时**把它编译成更快的版本。

**餐厅比喻：**
你第一天去餐厅，点什么厨师现做现学，比较慢。第二天你又来了，还是点那几道菜——厨师发现"这几道菜天天有人点"，于是提前把食材切好、调料配好放在旁边，下次再点就飞快上菜。**不是一开始就全部准备好（编译型），也不是每次都要从零开始（解释型），而是用着用着发现常用的东西就加速。**

**代码示例：**

~~~javascript
// 假设这段代码在一个循环里反复执行
function 计算总价(单价, 数量) {
  return 单价 * 数量;
}

// 模拟：这个函数被调用了10万次
for (let i = 0; i < 100000; i++) {
  计算总价(25, 3);
}
~~~

> - 第1次调用：JS 引擎说"哦，第一次见，先正常跑着"（解释执行）
> - 第1000次调用：JS 引擎发现"这函数也太常用了吧"，于是把它**优化编译成更快的机器码**
> - 第10万次调用：飞速执行
>
> **这就是 JIT——不是一开始就全部编译好，而是边跑边优化"热门代码"。**

## 1.3 基于原型（Prototype-Based）

**一句话解释：**
不需要先写 class 蓝图，直接造对象，然后"抄"着改。

**餐厅比喻：**
别的语言是——你要开连锁店，必须先写一份厚厚的《标准化操作手册》（class），然后每家店照着手册开。JS 是——你先开一家店直接干，干得不错，然后说"下一家店照着这家来，把桌子换成红色的"。第一家店就是**原型（prototype）**，后面的新店从它身上"抄"，再改。

**代码示例：**

~~~javascript
// 直接造一家店
const 原版奶茶店 = {
  招牌: "珍珠奶茶",
  价格: 12,
  做饮料() {
    console.log(`做一杯${this.招牌}，收${this.价格}元`);
  }
};

// 从原版"抄"出一家新店，改改就行
const 新店 = Object.create(原版奶茶店);
新店.招牌 = "杨枝甘露";
新店.价格 = 18;

原版奶茶店.做饮料();  // 做一杯珍珠奶茶，收12元
新店.做饮料();        // 做一杯杨枝甘露，收18元
~~~

**没有写 class，没有画蓝图。第一家店就是原型，新店从它身上抄，再改不同的地方。**

## 1.4 多范式（Multi-Paradigm）

**一句话解释：**
JS 不限你用哪种风格写代码，随你挑。

**餐厅比喻：**
有的餐厅只许你做法餐（只能用一种风格），有的只许你做日料。JS 这家餐厅说：**你法餐、日料、川菜、分子料理随便做，我都能接。** 你可以用面向对象写，也可以用函数式写，也可以混着来。

**代码示例：**

~~~javascript
const 订单们 = [
  { 菜名: "宫保鸡丁", 价格: 38 },
  { 菜名: "麻婆豆腐", 价格: 22 },
  { 菜名: "红烧肉",   价格: 55 },
];

// ===== 命令式风格：一步步告诉它怎么做 =====
let 总价 = 0;
for (let i = 0; i < 订单们.length; i++) {
  总价 += 订单们[i].价格;
}
console.log("命令式算出总价:", 总价);  // 115

// ===== 声明式（函数式）风格：只说要什么 =====
const 总价2 = 订单们.reduce((累加, 订单) => 累加 + 订单.价格, 0);
console.log("声明式算出总价:", 总价2);  // 115
~~~

> 同样是"算总价"，两种写法都能用。**JS 不限制你用哪种风格，这就是多范式。**

## 1.5 单线程（Single-Threaded）

**一句话解释：**
JS 只有**一个厨师**在炒菜，同一时间只能做一道菜。但这个厨师特别聪明——遇到要等的事情（比如等水烧开），他**不会傻站在那等**，而是先去切菜，等水开了再回来。这就是 JS 的**事件循环**机制——虽然只有一个厨师，但通过"不傻等"的方式看起来像同时在干很多事。

**代码示例：**

~~~javascript
console.log("1. 开始接单");

setTimeout(() => {
  console.log("3. 汤煮好了，上菜！");
}, 2000);  // 等2秒后执行

console.log("2. 先去收拾桌子");

// 输出顺序：
// 1. 开始接单
// 2. 先去收拾桌子     ← 不会傻等汤煮好，先去干别的
// 3. 汤煮好了，上菜！  ← 2秒后回来上菜
~~~

## 1.6 面向对象 / 命令式 / 声明式

### 面向对象

**一句话解释：**
把东西看成一个个**对象**，每个对象有自己的**属性**（特征）和**方法**（能干的事）。

**餐厅比喻：**
一个"服务员"就是一个对象。
- 属性：名字叫小王、工号008、今天心情不错
- 方法：能点菜、能上菜、能结账

你不用关心小王内部怎么记账、怎么端盘子，你只需要叫他"上菜"，他就上菜。**把复杂的东西包装成一个对象，对外只暴露你能用的功能。**

**代码示例：**

~~~javascript
class 服务员 {
  constructor(名字) {
    this.名字 = 名字;     // 属性：名字
    this.在忙 = false;    // 属性：状态
  }

  点菜(菜品) {            // 方法：点菜
    console.log(`${this.名字}记下了：${菜品}`);
  }

  上菜(菜品) {            // 方法：上菜
    console.log(`${this.名字}把${菜品}端上桌了`);
  }
}

const 小王 = new 服务员("小王");
小王.点菜("糖醋里脊");    // 小王记下了：糖醋里脊
小王.上菜("糖醋里脊");    // 小王把糖醋里脊端上桌了
~~~

### 命令式

**一句话解释：**
你一步步告诉计算机**怎么做**。

**餐厅比喻：**
你走进厨房，亲自指挥：
"先热锅，倒油，等油冒烟，放葱姜爆香，下肉翻炒两分钟，加酱油……"
**每一步你都自己说清楚，精确到动作。**

### 声明式

**一句话解释：**
你只告诉计算机你**要什么**，不管它怎么做。

**餐厅比喻：**
你坐在座位上，跟服务员说："给我来一份糖醋里脊。"
你不关心厨房怎么切肉、怎么调汁、油温多少——你只说了**你要的结果**，具体怎么做交给厨师。

**命令式 vs 声明式代码对比：**

~~~javascript
const 菜单 = ["宫保鸡丁", "麻婆豆腐", "红烧肉", "鱼香肉丝", "回锅肉"];

// ===== 命令式：一步步说怎么做 =====
const 便宜菜 = [];
for (let i = 0; i < 菜单.length; i++) {
  if (菜单[i].includes("豆")) {
    便宜菜.push(菜单[i]);
  }
}
console.log(便宜菜);  // ["麻婆豆腐"]

// ===== 声明式：只说要什么 =====
const 便宜菜2 = 菜单.filter(菜 => 菜.includes("豆"));
console.log(便宜菜2);  // ["麻婆豆腐"]
~~~

## 1.7 ECMAScript 标准（ECMA-262 / ECMA-402）

**一句话解释：**
ECMAScript 是 JavaScript 的"官方说明书"，规定了 JS 该怎么写、该怎么运行。ECMA-402 是补充标准，专门处理多国语言、日期、货币等本地化问题。

**餐厅比喻：**
你家楼下有好几家黄焖鸡米饭，味道都不太一样。于是行业协会出了一本《黄焖鸡米饭官方标准手册》，规定了"鸡肉要切多大、酱料配比是多少、焖多久"。**这本手册不等于黄焖鸡本身，但所有做黄焖鸡的人（浏览器厂商）都得照着它来。** ECMAScript 就是这本手册，JavaScript 就是各家做出来的黄焖鸡。

主手册（ECMA-262）教你怎么做菜，但没教你怎么招待外国客人。于是又出了一本补充手册（ECMA-402），教你"怎么用美元标价、怎么用日语打招呼、日期写成月/日/年还是日/月/年"。**菜还是那些菜，但服务方式要根据客人来自哪里做调整。**

**代码示例：**

~~~javascript
// ECMAScript 标准规定了这些语法该怎么用
// 比如箭头函数，就是 ES6（ES2015）标准里写明的新语法
const 做菜 = (菜名) => `正在做${菜名}`;

// 解构赋值，也是标准里规定的
const { 桌号, 菜品 } = { 桌号: 3, 菜品: "宫保鸡丁" };
console.log(桌号);  // 3
console.log(菜品);  // 宫保鸡丁

// ECMA-402：国际化能力
const 价格 = 1280;
console.log(new Intl.NumberFormat('zh-CN', { style: 'currency', currency: 'CNY' }).format(价格));
// ¥1,280.00
console.log(new Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' }).format(价格));
// $1,280.00
console.log(new Intl.NumberFormat('ja-JP', { style: 'currency', currency: 'JPY' }).format(价格));
// ￥1,280
~~~

## 1.8 浏览器实现 / 提案阶段（Stage 3/4）

**一句话解释：**
浏览器厂商（Chrome、Firefox 等）按照标准把 JS 功能"真正做出来"，让用户能用。一个 JS 新功能从提出想法到正式加入标准，要经过多个阶段。

**餐厅比喻：**
协会出了标准手册（ECMAScript），但手册上的菜不会自己出现在餐桌上。得有**真正的餐厅**（浏览器）买食材、雇厨师、按手册做菜，顾客才能吃到。Chrome 是一家大餐厅，Firefox 是另一家，它们都在按同一本手册做菜，但各自的厨房设备不同，做出来的速度和细节可能略有差异。

一个新功能从提出到加入标准的流程：

| 阶段 | 餐厅比喻 |
|---|---|
| Stage 0 | 有人随口提了一嘴"要不加个芝士焗龙虾？" |
| Stage 1 | 开始认真讨论这道菜怎么做 |
| Stage 2 | 出了初版菜谱，大家审阅 |
| **Stage 3** | 菜谱基本定稿，**有几家大胆的餐厅已经开始试做了**（浏览器开始实现） |
| **Stage 4** | 试做成功，**正式写入标准手册**，所有餐厅都得学 |

**代码示例：**

~~~javascript
// "可选链 ?." 曾经也是提案，现在已经 Stage 4 正式纳入标准了
const 订单 = { 顾客: { 名字: "小李" } };

console.log(订单.顾客?.名字);      // 小李
console.log(订单.服务员?.名字);    // undefined（不报错）

// 而 "管道操作符 |>" 曾经是 Stage 2 的提案，最终没有进入标准
// const 结果 = 菜品 |> 清洗 |> 切块 |> 炒熟;  // ❌ 这不是合法 JS
~~~

## 1.9 对象标准库概览（完整版 22 个内置对象）

**一句话解释：**
JS 自带的一套"现成工具箱"，开箱即用，不用自己造。

**餐厅比喻：**
你刚开一家餐厅，不用什么都自己从零做起。房东已经给你配好了**冰箱（Array）、时钟（Date）、计算器（Math）**。你直接拿来用就行，不用自己造冰箱、造时钟。这些就是 JS 自带的标准库——**别人提前造好的东西，你直接用。**

## 1.10 核心语言元素 / 客户端 JS / 服务器端 JS / DOM

### 核心语言元素

**一句话解释：**
JS 最基础的"语法零件"——运算符、控制结构和语句，就像语言里的"字词和标点"。

**餐厅比喻：**
不管你是开法餐还是川菜，你都得会一些最基础的本事：**算账（运算符）、判断该做什么（控制结构）、下达指令（语句）**。这些不是某道具体的菜，而是你**做任何菜都需要的底层能力**。

**代码示例：**

~~~javascript
const 营业额 = 8500;
const 成本 = 6200;

// 运算符：算账用的
const 利润 = 营业额 - 成本;       // 减法
const 打折价 = 营业额 * 0.8;      // 乘法
const 是否赚钱 = 利润 > 0;        // 比较运算
console.log(`利润：${利润}，打折价：${打折价}，赚钱了吗：${是否赚钱}`);
// 利润：2300，打折价：6800，赚钱了吗：true

// 控制结构（if）：做判断
if (利润 > 2000) {
  console.log("今天表现不错，加个菜！");
} else {
  console.log("一般般，省着点用。");
}
// 今天表现不错，加个菜！

// 控制结构（for 循环）：重复干活
const 每桌消费 = [220, 180, 350, 90, 410];
let 总消费 = 0;
for (const 消费 of 每桌消费) {
  总消费 += 消费;
}
console.log(`今日总收入：${总消费}元`);  // 今日总收入：1250元
~~~

### 客户端 JavaScript

**一句话解释：**
跑在用户浏览器里的 JS，负责页面长什么样、用户点了什么。

**餐厅比喻：**
餐厅有两个战场：
- **前厅（客户端）**：顾客看得见的地方——菜单长什么样、服务员怎么接待、桌子怎么摆
- **后厨（服务器端）**：顾客看不见的地方——食材从哪来、库存还有多少、账目怎么记

客户端 JS 就是**前厅**，它管的是顾客眼睛能看到、手能摸到的一切。

客户端 JS 通过提供控制浏览器及其**文档对象模型（DOM）**的对象对核心语言进行扩展。例如：客户端扩展允许应用程序将元素放在某个 HTML 表单中，并且支持响应用户事件，比如鼠标点击、表单输入和页面导航。

### DOM（文档对象模型）

**一句话解释：**
浏览器把网页变成了一棵树状结构，JS 可以通过这棵树找到并修改页面上的任何元素。

**餐厅比喻：**
你的餐厅有一面"菜单墙"，上面贴满了菜品卡片。DOM 就是这面墙的**完整结构图**：

~~~
菜单墙（document）
├── 招牌区（header）
│   └── 大标题（h1）："老王饭馆"
├── 菜品区（main）
│   ├── 川菜栏（section）
│   │   ├── 麻婆豆腐（div）
│   │   └── 水煮鱼（div）
│   └── 粤菜栏（section）
│       ├── 白切鸡（div）
│       └── 煲仔饭（div）
└── 结账区（footer）
    └── 电话号码（p）
~~~

有了这张图，JS 就能说："找到川菜栏里的麻婆豆腐，把它的价格改了！"

**代码示例：**

~~~javascript
// JS 通过 DOM 找到页面上的元素并修改它
const 标题 = document.getElementById("店名");
const 特价 = document.querySelector(".今日特价");
const 按钮 = document.getElementById("改价按钮");

// 改文字
标题.textContent = "老王饭馆·五周年";

// 点按钮时，改价格
按钮.addEventListener("click", function() {
  特价.textContent = "特价：28元！";
  特价.style.color = "red";
});
~~~

### 服务器端 JavaScript

**一句话解释：**
跑在服务器上的 JS（如 Node.js），负责处理数据、读写文件、跟数据库打交道。

**餐厅比喻：**
顾客在前厅看到的只是一道菜端上来，但**后厨**在忙活的事情多着呢：
- 仓库还有多少食材？（读数据库）
- 今天的采购单存到哪里？（写文件）
- 这个顾客上次来过，点了什么？（维护用户状态）

服务器端 JS 则通过提供和在服务器上运行 JavaScript 有关的对象对核心语言进行扩展。例如：服务器端扩展支持应用程序和数据库通信，提供应用不同调用间的信息连续性，或者在服务器上执行文件操作。

**代码示例（Node.js 环境）：**

~~~javascript
// 读写文件（后厨整理档案）
const 文件模块 = require('fs');

// 把今天的营业记录写进文件
文件模块.writeFileSync('今日记录.txt', '今日营业额：8500元');
console.log("记录已保存！");

// 从文件里读出来
const 记录 = 文件模块.readFileSync('今日记录.txt', 'utf-8');
console.log(记录);  // 今日营业额：8500元
~~~

### 客户端扩展 vs 服务器端扩展

**一句话解释：**
核心 JS 是一个"通用底座"，往上面加不同的"插件"就能在不同场景用。

**餐厅比喻：**
JS 核心就像一个**基础款厨师**——会切菜、会颠勺、会调味（运算符、控制结构、函数等）。然后你给他加不同的"技能包"：
- 给他加"前厅服务技能包"（客户端扩展：DOM、事件）→ 他去前厅当服务员，管菜单展示和顾客互动
- 给他加"后厨管理技能包"（服务器端扩展：文件系统、数据库）→ 他去后厨当大厨，管食材和库存

**厨师还是同一个厨师，但装了不同的技能包，干不同的活。**

~~~
┌───────────────────────────────────┐
│         JS 核心语言               │
│  运算符 / 控制结构 / 函数 / 对象   │
│         （通用底座）               │
├──────────────┬────────────────────┤
│  客户端扩展   │   服务器端扩展      │
│  · DOM       │   · 文件系统        │
│  · 事件监听   │   · 数据库通信      │
│  · 浏览器 API │   · 网络请求处理     │
├──────────────┼────────────────────┤
│  跑在浏览器里  │   跑在服务器上      │
│  管"前厅"     │   管"后厨"         │
└──────────────┴────────────────────┘
~~~

## 1.11 动态特性（6 个）

**一句话解释：**
JavaScript 的动态特性包括运行时对象的构造、变量参数列表、函数变量、动态脚本创建（通过 eval）、对象内枚举和源代码恢复。

### 1.11.1 运行时对象的构造

**一句话解释：**
程序跑着的时候，随时可以造新对象，不需要提前计划好。

**餐厅比喻：**
你去吃饭，本来菜单上没有"番茄鸡蛋盖饭"，你跟服务员说"能不能给我单独配一个"，服务员说"好嘞"，当场给你拼出一道新菜。**不是提前写好菜单才能卖，而是顾客来了，随时组合、随时创造。**

**代码示例：**

~~~javascript
// 程序跑着跑着，根据需要临时造一个新对象
const 菜名 = "皮蛋豆腐";
const 价格 = 18;

// 当场组装出一道菜
const 新菜 = { 菜名, 价格, 是否今日特惠: true };
console.log(新菜);
// { 菜名: "皮蛋豆腐", 价格: 18, 是否今日特惠: true }

// 甚至对象的结构也可以随时加
新菜.厨师推荐语 = "清凉爽口，夏日必备";
console.log(新菜.厨师推荐语);  // 清凉爽口，夏日必备
~~~

看到了吗？**没有提前声明"这道菜有哪几个字段"，程序跑着跑着就造出来了，还能随时往上面加东西。**

### 1.11.2 变量参数列表

**一句话解释：**
调用函数时，传几个参数都行，不固定。

**餐厅比喻：**
你去火锅店，跟服务员说"给我上蘸料"，你可以说：
- "就来个麻酱"（1个）
- "麻酱、蒜泥、香油"（3个）
- "麻酱、蒜泥、香油、辣椒、醋、花生碎"（6个）

服务员不会说"必须报3个，多了不行少了不行"，**你说几个他就给你上几个。**

**代码示例：**

~~~javascript
// 用 ... 收集所有传进来的参数，不管传了几个
function 上蘸料(...所有蘸料) {
  console.log(`本次上了${所有蘸料.length}种蘸料：${所有蘸料.join("、")}`);
}

上蘸料("麻酱");
// 本次上了1种蘸料：麻酱

上蘸料("麻酱", "蒜泥", "香油");
// 本次上了3种蘸料：麻酱、蒜泥、香油

上蘸料("麻酱", "蒜泥", "香油", "辣椒", "醋", "花生碎");
// 本次上了6种蘸料：麻酱、蒜泥、香油、辣椒、醋、花生碎
~~~

看到了吗？**同一个函数，传1个参数能用，传6个参数也能用，参数数量是活的。**

### 1.11.3 函数变量

**一句话解释：**
函数可以赋值给变量，像存一道菜名一样存起来。

**餐厅比喻：**
你把你最信任的张师傅的做菜流程写在一张纸条上，取名叫"祖传秘方"。然后你可以：
- 把这张纸条交给任何一个厨师，让他照着做
- 把这张纸条存在柜子里，需要的时候再拿出来用
- 把这张纸条传给朋友，朋友的餐厅也能用

**纸条就是变量，上面写的内容就是函数。**

**代码示例：**

~~~javascript
// 把一个函数存进变量
const 祖传秘方 = function(食材) {
  console.log(`把${食材}用祖传方法处理，出锅！`);
};

// 像普通变量一样用它
祖传秘方("红烧肉");  // 把红烧肉用祖传方法处理，出锅！

// 也可以传给别人
const 小李的新菜谱 = 祖传秘方;
小李的新菜谱("排骨");  // 把排骨用祖传方法处理，出锅！
~~~

### 1.11.4 动态脚本创建（eval）

**一句话解释：**
程序跑着的时候，临时"写"一段代码然后立刻执行。

**餐厅比喻：**
你走进餐厅，给厨师一张纸条，上面写着一道菜的做法。厨师看完，**当场就按这个做法做出来了**——但这张纸条是你进了餐厅之后才写的，不是提前准备好的菜单。

问题是：如果你乱写（比如"把厨房炸了"），厨师也会照做，**所以非常危险。**

**代码示例：**

~~~javascript
const 我的指令 = 'console.log("临时加菜：蒜蓉西兰花！")';

// eval 会把字符串当代码执行
eval(我的指令);
// 输出：临时加菜：蒜蓉西兰花！

// 动态计算也行
const 运算式 = "12 + 30 + 8";
console.log(eval(运算式));  // 50
~~~

看到了吗？**一段普通的字符串文字，通过 eval 就变成了正在运行的代码。** 但记住——这就像随便给厨师递纸条，很不安全，实际开发中要尽量避免。

### 1.11.5 对象内枚举（for...in 和 Object 工具方法）

**一句话解释：**
把一个对象里所有的"属性名"挨个翻出来看。

**餐厅比喻：**
你拿到一张桌子的账单，上面列了一堆东西。你想**从头到尾把每一条都看一遍**：这桌点了什么菜、多少钱、几号桌、几位客人……一条不漏地翻完。

**代码示例：**

~~~javascript
const 账单 = {
  桌号: 5,
  客人数: 4,
  菜品: "红烧肉、麻婆豆腐",
  总价: 93
};

// for...in：一条一条翻
for (const 项目 in 账单) {
  console.log(`${项目}：${账单[项目]}`);
}
// 桌号：5
// 客人数：4
// 菜品：红烧肉、麻婆豆腐
// 总价：93

// Object.keys()：直接拿到所有"项目名"
console.log(Object.keys(账单));
// ["桌号", "客人数", "菜品", "总价"]

// Object.values()：直接拿到所有"值"
console.log(Object.values(账单));
// [5, 4, "红烧肉、麻婆豆腐", 93]
~~~

看到了吗？**不知道账单上到底写了几项，但代码能把每一项都翻出来，这就是枚举。**

### 1.11.6 源代码恢复（toString()）

**一句话解释：**
函数能把自己"当初是怎么写的"原文吐出来。

**餐厅比喻：**
你以前把一道菜的做法写在了菜谱上，过了很久你忘了当时写的啥。没关系，**翻出那本菜谱，原文还在**，一个字都没变。

**代码示例：**

~~~javascript
function 红烧肉做法(肉) {
  // 先焯水
  肉 = "焯水后的" + 肉;
  return `把${肉}放锅里，加酱油炖40分钟`;
}

// 查看这个函数的原始代码
console.log(红烧肉做法.toString());
// function 红烧肉做法(肉) {
//   // 先焯水
//   肉 = "焯水后的" + 肉;
//   return `把${肉}放锅里，加酱油炖40分钟`;
// }
~~~

看到了吗？**当初写函数时的代码原文，直接就被打印出来了，这就是源代码恢复。**
