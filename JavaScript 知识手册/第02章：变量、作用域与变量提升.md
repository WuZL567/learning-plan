# 第02章：变量、作用域与变量提升

## 2.1 作用域（全局 / 模块 / 函数 / 块级）

**一句话解释：**
作用域决定了你声明的变量**在哪里能用，在哪里不能用**。

**餐厅比喻：**
你贴在公告栏上的告示（全局），全餐厅都能看到；你写在后厨黑板上的备忘（函数），只有后厨的人看得到；你写在便签纸上贴在某张桌子上的备注（块级），只有那张桌子附近的人看得到。**你把信息写在哪，决定了谁能看见它。**

**代码示例：**

~~~javascript
// ========== 全局作用域 ==========
const 餐厅名 = "老王饭馆";  // 在代码块之外，整个程序都能用

function 开门营业() {
  console.log(`欢迎来到${餐厅名}`);  // ✅ 函数内能访问全局变量
}

console.log(餐厅名);  // ✅ 全局都能用

// ========== 函数作用域 ==========
function 后厨备菜() {
  const 秘制酱料 = "酱油+醋+蒜末";  // 只在函数内能用
  console.log(秘制酱料);  // ✅
}

// console.log(秘制酱料);  // ❌ 报错！外面看不到

// ========== 块级作用域 ==========
if (true) {
  const 今日特价 = "红烧肉";  // 只在这个 { } 内能用
  let 折扣 = 0.8;              // 只在这个 { } 内能用
  console.log(今日特价);       // ✅
}
// console.log(今日特价);  // ❌ 报错！外面看不到

// ========== 模块作用域 ==========
// 在一个 .js 文件中（使用 ES Module）
// const 内部配置 = { API: "xxx" };  // 只有本文件能用，别的文件导入不了（除非 export）
~~~

### 四种作用域的层级关系

~~~
┌─────────────────────────────────────────┐
│           全局作用域（最外层）            │
│  任何地方都能访问                         │
│                                         │
│  ┌─────────────────────────────────┐    │
│  │        函数作用域                │    │
│  │  只有函数内部能访问               │    │
│  │                                 │    │
│  │  ┌─────────────────────────┐    │    │
│  │  │    块级作用域            │    │    │
│  │  │  只有 { } 内部能访问     │    │    │
│  │  │                         │    │    │
│  │  └─────────────────────────┘    │    │
│  └─────────────────────────────────┘    │
│                                         │
│  模块作用域：整个文件是一个"模块房间"     │
│  房间内的东西外面看不到，除非你主动开门   │
└─────────────────────────────────────────┘
~~~

## 2.2 全局变量 vs 局部变量

**一句话解释：**
在函数**外面**声明的变量叫全局变量，**任何地方**都能用；在函数**里面**声明的变量叫局部变量，只有**函数内部**能用。

**餐厅比喻：**
- **全局变量** = 贴在餐厅公告栏上的信息（营业时间、今日特价），**所有顾客和员工**都能看到
- **局部变量** = 后厨黑板上的笔记（备料清单、调味比例），只有**厨房里的人**才能看到，顾客看不到

**代码示例：**

~~~javascript
const 今日特价 = "麻婆豆腐";  // 全局变量：公告栏上的信息

function 后厨备菜() {
  const 备料 = "豆腐、肉末、辣椒";  // 局部变量：后厨黑板上的笔记
  console.log(今日特价);  // ✅ 后厨能看公告栏
  console.log(备料);      // ✅ 后厨当然知道自己的笔记
}

function 前台接待() {
  console.log(今日特价);  // ✅ 前台也能看公告栏
  // console.log(备料);  // ❌ 前台看不到后厨的黑板
}

后厨备菜();  // 后厨能访问全局变量，也能访问自己的局部变量
前台接待();  // 前台能访问全局变量，但访问不了后厨的局部变量
~~~

### 全局变量和局部变量同名时

**一句话解释：**
如果函数内部声明了一个跟外面**同名的变量**，函数内部会"用自己的"，就像后厨也有一个公告板，挡住了外面的公告栏。

**餐厅比喻：**
餐厅公告栏上写着"今日特价：红烧肉"（全局变量）。但是后厨的黑板上也写着"今日特价：麻婆豆腐"（局部变量）。后厨的人看自己黑板上的，看到的是麻婆豆腐；前厅的人看公告栏，看到的还是红烧肉。**互不影响。**

~~~javascript
const 今日特价 = "红烧肉";  // 全局变量：公告栏

function 后厨() {
  const 今日特价 = "麻婆豆腐";  // 局部变量：后厨黑板（同名！）
  console.log(今日特价);  // 麻婆豆腐（用自己黑板上的）
}

console.log(今日特价);  // 红烧肉（用公告栏上的）

后厨();  // 后厨里说的"今日特价"是麻婆豆腐，用的是自己黑板上的值

console.log(今日特价);  // 红烧肉（公告栏没被影响，还是红烧肉）
~~~

**一句话记住规则：**
> **内部有就用内部的，没有才去外面找。就像后厨有黑板就看自己的，没有才抬头看餐厅公告栏。**

## 2.3 作用域链

**一句话解释：**
当代码需要用到一个变量时，JS 引擎会**先在当前作用域找，找不到就去外层找，一层一层往外找，直到找到全局作用域**。这个查找路径就是作用域链。

**餐厅比喻：**
你在厨房里找胡椒粉——
1. 先看**灶台旁边**有没有（当前作用域）
2. 没有，去**调料柜**找（外层函数作用域）
3. 还没有，去**仓库**找（更外层作用域）
4. 最后去**公告栏**看看有没有记录（全局作用域）
5. 都没有 → 报错：胡椒粉 is not defined

**代码示例：**

~~~javascript
const 品牌 = "老王饭馆";  // 全局作用域：仓库级别

function 大厅() {
  const 装修风格 = "中式";  // 大厅作用域

  function 包间() {
    const 桌号 = 8;  // 包间作用域

    console.log(桌号);      // ✅ 先在包间找，找到了 → 8
    console.log(装修风格);  // ✅ 包间没有，往上找大厅，找到了 → "中式"
    console.log(品牌);      // ✅ 包间、大厅都没有，再往上找全局，找到了 → "老王饭馆"
    // console.log(厨师);   // ❌ 包间→大厅→全局都没找到 → 报错！
  }

  包间();
}

大厅();
~~~

### 作用域链图解

~~~
查找顺序：灶台 → 调料柜 → 仓库 → 报错

┌─── 包间作用域（最内层）──────┐
│  桌号 = 8                   │  ← ① 先在这找
│                             │
│  ┌─── 大厅作用域 ────────┐  │
│  │  装修风格 = "中式"     │  │  ← ② 找不到，来这找
│  │                       │  │
│  │  ┌─── 全局作用域 ──┐  │  │
│  │  │  品牌 = "老王"   │  │  │  ← ③ 还找不到，来这找
│  │  │                 │  │  │
│  │  │  (都找不到→报错)  │  │  │  ← ④ 还没有就报错
│  │  └─────────────────┘  │  │
│  └───────────────────────┘  │
└─────────────────────────────┘
~~~

### 作用域链的核心规则

~~~
规则1：查找方向是 从内到外（单向）
  → 内层可以访问外层，外层不能访问内层
  → 你站在包间里可以看到大厅，但你站在大厅看不到包间里在聊什么

规则2：找到就停
  → 在某一层找到了同名变量，就停止查找，用这一层的
  → 找到胡椒粉就用，不会再去看仓库里有没有另一瓶

规则3：外层不知道内层
  → 无论内层怎么改自己的变量，外层都不知道
  → 包间里吵翻天，大厅也听不到

规则4：同一级互不可见
  → 两个并列的函数互相看不到对方的变量
  → 包间A看不到包间B里有什么
~~~

### 作用域链的实际陷阱

~~~javascript
// 陷阱：误以为内层修改会影响外层
const 价格 = 100;

function 折扣活动() {
  const 价格 = 80;  // 这是新声明了一个局部变量，不是修改全局的！
  console.log(`活动价：${价格}`);  // 80
}

折扣活动();                 // 活动价：80
console.log(`原价：${价格}`); // 原价：100（全局的没变！）

// 如果真的想修改全局的：
let 价格2 = 100;

function 折扣活动2() {
  价格2 = 80;  // 没有用 const/let 声明，直接赋值 → 修改的是全局的
  console.log(`活动价：${价格2}`);  // 80
}

折扣活动2();
console.log(`现价：${价格2}`);  // 80（全局的被改了）
~~~

## 2.4 变量提升（Hoisting）

**一句话解释：**
在代码执行之前，JS 引擎会**把变量的声明"提前"到作用域的顶部**，但赋值不会提前。

**餐厅比喻：**
你一进餐厅，服务员就告诉你"我们有红烧肉这道菜"（声明提升），但**菜还没做好**（赋值没提升）。你点红烧肉，服务员说"有这道菜，但现在还没做好，你得等"。

**代码示例：**

~~~javascript
// ========== var 的提升 ==========
console.log(菜品);  // undefined（不是报错！声明被提升了，但值还没赋）
var 菜品 = "红烧肉";
console.log(菜品);  // 红烧肉

// JS 引擎实际看到的是这样的：
// var 菜品;              ← 声明被提升到顶部
// console.log(菜品);     ← 此时菜品存在，但值是 undefined
// 菜品 = "红烧肉";       ← 赋值还在原地
// console.log(菜品);     ← 红烧肉

// ========== let / const 的提升 ==========
// console.log(今日菜单);  // ❌ 报错！ReferenceError
let 今日菜单 = ["红烧肉", "麻婆豆腐"];
console.log(今日菜单);     // ["红烧肉", "麻婆豆腐"]
~~~

### var / let / const 提升行为对比

| | var | let | const |
|---|---|---|---|
| 是否提升 | ✅ 提升 | ✅ 提升 | ✅ 提升 |
| 提升后的初始值 | `undefined` | 无（暂时性死区） | 无（暂时性死区） |
| 能否先使用再声明 | 能用（但是 undefined） | ❌ 报错 | ❌ 报错 |
| 作用域 | 函数作用域 | 块级作用域 | 块级作用域 |
| 能否重复声明 | ✅ 能 | ❌ 不能 | ❌ 不能 |
| 能否不赋值 | ✅ 能（默认 undefined） | ✅ 能（默认 undefined） | ❌ 不能（必须赋值） |

## 2.5 暂时性死区（TDZ = Temporal Dead Zone）

**一句话解释：**
用 `let` / `const` 声明的变量，在声明语句之前的区域叫做"暂时性死区"——在这个区域内**变量存在但不能使用**，用了就报错。

**餐厅比喻：**
你一进餐厅就知道"今天有红烧肉"（let 声明被提升了），但在厨师**正式宣布"红烧肉做好了"之前**，你不能点这道菜。从你进门到宣布做好之间的这段时间，就是"暂时性死区"——**你知道它存在，但你碰不到。**

**代码示例：**

~~~javascript
// ========== 暂时性死区演示 ==========
{
  // 从这里开始，到 let 菜品 这一行，就是"暂时性死区"
  // console.log(菜品);  // ❌ ReferenceError: Cannot access '菜品' before initialization

  let 菜品 = "红烧肉";  // 声明 + 赋值，死区结束
  console.log(菜品);     // ✅ 红烧肉
}

// ========== 为什么叫"暂时性"？ ==========
// 因为只有在代码执行到 let 声明那一行之前的那一小段时间内不能用
// 执行过声明语句之后，就可以正常使用了

// ========== var 没有暂时性死区 ==========
{
  console.log(菜品2);  // ✅ undefined（不报错，因为 var 没有 TDZ）
  var 菜品2 = "红烧肉";
}
~~~

### 常见的 TDZ 陷阱

~~~javascript
// 陷阱1：在 if 块中提前使用
let x = 10;
if (true) {
  // console.log(x);  // ❌ TDZ！这个块里的 x 已经被 let 声明挡住了
  let x = 20;
  console.log(x);     // ✅ 20
}

// 陷阱2：typeof 也不能绕过
// console.log(typeof 还没声明的let变量);  // ❌ ReferenceError！
// 这是 let/const 的 TDZ 唯一会让 typeof 报错的情况
console.log(typeof 完全没声明的东西);  // ✅ "undefined"（正常情况）
~~~

## 2.6 函数声明提升

**一句话解释：**
函数声明（`function xxx()`）会被**整体提升**到作用域顶部——声明和函数体都提升，所以可以在声明之前调用。

**餐厅比喻：**
函数声明就像餐厅**提前贴出来的菜谱**——你一进门就能看到完整的做法（包括怎么做、放什么料），所以你直接说"来一份"就行。

**代码示例：**

~~~javascript
// ========== 函数声明：整体提升（声明 + 函数体都提升） ==========
做菜();  // ✅ 可以在声明之前调用！输出：正在做菜...

function 做菜() {
  console.log("正在做菜...");
}

// JS 引擎实际看到的是：
// function 做菜() {         ← 整个函数被提升到顶部
//   console.log("正在做菜...");
// }
// 做菜();                   ← 调用时函数已经定义好了

// ========== 函数表达式：只有变量声明提升，函数本身不提升 ==========
// 做菜2();  // ❌ TypeError: 做菜2 is not a function

var 做菜2 = function() {
  console.log("正在做菜2...");
};

做菜2();  // ✅ 这里才能调用

// JS 引擎实际看到的是：
// var 做菜2;                ← 只有变量声明提升，值是 undefined
// 做菜2();                  ← undefined() → TypeError！
// 做菜2 = function() {      ← 赋值还在原地
//   console.log("正在做菜2...");
// };
~~~

### 函数声明 vs 函数表达式的提升对比

| | 函数声明 | 函数表达式 |
|---|---|---|
| 写法 | `function 做菜() {}` | `const 做菜 = function() {}` |
| 提升方式 | **整体提升**（声明+函数体） | 只有变量声明提升（跟 var/let/const 一样） |
| 声明前能调用吗 | ✅ 能 | ❌ 不能 |
| 餐厅比喻 | 完整菜谱提前贴好了 | 先告诉你"有道菜"，但做法还没给 |

## 2.7 全局变量深入（window 挂载 / 隐式全局变量 / globalThis）

**一句话解释：**
在函数外部声明的变量成为全局变量。在浏览器中，全局变量被设置为 `window` 对象的属性。不使用 `var`、`let` 或 `const` 声明的变量是隐式全局变量。`window` 是浏览器中的全局对象，可以用它来访问全局变量。

**餐厅比喻：**
- **`window`** = 餐厅的公告栏，所有员工和顾客都能看到上面的内容
- **显式全局变量**（用 `var` 声明）= 你正式申请后贴上去的告示，会被挂在公告栏上
- **隐式全局变量**（没用 `var`/`let`/`const`）= 你直接在公告栏上随手写了一笔，虽然也能看到，但**不是正规操作**
- **`globalThis`** = 不管你在哪家分店（浏览器/Node.js/手机端），都统一用这个称呼来叫公告栏

### 显式全局变量（用 var 声明）

~~~javascript
// 用 var 在最外层声明 → 自动挂到 window 上
var 品牌名 = "老王饭馆";
console.log(window.品牌名);  // "老王饭馆"
console.log(品牌名 === window.品牌名);  // true（同一个东西！）

// let 和 const 不会挂到 window 上
let 今日日期 = "周一";
const 联系电话 = "123456";
console.log(window.今日日期);    // undefined
console.log(window.联系电话);    // undefined
~~~

### 隐式全局变量（忘记写 var/let/const）

~~~javascript
function 接待客人() {
  // 忘了写 let 或 var！
  客人数量 = 50;  // 没有用 var/let/const 声明 → 隐式全局变量
  console.log(客人数量);  // 50（函数内能用）
}

接待客人();
console.log(客人数量);      // 50（函数外也能用！因为变成了隐式全局变量）
console.log(window.客人数量); // 50（被挂到 window 上了）

// 这是非常危险的行为！容易导致变量污染
~~~

### 作用域对比

~~~
var 声明：函数作用域，限制在函数内
┌───────────────────────────────┐
│  if (true) {                  │
│    var 秘方 = "酱油配醋";     │
│  }                            │
│  console.log(秘方);           │  ← ✅ "酱油配醋"（var 不受块限制）
└───────────────────────────────┘

let 声明：块级作用域，严格限制在 { } 内
┌───────────────────────────────┐
│  if (true) {                  │
│    let 秘方 = "酱油配醋";     │
│  }                            │
│  console.log(秘方);           │  ← ❌ ReferenceError（let 被限制在 if 块内）
└───────────────────────────────┘
~~~

### globalThis（统一的全局对象访问方式）

~~~javascript
// 不同环境下，全局对象的名字不一样：
// 浏览器：window
// Node.js：global
// Web Worker：self

// 以前要写兼容代码很麻烦：
// const 全局 = (typeof window !== "undefined") ? window :
//              (typeof global !== "undefined") ? global :
//              (typeof self !== "undefined") ? self : {};

// ES2020 引入了 globalThis，所有环境都一样：
console.log(globalThis);  // 无论在浏览器还是 Node.js，都能用

// 浏览器中：
console.log(globalThis === window);  // true

// Node.js 中：
console.log(globalThis === global);  // true
~~~

## 2.8 解构赋值【新增】

**一句话解释：**
解构赋值是一种**快速从数组或对象中提取值**的语法，一步就能把需要的东西取出来放进变量里。

**餐厅比喻：**
快递员送来一个包裹（数组或对象），你不用一件一件慢慢拆——你直接说"第一份放左边、第二份放右边、名字给我、价格给我"，快递员**按照你的要求一次性全部分好**。这就是解构赋值。

### 数组解构

~~~javascript
// ========== 基本用法：按位置提取 ==========
const [甲, 乙, 丙] = ["红烧肉", "麻婆豆腐", "糖醋里脊"];
console.log(甲);  // 红烧肉
console.log(乙);  // 麻婆豆腐
console.log(丙);  // 糖醋里脊

// 等价于：
// const 甲 = ["红烧肉", "麻婆豆腐", "糖醋里脊"][0];
// const 乙 = ["红烧肉", "麻婆豆腐", "糖醋里脊"][1];
// const 丙 = ["红烧肉", "麻婆豆腐", "糖醋里脊"][2];

const [第一道, , 第三道] = ["红烧肉", "麻婆豆腐", "糖醋里脊"];
console.log(第一道);  // 红烧肉
console.log(第三道);  // 糖醋里脊（跳过了麻婆豆腐）

// ========== 剩余元素（...rest） ==========
const [招牌菜, ...其他菜] = ["红烧肉", "麻婆豆腐", "糖醋里脊", "宫保鸡丁"];
console.log(招牌菜);  // 红烧肉
console.log(其他菜);  // ["麻婆豆腐", "糖醋里脊", "宫保鸡丁"]

// ========== 默认值 ==========
const [菜A, 菜B, 菜C = "今日例汤"] = ["红烧肉", "麻婆豆腐"];
console.log(菜A);  // 红烧肉
console.log(菜B);  // 麻婆豆腐
console.log(菜C);  // 今日例汤（没有对应值，用默认值）

// ========== 交换变量（不用临时变量） ==========
let 甲菜 = "红烧肉";
let 乙菜 = "麻婆豆腐";
[甲菜, 乙菜] = [乙菜, 甲菜];
console.log(甲菜);  // 麻婆豆腐
console.log(乙菜);  // 红烧肉
~~~

## 第02章 总结

| 术语 | 一句话解释 | 餐厅比喻关键词 |
|---|---|---|
| 全局作用域 | 代码块之外声明的变量，整个程序都能用 | 贴在公告栏上，所有人可见 |
| 函数作用域 | 函数内声明的变量，只有函数内能用 | 后厨黑板，只有厨师能看到 |
| 块级作用域 | `{ }` 内用 let/const 声明的变量 | 便签纸贴在某张桌子上 |
| 模块作用域 | ES Module 文件内的变量 | 独立房间，要开门别人才能进来 |
| 全局变量 | 函数外声明的变量 | 公告栏上的信息 |
| 局部变量 | 函数内声明的变量 | 后厨黑板上的笔记 |
| 同名覆盖 | 内外层同名变量，内层覆盖外层 | 后厨黑板挡住公告栏 |
| 作用域链 | 从内到外逐层查找变量的路径 | 找胡椒粉：灶台→调料柜→仓库 |
| 变量提升 | 声明被提前到作用域顶部 | 服务员提前告诉你"有这道菜" |
| 暂时性死区 TDZ | let/const 声明前不能使用 | 菜谱贴出来了但菜还没做好 |
| 函数声明提升 | 整个函数（声明+函数体）都被提升 | 完整菜谱提前贴好了 |
| 函数表达式提升 | 只有变量声明提升，函数本身不提升 | 先告诉你有道菜，做法还没给 |
| window 全局对象 | 浏览器中的全局对象 | 餐厅的公告栏 |
| 隐式全局变量 | 不用 var/let/const 声明的变量 | 随手在公告栏上乱写 |
| globalThis | 所有环境统一的全局对象访问方式 | 不管哪家分店都统一叫"公告栏" |
| 解构赋值 | 快速从数组或对象中提取值 | 拆包裹，一次性按要求分好 |
| 数组解构 | 按位置提取数组元素 | 从左到右依次拿 |
| 对象解构 | 按属性名提取对象属性 | 按标签名字取东西 |
| 默认值 | 解构时没有对应值就用默认的 | 包裹里缺了东西就用备品 |
| 剩余元素 ...rest | 把剩下的打包成一个新数组/对象 | 剩下的全部装一个袋子 |
