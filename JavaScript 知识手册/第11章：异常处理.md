# 第11章：异常处理

## 11.1 throw 主动抛出错误

**一句话解释：**
`throw` 让你**主动抛出一个错误**，中断程序执行，并把错误信息传递出去。

**餐厅比喻：**
厨师发现食材过期了，他不会硬着头皮做，而是**直接举手喊停**："这批肉不能用！"——这就是 `throw`，主动报告问题，阻止后续流程继续。

~~~javascript
// ========== throw 基本用法 ==========
function 点菜(菜名) {
  if (!菜名) {
    throw new Error("菜名不能为空！");
  }
  console.log(`开始做${菜名}`);
}

// throw 可以抛出任何值（但推荐抛 Error 对象）
throw 42;                          // 抛出数字
throw "出错了";                     // 抛出字符串
throw { 类型: "自定义", 消息: "错误" }; // 抛出对象
throw new Error("标准错误");        // 推荐：抛出 Error 对象

// ========== throw 会中断执行 ==========
function 做菜(食材) {
  if (!食材) {
    throw new Error("没有食材，做不了！");
    // ↓ 以下代码不会执行
    console.log("这行永远不会执行");
  }
  return `${食材}做好了`;
}

console.log(做菜("红烧肉"));  // 红烧肉做好了
// console.log(做菜(null));   // ❌ Error: 没有食材，做不了！
~~~

## 11.2 try...catch...finally

**一句话解释：**
- `try`：尝试执行可能出错的代码
- `catch`：如果 `try` 里出错了，就执行 `catch` 里的代码来处理错误
- `finally`：不管有没有出错，**最后都会执行**

**餐厅比喻：**
- `try` = 厨师**尝试做一道新菜**
- `catch` = 如果做砸了，**启动应急预案**（比如换一道菜、给顾客道歉）
- `finally` = 不管成功还是失败，**最后都要打扫厨房**

~~~javascript
// ========== 基本 try...catch ==========
try {
  console.log("开始做菜");
  throw new Error("油锅着火了！");
  console.log("这行不会执行");
} catch (错误) {
  console.log(`出错了：${错误.message}`);
  // 出错了：油锅着火了！
}

console.log("餐厅继续营业");  // 不会被中断

// ========== try...catch...finally ==========
try {
  console.log("开始接单");
  const 结果 = 做菜("红烧肉");
  console.log(结果);
} catch (错误) {
  console.log(`处理错误：${错误.message}`);
} finally {
  console.log("清理厨房（无论如何都执行）");
}

// ========== finally 一定会执行 ==========
function 测试() {
  try {
    console.log("try");
    return "try 的返回值";
  } catch (错误) {
    console.log("catch");
  } finally {
    console.log("finally");  // 即使 try 里有 return，finally 也会执行
  }
}
console.log(测试());
// try
// finally      ← 在 return 之前执行
// try 的返回值

// ========== catch 中也可以抛出错误 ==========
try {
  try {
    throw new Error("原始错误");
  } catch (错误) {
    console.log(`内层捕获：${错误.message}`);
    throw new Error("处理时又出错了");  // catch 里再抛
  }
} catch (错误) {
  console.log(`外层捕获：${错误.message}`);
}
// 内层捕获：原始错误
// 外层捕获：处理时又出错了
~~~

## 11.3 Error 对象与内置错误类型

**一句话解释：**
`Error` 是所有错误的基类，JS 内置了多种具体错误类型，每种对应一种特定的错误场景。

**餐厅比喻：**
厨房出了事故，不同类型的事故有不同类型的报告单：
- 食材类型搞错了（TypeError）
- 温度范围不对（RangeError）
- 找不到调料（ReferenceError）
- 菜谱写错了（SyntaxError）

~~~javascript
// ========== Error 基类 ==========
const 错误 = new Error("红烧肉做糊了");
console.log(错误.message);   // "红烧肉做糊了"
console.log(错误.name);      // "Error"
console.log(错误.stack);     // 错误堆栈信息（调试用）

// ========== TypeError：类型错误 ==========
// 当值的类型不对时抛出
const 菜单 = ["红烧肉", "麻婆豆腐"];
// 菜单();  // ❌ TypeError: 菜单 is not a function（数组不能当函数调用）

const 对象 = { 名字: "红烧肉" };
// 对象.名字.不存在的方法();  // ❌ TypeError: Cannot read properties of undefined

// ========== RangeError：范围错误 ==========
// 当值超出有效范围时抛出
// [1, 2, 3].length = -1;  // ❌ RangeError: Invalid array length

// (1234).toFixed(101);     // ❌ RangeError: toFixed digits argument must be between 0 and 100

// function 栈溢出() { 栈溢出(); }
// 栈溢出();  // ❌ RangeError: Maximum call stack size exceeded

// ========== ReferenceError：引用错误 ==========
// 当访问不存在的变量时抛出
// console.log(不存在的变量);  // ❌ ReferenceError: 不存在的变量 is not defined

// 在暂时性死区访问 let/const 变量
// console.log(还未声明);  // ❌ ReferenceError: Cannot access '还未声明' before initialization
// let 还未声明 = 42;

// ========== SyntaxError：语法错误 ==========
// 当代码语法不合法时抛出（在解析阶段就报错）
// eval("if (true) {");      // ❌ SyntaxError: Unexpected end of input
// const 123abc = 42;         // ❌ SyntaxError
// JSON.parse("{name: 123}"); // ❌ SyntaxError（不是合法JSON）

// ========== URIError：URI 错误 ==========
// decodeURI("%");  // ❌ URIError: URI malformed

// ========== AggregateError：聚合错误 ==========
// Promise.any() 所有 Promise 都失败时抛出
const 错误们 = new AggregateError(
  [new Error("供应商A没货"), new Error("供应商B关门了")],
  "所有供应商都不可用"
);
console.log(错误们.message);           // 所有供应商都不可用
console.log(错误们.errors.length);     // 2
~~~

### 内置错误类型速查表

| 错误类型 | 触发场景 | 餐厅比喻 |
|---|---|---|
| Error | 通用错误（基类） | 通用事故报告单 |
| TypeError | 类型不对 | 食材类型搞错了（把醋当酱油） |
| RangeError | 值超出有效范围 | 温度设定超出了烤箱范围 |
| ReferenceError | 访问不存在的变量 | 找不到那个调料（根本没买） |
| SyntaxError | 语法错误 | 菜谱写错了，看不明白 |
| URIError | URI 编码/解码错误 | 快递地址格式写错了 |
| AggregateError | 多个错误的集合 | 所有供应商都联系不上 |

## 11.4 自定义错误类型

**一句话解释：**
通过 `extends Error` 创建自己的错误类型，可以区分不同业务场景的错误，让错误处理更精确。

**餐厅比喻：**
餐厅不仅有通用的事故报告单，还有细分的专用报告单——**食材问题用"食材报告"、温度问题用"温度报告"、顾客投诉用"投诉报告"**。这样出了问题能快速定位是哪个环节。

~~~javascript
// ========== 自定义错误：食材错误 ==========
class 食材错误 extends Error {
  constructor(食材名, 消息) {
    super(消息);
    this.name = "食材错误";
    this.食材名 = 食材名;
  }
}

// ========== 自定义错误：价格错误 ==========
class 价格错误 extends Error {
  constructor(菜品名, 价格, 消息) {
    super(消息);
    this.name = "价格错误";
    this.菜品名 = 菜品名;
    this.价格 = 价格;
  }
}

// ========== 自定义错误：订单错误 ==========
class 订单错误 extends Error {
  constructor(订单号, 消息, 原因) {
    super(消息);
    this.name = "订单错误";
    this.订单号 = 订单号;
    this.原因 = 原因;
  }
}

// ========== 使用自定义错误 ==========
function 检查食材(食材) {
  if (!食材) {
    throw new 食材错误(食材, `食材"${食材}"不可用`);
  }
  if (食材 === "过期肉") {
    throw new 食材错误(食材, `食材"${食材}"已过期，不能使用！`);
  }
  console.log(`食材"${食材}"检查通过`);
}

function 检查价格(菜品名, 价格) {
  if (价格 < 0) {
    throw new 价格错误(菜品名, 价格, `${菜品名}的价格不能为负数`);
  }
  if (价格 > 500) {
    throw new 价格错误(菜品名, 价格, `${菜品名}的价格${价格}元太贵了`);
  }
  console.log(`${菜品名}定价${价格}元，合理`);
}

// ========== 精确捕获不同类型的错误 ==========
try {
  检查食材("新鲜猪肉");    // ✅ 通过
  检查价格("红烧肉", 38);   // ✅ 通过
  检查食材("过期肉");       // ❌ 抛出食材错误
} catch (错误) {
  if (错误 instanceof 食材错误) {
    console.log(`🚫 食材问题：${错误.message}（食材：${错误.食材名}）`);
  } else if (错误 instanceof 价格错误) {
    console.log(`💰 价格问题：${错误.message}`);
  } else {
    console.log(`❓ 未知错误：${错误.message}`);
  }
}
// 食材"新鲜猪肉"检查通过
// 红烧肉定价38元，合理
// 🚫 食材问题：食材"过期肉"已过期，不能使用！（食材：过期肉）

// ========== 错误的层级捕获 ==========
function 处理订单(订单号) {
  try {
    检查食材("过期肉");
  } catch (错误) {
    // 包装成更具体的错误再抛出
    throw new 订单错误(订单号, `订单${订单号}处理失败`, 错误.message);
  }
}

try {
  处理订单("ORD-001");
} catch (错误) {
  if (错误 instanceof 订单错误) {
    console.log(`订单错误：${错误.message}`);
    console.log(`原因：${错误.原因}`);
    console.log(`订单号：${错误.订单号}`);
  }
}
// 订单错误：订单ORD-001处理失败
// 原因：食材"过期肉"已过期，不能使用！
// 订单号：ORD-001
~~~

## 11.5 try...catch 只能捕获同步错误

**一句话解释：**
`try...catch` 只能捕获**当前执行栈内同步执行**的代码抛出的错误。对于**异步代码**（setTimeout、Promise、事件回调等）中的错误，直接用 `try...catch` 是捕获不到的。

**餐厅比喻：**
你在前厅安排了一个应急人员（try...catch），他能处理**前厅正在发生的**事故。但你把一个任务交给了后厨（异步），后厨那边出了问题——前厅的应急人员根本不知道，因为他不在后厨现场。

~~~javascript
// ========== 同步错误：可以捕获 ==========
try {
  throw new Error("同步错误");
} catch (错误) {
  console.log(`捕获到：${错误.message}`);  // ✅ 捕获到：同步错误
}

// ========== setTimeout 中的错误：捕获不到 ==========
try {
  setTimeout(() => {
    throw new Error("异步错误");  // 这个错误在未来的某个时间点才发生
  }, 100);
} catch (错误) {
  // ❌ 这个 catch 永远不会执行！
  // 因为 setTimeout 的回调在 try...catch 已经执行完之后才运行
  console.log("捕获到异步错误");
}

// ========== Promise 中的错误：捕获不到 ==========
try {
  Promise.reject(new Error("Promise错误"));
} catch (错误) {
  // ❌ 捕获不到！Promise 的错误是异步的
  console.log("捕获到Promise错误");
}

// ========== 如何捕获异步错误？ ==========
// 方法1：在异步回调内部用 try...catch
setTimeout(() => {
  try {
    throw new Error("异步错误");
  } catch (错误) {
    console.log(`回调内捕获：${错误.message}`);  // ✅ 回调内捕获：异步错误
  }
}, 100);

// 方法2：Promise 用 .catch()
Promise.reject(new Error("Promise错误"))
  .catch(错误 => {
    console.log(`Promise捕获：${错误.message}`);  // ✅ Promise捕获：Promise错误
  });

// 方法3：async/await 用 try...catch
async function 异步操作() {
  try {
    await Promise.reject(new Error("async错误"));
  } catch (错误) {
    console.log(`async捕获：${错误.message}`);  // ✅ async捕获：async错误
  }
}
异步操作();

// 方法4：全局错误监听
// 浏览器：
// window.addEventListener("unhandledrejection", (事件) => {
//   console.log("未处理的Promise错误：", 事件.reason);
// });
// window.addEventListener("error", (事件) => {
//   console.log("未处理的错误：", 事件.message);
// });
~~~

### 错误捕获方式速查

| 错误来源 | 捕获方式 | 餐厅比喻 |
|---|---|---|
| 同步代码 | `try...catch` | 前厅出事，应急人员处理 |
| setTimeout/setInterval | 回调内部 `try...catch` | 后厨出事，后厨自己的应急处理 |
| Promise | `.catch()` | 后厨说"做不了"，前台收到通知 |
| async/await | `try...catch`（await 外层） | 等后厨结果时出错，前台能捕获 |
| 全局未捕获 | `window.onerror` / `unhandledrejection` | 整栋楼的监控系统 |

## 第11章 总结

| 术语 | 一句话解释 | 餐厅比喻关键词 |
|---|---|---|
| throw | 主动抛出错误，中断执行 | 厨师喊停"这批肉不能用" |
| try | 尝试执行可能出错的代码 | 尝试做一道新菜 |
| catch | 捕获错误并处理 | 启动应急预案 |
| finally | 不管有没有错都执行 | 最后都要打扫厨房 |
| Error | 通用错误基类 | 通用事故报告单 |
| TypeError | 类型错误 | 食材类型搞错了 |
| RangeError | 范围错误 | 温度超出烤箱范围 |
| ReferenceError | 引用不存在的变量 | 调料根本没买 |
| SyntaxError | 语法错误 | 菜谱写错了看不懂 |
| 自定义错误 | extends Error 创建专用错误 | 食材报告/温度报告/投诉报告 |
| instanceof 判断 | 区分不同类型的错误 | 看事故报告单的类别 |
| 错误包装 | catch 中包装成更具体的错误再抛出 | 食材问题包装成订单问题 |
| try...catch 局限 | 只能捕获同步错误 | 前厅应急人员管不了后厨 |
| 捕获异步错误 | 回调内 try...catch / .catch / async await | 后厨出事后厨自己处理 |
| 全局错误监听 | onerror / unhandledrejection | 整栋楼的监控系统 |
