# 第14章：同步异步与事件循环

## 14.1 同步（Synchronous）

**一句话解释：**
同步就是**一件事做完再做下一件**——排队买奶茶，前面的人买完你才能买，你必须**傻等**。

**餐厅比喻：**
只有一个厨师，一次只能做一道菜。**红烧肉没做完之前，他绝对不会开始炒麻婆豆腐**。后面所有订单都排着队等。

~~~javascript
// ========== 同步代码：一行一行按顺序执行 ==========

console.log("第1步：洗菜");
console.log("第2步：切菜");
console.log("第3步：炒菜");
console.log("第4步：装盘");

// 输出：
// 第1步：洗菜
// 第2步：切菜
// 第3步：炒菜
// 第4步：装盘

// 每一行必须等上一行执行完才能执行
~~~

~~~javascript
// ========== 同步的"问题"：遇到耗时操作会卡住 ==========

console.log("开始接单");

// 假装这个函数要计算3秒（同步阻塞）
function 慢计算() {
  const 开始 = Date.now();
  while (Date.now() - 开始 < 3000) {
    // 什么都不做，纯等3秒
  }
  return "算完了";
}

const 结果 = 慢计算();  // 整个程序卡在这里3秒

console.log(结果);       // 3秒后才执行
console.log("继续接单"); // 也要等3秒后

// 输出：
// 开始接单
// （卡了3秒...）
// 算完了
// 继续接单
~~~

**餐厅比喻：**
厨师在等汤炖好的2小时里**什么都不做，就站在灶台前盯着锅**。门口来了新顾客，不接；有人结账，不理。**所有事情都被"卡住"了。**

## 14.2 异步（Asynchronous）

**一句话解释：**
异步就是**不傻等**——遇到要等的操作（煮汤、等网络），先去干别的，等操作完成了再回来处理结果。

**餐厅比喻：**
厨师把汤炖上之后，**不站在灶台前傻等**，而是先去切菜、先去炒别的菜、先去收拾桌子。等汤炖好了（定时器响了/回调触发了），他再回来处理汤。

~~~
同步：傻等
────────────────────────────────
厨师：炖汤 →（盯着锅2小时）→ 汤好了 → 切菜 → 炒菜
                                ↑ 整个厨房停了2小时

异步：不傻等
────────────────────────────────
厨师：炖汤 → 切菜 → 炒菜 → 汤好了回来处理
         ↑ 不等，先干别的
~~~

~~~javascript
// ========== 异步代码：遇到等待就先去干别的 ==========

console.log("第1步：开始接单");

setTimeout(() => {
  console.log("第3步：汤炖好了（2秒后才执行）");
}, 2000);

console.log("第2步：先去切菜（不用等汤炖好）");

// 输出：
// 第1步：开始接单
// 第2步：先去切菜（不用等汤炖好）    ← 不等！直接执行！
// （2秒后...）
// 第3步：汤炖好了                    ← 定时器到了才执行
~~~

**关键问题：为什么"第2步"在"第3步"之前执行？**

~~~
代码的执行顺序：

第1步：console.log("开始接单")          → 立即执行
      │
      ▼
setTimeout(回调, 2000)                  → 注册一个"2秒后执行"的定时器
      │                                    然后立刻往后走（不等！）
      ▼
第2步：console.log("先去切菜")          → 立即执行
      │
      ▼
（主线程空闲了，等定时器触发...）
      │
      ▼ （2秒后）
第3步：console.log("汤炖好了")          → 定时器回调执行
~~~

**餐厅比喻：**
~~~
主线程（厨师本人）：
"开始接单" → 立刻说
"炖汤，2小时后叫我" → 交给灶台（不等）
"先去切菜" → 立刻做
（手里没活了，等灶台响...）

定时器（灶台）：
（2小时后）"叮！汤好了！" → 厨师回来处理
~~~

## 14.3 事件循环（Event Loop）

**一句话解释：**
JS 是单线程的（只有一个厨师），但它有一个**事件循环**机制——先把异步任务交给"别人"（浏览器/Node.js）去等，自己继续干主线程的事。等异步任务完成了，结果会被放进"待办队列"，主线程空了就去处理。

**餐厅比喻：**
餐厅只有一个厨师（主线程），但有一个**智能排队系统**：

~~~
┌─────────────────────────────────────────────────┐
│                  事件循环                         │
│                                                  │
│  ┌──────────┐                                   │
│  │  主线程   │  ← 厨师本人，一次只做一件事        │
│  │ （调用栈）│                                   │
│  └────┬─────┘                                   │
│       │                                         │
│       │  遇到异步操作？                           │
│       │  交给"别人"去等                           │
│       ▼                                         │
│  ┌──────────────┐    ┌──────────────┐           │
│  │ Web APIs     │    │  待办队列     │           │
│  │ （浏览器/Node）│──→│ （回调队列）  │──→ 主线程 │
│  │              │    │              │           │
│  │ setTimeout   │    │ 定时器回调    │           │
│  │ fetch        │    │ 网络回调      │           │
│  │ DOM事件      │    │ 事件回调      │           │
│  └──────────────┘    └──────────────┘           │
│                                                  │
│  工作流程：                                       │
│  1. 主线程执行同步代码                             │
│  2. 遇到异步操作 → 交给 Web APIs                   │
│  3. Web APIs 等待完成 → 把回调放进待办队列          │
│  4. 主线程空了 → 从待办队列取出回调执行              │
│  5. 循环往复                                      │
└─────────────────────────────────────────────────┘
~~~

~~~javascript
// ========== 完整的例子，看清每一步的执行顺序 ==========

console.log("1. 接单（同步）");

setTimeout(() => {
  console.log("4. 汤炖好了（异步回调）");
}, 0);  // 注意：0毫秒！但还是异步！

console.log("2. 切菜（同步）");

setTimeout(() => {
  console.log("5. 面煮好了（异步回调）");
}, 0);

console.log("3. 炒菜（同步）");

// 输出：
// 1. 接单（同步）
// 2. 切菜（同步）
// 3. 炒菜（同步）
// 4. 汤炖好了（异步回调）
// 5. 面煮好了（异步回调）
~~~

**为什么 setTimeout 0 毫秒也不立即执行？**

~~~
执行流程：

1. console.log("1. 接单") → 立即执行
2. setTimeout(汤的回调, 0) → 交给浏览器，"0毫秒后把回调放进待办队列"
                              然后立刻往下走（不等！）
3. console.log("2. 切菜") → 立即执行
4. setTimeout(面的回调, 0) → 交给浏览器，同上
5. console.log("3. 炒菜") → 立即执行
6. 主线程空了！去待办队列看看
7. 取出汤的回调 → console.log("4. 汤炖好了")
8. 取出面的回调 → console.log("5. 面煮好了")
~~~

**餐厅比喻：**
即使你跟厨师说"**0分钟后**帮我盛汤"（setTimeout 0），厨师也不会立刻放下手里的菜去盛汤——他会**先把手里正在切的菜切完**（执行完所有同步代码），然后再去处理你的请求。

### 宏任务与微任务

~~~javascript
// ========== 事件循环中的任务优先级 ==========
// 宏任务（Macro Task）：setTimeout、setInterval、I/O、UI渲染
// 微任务（Micro Task）：Promise.then/catch/finally、queueMicrotask、MutationObserver

// 规则：
// 1. 执行一个宏任务（一开始是整体 script）
// 2. 执行所有微任务（清空微任务队列）
// 3. 执行 UI 渲染（如果需要）
// 4. 从宏任务队列取出下一个宏任务 → 回到步骤 1

console.log("1. 同步：script 开始");

setTimeout(() => {
  console.log("5. 宏任务：setTimeout");
}, 0);

Promise.resolve().then(() => {
  console.log("3. 微任务：Promise.then 1");
}).then(() => {
  console.log("4. 微任务：Promise.then 2");
});

console.log("2. 同步：script 结束");

// 输出：
// 1. 同步：script 开始
// 2. 同步：script 结束
// 3. 微任务：Promise.then 1    ← 微任务先于宏任务
// 4. 微任务：Promise.then 2
// 5. 宏任务：setTimeout        ← 宏任务最后
~~~

### 执行顺序图解

~~~
时间 →

执行栈（主线程）：
  同步代码 → 同步代码 → ...

  每执行完一个宏任务后：
  ① 清空所有微任务
  ② 可能触发 UI 渲染
  ③ 取下一个宏任务

宏任务队列：
  [setTimeout回调, setInterval回调, ...]
   ↑ 每次只取一个

微任务队列：
  [Promise.then, Promise.then, ...]
   ↑ 每次清空全部

执行顺序：
  同步代码 → 微任务全部 → 宏任务1 → 微任务全部 → 宏任务2 → 微任务全部 → ...
~~~

### 综合示例

~~~javascript
// ========== 综合练习：预测输出顺序 ==========
console.log("1");

setTimeout(() => {
  console.log("2");
  Promise.resolve().then(() => console.log("3"));
}, 0);

Promise.resolve().then(() => {
  console.log("4");
  setTimeout(() => console.log("5"), 0);
});

console.log("6");

// 输出：
// 1   ← 同步
// 6   ← 同步
// 4   ← 微任务（第一个宏任务结束后清空微任务）
// 2   ← 宏任务（setTimeout 回调）
// 3   ← 微任务（第二个宏任务结束后清空微任务）
// 5   ← 宏任务（微任务里注册的 setTimeout）

// 解析：
// 1. 执行同步代码：输出 1、6
// 2. 清空微任务：输出 4（同时注册了 setTimeout）
// 3. 取宏任务1：输出 2
// 4. 清空微任务：输出 3
// 5. 取宏任务2：输出 5
~~~

## 14.4 常见的异步操作

~~~javascript
// ========== 1. setTimeout / setInterval ==========
setTimeout(() => console.log("1秒后"), 1000);     // 定时执行
setInterval(() => console.log("每秒"), 1000);     // 重复执行

// ========== 2. 网络请求 ==========
// fetch("https://api.example.com/menu")
//   .then(response => response.json())
//   .then(data => console.log(data));

// ========== 3. DOM 事件 ==========
// document.querySelector("button").addEventListener("click", () => {
//   console.log("按钮被点了");  // 事件回调（异步）
// });

// ========== 4. 文件读写（Node.js） ==========
// const fs = require("fs");
// fs.readFile("菜单.txt", "utf-8", (错误, 数据) => {
//   console.log(数据);  // 读完文件才回调（异步）
// });

// ========== 5. Promise ==========
const 小票 = new Promise((resolve) => {
  setTimeout(() => resolve("菜好了"), 2000);
});
小票.then(结果 => console.log(结果));

// ========== 6. async/await ==========
async function 点餐() {
  const 结果 = await 小票;
  console.log(结果);
}
~~~

## 第14章 总结

| 术语 | 一句话解释 | 餐厅比喻关键词 |
|---|---|---|
| 同步 | 一件事做完再做下一件，会傻等 | 厨师盯着锅2小时什么都不干 |
| 异步 | 不傻等，先去干别的，等完成了再回来处理 | 厨师炖上汤就去切别的菜 |
| 事件循环 | JS 的异步调度机制——主线程执行完就去队列取回调 | 厨师手里的活干完了就看排队系统有没有新任务 |
| 主线程 | JS 唯一的执行线程，一次只做一件事 | 餐厅只有一个厨师 |
| 回调队列 | 异步任务完成后，回调进入的等待队列 | 上菜窗口的叫号队列 |
| setTimeout(fn, 0) | 0毫秒后把回调放进队列（但还是异步） | "0分钟后叫我"也要等手里的活干完 |
| 宏任务 | setTimeout、setInterval、I/O 等 | 每次只取一个的大订单 |
| 微任务 | Promise.then、queueMicrotask 等 | 每次全部清空的小订单 |
| 执行顺序 | 同步 → 微任务全部 → 宏任务1 → 微任务全部 → 宏任务2 → ... | 先干手里的活 → 处理小订单 → 取一个大订单 → 处理小订单 → ... |
