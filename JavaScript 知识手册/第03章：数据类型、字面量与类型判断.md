# 第03章：数据类型、字面量与类型判断


## 3.1 八种数据类型逐个详解

**一句话解释：**
最新的 ECMAScript 标准定义了 8 种数据类型。前 7 种类型构成了基本数据类型。最后一种是基本 Object，用于存储键值对和更复杂的实体。

**餐厅比喻：**
餐厅里有 8 种不同的"东西"：
- 菜品（String 文字）、价格（Number 数字）、有没有营业（Boolean 真假）
- 特殊标记（Symbol 唯一标记）、超大账单金额（BigInt 大整数）
- 还有两种"什么都没有"（null 空 和 undefined 未定义）
- 最后是万能的"物件"（Object 对象），什么都能往里装

~~~
JS 数据类型（8种）
│
├── 基本类型（7种）：存的是值本身，简单、轻量
│   ├── boolean（布尔值）：true / false
│   ├── null（空值）：故意留空
│   ├── undefined（未定义）：还没赋值
│   ├── number（数字）：整数和小数
│   ├── bigint（大整数）：超大数字
│   ├── string（字符串）：文字内容
│   └── symbol（符号）：全球唯一的标记
│
└── 引用类型（1种）：存的是地址（引用），复杂
    └── object（对象）：键值对的集合
        包括：普通对象 {}、数组 []、函数 function、日期 Date、正则 RegExp 等
~~~

### 3.1.1 Boolean（布尔值）

**一句话解释：**
只有两个值：`true`（真/是）和 `false`（假/否），用于做判断。

**餐厅比喻：**
餐厅门口的牌子，只有两种状态：**"营业中"（true）** 或 **"已打烊"（false）**。没有第三种。

**代码示例：**

~~~javascript
// ========== 直接赋值 ==========
const 是否营业 = true;
const 是否有停车位 = false;

console.log(是否营业);      // true
console.log(是否有停车位);  // false

// ========== 比较运算产生布尔值 ==========
const 价格 = 38;
const 是否特价 = 价格 < 30;   // 38 < 30 → false
const 是否贵菜 = 价格 > 35;   // 38 > 35 → true

console.log(是否特价);  // false
console.log(是否贵菜);  // true

// ========== 逻辑运算 ==========
const 有食材 = true;
const 厨师在岗 = true;
const 能营业 = 有食材 && 厨师在岗;  // 两个都为 true → true
console.log(能营业);  // true
~~~

### 3.1.2 null（空值）

**一句话解释：**
表示"**故意什么都没有**"——你明确知道这里是空的，是你主动设置的"空"。

**餐厅比喻：**
客人结完账走了，桌上的菜被**收走了**——桌子是空的，这是**故意清空的**（null）。

**代码示例：**

~~~javascript
// null 表示"故意为空"
const 当前顾客 = null;  // 明确表示现在没有顾客
console.log(当前顾客);   // null

// typeof 的坑！
console.log(typeof null);  // "object" ← 这是 JS 的历史遗留 bug
// 正确判断 null 的方式：
console.log(当前顾客 === null);  // true（用 === 判断）

// 什么时候用 null？
// 1. 清空变量
let 旧顾客 = "张三";
旧顾客 = null;  // 主动清空

// 2. 函数找不到结果时返回 null
function 查找菜品(菜名) {
  const 菜单 = ["红烧肉", "麻婆豆腐"];
  const 找到的 = 菜单.find(菜 => 菜 === 菜名);
  return 找到的 || null;  // 找不到返回 null（不是 undefined）
}
console.log(查找菜品("红烧肉"));  // "红烧肉"
console.log(查找菜品("龙虾"));    // null
~~~

### 3.1.3 undefined（未定义）

**一句话解释：**
表示"**还没赋值**"——变量声明了但没赋值、函数没有返回值、对象没有这个属性，都是 undefined。

**餐厅比喻：**
餐厅菜单上有一道菜叫"今日特选"，但**具体是什么还没定**——这个"今日特选"目前就是 undefined。

**代码示例：**

~~~javascript
// ========== 变量声明了但没赋值 ==========
let 今日特选;
console.log(今日特选);  // undefined

// ========== 函数没有 return ==========
function 打招呼() {
  console.log("欢迎光临");
  // 没有 return，返回 undefined
}
const 结果 = 打招呼();  // 打印"欢迎光临"
console.log(结果);       // undefined

// ========== 对象没有这个属性 ==========
const 菜品 = { 名字: "红烧肉", 价格: 38 };
console.log(菜品.厨师);  // undefined（没有"厨师"这个属性）

// ========== 数组越界 ==========
const 菜单 = ["红烧肉", "麻婆豆腐"];
console.log(菜单[5]);    // undefined（没有第6个元素）

// ========== null vs undefined ==========
console.log(null == undefined);   // true  （宽松相等，两者相等）
console.log(null === undefined);  // false （严格相等，类型不同）
console.log(typeof null);         // "object"（历史 bug）
console.log(typeof undefined);    // "undefined"
~~~

### 3.1.4 Number（数字）

**一句话解释：**
表示整数和小数（浮点数），是 JS 中唯一的数字类型（不像有些语言分 int、float、double）。

**餐厅比喻：**
计算器上只有一个数字键盘，**不管是整数 38 还是小数 3.14，都是按同一排键输入的**。

**代码示例：**

~~~javascript
// ========== 整数和小数 ==========
const 价格 = 38;           // 整数
const 折扣 = 0.85;         // 小数
const 实付 = 价格 * 折扣;  // 32.3
console.log(实付);          // 32.3

// ========== 特殊的数字值 ==========
console.log(1 / 0);           // Infinity（无穷大）
console.log(-1 / 0);          // -Infinity（负无穷大）
console.log("abc" * 2);       // NaN（Not a Number，不是数字）
console.log(NaN === NaN);     // false（NaN 不等于自己！）
console.log(isNaN(NaN));      // true（用 isNaN 判断）
console.log(Number.isNaN(NaN)); // true（推荐用这个）

// ========== 二进制浮点数的坑 ==========
console.log(0.1 + 0.2);       // 0.30000000000000004（不是 0.3！）
console.log(0.1 + 0.2 === 0.3); // false
// 解决方案：
console.log(Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON);  // true

// ========== 安全整数范围 ==========
console.log(Number.MAX_SAFE_INTEGER);  // 9007199254740991
console.log(Number.MIN_SAFE_INTEGER);  // -9007199254740991
console.log(9007199254740992 === 9007199254740993);  // true ← 超出安全范围出bug！
~~~

### 3.1.5 BigInt（大整数）

**一句话解释：**
用来表示**超大整数**，比 Number 能表示的最大整数还大得多。在数字后面加 `n` 就是 BigInt。

**餐厅比喻：**
普通计算器（Number）最多只能算到 16 位数字，再大就按不下了。BigInt 是一台**超级计算器**，你想算多少位都行，但**只能算整数**，不能算小数。

**代码示例：**

~~~javascript
// ========== 创建 BigInt ==========
const 超大金额 = 9007199254740993n;  // 在数字后面加 n
const 从Number创建 = BigInt(9007199254740993);

console.log(超大金额);      // 9007199254740993n
console.log(从Number创建);  // 9007199254740993n

// ========== 解决 Number 的安全整数问题 ==========
console.log(9007199254740992 === 9007199254740993);           // false ← Number 精度丢失
console.log(9007199254740992n === 9007199254740993n);         // true ← BigInt 精确！

// ========== BigInt 可以做加减乘除 ==========
const 大数A = 123456789012345678901234567890n;
const 大数B = 987654321098765432109876543210n;

console.log(大数A + 大数B);  // 1111111110111111111011111111100n
console.log(大数A * 大数B);  // 一大串数字...n

// ========== 注意事项 ==========
// 1. BigInt 不能和 Number 混用
// console.log(1n + 1);  // ❌ TypeError: Cannot mix BigInt and other types
console.log(1n + BigInt(1));  // ✅ 2n（先转成同一类型）

// 2. BigInt 不能做小数运算
// console.log(10n / 3n);  // 3n（直接丢掉小数部分，不是 3.333...）

// 3. typeof
console.log(typeof 123n);  // "bigint"
~~~

### 3.1.6 String（字符串）

**一句话解释：**
表示文字内容，用单引号 `''`、双引号 `""` 或反引号 `` ` `` 包起来。

**餐厅比喻：**
菜单上的文字——菜名、描述、备注，都是字符串。你可以用不同的方式写（单引号、双引号、反引号），效果一样。

**代码示例：**

~~~javascript
// ========== 三种写法 ==========
const 菜名1 = '红烧肉';        // 单引号
const 菜名2 = "麻婆豆腐";      // 双引号
const 菜名3 = `糖醋里脊`;      // 反引号（模板字符串）

// ========== 模板字符串（反引号的特殊能力） ==========
const 菜名 = "红烧肉";
const 价格 = 38;

// 反引号可以用 ${} 嵌入变量和表达式
const 描述 = `${菜名}售价${价格}元，打8折后${价格 * 0.8}元`;
console.log(描述);  // 红烧肉售价38元，打8折后30.4元

// 反引号可以换行，不需要 \n
const 多行描述 = `
  菜名：${菜名}
  价格：${价格}元
  评分：4.8
`;
console.log(多行描述);

// ========== 字符串是不可变的 ==========
let 菜单文字 = "红烧肉";
菜单文字[0] = "绿";  // 静默失败，不会报错但也不会改
console.log(菜单文字);  // "红烧肉"（没变！）

// 要"修改"只能创建新字符串
菜单文字 = "绿烧肉";  // 重新赋值（不是修改原字符串）
console.log(菜单文字);  // "绿烧肉"

// ========== typeof ==========
console.log(typeof "红烧肉");  // "string"
console.log(typeof "");        // "string"（空字符串也是字符串）
~~~

### 3.1.7 Symbol（符号）

**一句话解释：**
Symbol 是**全球唯一的标记**，永远不会跟其他 Symbol 重复。通常用来给对象加"不会冲突"的属性。

**餐厅比喻：**
每道菜都贴了一个**防伪二维码**（Symbol），全球唯一，不可能有两道菜的二维码一模一样。你用这个二维码来标记"这是VIP菜品"、"这是隐藏菜单"等特殊信息，不用担心跟别人的标记撞车。

**代码示例：**

~~~javascript
// ========== 创建 Symbol ==========
const VIP标记 = Symbol("VIP菜品");
const 隐藏标记 = Symbol("隐藏菜单");

console.log(VIP标记);     // Symbol(VIP菜品)
console.log(隐藏标记);    // Symbol(隐藏菜单)
console.log(VIP标记 === 隐藏标记);  // false（每个 Symbol 都是唯一的）

// 即使描述一样，也是不同的 Symbol
const 标记A = Symbol("测试");
const 标记B = Symbol("测试");
console.log(标记A === 标记B);  // false（描述一样，但 Symbol 不一样）

// ========== 用 Symbol 做对象的属性名 ==========
const 菜品 = {
  名字: "红烧肉",
  价格: 38,
  [VIP标记]: true,        // 用 Symbol 做键
  [隐藏标记]: "老板私房菜"
};

console.log(菜品.名字);       // 红烧肉
console.log(菜品[VIP标记]);   // true
console.log(菜品[隐藏标记]);  // 老板私房菜

// Symbol 属性不会出现在 for...in 和 Object.keys 中（隐藏的）
for (const 键 in 菜品) {
  console.log(键);  // 只输出 "名字" 和 "价格"，不会输出 Symbol 属性
}
console.log(Object.keys(菜品));  // ["名字", "价格"]

// 要获取 Symbol 属性，需要用专门的方法
console.log(Object.getOwnPropertySymbols(菜品));  // [Symbol(VIP菜品), Symbol(隐藏菜单)]

// ========== typeof ==========
console.log(typeof VIP标记);  // "symbol"
~~~

### 3.1.8 Object（对象）

**一句话解释：**
对象是一种**复合数据类型**，可以存储多个键值对（key-value pairs）。几乎所有非基本类型的数据都是对象。

**餐厅比喻：**
对象就是一个**储物柜**，里面有很多格子，每个格子都有一个标签（键/key），标签对应一个东西（值/value）。你可以往里面放任何东西——数字、文字、甚至另一个储物柜。

**代码示例：**

~~~javascript
// ========== 创建对象 ==========
const 菜品 = {
  名字: "红烧肉",       // 字符串值
  价格: 38,              // 数字值
  是否推荐: true,        // 布尔值
  配料: ["五花肉", "酱油", "冰糖"],  // 数组值
  做法: {                // 嵌套对象
    步骤1: "焯水",
    步骤2: "炒糖色",
    步骤3: "炖40分钟"
  }
};

console.log(菜品.名字);          // 红烧肉
console.log(菜品.配料[0]);       // 五花肉
console.log(菜品.做法.步骤3);    // 炖40分钟

// ========== 对象可以动态添加和删除属性 ==========
菜品.厨师 = "张师傅";           // 添加属性
菜品.评分 = 4.8;                 // 添加属性
delete 菜品.是否推荐;            // 删除属性

console.log(菜品);
// { 名字: "红烧肉", 价格: 38, 配料: [...], 做法: {...}, 厨师: "张师傅", 评分: 4.8 }

// ========== typeof 的坑 ==========
console.log(typeof {});             // "object"
console.log(typeof []);             // "object" ← 数组也是 object！
console.log(typeof null);           // "object" ← null 也是 object！
console.log(typeof function(){});   // "function"

// 判断是不是数组，要用 Array.isArray
console.log(Array.isArray([]));     // true
console.log(Array.isArray({}));     // false
~~~

## 3.2 假值 Falsy Values

**一句话解释：**
在 JS 中，有些值在条件判断中会被当作 `false` 来处理，这些值叫做**假值（Falsy）**。除了这 6 个假值之外，**其他所有值都是真值（Truthy）**。

**餐厅比喻：**
餐厅门口的"营业检测系统"规定了**只有 6 种情况**会被判定为"不营业"。除此之外的任何情况，都算"营业中"。

### 6 个假值（Falsy Values）

| 假值 | 说明 | 餐厅比喻 |
|---|---|---|
| `false` | 布尔值 false | 门口牌子写着"已打烊" |
| `0` | 数字 0 | 今日营业额为 0 |
| `-0` | 负零 | 营业额为负零（虽然很奇怪，但也是 0） |
| `""` 或 `''` | 空字符串 | 菜单上什么字都没写 |
| `null` | 空值 | 桌上的菜被故意收走了 |
| `undefined` | 未定义 | 今日特选还没定 |
| `NaN` | 不是数字 | 计算器算出了一个错误结果 |

**代码示例：**

~~~javascript
// ========== 6个假值，放在 if 里都是 false ==========
if (false)       { console.log("不会执行"); }
if (0)           { console.log("不会执行"); }
if (-0)          { console.log("不会执行"); }
if ("")          { console.log("不会执行"); }
if (null)        { console.log("不会执行"); }
if (undefined)   { console.log("不会执行"); }
if (NaN)         { console.log("不会执行"); }
// 以上全部不会执行，因为它们都是假值

// ========== 除假值外，其他全部是真值 ==========
if (true)        { console.log("会执行"); }
if (1)           { console.log("会执行"); }
if (-1)          { console.log("会执行"); }
if ("hello")     { console.log("会执行"); }
if ([])          { console.log("会执行"); }
if ({})          { console.log("会执行"); }
if (function(){}){ console.log("会执行"); }
// 以上全部会执行，因为它们都是真值
~~~

### 容易踩坑的真值

~~~javascript
// ========== 这些看起来像假值，但其实是真值！ ==========
if ("0")          { console.log("真值！"); }   // ✅ "0" 是非空字符串 → 真值
if ("false")      { console.log("真值！"); }   // ✅ "false" 是非空字符串 → 真值
if ([])           { console.log("真值！"); }   // ✅ 空数组是真值！
if ({})           { console.log("真值！"); }   // ✅ 空对象是真值！
if (new Boolean(false)) { console.log("真值！"); } // ✅ Boolean 包装对象是真值！

// 常见陷阱
const 菜品数量 = 0;
if (菜品数量) {
  console.log("有菜品");    // 不会执行（0 是假值）
} else {
  console.log("没有菜品");  // 会执行
}

// 但如果用户输入的是字符串 "0" 呢？
const 用户输入 = "0";
if (用户输入) {
  console.log("有输入");    // 会执行！"0" 是真值！
}

// 如果想同时排除 0 和 "0"，应该这样：
if (用户输入 !== "" && 用户输入 !== null && 用户输入 !== undefined) {
  console.log("有有效输入");  // 会执行
}
~~~

## 3.3 typeof 运算符速查

**一句话解释：**
`typeof` 用来检查一个值**是什么类型**，返回一个类型名称的字符串。

**餐厅比喻：**
你拿起一个东西，问"这是什么？"——对方回答"这是数字"、"这是文字"、"这是物件"。`typeof` 就是这个"这是什么"的提问。

~~~javascript
// ========== typeof 速查表 ==========
typeof 42                // "number"
typeof 3.14              // "number"
typeof NaN               // "number"   ← NaN 是"数字"类型！
typeof Infinity          // "number"
typeof 42n               // "bigint"
typeof "红烧肉"          // "string"
typeof ""                // "string"
typeof true              // "boolean"
typeof false             // "boolean"
typeof undefined         // "undefined"
typeof Symbol()          // "symbol"
typeof {}                // "object"
typeof []                // "object"   ← 数组也是 object！
typeof null              // "object"   ← 历史 bug！
typeof function(){}      // "function"

// ========== typeof 的坑总结 ==========
console.log(typeof null);           // "object"  ← 应该是 "null"，但这是历史bug
console.log(typeof []);             // "object"  ← 应该是 "array"，但数组本质是对象
console.log(typeof NaN);            // "number"  ← "Not a Number"的类型是number，讽刺

// ========== 精确判断的方式 ==========
// 判断 null
值 === null                              // true 或 false

// 判断数组
Array.isArray([])                        // true

// 判断 NaN
Number.isNaN(NaN)                        // true（推荐，不会误判字符串）
isNaN("abc")                             // true（不推荐，会把字符串转成NaN）

// 判断具体类型
Object.prototype.toString.call([])       // "[object Array]"
Object.prototype.toString.call({})       // "[object Object]"
Object.prototype.toString.call(null)     // "[object Null]"
Object.prototype.toString.call(new Date()) // "[object Date]"
~~~

## 3.4 字面量

**一句话解释：**
字面量就是**直接写出来的值**——你写 `42` 就是一个数字，写 `"红烧肉"` 就是一个字符串，写 `true` 就是一个布尔值。不需要调用任何函数或构造器。

**餐厅比喻：**
字面量就像**实物本身**——你手里拿着一个苹果，你不需要说"请给我创建一个苹果对象"（`new Apple()`），你直接说"这里有个苹果"就行。**字面量就是最直接、最简单的创建值的方式。**

### 全部类型的字面量一览

| 类型 | 字面量写法 | 示例 |
|---|---|---|
| 数字 | 直接写数字 | `42`、`3.14`、`0xff`、`1e3` |
| 大整数 | 数字后加 `n` | `9007199254740993n` |
| 字符串 | 引号包裹 | `"红烧肉"`、`'麻婆豆腐'`、`` `糖醋里脊` `` |
| 布尔 | true / false | `true`、`false` |
| null | null | `null` |
| 正则表达式 | 斜杠包裹 | `/正则/g`、`/\d+/` |
| 数组 | 方括号 | `[1, 2, 3]`、`["红烧肉", "麻婆豆腐"]` |
| 对象 | 花括号 | `{ 名字: "红烧肉", 价格: 38 }` |
| 函数 | function 关键字 | `function() {}`、`() => {}` |

## 3.5 基本类型 vs 引用类型

**一句话解释：**
JavaScript 的数据类型分两大阵营——**基本类型**（Primitive）的值存在变量本身里，**引用类型**（Reference）的值存在堆内存里，变量只存了一个"地址"。

**餐厅比喻：**
基本类型就像**一份红烧肉**——你拿到的就是肉本身，吃完了就没了。引用类型就像**一张取餐号牌**——号牌本身不是菜，但它指向厨房里那道菜的位置。你把号牌给别人（赋值），别人也指向同一道菜；你们任何一个人让厨师加辣（修改），另一个人拿到的菜也会变。

~~~
内存模型：

基本类型（存在栈上）：
┌──────────┐
│ 变量 a    │
│ 值: 38    │   ← 值直接存在变量里
└──────────┘

引用类型（存在堆上）：
┌──────────┐      ┌──────────────────┐
│ 变量 obj  │      │ 堆内存            │
│ 地址: 0x1 │ ──→  │ { 名字: "红烧肉" } │  ← 变量只存地址
└──────────┘      └──────────────────┘
~~~

### 赋值行为差异

~~~javascript
// ========== 基本类型：赋值是"复制一份" ==========
let 价格A = 38;
let 价格B = 价格A;     // 复制一份值给 B

价格B = 42;
console.log(价格A);    // 38（A 不受影响）
console.log(价格B);    // 42

// A 和 B 是两个独立的值，互不影响

// ========== 引用类型：赋值是"复制地址" ==========
let 菜品A = { 名字: "红烧肉", 价格: 38 };
let 菜品B = 菜品A;     // 复制的是地址，B 也指向同一个对象

菜品B.价格 = 42;
console.log(菜品A.价格);  // 42（A 也变了！）
console.log(菜品B.价格);  // 42

// A 和 B 指向同一个对象，改 B 就是改 A

// ========== 证明是同一个对象 ==========
console.log(菜品A === 菜品B);  // true（地址相同）
~~~

### 比较行为差异

~~~javascript
// ========== 基本类型比较：比的是"值" ==========
console.log(38 === 38);           // true（值相同）
console.log("红烧肉" === "红烧肉"); // true（值相同）

// ========== 引用类型比较：比的是"地址"（是不是同一个对象） ==========
let 菜品1 = { 名字: "红烧肉" };
let 菜品2 = { 名字: "红烧肉" };
let 菜品3 = 菜品1;

console.log(菜品1 === 菜品2);  // false（内容一样，但不是同一个对象）
console.log(菜品1 === 菜品3);  // true（同一个对象）

// ========== 数组也一样 ==========
console.log([1, 2] === [1, 2]);  // false（两个不同的数组对象）
console.log([] === []);           // false（两个不同的空数组）
~~~

### 函数传参差异

~~~javascript
// ========== 基本类型传参：传的是"值的副本" ==========
function 改价格(价格) {
  价格 = 999;  // 修改的是副本
}

let 原价 = 38;
改价格(原价);
console.log(原价);  // 38（原值不受影响）

// ========== 引用类型传参：传的是"地址的副本" ==========
function 改菜品(菜品) {
  菜品.价格 = 999;  // 通过地址找到原对象，修改它
}

let 红烧肉 = { 名字: "红烧肉", 价格: 38 };
改菜品(红烧肉);
console.log(红烧肉.价格);  // 999（原对象被修改了！）

// ========== 注意：重新赋值不会影响原对象 ==========
function 重新赋值(菜品) {
  菜品 = { 名字: "新菜", 价格: 0 };  // 让参数指向一个新对象
}

let 原菜 = { 名字: "红烧肉", 价格: 38 };
重新赋值(原菜);
console.log(原菜);  // { 名字: "红烧肉", 价格: 38 }（没变！）

// 因为 菜品 = 新对象 只是让"地址的副本"指向了新地方
// 原菜 的地址没有变
~~~

### 如何实现深拷贝（不互相影响）

~~~javascript
// ========== 浅拷贝：只复制第一层 ==========
let 菜品 = { 名字: "红烧肉", 配料: ["五花肉", "酱油"] };

// 展开运算符（浅拷贝）
let 拷贝1 = { ...菜品 };

// Object.assign（浅拷贝）
let 拷贝2 = Object.assign({}, 菜品);

拷贝1.名字 = "糖醋里脊";
console.log(菜品.名字);  // "红烧肉"（第一层互不影响）

拷贝1.配料.push("醋");
console.log(菜品.配料);  // ["五花肉", "酱油", "醋"]（深层还是同一个！）

// ========== 深拷贝：完全独立的副本 ==========
// 方法1：structuredClone（推荐，现代浏览器支持）
let 深拷贝1 = structuredClone(菜品);

// 方法2：JSON 转一圈（有限制：不能处理函数、undefined、循环引用）
let 深拷贝2 = JSON.parse(JSON.stringify(菜品));

深拷贝1.配料.push("糖");
console.log(菜品.配料);  // ["五花肉", "酱油", "醋"]（不受影响了！）
~~~

## 3.6 隐式类型转换规则

**一句话解释：**
JavaScript 在运算时会**自动**把不同类型的数据转成同一类型再计算，这就是隐式转换。它是很多"诡异"结果的根源。

**餐厅比喻：**
你问服务员"红烧肉多少钱"，服务员可以回答你"38元"（数字），也可以回答你"38元"（文字）。但如果你要算"红烧肉 + 麻婆豆腐"，服务员就懵了——**字符串和数字怎么加？** JS 的做法是：**偷偷把其中一个转成另一个的类型**（隐式转换），然后才计算。

### 转数字的场景

~~~javascript
// ========== 一元加号 +：把值转成数字 ==========
console.log(+"42");           // 42
console.log(+"");             // 0
console.log(+"abc");          // NaN
console.log(+true);           // 1
console.log(+false);          // 0
console.log(+null);           // 0
console.log(+undefined);      // NaN

// ========== 一元减号 -：也转数字（再取反） ==========
console.log(-"42");           // -42

// ========== 比较运算符：把两边转成数字 ==========
console.log("5" > 3);         // true（"5" 转成 5，5 > 3）
console.log("01" == 1);       // true（"01" 转成 1）

// ========== 算术运算（减、乘、除、取模）：转数字 ==========
console.log("10" - 5);        // 5
console.log("10" * "2");      // 20
console.log("10" / "2");      // 5
console.log("10" % "3");      // 1
~~~

### 转字符串的场景

~~~javascript
// ========== 加号 + 有一边是字符串：另一边转字符串 ==========
console.log("价格：" + 38);    // "价格：38"
console.log("abc" + true);    // "abcture"
console.log("abc" + null);    // "abcnull"
console.log("abc" + undefined); // "abcundefined"

// ========== 对象转字符串：调用 toString() ==========
console.log("" + { 名字: "红烧肉" });  // "[object Object]"
console.log("" + [1, 2, 3]);           // "1,2,3"
console.log("" + [1]);                 // "1"
console.log("" + []);                  // ""

// ========== 模板字符串也会触发转字符串 ==========
console.log(`数字：${42}`);    // "数字：42"
console.log(`布尔：${true}`);  // "布尔：true"
~~~

### 转布尔的场景

~~~javascript
// ========== 逻辑运算符：先转布尔 ==========
// &&：左边为假返回左边，否则返回右边
console.log(0 && "红烧肉");       // 0
console.log("有值" && "红烧肉");  // "红烧肉"

// ||：左边为真返回左边，否则返回右边
console.log(0 || "红烧肉");       // "红烧肉"
console.log("有值" || "红烧肉");  // "有值"

// ??：左边为 null/undefined 返回右边，否则返回左边
console.log(0 ?? "红烧肉");       // 0（0 不是 null/undefined）
console.log(null ?? "红烧肉");    // "红烧肉"

// ========== if / while / 三元：条件转布尔 ==========
if ("红烧肉") { }   // true（非空字符串）
if ("") { }          // false（空字符串）
if (0) { }           // false
if ([]) { }          // true ← 坑！空数组是 truthy
if ({}) { }          // true ← 坑！空对象是 truthy
~~~

### 对象的转换规则（ToPrimitive）

~~~javascript
// ========== 对象转基本类型的顺序 ==========

// 1. 调用 Symbol.toPrimitive（如果有的话）
// 2. 调用 valueOf()
// 3. 调用 toString()
// 4. 都不行就报错

// 数组的转换：
console.log([1] + [2]);     // "12"
// 步骤：[1].toString() → "1"，[2].toString() → "2"，"1" + "2" → "12"

console.log([1, 2] + [3]);  // "1,23"
// [1,2].toString() → "1,2"，[3].toString() → "3"，"1,2" + "3" → "1,23"

// 对象的转换：
console.log({} + []);       // "[object Object]"
// {}.toString() → "[object Object]"，[].toString() → ""，拼接

console.log([] + {});       // "[object Object]"
// 同上
~~~

### 隐式转换速查表

~~~
┌──────────────┬──────────────┬───────────────────────────────┐
│  运算/场景    │  转换成什么   │  规则                          │
├──────────────┼──────────────┼───────────────────────────────┤
│  + (有字符串) │  字符串      │  另一边转字符串再拼接           │
│  + (纯数字)   │  数字        │  正常加法                      │
│  - * / %      │  数字        │  两边都转数字                  │
│  ==           │  见下面等号表 │  有复杂规则                    │
│  ===          │  不转换      │  类型不同直接 false            │
│  > < >= <=    │  数字        │  两边都转数字（有字符串例外）   │
│  !            │  布尔        │  转布尔再取反                  │
│  && ||        │  不转换      │  返回操作数本身（不转布尔）    │
│  if / while   │  布尔        │  转布尔判断                    │
│  模板字符串    │  字符串      │  ${} 内转字符串                │
└──────────────┴──────────────┴───────────────────────────────┘
~~~

## 3.7 `==` vs `===` 的差异

**一句话解释：**
- `===`（严格相等）：类型不同直接 false，**不做任何转换**
- `==`（宽松相等）：类型不同时会**隐式转换**后再比较

**餐厅比喻：**
- `===` 就像查身份证——名字一样但身份证号不同，那就是不同的人
- `==` 就像只看名字——"张三"和"张三"就算不是同一个人，名字一样就算

~~~javascript
// ========== 基本类型 vs 引用类型 ==========

// === 严格相等（推荐，永远用这个）
console.log(38 === 38);           // true
console.log(38 === "38");         // false（类型不同，直接 false）
console.log(null === undefined);  // false
console.log(0 === false);         // false
console.log("" === false);        // false
console.log(NaN === NaN);         // false ← 坑！NaN 不等于自己

// == 宽松相等（有隐式转换，容易出 bug）
console.log(38 == "38");          // true（"38" 转成 38）
console.log(null == undefined);   // true（特殊规则）
console.log(0 == false);          // true（false 转成 0）
console.log("" == false);         // true（都转成 0）
console.log(0 == "");             // true（都转成 0）
console.log("" == 0);             // true
console.log(NaN == NaN);          // false
console.log([] == false);         // true ← 坑！
console.log([0] == false);        // true ← 坑！
console.log("" == []);            // true ← 坑！
console.log(0 == []);             // true ← 坑！
~~~

### `==` 的完整转换规则

~~~
== 宽松相等的判断流程：

1. 类型相同？
   └── 是 → 直接用 === 比较

2. null == undefined？
   └── 是 → true（这是唯一的特殊规则）

3. 一边是数字，另一边不是？
   └── 把另一边转成数字再比较

4. 一边是布尔？
   └── 把布尔转成数字（true→1, false→0）再比较

5. 一边是对象，另一边是基本类型？
   └── 把对象转成基本类型（ToPrimitive）再比较
~~~

~~~javascript
// ========== 规则演示 ==========

// 规则2：null == undefined
null == undefined          // true
null == null               // true
undefined == undefined     // true
null == 0                  // false（null 只和 undefined 宽松相等）

// 规则3：有一边是数字
"38" == 38                 // true（"38" → 38）
"" == 0                    // true（"" → 0）
"abc" == 0                 // false（NaN == 0 → false）
true == 1                  // true（true → 1）
false == 0                 // true（false → 0）

// 规则4：布尔先转数字
true == "1"                // true（true→1，"1"→1）
false == ""                // true（false→0，""→0）
true == "true"             // false（true→1，"true"→NaN）

// 规则5：对象转基本类型
[1] == 1                   // true（[1].toString()→"1"→1）
[] == 0                    // true（[].toString()→""→0）
[] == ""                   // true（[].toString()→""）
[] == false                // true（[]→""→0，false→0）
[1] == true                // true（[1]→"1"→1，true→1）
~~~

### 终极建议

~~~javascript
// 永远用 ===，不要用 ==

// ❌ 不要这样
if (值 == null) { }        // 虽然能同时判断 null 和 undefined，但容易误判

// ✅ 这样写更清晰
if (值 === null || 值 === undefined) { }

// ✅ 或者用 ?? 运算符
const 结果 = 值 ?? 默认值;  // null/undefined 时用默认值
~~~

## 3.8 `typeof` / `instanceof` 的实现原理

**一句话解释：**
- `typeof` 看的是值在**底层的类型标签**（存在内存中）
- `instanceof` 看的是对象的**原型链**上有没有这个构造函数的 prototype

**餐厅比喻：**
- `typeof` 就像看一个人的**工牌颜色**——红牌是厨师，蓝牌是服务员，一眼就知道类型
- `instanceof` 就像看一个人的**师承关系**——查他师傅的师傅的师傅，有没有拜过某个门派

### typeof 的原理

~~~javascript
// ========== typeof 的底层实现 ==========

// JS 引擎在每个值的底层存储了一个"类型标签"（Type Tag）
// typeof 就是读这个标签

// 底层类型标签：
// 000 → 对象（Object）
// 001 → 整数（int）
// 010 → 浮点数（double）
// 100 → 字符串（string）
// 110 → 布尔（boolean）

// 特殊情况：
// undefined → 用 JSVAL_VOID 标签
// null → 底层标签是 000（和对象一样！）→ 所以 typeof null === "object"（历史bug）

// ========== typeof 的所有返回值 ==========
typeof 42              // "number"
typeof "红烧肉"        // "string"
typeof true            // "boolean"
typeof undefined       // "undefined"
typeof Symbol()        // "symbol"  ← ES6 新增
typeof 42n             // "bigint"  ← ES2020 新增
typeof function(){}    // "function" ← 特殊处理，其实是对象的子类型
typeof {}              // "object"
typeof []              // "object"  ← 坑！
typeof null            // "object"  ← 经典坑！历史遗留 bug
typeof new Date()      // "object"
typeof /abc/           // "object"
typeof new Map()       // "object"
~~~

~~~javascript
// ========== typeof null === "object" 的历史原因 ==========

// JS 的第一个版本（1995年）用 32 位存储值
// 低位 1~3 位是类型标签：
//   000 → 对象
//   1   → 整数
//   010 → 浮点数
//   100 → 字符串
//   110 → 布尔
//
// null 被表示为"空指针"（全零 → 0x00000000）
// 低位是 000 → typeof 读到了"对象"标签
// 这个 bug 一直存在，因为修复它会破坏大量现有代码

// ========== typeof 的实际用途 ==========

// 最佳用法：判断基本类型
function 判断类型(值) {
  if (值 === null) return "null";        // 先排除 null
  if (Array.isArray(值)) return "array"; // 再排除数组
  return typeof 值;                       // 最后用 typeof
}
~~~

### instanceof 的原理

~~~javascript
// ========== instanceof 的底层实现 ==========

// instanceof 沿着对象的原型链往上找
// 看 构造函数.prototype 是否在原型链上

// 伪代码实现：
function myInstanceof(对象, 构造函数) {
  let 原型 = Object.getPrototypeOf(对象);  // 获取对象的原型

  while (原型 !== null) {                  // 沿着原型链往上找
    if (原型 === 构造函数.prototype) {     // 找到了！
      return true;
    }
    原型 = Object.getPrototypeOf(原型);    // 继续往上
  }

  return false;                            // 找到 null 还没找到
}

// ========== 验证 ==========

class 厨师 { }
class 学徒 extends 厨师 { }

const 小王 = new 学徒();

console.log(myInstanceof(小王, 学徒));    // true（小王.__proto__ === 学徒.prototype）
console.log(myInstanceof(小王, 厨师));    // true（继续往上找到了 厨师.prototype）
console.log(myInstanceof(小王, Object)); // true（原型链顶端是 Object.prototype）
console.log(myInstanceof(小王, Array));  // false

// 等价于：
console.log(小王 instanceof 学徒);        // true
console.log(小王 instanceof 厨师);        // true
console.log(小王 instanceof Object);     // true
~~~

~~~javascript
// ========== instanceof 的局限性 ==========

// 1. 只能判断对象，不能判断基本类型
console.log(42 instanceof Number);        // false（基本类型不是对象）
console.log("abc" instanceof String);     // false
console.log(new Number(42) instanceof Number);  // true（包装对象才行）

// 2. 跨 iframe / 跨窗口失效
// 因为不同窗口有自己的构造函数，prototype 不是同一个

// 3. 可以通过改 prototype 绕过
class 餐厅 { }
const 店 = new 餐厅();
console.log(店 instanceof 餐厅);     // true

餐厅.prototype = {};                 // 改了 prototype
console.log(店 instanceof 餐厅);     // false（找不到了！）
~~~

### typeof vs instanceof 对比

| | typeof | instanceof |
|---|---|---|
| 判断什么 | 基本类型的类型 | 对象是否属于某个"类" |
| 返回值 | 类型字符串 | true / false |
| 原理 | 读底层类型标签 | 沿原型链查找 |
| 基本类型 | ✅ 能判断 | ❌ 不能判断（除了包装对象） |
| null | ❌ 返回 "object"（bug） | ❌ 报错 |
| 对象细分 | ❌ 全返回 "object" | ✅ 能区分 Array/Date/RegExp 等 |
| 餐厅比喻 | 看工牌颜色（一眼知道类型） | 查师承关系（查原型链） |
| 推荐用法 | 判断基本类型 | 判断对象类型 |

~~~javascript
// ========== 最佳实践：组合使用 ==========

function 精确类型判断(值) {
  // null 单独判断
  if (值 === null) return "null";

  // 基本类型用 typeof
  if (typeof 值 !== "object") return typeof 值;

  // 引用类型用 Object.prototype.toString
  return Object.prototype.toString.call(值).slice(8, -1);
}

精确类型判断(42);              // "Number"
精确类型判断("红烧肉");        // "String"
精确类型判断(null);            // "null"
精确类型判断([]);              // "Array"
精确类型判断({});              // "Object"
精确类型判断(new Date());      // "Date"
精确类型判断(/abc/);           // "RegExp"
精确类型判断(new Map());       // "Map"
精确类型判断(new Set());       // "Set"
~~~

## 第03章 总结

| 术语 | 一句话解释 | 餐厅比喻关键词 |
|---|---|---|
| Boolean | 只有 true 和 false | 营业/打烊的牌子 |

| undefined | 还没赋值/没定义 | 今日特选还没定 |
| Number | 整数和小数（唯一数字类型） | 计算器上同一排键 |
| BigInt | 超大整数（数字后加 n） | 超级计算器，只算整数 |
| String | 文字内容（引号包裹） | 菜单上的文字 |
| Symbol | 全球唯一的标记 | 防伪二维码 |
| Object | 键值对的集合（万能储物柜） | 有标签格子的储物柜 |
| 假值 Falsy | 6个值在条件中当 false | 只有6种情况判定不营业 |
| typeof | 检查值是什么类型 | "这是什么？" |
| 字面量 | 直接写出来的值 | 实物本身，不需要"创建" |
| 基本类型 | 值存在变量本身，赋值复制值 | 一份红烧肉，吃了就没了 |
| 引用类型 | 值存在堆内存，变量只存地址 | 取餐号牌，指向厨房里的菜 |
| 值传递 | 基本类型赋值/传参，复制一份独立的值 | 肉给你一份，我的还在 |
| 引用传递 | 引用类型赋值/传参，复制的是地址 | 号牌给你一张，指向同一道菜 |
| 浅拷贝 | 只复制第一层，深层还是共享 | 包装换了，里面的东西还是同一份 |
| 深拷贝 | 完全独立的副本 | 完全重新做了一份一模一样的菜 |
| structuredClone | 现代深拷贝 API | 复印机，完整复印一份 |
| 隐式转换 | JS 自动把不同类型转成同一类型再运算 | 服务员自动把文字转成数字再算 |
| ToPrimitive | 对象转基本类型的规则 | 先问 toPrimitive，再问 valueOf，再问 toString |
| == 宽松相等 | 类型不同时隐式转换再比较 | 只看名字，不查身份证 |
| === 严格相等 | 类型不同直接 false | 查身份证，姓名+号码都一样才算 |
| typeof | 读底层类型标签 | 看工牌颜色 |
| typeof null | 历史 bug，返回 "object" | 工牌颜色标错了，一直是已知问题 |
| instanceof | 沿原型链查找是否属于某个类 | 查师承关系，有没有拜过某个门派 |
| Object.prototype.toString | 最精确的类型判断方法 | 查人事档案，最权威 |
