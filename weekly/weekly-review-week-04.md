**出题提醒（历史 bug）：**
- 你的 `splitText` 迭代了 3 轮：第 1 轮无脑 append（产生冗余尾块）、第 2 轮用「长度」判断（**丢了内容**）、第 3 轮用了「名义位置」（死代码）。想清楚判断标准再动笔——**"这块有没有带来新内容"**。

- 你的 `cosineSimilarity` 上次处理了零向量和维度不一致，这次继续。

**你的代码：**

```javascript
// ========== 任务1：滑动窗口切块 ==========
function splitText(text, chunkSize, overlap) {
    if (!text) return [];

    // 校验参数
    if (chunkSize <= 0) throw new Error("chunkSize 必须大于 0");
    if (overlap < 0) throw new Error("overlap 不能为负数");
    if (overlap >= chunkSize) throw new Error("overlap 必须小于 chunkSize");

    const chunkList = [];
    const step = chunkSize - overlap;
    let prevEnd = 0;

    for (let i = 0; i < text.length; i += step) {
        const chunk = text.slice(i, i + chunkSize);
        const currEnd = i + chunk.length;

        // 最后一块没有新内容，丢弃
        if (currEnd <= prevEnd) break;

        chunkList.push(chunk);
        prevEnd = currEnd;
    }

    return chunkList;
}


// ========== 任务2：余弦相似度 ==========
function cosineSimilarity(a, b) {
    // 维度必须一致
    if (a.length !== b.length) {
        throw new Error(`向量维度不一致: ${a.length} vs ${b.length}`);
    }

    // 点积
    let dotProduct = 0;
    for (let i = 0; i < a.length; i++) {
        dotProduct += a[i] * b[i];
    }

    // 向量模
    let normA = 0;
    let normB = 0;
    for (let i = 0; i < a.length; i++) {
        normA += a[i] * a[i];
        normB += b[i] * b[i];
    }
    normA = Math.sqrt(normA);
    normB = Math.sqrt(normB);

    // 防止除以0
    if (normA === 0 || normB === 0) return 0;

    return dotProduct / (normA * normB);
}


// ========== 测试用例 ==========
console.log(splitText("ABCDEFGHIJ", 4, 1));
// 自己和自己 → 1.0
console.log(cosineSimilarity([0.1, 0.3, 0.5], [0.1, 0.3, 0.5]));
// 正交 → 0.0
console.log(cosineSimilarity([1, 0], [0, 1]));
// 反交 → -1.0
console.log(cosineSimilarity([1, 0], [-1, 0]));

```

> **前两层是"检测和拦截"，攻击者总有办法绕过（同义词、Unicode、编码变形）。第三层是"就算你被劫持了，也干不了大事"——最后一道防线。**

本题场景下的具体做法：不要给 LLM 任何不该看的敏感信息（API Key、数据库密码、其他用户的资料不进上下文），不要给它危险工具的调用权限。这样即使 System Prompt 被套出来了，损失也有限。

❌ **Function Calling 又答错了（第二次）**：
> 你的答案：「Function Calling 里 LLM 调用后端的工具来处理」

**正确答案：LLM 从头到尾没有调用任何工具。** 它只做一件事——返回一段 JSON 告诉你"建议调用 `query_order`，参数是 `{"order_id": "12345"}`"。**真正执行工具的是你的后端代码。**

完整流程：
```
① 你把工具清单（name + 描述 + 参数 schema）一起发给 LLM
② LLM 返回 {"tool_calls": [{"function": {"name": "query_order", "arguments": "{...}"}}]}   ← 它只给建议
③ 你的后端解析这段 JSON，真正调用 query_order()                                  ← 你执行
④ 你把工具执行结果拼成一条 role="tool" 的消息，再发回给 LLM
⑤ LLM 基于结果生成人话回复
```

为什么这个区别重要：面试官问「你怎么防止 AI 乱调工具」，答"LLM 不会自己调，是我拿到建议后决定要不要执行"——这才是安全设计的**立足点**（工具白名单、参数校验、人工审批，全都建立在"执行权在我手里"这个事实上）。
