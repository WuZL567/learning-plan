## 验收过程

### 11.2.1 System Prompt：角色设定

**第一层追问：白话复述**
- 学生回答：角色设定就是告诉AI，它是谁，是什么角色，以此来限制AI回复时候的语气，角度，专业度
- 评判：✅ 通过，理解准确

**第二层追问：对比理解**
- 导师提问：角色设定和用户消息中的"问题描述"有什么区别？比如我直接在用户消息里说"请用资深前端工程师的角度分析"，和在 System Prompt 里设定"你是资深前端工程师"，效果一样吗？
- 学生回答：没有区别，效果一样
- 评判：❌ 未通过
- 正确答案：有区别。System Prompt 中的角色设定是持久生效的，影响整个对话的所有轮次。用户消息中临时要求只对当前这一轮生效。类比：System Prompt 像组件的 props.default，用户消息像某次调用时临时传的参数。

**第三层追问：场景应用**
- 导师提问：你在做一个代码审查工具，需要 AI 检查用户提交的代码。你会怎么设计角色设定？说出具体的 System Prompt 内容。
- 学生回答：你是一个代码审查机器人，你会对用户提供的代码全面review，找到代码中不合理的设计，找出导致代码崩溃的BUG
- 评判：✅ 通过，明确角色、任务范围、关注重点

### 11.2.2 System Prompt：输出格式约束

**第一层追问：白话复述**
- 学生回答：输出格式是为了限制AI必须按照指定格式来返回内容，比如说JSON对象，Markdown格式等，目的是为了让AI输出用户需要的格式内容
- 评判：✅ 通过

**第二层追问：对比理解**
- 导师提问：输出格式约束和后端接口的响应格式约定，有什么相似之处和不同之处？
- 学生回答：相似之处：都是按照用户的格式要求来返回用户需要的格式内容，方便用户使用；不同之处：后端接口的格式约定后，接口严格遵守，不会随意变更，但是AI输出格式约定后，有可能因为温度temperature过高导致AI不完全遵守
- 评判：✅ 通过，抓住了强约束 vs 软约束的核心差异

**第三层追问：场景应用**
- 导师提问：你要做一个"简历解析工具"，用户上传简历文本，AI 提取出姓名、工作经验、技能列表。你会怎么设计输出格式约束？说出具体的 System Prompt 内容。
- 学生回答：将用户简历提取内容按照STAR的准则，按照Markdown内容格式返回，返回示例如：## 姓名 ....
- 评判：⚠️ 部分通过但有偏差
- 正确答案：场景要求是"提取结构化数据"，更适合用 JSON 格式，而不是 Markdown 文档格式。应该设计为：
```
你必须返回 JSON 格式：
{
  "name": "姓名",
  "experience": [{"company": "公司", "duration": "时长", "role": "职位"}],
  "skills": ["技能1", "技能2"]
}
```
- 关键区别：JSON 用于结构化数据提取和前端解析，Markdown 用于生成文档报告

### 11.2.3 System Prompt：任务分解指令

**第一层追问：白话复述**
- 学生回答：告诉AI，复杂任务应该怎么去拆分步骤，每一步怎么走，顺序如何，控制AI的执行过程，避免不必要的Token浪费和尝试
- 评判：✅ 通过，抓住核心 + 提到 token 节省

**第二层追问：对比理解**
- 导师提问：任务分解指令和 CoT（Chain of Thought，思维链）有什么区别？
- 学生回答：任务分解指令是靠工程师去拆解任务，然后告知AI按照步骤去执行复杂任务，达到目的；CoT是完全由AI自身去拆解复杂任务，并且自己决策如何执行等，依靠的是AI自身模型能力和算力等，能力越低的模型越无法实现，能力越高则价格越贵
- 评判：✅ 通过，核心差异清晰（人控制 vs AI 推理）
- 补充：任务分解指令更可控、可预测，适合生产环境；CoT 更灵活、适合复杂推理，但结果不稳定。实际项目中常用"任务分解 + CoT 混合"

**第三层追问：场景应用**
- 导师提问：你要做一个"技术方案评审助手"，用户提交一个技术方案文档，AI 要评审并给出建议。你会怎么设计任务分解指令？说出具体的步骤。
- 学生回答：严格按照以下步骤进行，每一步需要一个结果反馈：1、调用read工具，获取技术方案文档内容；2、按照 @xxx文档 中的准则，每一条进行Check，返回Check结果；3、查看第2步返回的Check结果，按照通过率进行打分；4、获取第3步的分数，如果高于90分，则直接通过，告知用户结果；低于90分则将有问题的列出来，告知用户并给予1～2条关键措施以及理由
- 评判：✅ 通过，步骤完整（输入 → 处理 → 评估 → 输出），有量化评估，有分支决策

## 关键知识点纠正

1. **System Prompt 的持久性**：System Prompt 中的角色设定是全局持久的，影响整个对话；用户消息中的临时要求只对当前轮次生效。这是设计多轮对话系统时的关键区别。

2. **格式选择原则**：
   - JSON 用于结构化数据提取和前端解析
   - Markdown 用于生成文档、报告、笔记
   - 选格式要看下游用途：数据处理用 JSON，人类阅读用 Markdown
