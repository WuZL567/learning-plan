# 6.1 Cookie 基本属性

冲刺模式模板：一句话说清楚 + 三个要点 + 不确定的点

## 一句话说清楚

这里用一句白话写：Cookie 是什么、存在哪、浏览器什么时候会自动带上它。

Cookie是一段键值对文本，是服务器通过Set-Cookie响应头下发给浏览器的一段domain/path的规则，存在浏览器，浏览器下次发送请求时会自动带上；

## 三个要点

**要点1：基本属性清单**
这里逐个写清楚以下属性是干什么的、默认值是什么：
- name / value：键值对，value 存什么
value存的时设置的name的属性值；
- domain：默认是谁？设置后哪些域名能携带？
domain默认是当前域名，设置后所有的子域都可以携带，但是跨域不能携带，例如设置了domain=baidu.com，那么a.baidu.com和b.baidu.com都可以携带，但是google.com是无法携带的；
- path：默认值是什么？控制什么？
path默认是（/），控制访问的URL路径，设置了path=/a后，只有/a开头的路径才携带cookie；
- expires / max-age：两者有什么区别？都不设置时 Cookie 是什么状态？
expires是设置具体的时间，比如说2027-01-01，表示到期时间是2027-01-01，而max-age则是设置的剩余时间，比如说3600，则是表示现在开始倒计时3600秒后就会过期，都不设置时，浏览器关闭则cookie过期，而不是标签页关闭的时机；
- 大小限制：单个 Cookie 最大约多大？一个域名最多多少个？
最大4KB，最多20个；

**要点2：浏览器自动携带的机制**
这里写：Cookie 的携带流程——服务端怎么设置、浏览器怎么存、下次请求时怎么带回来。注意：
- 用 `Set-Cookie` 响应头还是 JS `document.cookie`？两者有什么区别？
1、Set-Cookie（服务端）：服务器在响应头下发，浏览器自动存。能设置 httpOnly、domain 这些高级属性。登录态的标准做法。
2、document.cookie（前端 JS）：前端写入，每次写一个键值对，会覆盖同 name 的 Cookie。只能操作 httpOnly 为 false 的 Cookie。
- 跨域请求（fetch 带 credentials）时 Cookie 会不会自动带上？
默认 credentials: 'same-origin' 跨域不带，要跨域带需 credentials: 'include' 且服务端 CORS 配置 Allow-Credentials。
- 一个你工作中真实遇到过或听过的 Cookie 场景（比如登录态、埋点、购物车）
登录注册的接口请求没有cookie携带，只有登录之后，才会在接口请求中进行携带cookie操作；

**要点3：与前端框架无关的事实**
这里写：Cookie 是浏览器的能力，不是 HTTP 的"专属物"。想两个问题：
- 关闭浏览器标签页，会话 Cookie 还在吗？过期时间由什么决定？
会话Cookie还在，由expires和max-age设置来决定，如果没设置则是浏览器的退出时间决定；
- 前端能不能把 Cookie 的值删掉？怎么删？
能删掉，可以通过设置Cookie的过期时间，让Cookie立即过期，让浏览器自动清理掉；

## 我的理解中不确定的部分

这里诚实写出还没完全搞懂的点。比如：domain 设置成顶级域名和子域名的区别？max-age 和 expires 同时出现听谁的？Cookie 在不同标签页之间共享吗？
上面写了不知道的就是没搞懂的。
1、设置成顶级域名可以允许子域名携带Cookie，而设置成子域名则另外的子域名无法携带Cookie；
2、同时出现时先听max-age的；
3、不知道，我猜测是共享的，和域名相关；

## 三层追问（验收时口答，不用写）

1. 白话复述：30 秒讲清楚 Cookie 是什么、浏览器为什么能记住它。
Cookie是一个键值对文本，由服务端通过set-cookie响应头，保存在浏览器，浏览器有专门存Cookie的地方；
2. 对比理解：Cookie 和 localStorage 最大的区别是什么（带不带、过期、大小）？
Cookie会过期，localStorage不主动清理则不会过期；
Cookie的大小只有4KB，而localStorage则可以达到5MB；
Cookie是接口请求时自动携带的，而localStorage则是需要主动去获取，一般由前端主动存储和查询；
3. 场景应用：面试官问"为什么网站能记住我的登录状态，关掉浏览器再打开还在"，你怎么答？
这个就是Cookie在生效，Cookie中保存了这个用户对应的登录状态，而没有过期时，你再次访问这个网站时，会携带Cookie告诉服务器，你还在登录中；
