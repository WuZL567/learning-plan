# 6.8 IndexedDB 基本概念

冲刺模式模板：一句话说清楚 + 三个要点 + 不确定的点

## 一句话说清楚

这里用一句白话写：IndexedDB 是什么、适合存什么。
是浏览器内置的完整数据库，可以存对象，数组，Blob，File这些大容量数据；

## 三个要点

**要点1：IndexedDB 是什么**
写清楚：
- 它是数据库吗？浏览器内置的？
是的，是的；
- 存的是键值对还是对象？支持"查询"吗（索引）？
支持存对象，数组，Blob，File，支持索引和查询；
- 容量多大？（对比：Cookie 4KB / localStorage 5MB / IndexedDB 多大？）
几百MB～GB级别；

**要点2：和 localStorage 的区别（核心）**
对比写：
- localStorage 存什么量级的数据？IndexedDB 存什么量级？
localStorage存小量级别数据，IndexDB存大数据；
- localStorage 能存二进制（图片/视频/文件）吗？IndexedDB 呢？
localStorage不能存二进制。IndexDB则可以存，容量大；
- 异步还是同步？为什么异步重要？（提示：大容量数据操作不能阻塞主线程）
异步，不阻塞主线程；

**要点3：典型场景**
写清楚：
- 什么场景必须用 IndexedDB？（提示：离线应用 PWA、超大缓存、文件/图片缓存）
大量结构化数据时使用IndexDB，离线应用数据，支持无网使用，大文件或图片的缓存；
- 你用过吗？或见过什么产品用它？
没有见过，也没有使用过；

## 我的理解中不确定的部分

这里诚实写出还没完全搞懂的点。比如：IndexedDB 和 localStorage 的 API 风格差异？事务是什么？为什么前端要用数据库？
1、localStorage是同步，IndexDB是异步 + 复杂生命周期（open 打开库 → onupgradeneeded 建表 → transaction 起事务 → objectStore 读写）；
2、一组数据库操作的原子单元——要么全部成功，要么全部回滚。举例：转账 = 扣钱 + 入账两步，第二步失败，第一步必须撤回，不能出现"钱扣了但没到账"。IndexedDB 的所有读写都包在事务里；
3、有些大量结构化数据需要存储时需要用到数据库；

## 三层追问（验收时口答，不用写）

1. 白话复述：30 秒讲清楚 IndexedDB 是什么、和 localStorage 什么关系。
是一个前端使用的浏览器内置的数据库，和localStorage没有关系，都是用来存储的；
2. 对比理解：localStorage 能做的事 IndexedDB 都能做吗？为什么还要 localStorage？
都能做，localStorage可以在一些小容量的数据中做到更快更简便的操作；
3. 场景应用：你做一个图片浏览器网站，要把用户看过的图片缓存到本地减少流量，选哪个存储方案？
图片很大，localStorage不够用，所以用IndexDB；
