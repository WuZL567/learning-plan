# 6.6 sessionStorage 特性

冲刺模式模板：一句话说清楚 + 三个要点 + 不确定的点

## 一句话说清楚

这里用一句白话写：sessionStorage 和 localStorage 的本质区别（什么时候清）。
本质在于清理时机，sessionStorage是会话级存储，关闭标签页时就会清理掉；localStorage是持久型存储，不主动删除不会清理；

## 三个要点

**要点1：生命周期（核心）**
写清楚：
- 什么时候创建？什么时候销毁？
手动创建，标签页关闭时清理；
- 关闭标签页会清吗？关浏览器呢？刷新页面会清吗？
关闭标签页会清理，关闭浏览器也会清理，刷新页面不会清理
- **复制标签页**（Ctrl+Shift+T 恢复或右键复制）：sessionStorage 是复制了一份还是共享的？localStorage 呢？（这个是经典面试题）
复制一份，但是两个标签页面之间不会同步，也就是说你复制后修改其中一份，另外的标签页中不会同步修改。
localstorage中是共享一份的；

**要点2：作用域**
写清楚：
- 不同标签页之间 sessionStorage 共享吗？（和 localStorage 对比）
不共享，localstorage是共享的；
- 同标签页内跳转同源页面，数据还在吗？跨域跳转呢？
同源的存在，不同源的不存在；
- iframe 里的 sessionStorage 和父页面共享吗？（提示：一般情况不共享）
不共享；

**要点3：典型使用场景**
想一个真实场景回答：
- 什么场景适合用 sessionStorage 而不是 localStorage？（提示：表单填写中途刷新不丢、一次性流程、敏感信息不想留持久）
一些步骤表单的填充内容需要sessionStorage，这样不小心刷新了也不会丢失，关闭了也不会保存垃圾；
而一些持久设置就需要localstorage，比如说主题状态，首次进入路由后的提示；
- 你工作中有没有用过它？为什么？
用过；

## 我的理解中不确定的部分

这里诚实写出还没完全搞懂的点。比如：复制标签页后 sessionStorage 是复制还是共享？跳转新页面（window.open）数据还在吗？sessionStorage 和 localStorage 容量一样吗？
1、复制的；
2、新开标签页后，数据不会保留；
3、localStorage 和 sessionStorage 在浏览器里都是约 5MB/源，而且共享同一个配额：localStorage 占了 3MB，sessionStorage 就只能用剩下的 2MB；

## 三层追问（验收时口答，不用写）

1. 白话复述：30 秒讲清楚 sessionStorage 和 localStorage 的区别。
存储生命周期不一致；一个是会话级存储，一个是持久型存储；
2. 对比理解：会话（session）和持久（persistent）在 Cookie 里的对应关系是什么？（提示：会话 Cookie）
会话 Cookie ≈ sessionStorage，持久 Cookie ≈ localStorage；
3. 场景应用：用户在一个多步骤表单里填了一半，不小心刷新了页面，数据全没了。用哪个 API 能保住？为什么？
两个都可以保留，但是没有必要用localStorage，毕竟不需要持久保留，因为这个只是临时填写需要，所以用sessionStorage可以临时存储就好；
