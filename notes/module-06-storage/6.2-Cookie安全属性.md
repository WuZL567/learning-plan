# 6.2 Cookie 安全属性

冲刺模式模板：一句话说清楚 + 三个要点 + 不确定的点

## 一句话说清楚

这里用一句白话写：httpOnly / Secure / SameSite 三个属性各防什么攻击。

httpOnly防止JS脚本注入攻击（XSS）；
Secure防止Http通道窃取；
SameSite防止跨域攻击（CSRF）；

## 三个要点

**要点1：httpOnly**
- 防什么攻击？攻击者拿到 Cookie 后能干嘛？
防XSS攻击，拿到Cookie后可以获取你的登录状态盗取账号信息；
- 设置了 httpOnly 后，`document.cookie` 还能读到吗？
设置了httpOnly之后，JS读不到，写不了，删不掉；
- 你工作中见过这个属性吗（浏览器 DevTools Application 面板里 Cookie 带不带 httpOnly 标志）？
见过，带；

**要点2：Secure**
- 防什么？在什么协议下才携带？
防Http通道窃取；只有Https协议下才携带Cookie；
- localhost（本地开发）算 HTTPS 吗？Secure Cookie 在 localhost 下能不能用？
不算，但是能用，因为localhost在浏览器中属于可信源；

**要点3：SameSite（重点）**
- 三个值：Strict / Lax / None，各自什么行为？
Strict：禁止任何跨站请求携带Cookie；
Lax：默认设置，跨站请求的顶层导航可以携带Cookie，也就是从我这个域名点击链接进去的就允许携带我的Cookie；
None：允许任何跨站请求携带Cookie；
- 默认值是什么（现代浏览器）？
默认是Lax；
- 什么场景必须用 SameSite=None？（提示：跨站，还要配合一个什么属性才能发？）
第三方支付回调，配合Secure使用；

## 我的理解中不确定的部分

这里诚实写出还没完全搞懂的点。比如：SameSite=Lax 下哪些请求还能带 Cookie？httpOnly 和 Secure 是同一个概念吗？SameSite=None 是不是必须配 Secure？
1、SameSite=Lax下，从顶层导航进去的都可以携带Cookie；
2、不是同一个概念，httpOnly是防止前端修改Cookie，避免脚本注入后形成XSS攻击；
3、SameSite=None时，必须要配合Secure使用；

## 三层追问（验收时口答，不用写）

1. 白话复述：30 秒讲清楚三个安全属性各防什么。
httpOnly防XSS攻击，Secure防Http通道的请求窃取，SameSite防止CSRF攻击；
2. 对比理解：httpOnly 防 XSS 窃取，SameSite 防 CSRF——两者防的攻击入口有什么不同？
XSS是从前端注入脚本攻击，而CSRF则是通过外部网站进行跨域请求攻击；
3. 场景应用：你的登录态 Cookie 被 XSS 脚本偷走了，面试官问你当时该设哪个属性能避免？
httpOnly设置为true；
