# 6.3 Cookie 与 CSRF 的关系

冲刺模式模板：一句话说清楚 + 三个要点 + 不确定的点

## 一句话说清楚

这里用一句白话写：CSRF 是什么、攻击者靠 Cookie 的什么特性得手。

CSRF是跨站请求伪造攻击，是攻击者利用浏览器自带Cookie的特性，引导你登录钓鱼网站后借用你的Cookie来发送请求伪造；

## 三个要点

**要点1：CSRF 攻击链路**
把完整链路写清楚，按顺序：
1. 受害者什么时候处于"已登录"状态（Cookie 在哪、有什么值）？
受害者已经登录被攻击的网站A，处于已登录状态，Cookie在浏览器，存了受害者的信息和状态；
2. 攻击者怎么诱导受害者触发请求（钓鱼网站/图片/表单/链接）？
通过一些恶意网站的超链接，引导受害者点击访问超链接；
3. 请求发出时，浏览器为什么自动带上受害者的 Cookie？
这些请求中由于访问的是被攻击的网站A，所以会自动带上Cookie；
4. 服务端收到请求时，为什么分不清是本人还是攻击者发的？
服务端只是识别Cookie，Cookie正确就可以下发请求；

**要点2：为什么 httpOnly 防不了 CSRF**
httpOnly 防的是 JS **读** Cookie，而 CSRF 攻击根本不需要读取 Cookie——攻击者只借浏览器的**自动携带机制**。想通这一点，用一句话说清"为什么读不到 Cookie 照样能攻击"。
这里CSRF根本不需要知道你的Cookie是什么，只是需要借助你已经登录的浏览器，让它自动带上你的Cookie即可；

**要点3：三道防线**
CSRF 的防御手段（面试答全）：
- SameSite 属性怎么设（哪个值能挡住）？挡的是什么类型的请求？
Strict：禁止任何跨站请求携带Cookie；
Lax：允许跨站请求的顶层导航携带Cookie；
- 服务端校验 Referer / Origin 是什么思路？
服务端检查请求来源是不是自己的站点；
- CSRF Token 是什么？攻击者为什么拿不到？
是服务端生成的Token，因为跨域页面无法获取到我的界面的内容，所以无法拿到；

## 我的理解中不确定的部分

这里诚实写出还没完全搞懂的点。比如：SameSite=Lax 默认值为什么还能被攻破？CSRF Token 和登录 Token 是同一个东西吗？GET 请求能发起 CSRF 吗？
1、Lax并不是所有的浏览器都支持，Lax下只有跨站顶层导航的GET请求带Cookie；
2、不是，登录Token是身份认证，而CSRF Token是请求来源合法性；
3、能；
4、CSRF Token 攻击者为什么拿不到？

## 三层追问（验收时口答，不用写）

1. 白话复述：30 秒讲清楚 CSRF 攻击的完整链路。
首先等受害者登录目标网站，浏览器保存准确的Cookie，然后引导受害者点击病毒页面中的超链接访问目标网站，通过浏览器自动携带目标网站的Cookie，成功请求目标网站接口请求，最终达到攻击目的；
2. 对比理解：XSS 和 CSRF 都是攻击，本质区别是什么（谁来执行攻击、目标是什么）？
XSS是在当前网站中，通过注入的恶意JS脚本获取你的Cookie，来攻击当前网站；
CSRF则是在别的网站中，访问目标网站，通过浏览器自动携带Cookie来伪造请求发起攻击；
3. 场景应用：你登录了购物网站，又打开了一个陌生网页，这个网页是个恶意页。它有没有可能利用你的登录态买东西？通过什么机制？
有可能，通过浏览器自动携带Cookie的机制；
