# 6.7 localStorage 与 sessionStorage 对比

冲刺模式模板：一句话说清楚 + 三个要点 + 不确定的点

## 一句话说清楚

这里用一句白话写：两者的本质区别（生命周期）。

localStorage是持久型存储，sessionStorage是会话型存储，localStorage不主动删除不会被清理，sessionStorage在标签页关闭时会被清理；

## 对比表

用表格从六个维度对比（生命周期 / 作用域 / 容量 / 刷新后 / 复制标签页 / 典型场景）：

| 维度 | localStorage | sessionStorage |
|------|-------------|----------------|
| 生命周期 | 持久型 | 会话型 |
| 作用域 | 同源 | 同源 |
| 容量 | 5MB/源 | 5MB/源 |
| 刷新页面后 | 数据保留 | 数据保留 |
| 复制标签页后 | 数据共享 | 数据复制不共享 |
| 典型场景 | 缓存用户设置，界面主题 | 缓存步骤表单临时填写内容 |

## 三个要点

**要点1：复制标签页的行为**
写清楚：复制标签页后，sessionStorage 是复制一份还是共享？localStorage 呢？
复制一份，不会共享；localStorage是共享一份的；

**要点2：场景选择**
写清楚：
- 什么场景必须用 sessionStorage（举个真实例子）？
步骤表单的临时填写内容；
- 什么场景必须用 localStorage（举个真实例子）？
用户界面的设置；

**要点3：为什么 sessionStorage 不常用**
想这个问题：埋点上报、跨标签页同步数据（比如左侧菜单选择同步到右侧内容页）、多标签页保持同一登录态——这些场景为什么用不上 sessionStorage？什么特性的场景才用得上它？
因为sessionStorage的特性，无法在多个标签页之间共享，并且没有持久存储特性，所以不能用在你这些场景，只能用在临时需要缓存，稍后需要释放的那种，比如说表单数据填写时临时存储，避免刷新后数据丢失；

## 我的理解中不确定的部分

这里诚实写出还没完全搞懂的点。比如：两个 API 容量一样吗？共享配额吗？切换标签页（不关闭）数据还在吗？
容量一样，共享配额，都是5MB/源。切换标签页后，localStorage的数据仍在，而sessionStorage的数据不会共享；

## 三层追问（验收时口答，不用写）

1. 白话复述：30 秒讲清楚 localStorage 和 sessionStorage 的区别。
生命周期存在本质差异，localStorage是持久缓存，不主动删除不会被清理，而sessionStorage是会话级缓存，标签页关闭则被清理；
2. 对比理解：会话 Cookie 和 sessionStorage 的对应关系是什么？
会话Cookie ≈ sessionStorage；持久Cookie ≈ localStorage；
3. 场景应用：用户打开两个标签页操作同一份"草稿"，用哪个 API 保证两个标签页看到同一份数据？
localStorage，这里需要跨标签页，sessionStorage在同源的不同标签页之间不会共享；
