# 6.9 四种存储方式横向对比

冲刺模式模板：一句话说清楚 + 三个要点 + 不确定的点

## 一句话说清楚

用一句话总览四种存储的定位。
Cookie：4KB，浏览器自动携带；
localStorage：5MB 持久型存储；
sessionStorage：5MB 会话型存储；
IndexDB：GB级别 浏览器内置完整数据库；

## 对比表（核心，默写）

| 维度 | Cookie | localStorage | sessionStorage | IndexedDB |
|------|--------|-------------|----------------|-----------|
| 容量 | ～4KB | ～5MB | ～5MB | ～几百MB～GB |
| 存储类型 | 字符串 | 字符串 | 字符串 | 对象/Blob/File |
| 生命周期 | 看expires/max-age，不设置则是会话型 | 持久型存储，不手动删除不会被清理 | 会话型存储，标签页关闭则被清理 | 持久型，不手动删除不会被清理 |
| 作用域 | 按domain/path | 同源（协议+域名+端口） | 同源（协议+域名+端口） + 单标签页 | 同源（协议+域名+端口） |
| 携带方式 | 浏览器自动携带 | 不自动携带，手动查询获取 | 不自动携带，手动查询获取 | 不自动携带，手动查询获取 |
| 安全属性 | httpOnly/Secure/SameSite | 无 | 无 | 无 |
| 典型场景 | 登录状态 | 用户设置，主题 | 表单填写内容 | 大文件缓存 |

## 三个要点

**要点1：什么时候选哪个**
一句话场景题：登录态、临时表单、用户主题设置、离线大数据缓存——各选哪个存储？
登录态：cookie；
临时表单：sessionStorage；
用户主题设置：localStorage；
离线大数据缓存：IndexDB；

**要点2：Cookie 和其他三种的本质区别**
写清楚：Cookie 的"自动携带"特性是它区别于其他三种的根因——这个特性带来什么好处（服务端无感知）、带来什么风险（CSRF）？
服务端无感知，容易带来CSRF风险，但是可以用SameSite/Secure来解决；

**要点3：容量阶梯**
从大到小排出四种存储的容量顺序，一句话说明"数据量越大，存储方案越往哪边走"。
IndexDB > localStorage/sessionStorage > cookie
数据量越大，越往左边走；

## 我的理解中不确定的部分

这里诚实写出还没完全搞懂的点。比如：sessionStorage 和 Cookie 的会话是同一个会话吗？Token 到底该存哪？
不是同一个会话，sessionStorage是标签页会话，而会话Cookie是浏览器进程会话，关掉标签页会话Cookie还在；
token存在Cookie中；

## 三层追问（验收时口答，不用写）

1. 白话复述：30 秒讲清四种存储各自定位。
cookie：存Token，登录状态；
localStorage：存用户主题设置；
sessionStorage：存临时表单填写内容；
IndexDB：存大文件缓存数据；
2. 对比理解：为什么说"Cookie 是唯一会被浏览器自动带走的存储"？这个特性带来什么？
因为浏览器特性，Cookie会自动被浏览器携带来下发；
特性带来了登录态自动随请求下发、用户无感知，也带来了CSRF的风险；
3. 场景应用：面试官问"你的项目登录态 Token 存哪了？为什么这么选？"你怎么答？
存在Cookie中，因为这里浏览器会自动携带，下发时会自动带上，配 httpOnly（防 XSS）+ SameSite（防 CSRF）。
