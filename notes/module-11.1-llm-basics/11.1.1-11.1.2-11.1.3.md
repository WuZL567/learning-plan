## 11.1.1 Token 机制

### 一句话说清楚
<!-- 这里用你自己的话解释 Token 是什么，不要抄教学内容 -->
Token 是 LLM 处理文本的最小单位，输入和输出都会被切分成 Token，模型按 Token 计费、计算、限制长度。

### 核心要点（写 2 个）
<!-- 
要点 1：Token 和字数/单词的对应关系（中文、英文、代码各是什么情况）
要点 2：Token 为什么重要（计费、窗口限制）
-->
1、1个中文汉字 ≈ 1～2 Token；1个英文单词 ≈ 1 Token；
2、模型的API计费一般通过Token的数量来计费，上下文窗口大小就是模型每次能读取到的最大Token的数量，超出这个数量的Token就会被遗忘；
3、Token 不是"一个字 = 1 个 Token"，而是 Tokenizer 根据词表切分的，常见词可能是 1 个 Token，生僻字可能是 2-3 个 Token。


### 不确定的点
<!-- 诚实写出你没完全搞懂的地方，比如：
- Tokenizer 是怎么切分的？为什么同样的文本不同模型 Token 数量不一样？
- 特殊符号、Emoji 占多少 Token？
-->
1、Tokenizer是根据模型自己来决定的，不同模型切分Token的方式不一样，所以可能产生不用的Token数量计算；
2、
 - 常见标点符号（, . ! ?）通常是 1 个 Token
 - Emoji 通常是 2-4 个 Token（因为 Emoji 是 Unicode 编码，占用多个字节）
 - 代码中的特殊符号（{} [] ()）通常是 1 个 Token

## 11.1.2 上下文窗口

### 一句话说清楚
<!-- 这里用你自己的话解释上下文窗口是什么，可以用类比 -->
就是大模型能记住的内容Token数量，超过这个限制的就会被遗忘，就像人类脑容量一样有限制，不能记住所有的事情，所以超多事情的时候会遗忘一部分内容；

### 核心要点（写 2 个）
<!-- 
要点 1：上下文窗口的计算方式（输入 + 输出）
要点 2：超过窗口后会发生什么（遗忘、报错、截断）
-->
1、上下文窗口的容量是指用户输入+模型输出的总量；
2、超过限制后，会遗忘超出的内容；

### 不确定的点

-->
1、整个对话的累计；
2、我猜测应该是类似堆栈，先进先出，在上面的最先被遗忘；

## 11.1.3 Temperature 参数

### 一句话说清楚
<!-- 这里用你自己的话解释 Temperature 是什么，可以用类比 -->
就是大模型的想象力或创新力；

### 核心要点（写 2 个）
<!-- 
要点 1：Temperature 的取值范围和含义（0、0.7、1+ 分别适合什么场景）
要点 2：Temperature 如何影响输出（随机性、一致性）
-->
1、取值范围0-1，越小的数值越稳重，答案更加固定，越大的数值越随机，答案更加创新；写代码等严肃场景建议设置更低温度，文章创作等创作场景建议设置更高温度；
2、通过设置数值大小；

### 不确定的点
<!-- 诚实写出你没完全搞懂的地方，比如：
- Temperature = 0 真的每次输出完全一致吗？
- Temperature 和 top_p 有什么区别？
-->
1、不一定，只是趋于更加一致；
2、
 - Temperature：控制概率分布的"平滑度"，0 表示只选概率最高的词，1 表示按原始概率分布随机选
 - top_p（nucleus sampling）：只从累计概率前 p% 的词中选，比如 top_p=0.9 表示只考虑概率加起来占 90% 的候选词
 - 区别：Temperature 影响"随机性"，top_p 影响"候选范围"。一般两者配合使用，比如 Temperature=0.7 + top_p=0.9
