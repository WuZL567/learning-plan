# 11.1.4 Context Window 概念

## 一句话说清楚
（用你自己的话解释：上下文窗口是什么？类比前端的什么概念？）
上下文窗口就是LLM单次请求能处理的最大的输入+输出的Token的数量，超出就会截断或报错；

## 核心要点一：窗口大小的实际影响
（写清楚：假设窗口是 4096 tokens，你输入 3500 tokens，LLM 最多能回复多少？如果输入超了会怎样？）
最多回复 4096 - 3500 = 596 tokens，输出超了就不会输出或者报错；

## 核心要点二：溢出处理策略
（写清楚：当对话历史超出窗口时，有哪几种处理方式？各自的优缺点是什么？你会在什么场景选择哪种策略？）
1、截断：丢失最早期的上下文；优点是实现简单，应该是早期的操作，上下文直接对话内容没有关联性的时候；
2、生成摘要：总结历史对话生成短文本；优点是不会完全丢失，缺点是丢失细节部分，上下文之间关联性不强；
3、只保留近期指定数量的对话；优点是实现简单，缺点是丢失上下文，上下文之间没有什么关联时使用；
4、压缩：将长文本压缩提取关键信息作为上下文内容；优点是可以保留关键信息，上下文缺失不会很严重，上下文关联性强可以选择；

## 和 Max Tokens 的关系
（写清楚：Context Window 和 Max Tokens 有什么区别？它们是怎么配合工作的？）
context window是用户输入+LLM输出的总和Token数；Max Tokens是指LLM输出的最大长度限制；
Max Tokens用来控制LLM单次回复的最大Token数，强制截断超出部分，避免计费超出；

## 我不确定的点
（诚实写出你没完全搞懂的部分，比如：不同模型的窗口大小为什么差这么多？摘要策略会不会丢失关键信息？）
1、和模型的transformer架构层数，注意力机制设计有关；
2、会丢失关键信息，摘要策略适合上下文关联不强的场景，比如客服对话，每轮独立，如果是连续推理，用滑动窗口更安全；
