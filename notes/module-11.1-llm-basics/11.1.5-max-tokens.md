# 11.1.5 Max Tokens / 输出长度控制

## 一句话说清楚
（用你自己的话解释：max_tokens 参数是干什么的？类比前端的什么功能？）
用来限制LLM单次回复的Tokens数量，类比前端输入框的max-length输入限制；

## 核心要点一：截断行为
（写清楚：如果 LLM 回复到第 50 个 token 被截断了，会发生什么？返回的数据结构有什么标识？你怎么判断是正常结束还是被截断？）
会返回一个finish_reason，如果返回的是length，表示因为长度限制了回复导致截断，如果返回了stop，就是正常结束；

## 核心要点二：典型场景的值设置
（写清楚：生成摘要、生成标题、问答对话，分别应该设置多少 max_tokens？为什么？）
摘要：100，简短就行；
标题：20，更加短；
对话：1000，详细回答又控制成本；

## 和 Context Window 的区别
（写清楚：Context Window 限制的是什么？Max Tokens 限制的是什么？它们是叠加关系还是包含关系？举个例子说明）
Context Window限制的是用户输入Tokens数 + LLM输出的Tokens数 的总和；
Max Tokens是限制LLM单次回复的Tokens数；
包含关系，Context window包含Max Tokens；

## 我不确定的点
（诚实写出你没完全搞懂的部分，比如：max_tokens 设太小会不会影响回复质量？设多少算合理？）
1、会，导致回复不完整，用户体验差；
2、看场景，没有标准的答案，看业务容忍度和成本预算；
