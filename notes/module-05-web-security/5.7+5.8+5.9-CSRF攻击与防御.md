# 5.7+5.8+5.9 CSRF攻击与防御

## 一句话说清楚
<!-- 用一句话解释：HttpOnly Cookie的作用 + CSRF攻击原理 + CSRF Token如何防御 -->
HttpOnly Cookie是防止JS读取Cookie的，读取不到就无法发起XSS攻击；
CSRF的攻击原理是利用浏览器会自动携带Cookie的特性，来伪造用户请求发起攻击；
CSRF Token的防御原理是通过服务器签发随机的Token，在客户端发起请求的时候，携带这个Token，后端校验Token来判断请求是否合法；

## 核心要点一：CSRF 攻击的完整流程
<!-- 
用自己的话描述一个完整的 CSRF 攻击场景，至少包含：
- 用户做了什么？（登录了哪个网站）
- 攻击者做了什么？（构造了什么恶意页面）
- 浏览器做了什么？（自动携带 Cookie）
- 为什么后端会上当？（看到合法 Cookie 就执行）
- 画出或写出攻击流程图（用户→evil.com→bank.com）
-->
1、用户先登录了目标网站，浏览器保存了Cookie；
2、攻击者诱导用户点击钓鱼网站，网站中会向目标网站发送伪造的攻击请求；
3、由于浏览器携带目标网站的Cookie，目标网站以为是用户，就放行了；
4、因此目标网站收到了CSRF的攻击；


## 核心要点二：HttpOnly Cookie 和 CSRF Token 的防御作用
<!-- 
分两部分写：
1. HttpOnly Cookie：
   - 防什么攻击？（XSS偷Cookie）
   - 为什么防不了CSRF？（浏览器仍自动携带Cookie）
   
2. CSRF Token：
   - Token 存在哪两个地方？（Session + 表单隐藏字段）
   - 为什么攻击者拿不到 Token？（同源策略限制跨域读取）
   - 后端怎么校验？（对比请求中的Token和Session中的Token）
-->
HttpOnly Cookie：
 - 防止XSS攻击，JS无法通过document.cookie来读取设置了HttpOnly的Cookie；
 - 无法防止CSRF攻击，因为CSRF不需要知道你的Cookie，通过浏览器自动携带Cookie的方式来发起伪造请求攻击；
CSRF Token：
 - Token存在服务器和前端；
 - 因为攻击者和目标不是同源的，所以无法获取到目标上的Token；
 - 后端直接对比请求中携带的Token，与服务器中的Token进行校验；
