# 5.10+5.11+5.12 CSRF其他防御与Cookie安全

## 一句话说清楚
<!-- 用一句话解释：SameSite Cookie 如何防 CSRF + Referer 验证的作用和局限 + Cookie 安全属性的完整配置 -->
SameSite Cookie通过配置来限制跨站请求是否携带Cookie来防止CSRF，Referer是在请求头中增加的属性来验证请求是否来自合法页面，局限是容易被篡改，无法防御同站攻击；Cookie安全属性完整配置：HttpOnly、Secure 、SameSite=Lax、Max-Age=3600；

## 核心要点一：SameSite Cookie 三种值的区别
<!-- 
用对比表或分点说明：
- Strict：什么时候携带 Cookie？防御效果如何？适用场景？
- Lax：什么时候携带 Cookie？为什么能防大部分 CSRF？适用场景？
- None：什么时候携带 Cookie？有什么限制（必须配合 Secure）？

重点解释：为什么 Lax 模式下，用户点击链接跳转能携带 Cookie，但表单 POST 不携带？
-->
Strict：跨站请求完全不携带Cookie，防御效果最强，适用高等级安全场景，如银行；
Lax：只有顶级导航的跨站请求才会携带Cookie，但是表单POST不携带，防御效果能防住大部分CSRF，适用大部分普通场景，是默认设置；
   - 从顶层导航的跨站请求携带Cookie是为了保证用户登录状态，提升用户体验；但是表单POST请求不携带是为了防止CSRF攻击；
None：跨站请求都携带Cookie，不防CSRF，适用需要跨站携带Cookie的场景，如第三方登录；

## 核心要点二：Referer/Origin 验证和 Cookie 安全属性总览
<!--

1、Referer/Origin验证：
 - 检查HTTP请求头中的Referer或Origin字段，验证请求是否来自合法页面；
 - Referer是完整的URL，Origin只有域名；
 - 可以被隐藏和篡改，无法防御同站的攻击；

2、Cookie安全属性总览：
 - HttpOnly：防止XSS攻击偷取Cookie；
 - Secure：防止中间人劫持Cookie；
 - SameSite：防止CSRF攻击；
 - Domain/Path：限制Cookie的作用域和路径；
 - 推荐的安全配置是：HttpOnly + Secure + SameSite=Lax + Max-Age=3600
