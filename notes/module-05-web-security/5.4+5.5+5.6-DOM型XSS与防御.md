# 5.4+5.5+5.6 DOM型XSS与防御

## 一句话说清楚
<!-- 用自己的话一句话解释 DOM型XSS 和两种防御手段（输出转义+CSP） -->
1、输出转义，就是将<script>转义成&lt;script&gt; 
2、CSP，就是限制只能执行自己域名的脚本；

## 核心要点一：DOM型XSS 的危险 API 和安全替代
<!-- 
列出至少 3 个危险 API，说明：
- 为什么危险？（会执行脚本/解析HTML）
- 安全替代方案是什么？（textContent/createElement 等）
- Vue 项目中哪个指令等同于 innerHTML？（v-html）
-->
innerHTML：解析HTML标签并且执行脚本；
document.write()：直接写入HTML，会执行脚本；
eval()：直接执行字符串代码；
替代方案：
 - textContent：只渲染文本；
 - createElement+appendChild；
Vue中，v-html指令等同于innerHTML；

## 核心要点二：输出转义和 CSP 配置
<!-- 
分两部分写：
1. 输出转义：用自己的话解释为什么要转义？转义哪些字符？举个例子说明转义前后的差异
2. CSP 配置：用自己的话解释 CSP 是什么？script-src 'self' 是什么意思？为什么能防 XSS？
-->
输出转义：
 - 转义是为了HTML渲染时不执行脚本代码，而是正常渲染；
 - 转义字符包括<，>，单引号，双引号，/；
 - < 转义成 &lt;，>转义成 &gt;
CSP配置：
 - 通过HTTP响应头告诉浏览器，允许哪些来源的脚本；
 - 只允许执行同域脚本，禁止内联 <script> 和 eval()；
 - 通过白名单拦截，攻击者不在白名单上，就不会被攻击；
