# 1.22 Promise 状态机与链式调用原理

## 第一部分：一句话说清楚

（提示语：用一句不超过 30 字的白话，说清楚 Promise 到底是个什么东西。假设对面是个完全不懂技术的人，你怎么介绍它？不要抄文档定义。）

Promise就是一个外卖订单，只能从配送中（pending）进入已完成（fulfilled）或者已拒收（rejected），状态修改后不可变更；

## 第二部分：核心原理

（提示语：画一个三态流转图，把 pending / fulfilled / rejected 三个状态和它们之间的转移方向标出来。然后回答两个问题：

pending -> fulfilled (resolved)
pending -> rejected (rejected)

1. 状态流转是单向还是可逆的？用一句话说明原因。
单向的；如果可逆会导致promise状态不可控，甚至永远不结束；

2. then 的回调里 return 不同东西（普通值 / Promise / 抛出异常 / 什么都不写），链上下一个 then 分别会收到什么？用一张小表列出来。）
普通值：fulfilled，返回值；
Promise：上一个Promise返回的状态和值；
抛出异常：rejected，返回错误reason；
什么都不写：fulfilled，返回undefined；

## 第三部分：和回调函数的区别，以及 then 的返回值规则

（提示语：用对比表写出 Promise 和传统 callback 在错误处理、多层异步嵌套、可读性三个方面的区别。另外写清楚一个具体例子：then 里 return 一个 Promise 和 return 一个普通值，下一个 then 的回调参数分别是什么？）

错误处理：Promise单独在最后面使用catch来捕获前面所有的错误，而callback需要每一个单独错误处理；
多层异步嵌套：Promise可以使用.then来链式调用，而callback只能无限嵌套回调，形成回调地狱；
可读性：Promise可读性非常好，而callback可读性越多嵌套越差；

then中return一个Promise则下一个then里面回调就是Promise resolve的值，而return一个普通值则下一个then里面回调就是这个普通值；
