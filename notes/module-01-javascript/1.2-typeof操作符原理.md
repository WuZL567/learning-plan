# typeof 操作符原理与边界情况

## 一、一句话说清楚
（用一句白话解释：typeof 是干什么的？它为什么不能区分数组和对象？它本质上是读了什么东西？）

typeof是区分值的类型的工具，本质是读取JS引擎存储值时在值前面加的二进制标记位，获取值的类型标签；

## 二、核心原理
（用类比或图解讲清楚：typeof 在 JS 引擎底层是怎么判断类型的？为什么 typeof null 返回 "object"？这和 JS 的二进制类型标记位有什么关系？另外，typeof 能准确判断哪几种类型？哪几种类型区分不了？建议列个对照表。）

获取JS引擎在值前面放置的三位二进制标签位数字，来判断它的标签类型；
判断前面三位标记位为000的时候，会把它当成object，但是null是全0，所以也是判断为object了；
typeof 可以判断string，number，boolean，undefined，bigInt，symbol，function；无法区分object，null，array等；

## 三、和 Object.prototype.toString.call() 的区别或关系
（typeof 区分不了数组、null、Date 这些，那 Object.prototype.toString.call() 为什么能区分？这两种方式分别适合什么场景？typeof 的优势是什么？Object.prototype.toString.call() 的局限性又是什么？）

因为Object.prototype.toString是直接读取JS底层的[[class]]属性，获取到类型标记，所以可以区分。
typeof适合除了null之外的基本类型判断，而Object.prototype.toString则适合typeof无法判断的以及原型上的属性关系；
typeof的优势是性能好，因为只需要读取标记位；
Object.prototype.toString则性能稍微差点，因为要走原型链查询并且调用函数，还需要额外处理返回字符串的格式；

## 四、我的理解中不确定的部分
（诚实写出还没完全搞懂的点。比如：typeof NaN 为什么是 "number"？typeof document.all 在不同浏览器里表现一样吗？为什么 typeof 对未声明的变量不会报 ReferenceError 而是返回 "undefined"？或者其他让你困惑的地方。）

1、不知道 typeof NaN 为什么是 "number"；
 —— NaN 全称 "Not a Number"，但它本质上是 IEEE 754 浮点数标准定义的一个特殊数值标记。在 JS 引擎里，NaN 存在 Number 类型的内存槽位里，类型标记就是 Number。可以理解为：NaN 是"一个无效的数字"，而不是"这个概念不是数字"。
2、不知道 typeof document.all 在不同浏览器里表现是否一样；
 —— 不一样。document.all 是 IE 时代遗留的 DOM API。现代浏览器为了兼容老代码，typeof document.all 故意返回 "undefined"（假装不存在），但实际访问它又存在。这是 HTML 规范明确规定的唯一一个违反 typeof 规则的反例。
3、typeof 的内部机制，对于作用域中找不到的变量，会直接返回undefined，而不是报错；
4、不知道它为什么不能区分数组和对象；
 —— 因为数组、对象、Date、RegExp、Map 等在 JS 引擎底层二进制标记位都是 000（对象）。typeof 只看这三位的标记，不看更细的分类。要区分它们需要读 [[class]] 内部属性，这就是 Object.prototype.toString 做的事。
