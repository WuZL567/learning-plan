# 对话记录：手写深拷贝（含循环引用/Symbol/特殊对象）

日期：2026-08-18

## 一、教学过程

### 为什么需要它

在 Vue 项目里一定踩过这个坑：把 `config` 对象传给子组件后改了子组件里的值，父组件的 `config` 也变了——因为传的是引用，不是副本。所以会写 `JSON.parse(JSON.stringify(config))` 来"深拷贝"。

但这个"万能公式"实际上坑很多：`undefined` 会丢、函数会丢、`Date` 变字符串、`RegExp` 变 `{}`、循环引用直接**报错崩溃**。大厂面试最爱让你手写一个能扛住这些情况的深拷贝——这不是背题，是因为深拷贝的边界情况几乎覆盖了 JS 值类型的全部知识点。

### 一句话说清楚

深拷贝就是递归地遍历一个对象的每一层，把每个引用类型的值都重新"造一份"，而不是复制指向它的指针；用 WeakMap 记录已拷贝过的对象来对付循环引用。

### 核心原理

类比复印：**浅拷贝**是复印了封面，里面的内容还是指向同一份原稿（改了一处，两处都变）；**深拷贝**是整本书逐页复印，改任何一页都不影响原稿。

```js
// 伪代码：核心就三步
function deepClone(target, map = new WeakMap()) {
  if (typeof target !== 'object' || target === null) return target; // ① 基础类型直接返回
  if (map.has(target)) return map.get(target);                       // ② 循环引用：查表返回旧副本
  const result = Array.isArray(target) ? [] : {};                    // ③ 递归处理每个属性
  map.set(target, result);
  for (const key in target) {
    if (Object.prototype.hasOwnProperty.call(target, key)) {
      result[key] = deepClone(target[key], map);
    }
  }
  return result;
}
```

用 Vue 经验类比：

| 深拷贝的知识点 | 熟悉的前端概念 |
|---|---|
| WeakMap 存"原对象 → 副本" | 类似 Vue 3 的 `targetMap`（`WeakMap<target, Map<key, dep>>`），都是拿对象当 key 且不影响 GC |
| `for...in` + `hasOwnProperty` | 相当于遍历 props 时只处理自己的属性，忽略原型上的 |
| 递归 | 和递归渲染嵌套组件树一个道理，每层都做同样的处理 |

### 练习任务说明

手写 `deepClone` 函数，要求处理这些边界 case：
1. 基础类型（string/number/boolean/null/undefined）直接返回
2. 循环引用不报错（WeakMap 记录）
3. 数组拷贝后是全新数组
4. Symbol 键属性也要拷贝（`Object.getOwnPropertySymbols`）
5. Date / RegExp 拷贝后仍是原类型（`new target.constructor(target)`）
6. 函数直接引用即可
7. 嵌套多层对象互不影响

初始文件：`src/module-01-javascript/1.32-手写深拷贝/deepClone.js`，内含 7 组测试用例。

提示只给了三条：循环引用关键在"先建空壳、存进 map、再填属性"；Symbol 键用 `Object.getOwnPropertySymbols`；Date/RegExp 用 `instanceof` 判断后 `new target.constructor(target)`。

## 二、验收过程

### 第一次提交（学生提交时自述：两个用例没通过）

**学生代码核心内容：**

```js
function deepClone(target, map = new WeakMap()) {
  if (target === null || typeof target !== "object") {
    return target;   // 基本类型直接返回自身
  }
  if (map.has(target)) {
    return map.get(target);
  }
  if (target instanceof RegExp) {
    return new RegExp(target.source, target.flags);
  }
  if (target instanceof Date) {
    return new Date(target);
  }
  if (target instanceof Map) {
    const newMap = new Map();
    map.set(target, newMap);
    target.forEach((value, key) => {
      newMap.set(deepClone(key, newMap), deepClone(value, newMap));
    });
    return newMap;
  }
  if (target instanceof Set) { /* 类似处理 */ }
  const clone = Array.isArray(target) ? [] : {};
  map.set(target, clone);
  for (const key of Reflect.ownKeys(clone)) {   // ← 问题所在

  return clone;
}
```

**导师第一次评判（原话要点）：**

- 学生说"两个用例没通过"——不准确，**实际 5 个用例都没通过**。报错只有 2 个（嵌套对象、数组），但循环引用、Symbol、Date/RegExp 三个测试块虽然标记"通过"，`console.log` 输出的是 **false**。测试块用 `console.log` 打结果不抛错，没被 try/catch 抓到。以后自查要逐行看输出是不是 `true`。
- 核心 bug：`Reflect.ownKeys(clone)` 应改为 `Reflect.ownKeys(target)`。`clone` 是空壳 `{}`/`[]`，遍历空壳拿不到任何属性。深拷贝的灵魂是"遍历源对象 target 的键，把值递归拷贝到新壳里"。
- 顺带肯定：`Reflect.ownKeys` 只返回自身键（不含原型链），所以不加 `hasOwnProperty` 也安全——这处歪打正着处理对了。
- 还主动指出：Map/Set 处理是超额完成，思路对（先建壳、存 map、再递归）。

### 第二次提交（学生修改后）

**修改内容：** 仅一处关键改动——`for (const key of Reflect.ownKeys(clone))` 改为 `for (const key of Reflect.ownKeys(target))`。同时把 Map/Set 分支的递归传参从 `deepClone(key, newMap)` 统一改为传外层 `deepClone(key, map)`。

**运行结果：** 全部输出 true，`测试结果: 7 / 7`。

**导师第二次评判（原话要点）：**

- 核心 bug 修复正确，7/7 全过。
- 额外加分点：Map/Set 递归统一传外层 `map` 比第一次传 `newMap` 更正确——所有对象在同一张表登记，跨对象循环引用（如 Map 的 key/value 引用了外部已拷贝对象）也能复用副本，不会重复拷贝。这是学生自己主动改的，说明理解了 WeakMap 表"一张表管全部对象"的设计意图。
