## 第二部分：核心原理

**提示语：** 这一部分分三块写，缺一不可：

1. **13 种拦截操作**：按"属性操作 / 对象操作 / 函数操作"三组列出，每组举 1 个 trap 的触发场景。要求至少能完整说出 `get` / `set` / `has` / `deleteProperty` / `ownKeys` / `apply` / `construct` 这几个。
get：读取对象的属性时触发拦截操作；
set：写入对象的属性时触发拦截操作；
has：判断对象属性时候触发拦截操作；
deleteProperty：删除对象属性时触发拦截操作；
ownKeys：枚举对象属性时触发拦截操作；
函数专属：apply 拦 proxyFn() 调用，construct 拦 new proxyFn()，target 为函数时才有

2. **Reflect 的作用**：写清楚为什么 handler 里写默认行为要用 `Reflect.get(target, key, receiver)` 而不是 `target[key]`。从"this 指向""返回值规范""避免死循环"三个角度任选两个写。
 - 保证this指向的准确性，因为我们要保证this指向代理的对象target，而不是在属性冲突时this指向原对象；
 - 返回值更符合规范，Reflect的get读取不到属性返回undefined，set成功为true失败为false；
 - 避免死循环，receiver为代理对象时，Reflect.set会再次触发set；

3. **Vue3 响应式链路**：用你熟悉的 Vue 体感写——`reactive()` 内部是怎么用 `get` 和 `set` 两个 trap 实现"读取时收集依赖、修改时触发更新"的。可以贴一小段伪代码或画箭头图。
const myObj = reactive({id:1,name:"x1"});
通过Proxy({id:1,name:"x1"}, {
    get(target, key, receiver) {
        // 收集依赖，把当前正在读的属性登记；
        return Reflect.get(target, key, receiver);
    },
    set(target, key, value, receiver) {
        // 触发更新，通知所有登记的内容重新读取
        return Reflect.set(target, key, value, receiver);
    }
});

## 第三部分：和 XX 的区别或关系

**提示语：** 至少写两组对比：

1. **Proxy vs Object.defineProperty**：这是必考的对比。从"拦截粒度（整个对象 vs 单个属性）""能否拦截新增属性""能拦截的操作种类（2种 vs 13种）""Vue2/Vue3 为什么分别选它们"四个角度对比。

Object.defineProperty拦截单个属性，不能拦截新增的属性，能拦截的操作是2种（get/set）；
Proxy拦截整个对象，能拦截新增属性，能拦截的操作是13种（get/set/has/deleteProperty/ownKeys等）
能力差异：defineProperty 拦不了新增属性、拦不了数组索引，只能拦 2 种操作，做不出完整的响应式；

2. **Proxy vs Reflect**：不是竞争关系而是配套关系，写清楚谁是谁的影子。
Reflect是Proxy的影子；

## 第四部分：我的理解中不确定的部分

**提示语：** 诚实写出你还没完全搞懂的点，至少写 1 个，写 3 个更好。例举一些方向供参考（不限于这些）：

- Proxy 的 `receiver` 参数到底什么时候有用？什么场景下 `this` 会指向原对象导致问题？
target 属性是 getter/setter 时，Reflect.get(target, key, receiver) 把 getter 内部的 this 修正为 receiver（代理对象），内部属性访问继续走代理，依赖收集不漏；
直接用target[key]，并且在原对象也存在getter这样的属性时会导致this指向原对象；

- 为什么 `Object.keys(proxy)` 和 `for...in` 的结果可能不一致？`ownKeys` 返回的数组有什么格式要求？
Object.keys 只返回自有可枚举属性；for...in 会遍历整条原型链的可枚举属性。ownKeys trap 拦的是 Object.keys/for...in 的第一步（拿到所有自有键），Object.keys 之后还会过滤掉不可枚举的。格式要求：返回的数组必须是 string/symbol 的键，且必须包含 target 所有不可配置的自有属性，否则抛 TypeError。

- `Proxy.revocable` 是什么？什么场景会用？
创建 { proxy, revoke }，调用 revoke() 之后，代理上任何操作都抛 TypeError（"proxy revoked"）。
场景：把对象交给第三方库，用完即回收，防止长期持有；或权限过期失效。

- 为什么 Proxy 无法代理原始类型（number/string）？那 Vue 的 `ref()` 是怎么解决这个问题的？
new Proxy(1, ...) 直接 TypeError，Proxy 只接受对象。
Vue3 的 ref() 就是把原始值包一层：{ value: 1 }，再对这个包装对象做代理——这就是为什么用 ref 时要写 .value。

- 代理对象的 `===` 还是原来的对象吗？`obj instanceof` 会怎样？
不是 === 的，，Proxy 是引擎内部的特殊对象（exotic object）。
instanceof 走原型链，proxy 的原型通过 getPrototypeOf 转发到 target，所以 proxy instanceof 某个类 和 target instanceof 某个类 结果一致（是 true）

- 13 种 trap 里哪几种是必选的（会影响其他 trap 的行为）？
get/set/has/deleteProperty 增删改查
