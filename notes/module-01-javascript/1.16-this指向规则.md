# 1.16 this 指向规则

## 一、一句话说清楚

（提示：用一句白话解释 this 的指向是在什么时候、由什么决定的。不要写代码，用大白话。）
普通函数，this是在调用的时候指定的，谁调用就指向谁，而箭头函数则是在定义的时候决定的，它的this指向外层作用域的this，可以继承外层作用域的this；
this指向可以通过new绑定，apply/call/bind（显式绑定）来改变；

## 三、箭头函数的 this：什么时候必须用？什么时候不能用？

（必用）什么场景下必须用箭头函数才能拿到正确的 this？至少写两个场景，写出代码和解释。
1、在class中定义的普通函数中使用setTimeout或setInterval时，必须用到箭头函数，不然使用普通函数时，this指向的是setTimeout或setInterval的内部，就找不到this了，而用箭头函数则会使this指向外层作用域，就会来到普通函数这里继承；
2、当class被new调用之后，解构内部暴露的函数时，如果内部函数不是箭头函数，则会导致无法获取正确的this，因为class内部默认严格模式，会拿不到this，而箭头函数则在定义的时候就保存了this，所以可以在外部调用解构后的函数时可以正常访问this；

（禁用）什么场景下不能用箭头函数（用了会出问题）？至少写两个场景，写出代码和解释。提示：Vue Options API 的 methods 为什么不能用箭头函数？
1、Vue options API 的methods是一个函数，里面的函数不能用箭头函数，因为用了箭头函数时，会去外层作用域找this，导致methods层的作用域下无法找到this；
2、// DOM 事件回调里需要 this 指向触发元素时
document.querySelector('.btn').addEventListener('click', function() {
  this.classList.add('active')   // this = 触发事件的元素
})
// 换成箭头函数就拿不到元素了，this 变成外层作用域

## 四、我的理解中不确定的部分

请诚实写至少两个你还不够确定的问题。比如：
- new 绑定和 bind 同时存在时，new 优先了，那 bind 绑的对象是不是就废了？
    不是，只是后面调用new的实例会变化，不影响之前的；
- 箭头函数用 call 能不能改 this？为什么？
    不能，箭头函数的this在外层作用域上，不能用call改变；
- class field 箭头函数和 constructor 里 bind 有什么区别？
    这两个的效果一样，只是constructor中通过bind来绑定this指向，是通过原型链来找this；
- 这种题下次遇到有没有一个固定的解题口诀？
    普通函数调用时确定this指向，谁调用指向谁，箭头函数在定义时就确定this指向，指向定义时的外层作用域的this；

每个不确定的地方，先写你自己的猜测，再写你为什么不确定。
    Vue options API 的 methods 中使用 箭头函数，使用this时是不是用的全局this呢？
    不是。ES Module（严格模式）顶层 this 是 undefined，箭头函数继承的就是 undefined。只有非严格的 <script> 里才是 window。Vue 内部会把 methods 绑定到组件实例，但箭头函数无法被重新绑定，所以拿不到 vm。
