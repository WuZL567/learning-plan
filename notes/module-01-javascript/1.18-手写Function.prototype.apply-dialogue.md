# 对话记录：手写 Function.prototype.apply

日期：2026-08-13

## 一、教学过程

### 为什么需要它

三个理由：

1. **面试标配**。面试官问完 call 十有八九接着问 apply，答不上来等于把到手的加分题让回去。
2. **它比 call 更"顺手"的场景**。你手里参数如果本来就是个数组，call 还得展开成 `fn.call(ctx, ...arr)`，apply 直接 `fn.apply(ctx, arr)` 一步到位。就像 Vue 里给子组件传 props：call 是一个个属性写过去，apply 是把整个 props 对象直接递过去。
3. **它是 1.19 手写 bind 的地基**。手写 bind 内部要用 apply 传参，这关不扎实，下一关直接卡壳。

实际开发里常见写法：`Math.max.apply(null, [1, 5, 3])` —— Math.max 不认数组，apply 帮它"拆包装"。

### 一句话说清楚

apply 和 call 干的是同一件事——借别人的函数、用自己的 this、立即执行。唯一区别是**参数怎么给**：call 像点外卖一个一个报菜名，apply 像直接递一张写好的菜单（数组）。

### 核心原理

myCall 的核心三件套：挂函数 → 调函数 → 删函数。apply 的逻辑一模一样，全身上下只有一处不同：

```js
// call：参数从 rest 收集，一个个传
context[sId](...args);

// apply：参数藏在第二个参数 argsArray 里，拆出来传
context[sId](...argsArray);
```

两个容易踩的坑：

1. **第二参数为 null/undefined**：`fn.apply(ctx, null)` 等价于 `fn.apply(ctx)`，等于不传参，不能报错。
2. **第二参数不是数组**（比如 `fn.apply(ctx, 123)`）：非严格模式下同样等价于不传参，忽略它。

### 练习任务

在 `src/module-01-javascript/1.18-手写Function.prototype.apply/index.js` 手写 `Function.prototype.myApply` 并补充测试用例，覆盖：普通调用、数组传参、返回值、null/undefined 的 context、原始类型 context、第二参数为 null/undefined、第二参数非数组、属性名冲突。提示：`Math.max.myApply(null, [1, 5, 3])` 应该返回 5。

## 二、验收过程

### 学生提交的核心代码

```js
Function.prototype.myApply = function (context, argsArray) {
    // myApply和myCall的唯一区别在于传入的参数，除了context之外的参数，apply需要的是数组形式，而call则是一个个参数的传递；
    context = context == null ? globalThis : context;

    if (typeof context !== 'object' && typeof context !== 'function') {
        context = Object(context);
    }

    const sid = Symbol("id");
    context[sid] = this;

    let result;

    // 判断argsArray是否存在且为数组类型，如果是则正常请求，否则当作未传入参数
    if (argsArray && Array.isArray(argsArray) && argsArray.length > 0) {
        result = context[sid](argsArray);
    } else {
        result = context[sid]();
    }

    delete context[sid];
    return result;
}
```

### 导师实际运行测试（与原生 apply 对比）

```
原生: Math.max.apply(null, [1,5,3]) = 5
你的: Math.max.myApply(null, [1,5,3]) = NaN

原生: greet.apply(person, ["Hi,", "WZL"]) = Hi,你好，WZL
你的: greet.myApply(person, ["Hi,", "WZL"]) = Hi,,WZL你好，undefined

你的: fn.myApply(null, undefined) = undefined   // 边界 ✓
你的: fn.myApply(null, 123) = undefined         // 边界 ✓
```

### 评判

**致命 bug**：第 49 行 `context[sid](argsArray)` 把整个数组当成**一个参数**传给了原函数，没有展开。`greet` 用例中 prefix 收到了整个数组（数组转字符串变成 `Hi,,WZL`），name 变成了 undefined。这说明"参数要拆开成一个个独立参数"这个 apply 的灵魂没理解到位。

**其他部分**：context 为 null/undefined 兜底 ✓、原始类型装箱 ✓、Symbol 防属性冲突 ✓、执行后删除防污染 ✓、第二参数为 null/undefined/非数组兜底 ✓。

**测试用例缺失**：初始文件明确要求补充测试用例，学生没有写。如果跑了头部注释里提示的 Math.max 用例，立刻就能看到 NaN 而不是 5。

## 三、验收结论

- **评分：5 分（2 + 0 + 2 + 1）**
- **判定：补一个点，打回修改**

### 扣分项

1. **代码正确性 -3 分**：`context[sid](argsArray)` 未展开数组参数，`Math.max.myApply(null, [1,5,3])` 返回 NaN（原生为 5）。核心路径错误。
2. **概念理解 -2 分**：说对了"apply 参数是数组形式"，但没理解关键后半段——数组到函数手里之前要"拆开"，变成和 call 一样的一个个独立参数。apply 的本质是"打包运输，到货拆箱"。

### 需要修改的地方

1. 把 `context[sid](argsArray)` 改成 `context[sid](...argsArray)`（展开运算符，和 1.17 myCall 里的 `...args` 同一招）。
2. 在文件下方补充测试用例，覆盖文件头注释列出的全部 case（含 Math.max 那个提示用例），node 跑通全绿后再提交。
