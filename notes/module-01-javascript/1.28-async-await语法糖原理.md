# 1.28 async / await 语法糖原理

## 一、一句话说清楚

> 用一句大白话解释：async/await 的本质是什么？它和 Generator 函数是什么关系？

本质就是语法糖，将Generator函数结合自动处理函数run和Promise的机制，来实现将手动执行的函数用自动方式实现；

---

## 二、核心原理

> 用你自己的话解释以下三个问题，可以画图、用类比、用代码示例：

1. **Generator 的暂停/恢复机制**：yield 和 next() 分别做了什么？Generator 函数的执行是怎么"走走停停"的？画一个执行顺序图。
yield 接受来自next传入的参数，自身传递参数到next，双向数据传输，暂停函数执行；
next() 则继续恢复函数执行到下一个yield，支持传递参数到yield，也支持接受来自yield的参数，格式是{value: yield右侧的值原样交出去, done: true或false，表示是否结束};

Generator函数：

执行next() -> 走到第一个yield暂停，next获取到当前暂停yield的传递参数对象{ value:xxx, done:false }
继续执行下一个next(params1) -> 接受来自next传递的值，走到下一个yield暂停，next获取到当前暂停yield的传递参数对象{ value:xxx, done:false }
继续执行下一个next(params2) -> 和上一部一样，走到return结束，返回的对象中done为true，{ value:xxx, done:true }


2. **自动执行器（co）的核心逻辑**：为什么 Generator 不会自己走完，需要"自动执行器"？如果 yield 后面跟的是 Promise，执行器应该怎么处理它（提示：.then 之后拿到值，再调用 next(value) 把值传回去）？用伪代码写出执行器的大致逻辑。

1、因为Generator中的yield会暂停函数执行，必须手动执行next才会继续走，所以需要自动执行器；
2、如果yield是Promise，Generator则会将它直接返回出去 { value: Promise, done: false }，而自动执行器则会将它放到Promise.resolve()中执行一次，将结果传递给then函数之后继续走；
 function run(gen) {
  // 获取实例
  const g = gen();
  // 创建步骤执行函数
  function step(arg) {
    // 获取next的对象结果，不管是promise或是普通值
    const result = g.next(arg);
    // 结束时直接返回结果
    if (result.done) return result.value;
    // 未结束时，将它通过resolve处理，将结果给then传入后，将结果v继续给step执行下一步；
    Promise.resolve(result.value).then(v => step(v));
  };
  // 首次直接执行，没有参数
  step();
 }

3. **async/await 是语法糖**：把下面的 async 函数"展开"成 Generator + 自动执行器的形式，你会怎么写？注意：async 函数的返回值是什么类型？throw 的错误在展开后对应什么处理？

```js
async function getUser() {
  const user = await fetch('/user');   // await 一个 Promise
  const detail = await fetch(`/user/${user.id}`);  // 再 await 一个
  return detail;
}
```

function* getUser() {
  const user = yield fetch("/user");
  const detail = yield fetch(`/user/${user.id}`);
  return detail;
}
run(getUser);

async函数返回的是promise；
throw错误处理对应catch处理；

## 三、和 XX 的区别或关系

> 两个对比，选一个重点写透：

1. **async/await vs 手写 Generator + 执行器**：语言层面帮我们省掉了什么？（提示：错误处理、返回值包装、执行器本身）
2. **async/await vs Promise 链（.then）**：同一个需求用两种写法，可读性和错误处理上有什么差别？（提示：try/catch 是同步写法；.then 链里一旦某个中间 Promise  reject，错误会被捕获几次、代码会写多长）

async/await：省掉了自动执行器函数，错误处理可以通过try/catch捕获，返回值是promise格式；
async/await和Promise链(.then)，async/await是同步写法的异步代码，不同于then的链式调用，同步写法更清晰可读；
Promise 链里错误会沿链向后传递，直到遇见 .catch——所以很难判断错误出在链的哪一环。而 async/await 用 try/catch 包住整段，错误精确抛出在对应位置，像同步代码一样定位。

## 四、我的理解中不确定的部分

> 诚实写出没完全搞懂的点。以下候选供参考，也可以写你自己的：
>
> - "await 后面跟一个普通值（不是 Promise）会发生什么？"
会处理成Promise.resolve(普通值)返回；
> - "async 函数里没有写 return，返回的是什么？"
返回已完成的 Promise，值为 undefined。
> - "await 真的'阻塞'了后面的代码吗？阻塞的是谁？"
await 谁都不阻塞。它只是挂起当前 async 函数自身，把后面的代码变成微任务排进队列；主线程、其他微任务照常执行。
> - "Generator 里 yield 后面的值是怎么被'传'给执行器的？"
放在{value: yield的值}中被传给next();
> - "为什么说 await 只能在 async 函数里用？"
它们是一对的，不能拆开用；
