# 1.7 作用域与作用域链

## 一、一句话说清楚

> 用一句大白话解释"作用域"和"作用域链"分别是什么。

作用域就是指变量所能被定义和被找到的区域，作用域链则是找到这个变量时经过的作用域的顺序链接；

---

## 二、核心原理

> 用你自己的话解释以下三个概念，可以画图（用文字画也行）、用类比、用代码示例。
>
> 1. JS 中有哪几种作用域？var / let / const 的作用域行为有什么不同？
> 2. 什么是"词法作用域"（静态作用域）？用一段代码举例说明。
> 3. 什么是"作用域链"？画一个简单的查找链路图（示例中有至少三层嵌套），解释变量查找过程。

1. 全局作用域：代码开始执行的时候创建的作用域；函数作用域：函数被调用时创建的作用域；块级作用域：{}创建时内部的作用域；
var没有块级作用域，只有全局作用域和函数作用域，let和const才有块级作用域；
2. 就是代码被创建时就定义了它的作用域，而不是直到执行调用时才去定义作用域；
3. 作用域链就是查找变量所在作用域的路径，
全局作用域 const x = "1";
    function foo () {
        const y = "2";
        function bar () {
            console.log(x);
        }
        bar();
    }

    bar中需要找到x，在bar中没法找到，向上一层找foo的作用域中，没有则继续向上层找，直到在全局作用域中找到x为"1"；

## 三、作用域链与闭包的关系

> 闭包是 1.8 的技术点，但你已经有 5 年前端经验一定用过闭包。请用一句话说清楚：作用域链和闭包之间是什么关系？闭包为什么能"记住"外层变量？
闭包能记住外层的变量就是因为作用域链的作用，闭包中使用的变量定义在外层，而静态作用域则在这时候创建变量时就产生了作用域链，则后续外部调用闭包函数是可以顺着作用域链来找到原本定义地方的变量；

## 四、我的理解中不确定的部分

> 诚实写出你对作用域/作用域链还有哪些疑问或不太确定的地方。比如：
> - 有没有哪种场景下作用域链的查找行为让你感到意外？
 - 就近匹配，找到就停了。
> - TDZ（暂时性死区）和作用域是什么关系？
 - let/const 声明的变量，从块开始到声明语句之前，变量存在但不能访问，访问就报 ReferenceError，这段区域就是 TDZ。TDZ 是块级作用域机制的一部分。
 - TDZ 的存在就是为了让 let/const 的行为更符合直觉——"先声明才能用"。没有 TDZ 就没有 let/const 的块级作用域语义。
    // 块开始 ↓
    console.log(a)  // ❌ ReferenceError: TDZ，安检区不能进
    console.log(b)  // undefined，var 没有 TDZ，已经挂到函数/全局作用域了
    let a = 1       // ↑ 这句之前都是 a 的 TDZ
    var b = 2
    // 块结束 ↑
> - 你对"词法环境"和"变量环境"的区别清楚吗？
 - 变量环境存 var，词法环境存 let/const 和函数声明，每个执行上下文（函数被调用时创建的运行环境）里有这两个东西；
