# 对话记录：手写 Promise.race

日期：2026-08-17

## 一、教学过程

### 为什么需要它

你已经会用 `Promise.all` 了，它解决的是"等所有人"的问题。但真实业务里还有一类场景是"抢第一名"：

- **场景一：接口竞速**。页面要加载一段内容，来源有两个 CDN 地址，谁先返回就用谁的，不用傻等慢的那个。
- **场景二：超时控制**。前端最常见的用法：`Promise.race([fetch(url), timeout(3000)])`——请求和 3 秒倒计时赛跑，如果倒计时先到，整体就 reject，页面就能给用户提示"请求超时了"，而不是一直转圈。

面试官问你"怎么给 fetch 加超时"，答案就是 `Promise.race`。这是 P0 必考点。

### 一句话说清楚

`Promise.race` 把多个 promise 丢进一场比赛，第一个落定（不管成功还是失败）的那个的结果，就是整个 race 的结果，其他选手的成绩全部作废。

### 核心原理

和 `all` 对比着记：

| | Promise.all | Promise.race |
|---|---|---|
| 目标 | 等**所有人**跑完 | 抢**第一名** |
| 成功条件 | 全部成功才 resolve | 第一个 resolve 就 resolve |
| 失败条件 | 任意一个失败就 reject | 第一个 reject 就 reject |
| 空数组 | resolve `[]` | **永远 pending**（没有选手，比赛永远不结束） |

类比：运动会接力赛（all）——每个人都要跑，最后算总成绩；race 就像赛马（racing 本身就是赛马的意思）——第一名冲线，比赛立刻结束，后面的马跑成什么样没人关心。

**核心实现思路**（就一句话）：外层建一个 Promise，遍历每个输入项，给每个项都挂上 `then(resolve, reject)`——谁先触发，外层的状态就被谁定死。Promise 状态一旦落定不可变，后触发的自然被忽略，这就是 race 的全部魔法。

**和 all 的关键差异**（面试爱问）：
- all 需要**计数器 + 结果数组**（因为要等所有人，还要按顺序排结果）
- race **什么都不需要**——没有计数器，没有结果数组，只有一个"转发"动作。如果写 race 还在计数、还在存结果，说明思路错了。

## 二、验收过程

### 学生提交的代码核心内容

```js
function promiseRace(iterable) {
  return new Promise((resolve, reject) => {
    const newArray = Array.from(iterable);
    newArray.forEach((item, index) => {
      Promise.resolve(item).then(
        (value) => resolve(value),
        (error) => reject(error),
      );
    });
  });
}
```

自测用例：`[Promise.resolve(1), new Promise(() => {})]`、慢 reject + fast resolve、空数组、`[1, 2]` 普通值。

### 运行验证结果

```
1        <- 第一个落定的 resolve 胜出，第二个永远 pending 不影响
fast     <- 慢的 reject 结果作废，快的 resolve 胜出
（无输出） <- 空数组永远 pending，不会打印"打印了吗？"
1        <- 普通值立即胜出
```

四个自测用例全部通过。
