### 为什么需要它

你昨天刚学完 this 指向规则，应该记得**显式绑定**这条规则：call 就是显式绑定的实现手段。面试里 call/apply/bind 是必考三兄弟，手写 call 是第一个，也是最简单的一个，但它背后的原理你理解了，后面 apply（只改传参方式）和 bind（加个返回函数）就是套壳。

再给你一个实际场景：Vue 2 时代到处是 `Array.prototype.slice.call(arguments)` 把类数组转成真数组——`arguments` 不是数组，但人家数组的 slice 方法可以"借"过来用，靠的就是 call 改 this。包括老版 jQuery 内部判断类型、lodash 的工具函数，底层都大量用 call 来借用方法。这个技术点不是考背诵，是考你对 this 绑定机制的真正理解。

### 一句话说清楚

**call 就是"借方法"：把别人的函数拿过来，指定一个 this，立刻执行一次。**

### 核心原理

先想一个问题：什么时候函数的 this 会变成某个对象？——当它**作为那个对象的方法被调用**时（隐式绑定）。`obj.fn()` 里的 this 就是 obj。

所以手写 call 的思路反过来用这条规则：**把函数临时塞到目标对象身上，变成它的方法，调一下，再删掉**。this 就被"骗"过去了。

用生活类比：外卖单上写着你的地址，但你想让小哥送到你朋友家。call 的做法不是改外卖系统，而是**临时把朋友家的地址贴在外卖单上**，小哥照常按单子送，送到之后把贴纸撕掉，一切恢复原样。

```
myCall(context, ...args) {
  ① context 为 null/undefined 时，非严格模式指向全局对象
  ② context 是原始类型（数字/字符串/布尔）时，先 Object(context) 装箱
  ③ 生成一个 Symbol 当临时 key（避免和 context 已有属性撞名）
  ④ context[key] = this        // 关键！this 就是调用 myCall 的那个函数
  ⑤ const result = context[key](...args)   // 现在它是 context 的方法，this 自然指向 context
  ⑥ delete context[key]        // 撕掉贴纸，别污染别人
  ⑦ return result
}
```

两个最容易懵的点，提前点破：

1. **第④步的 `this` 是谁？** 是调用 `myCall` 的那个函数。比如 `fn.myCall(obj)`，`myCall` 是作为 `fn` 的方法被调用的，所以 `myCall` 内部的 this 就是 `fn`（还是隐式绑定）。
2. **为什么挂上去再调，this 就变了？** 因为 `context[key]()` 这种调用形式就是对象方法调用，1.16 的隐式绑定规则生效，this 指向 context。

## 二、验收过程

### 学生提交的代码核心内容

```javascript
Function.prototype.myCall = function (context, ...args) {
    // myCall内部的this是调用这个函数的Function的prototype；
    // 把函数挂在context上，就等于是通过context来调用这个函数，符合隐式绑定this的逻辑，谁调用，this就指向谁；

    // context是null/undefined的时候，使用全局的this
    context = context == null ? globalThis : context;

    // 如果context是原始类型，则需要用Object包裹；
    if (typeof context !== 'object' && typeof context !== 'function') {
        context = Object(context);
    }

    // 唯一属性
    const sId = Symbol('id');

    // 把原函数的当作属性放在context中
    context[sId] = this;

    // 执行原函数获取返回值
    const result = context[sId](...args);

    // 删除context中的原函数属性
    delete context[sId];

    // 返回结果
    return result;
}
```

### 概念纠错：注释中的表述错误

学生注释第 1 行写：「myCall内部的this是调用这个函数的Function的prototype」。

**这句话是错的。** 正确说法：myCall 内部的 this 是**调用 myCall 的那个函数对象本身**。

- 比如 `fn.myCall(obj)`，`myCall` 是作为 `fn` 的方法被调用的，所以 myCall 内部的 this 就是 `fn` 这个函数对象。
- `Function.prototype` 是所有函数共享的原型对象（所有函数通过它继承 call/apply/bind 等），它和「被借用的那个具体函数」是两回事。
- 类比：this 是「被你借走的那把具体的螺丝刀」，Function.prototype 是「全天下螺丝刀共用的图纸」。说 this 是 Function.prototype，等于说借走的是图纸而不是螺丝刀。

学生的第二句注释「把函数挂在context上，就等于是通过context来调用这个函数，符合隐式绑定this的逻辑，谁调用，this就指向谁」是正确的，抓住了实现的核心。
