# 1.30 ESM 与 CommonJS 的核心差异

## 一句话说清楚

（用一句白话解释 ESM 和 CJS 最根本的区别。提示：抓住"静态 vs 动态"——一个编译时就定好依赖，一个运行时才执行加载。这句是后面所有差异的总根源）

ESM：静态分析，通过顶层import，在执行代码之前就知道模块之间的依赖关系；
CJS：动态引入，require是一个函数，可以在任意地方动态调用，代码执行到才会加载；

## 核心原理

（这里是重点，要求覆盖三个对比，每个对比都要写清"为什么"，不要只列现象。建议每个对比配一个你亲手跑过的代码场景）

1. **加载方式对比**：为什么 import 必须写顶层而 require 可以写函数里？require 本质上是什么？
因为import是语法，写在顶层时引擎可以在编译时就识别模块之间的依赖关系，而require是函数，所以支持写到函数内；
import也可以写到函数内部，但是属于动态引入；
2. **值传递对比**：写一个"模块内部 1 秒后修改导出值，外部观察"的代码，分别用 CJS 和 ESM 跑一遍，记录两个文件各自的输出。用这个输出解释"快照拷贝"和"live binding"分别意味着什么
// a.mjs
export let count = 0;
setTimeout(() => { count = 10; }, 1000);

// b.mjs
import { count } from './a.mjs';
console.log('立刻:', count);
setTimeout(() => { console.log('1.5秒后:', count); }, 1500);

在ESM中，b模块中打印时，count为0，1.5秒后打印count为10，这是因为ESM是live binding，暴露的是count的引用地址，所以原始值改变时，外边使用会获取到实时变化后的值；
在CJS中，b模块中打印的就是0，1.5秒后也还是0，因为require 返回的是 module.exports 对象的引用，不是拷贝；拷贝发生在把值放进对象的那一刻（module.exports = { count }），之后模块内部 count = 10 只是改模块作用域的变量，没更新对象，所以外部看到的是旧值；

3. **循环依赖对比**：写一个 a/b 互相 require 的 CJS 场景，解释为什么后执行方拿到 undefined。再写一个 ESM 的对应场景，解释为什么 ESM 能拿到真值、以及什么情况下会报 TDZ 错误
// a.js
const { b } = require("./b.js");
console.log(b);
const a = "aaaaa";
module.exports = { a };

// b.js
const { a } = require("./a.js");
console.log(a);
const b = "bbbbb";
module.exports = { b };

node a.js在CJS中，先执行a，然后碰到require b模块，转而执行b，在b模块中遇到require a，暂时跳过，继续执行b，执行完之后再执行a，所以此时b模块中会先拿到a，此时是半成品，则打印undefined；node b.js则相反；

// a.mjs
import { b } from "./b.mjs";
console.log(b);
const a = "aa";
export { a };

// b.mjs
import { a } from "./a.mjs";
console.log(a);
const b = "bb";
export { b };

node a.mjs在ESM中，先执行a，碰到import b时，进入b模块执行，又遇到import a模块，此时跳过，继续执行b，打印时没有a变量，所以此时b模块TDZ报错；node b.mjs则相反；

（补充：其他差异——浏览器支持、顶层 this、严格模式、动态 import()，简单列个对比表即可）
浏览器支持：ESM支持；CJS不支持，需要打包处理成支持的语言；
顶层this：ESM顶层没有this；CJS顶层存在this；
严格模式：ESM自带严格模式；CJS需要手动指定 "use strict"
动态import：ESM支持import()来动态引入；CJS则任意执行require来动态引入；

## 和动态 import() / require 的关系

（提示：这部分写 ESM 的动态 import() 和 CJS 的 require 的对比——都是运行时加载，它们有什么异同？比如：返回值类型、能否 tree-shaking、应用场景。也可以写实际工程中两者如何互操作，比如 Node 的 .cjs 文件怎么 require 一个 .mjs，或者 webpack 打包时两种模块混用会发生什么）

1、import()动态引入返回的是Promise，而require则返回对象，包含要暴露的变量作为属性；
2、import()动态引入和require都不支持 tree-shaking；
3、import()动态引入可以用来通过条件控制加载组件，避免一开始就整个组件加载，拖慢首屏加载速度；

打包器（Vite/webpack）是个翻译官：它读你的源码时按 ESM 语法解析——这样可以拿到静态依赖图，做 tree-shaking；但执行和输出时，它可以转成任何格式（CJS、ESM、或者打成一个大文件）。你写的 import 是"书写格式"，和"执行环境"是两码事。

## 我的理解中不确定的部分

（诚实写出没完全搞懂的点。提示：比如"CJS 的 exports 到底是引用还是拷贝，为什么解构出来是旧值"、"TDZ 在模块循环依赖里具体怎么触发的"、"Node 里 .js 文件到底默认是 CJS 还是 ESM"。写"没有"不算数）

TDZ在ESM的模块循环依赖中，如果后执行的模块没有延迟调用变量，而是直接调用就会因为找不到变量而直接TDZ报错；
Node中的.js通过type属性来判断，不写默认是CJS，type为module时，为ESM；
