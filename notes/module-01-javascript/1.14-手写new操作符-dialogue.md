## 教学过程

### 为什么需要它

你写过 `new Vue({...})`、`new Promise(...)`、`new Date()`，`new` 是 JS 里天天用的操作符。面试官让你手写 `new`，不是想看你背代码，而是想知道：你到底理不理解 `new` 背后发生了什么。

这跟前面学的原型链（1.12）和继承（1.13）是一脉相承的。`new` 做的事，本质上就是把一个空对象的 `__proto__` 指向构造函数的 `prototype`，然后执行构造函数。如果你不理解这四步，`this` 指向（1.16）后面也会卡壳。

类比：`new` 就像一条流水线。你给流水线一台"模具"（构造函数），它自动帮你完成四件事——造一个空壳、贴上标签（原型）、注入零件（执行构造函数）、检查产出（判断返回值）。

### 一句话说清楚

`new` 操作符做了四件事：创建空对象 → 绑定原型 → 执行构造函数 → 判断返回值。

### 核心原理

当你写 `const obj = new Foo(arg1, arg2)` 时，JS 引擎实际执行了以下四步：

```
// 1. 创建一个空对象
const obj = {};

// 2. 把这个空对象的 __proto__ 指向构造函数的 prototype
obj.__proto__ = Foo.prototype;

// 3. 以这个空对象为 this，执行构造函数
const result = Foo.apply(obj, [arg1, arg2]);

// 4. 判断构造函数的返回值
//    如果构造函数返回了一个对象（包括数组、函数），就用这个返回值
//    否则，忽略返回值，返回前面创建的空对象
const finalResult = result instanceof Object ? result : obj;
```

关键细节：构造函数如果 `return` 了一个引用类型（对象/数组/函数），`new` 会返回这个引用类型而不是新创建的对象。但如果 `return` 的是基本类型（数字/字符串/null），`new` 会忽略它，仍然返回新对象。

## 验收过程

### 学生提交的代码

```javascript
function myNew(constructor, ...args) {
    // 创建基于构造函数原型生成的全新对象
    const newObj = Object.create(constructor.prototype);

    // 获取结果
    const result = constructor.apply(newObj, [...args]);

    // 判断结果是不是对象或函数，如果是则返回结果，如果不是则返回新对象
    return (result !== null && (typeof result === 'object' || typeof result === 'function')) ? result : newObj;
}
```

### 测试结果

全部 5 个测试用例通过：
- 测试1（基本用例）：Person 实例，name/age/sayHi/instanceof 全部正确
- 测试2（返回对象）：Foo 返回 `{b:2}`，myNew 正确返回了 `{b:2}` 而非 Foo 实例
- 测试3（返回基本类型）：Bar 返回 42，myNew 正确忽略，返回 `{a:1}`
- 测试4（返回 null）：Baz 返回 null，`typeof null === 'object'` 但 `result !== null` 正确处理
- 测试5（返回函数）：Qux 返回函数，myNew 正确返回函数而不是实例
