## 一、教学过程

### 为什么需要它

你在 Vue 里应该用过这个场景：两个没有父子关系的组件要通信，最朴素的方案是搞一个"事件总线"，一个组件 `$emit('xxx')`，另一个组件 `$on('xxx')` 接住。Vue2 里有个 `$bus` 就是这么干的，Vue3 官方推荐用 `mitt` 这个库——它核心就是几十行代码的 EventEmitter。

再往前想，你天天用的事件监听 `element.addEventListener('click', fn)` 本质上也是发布订阅。Node.js 里更是遍地都是，`EventEmitter` 是 Node 的基石类之一。

面试为什么爱考手写它：代码量小（不到 50 行），但能一次性考察闭包、this 绑定、函数参数收集、边界情况处理，是手写题里性价比最高的一类。

### 一句话说清楚

一个"事件通知中心"：`on` 注册回调、`emit` 触发回调、`off` 取消注册、`once` 只触发一次。

### 核心原理

类比一个微信聊天群：

- `on('新消息', fn)` = 你订阅了这个群，群里有消息你会收到 → 回调被存进名单
- `emit('新消息', data)` = 群主发消息 → 名单上所有人挨个被通知，data 就是消息内容
- `off('新消息', fn)` = 你退群，不再收到 → 从名单里移除
- `once('新消息', fn)` = 你只想知道"下一条"消息，收到一条就自动退群

数据结构核心只有一句话：一个 Map（或普通对象）：事件名 → 回调函数数组。

```
{
  'click': [fn1, fn2],
  'load': [fn3]
}
```

伪代码：

```js
class EventEmitter {
  handlers = new Map()          // 事件名 -> 回调数组

  on(name, fn) {
    // 没有这个事件的数组就先建一个空的，然后 push 进去
  }
  emit(name, ...args) {
    // 取出数组，挨个 fn(...args)
  }
  off(name, fn) {
    // 找到数组，把 fn 从里面移除（没有 fn 参数就清空整个事件）
  }
  once(name, fn) {
    // 包一层：先注册一个"执行完就 off 自己"的壳函数
  }
}
```

面试加分点：

1. once 的实现：不能直接注册 fn，要注册包装函数 wrapper——wrapper 先 off(name, wrapper) 再执行 fn(...args)。off 掉的必须是 wrapper 自己。
2. off 时要判断"这回调到底是不是注册时的那个"：如果用户 once 里传的是 fn，而你 off(name, fn) 时注册的是 wrapper，是删不掉的。
3. emit 时没有订阅者：别报错，静默返回。
4. 一个回调里抛异常：不能中断其他回调，最好 try/catch 包住逐个执行。
5. 同一回调重复 on 多次：会触发多次，这是合理行为，不用去重。

## 二、验收过程

### 学生提交的核心内容

```js
class EventEmitter {
  constructor() {
    this.eventMap = {};
  }

  on(message, cb) {
    (this.eventMap[message] ||= []).push(cb);
    return this;
  };

  off(message, cb) {
    if (!this.eventMap[message]) return this;
    this.eventMap[message] = this.eventMap[message].filter((item) => item !== cb);
    return this;
  };

  once(message, cb) {
    const wrapper = (...args) => {
      cb(...args);
      this.off(message, wrapper);
    };
    return this.on(message, wrapper);
  };

  emit(message, ...args) {
    if (!this.eventMap[message]) return false;
    this.eventMap[message].forEach(item => {
      item(...args);
    });
    return true;
  };
}
```

学生自带测试：on 两个 save 回调 + emit、once flash + 两次 emit、off save 后再次 emit、emit 不存在的事件。

### 运行结果

```
save1: 3
save2: 2
only once
save1: 3
save2: 2
```

### 逐项评判

1. **on + emit 多回调（判：正确）**。输出 `save1: 3`、`save2: 2`，符合预期。`(this.eventMap[message] ||= [])` 写法简洁，首次注册自动建数组。
2. **once（判：正确）**。`only once` 只输出一次，第二次 emit('flash') 无输出，wrapper 移除成功。但移除时序是先执行 cb 再 off，存在隐患（见扣分项3）。
3. **off（判：实现正确，但测试用例写错）**。测试里 `bus.off('save', (a, b) => ...)` 传的是新建函数，和注册时不是同一个引用，所以删不掉，save1 仍输出。实现用 filter 按引用比较是正确做法，问题在学生测试代码没保存函数引用。
4. **emit 不存在的事件（判：正确）**。`if (!this.eventMap[message]) return false`，静默返回不报错。
5. **回调抛错防护（判：缺失）**。forEach 遍历执行，一个回调 throw 会中断后续回调，真实场景应该 try/catch 逐个保护。
6. **once 移除时序（判：有隐患）**。wrapper 先执行 cb 再 off 自己，若 cb 内部再次 emit 同一事件，wrapper 还在数组里会被重复触发，甚至递归。先 off 再执行更稳，Node 官方实现也是先移除再调用。
