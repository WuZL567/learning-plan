# 对话记录：1.4 Object.prototype.toString.call() 类型判断

**日期：** 2026-08-10

## 一、教了什么

Object.prototype.toString.call() 是 JS 中精准类型判断的终极方法。核心原理是读取值内部的 [[Class]] 类型标签，返回 "[object Xxx]" 字符串。不能直接用值.toString() 是因为大部分内置类型重写了 toString。ES6 引入 Symbol.toStringTag 允许自定义标签。重点对比了它与 typeof（只能基本类型）、instanceof（只能原型链判断，跨 iframe 失效）的适用场景差异。

## 二、他答了什么

学生笔记核心理解：该方法通过 .call() 跳过重写的 toString，直接读 Object.prototype 上的原始 toString 获取内部类型标签。对比表基本正确，typeof 适合基本类型、instanceof 适合原型链判断、该方法适合精确类型判断。

三层追问：
1. 白话复述通过——抓住了"跳回原始 toString 读标签"的核心
2. 对比理解通过——正确回答 null instanceof Object 返回 false 及原因
3. 场景应用部分通过——知道判断 Plain Object 用 "[object Object]" 匹配，但替代方案（getPrototypeOf、constructor）不了解

学生的疑问：跨 iframe 对象的原理（已回答——独立执行环境导致原型链不同），ES6 后 Symbol.toStringTag 的应用场景（未回答——axios CanceledError、React element 检测等库中使用）。
