# 对话记录：1.31 Proxy 与 Reflect 基本用法与原理

日期：2026-08-18

## 一、教学过程

### 为什么需要它

学生有 5 年 Vue 经验，Vue2 的响应式有各种毛病——新增属性不响应、数组索引不响应、需要 `$set` 兜底。Vue3 全治好了，靠的就是 Proxy。

面试官问的往往是：
- Proxy 能拦截哪些操作？13 种 trap 都说得出来吗？
- 为什么 Vue3 用 Proxy 能监听新增属性，而 `Object.defineProperty` 不能？
- 为什么 handler 里写默认操作要用 `Reflect`，直接用 `target[key]` 不行吗？

另外 AI+前端方向的工具调用中间层、RAG 权限校验层也常用 Proxy 做拦截。

### 一句话说清楚

Proxy 是在对象外面套一层"门卫"，你对对象的每一次读写、删除、遍历、甚至 `new`，都要先经过门卫；Reflect 是门卫的"标准放行手册"——门卫不知道该怎么处理时，照手册办事就能还原默认行为。

### 核心原理

1. **基本形态**：`new Proxy(target, handler)`。handler 里可以挂 13 种拦截函数（trap），没挂的按原样放行。类比快递柜：存取都要过柜子，标准流程是 Reflect。
2. **13 种拦截操作**，分三类记：
   - 属性操作（最常考）：`get` 读、`set` 写、`has`（in 判断）、`deleteProperty`、`ownKeys`、`getOwnPropertyDescriptor`、`defineProperty`
   - 对象级操作：`getPrototypeOf`/`setPrototypeOf`、`isExtensible`/`preventExtensions`
   - 函数专属（target 是函数才生效）：`apply` 拦 `p()` 调用、`construct` 拦 `new p()`
3. **为什么必须配 Reflect**：
   - 保证 this 指向：`Reflect.get` 第三个参数 `receiver` 把 this 修正为代理对象；getter 里 this 是原对象时行为会绕开代理
   - 返回值符合规范：`Reflect.get` 读不到返回 undefined；`Reflect.set` 成功 true / 失败 false；set trap 返回 falsy 时严格模式赋值直接 TypeError
   - 避免死循环/递归：在 set trap 内直接 `target[key] = value` 不触发代理但会绕过；用 `Reflect.set(target, key, value, receiver)` 且 receiver 是代理时会再次触发 set trap
4. **与 Vue2 Object.defineProperty 对比**：defineProperty 是对具体某个属性打补丁，新增属性拦不到（所以需要 `$set`），只能拦 get/set 两种；Proxy 拦整个对象，13 种操作，能监听新增属性，所以 Vue3 的 `reactive` 本质是 `new Proxy(obj, { get 收集依赖, set 触发更新 })`。

**第二层追问（对比理解）**："用你自己的话把 Proxy vs Object.defineProperty 重新对比一遍，四句话以内：拦截粒度分别是什么？为什么 Vue2 需要 $set 而 Vue3 不需要？Vue3 选 Proxy 的根本原因是什么？"

学生回答："拦截粒度：Proxy是整个对象，defineProperty是单个属性；新增属性无法拦截到，vue2中需要使用 $set 来手动设置，vue3中则不需要；vue3选择Proxy的根本原因是因为要做响应式的对象"

评判：前两句正确（已纠正笔记中的写反），第三句是循环论证——"因为要做响应式，所以选 Proxy"等于没说。根本原因是能力差异：defineProperty 拦不了新增属性、拦不了数组索引，只能拦 2 种操作，做不出完整响应式；Proxy 能拦整个对象 13 种操作。✅前两句 / ❌根本原因。

**第三层追问（场景应用）**：场景题——用户对象 user = { name: '张三', age: 25 }，要求：① age 赋值必须 18-65 之间数字否则抛错 ② 读 name 返回脱敏 '张**' ③ 禁止 delete。写 Proxy 实现。

学生回答（原文）：

```js
new Proxy(user, {
    get(target, key) {
        if (key === 'name') {
            return Reflect.get(target, key).slice(0, -1).padEnd(3, "*");
        }
    },
    set(target, key, value) {
        if (key === 'age') {
            if (Number.isNaN(value) || value <= 18 || value >= 65) {
                throw new TypeError('age需要是18-65之间的数字');
            }
            Reflect.set(target, key, value);
        }
    },
    deleteProperty() {
        return false;
    },
});
```

评判：
- ✅ 脱敏逻辑正确：'张三'.slice(0,-1) = '张'，padEnd(3,'*') = '张**'
- ❌ get 无默认返回值：读 age 返回 undefined（最重 bug）
- ❌ set 只处理 age 分支：改 name 静默失败；整个 set 无 return（返回 undefined，严格模式下赋值抛 TypeError）
- ❌ 类型校验残缺：Number.isNaN('25') 为 false，字符串 '25' 能穿过校验
- ❌ deleteProperty 缺参数，签名应为 (target, key)
- 边界：按开区间处理 18 < age < 65，题目原文"18-65 之间"可接受

## 四、补充验收（第二轮：修改后重新提交）

### 学生主动提问

"receiver是怎么修改this的呢？我没理解"

导师解答（核心）：`Reflect.get(target, key, receiver)` 内部大致是 `prop.get.call(receiver)`——当属性是 getter 时，Reflect.get 用 `.call(receiver)` 调用 getter，getter 函数体内部的 this 就是 receiver；不传 receiver 时 this 是 target（原对象）。

实例：user 对象有 get fullName() { return this.firstName + this.lastName }。传 receiver 版本打印 'get: fullName'、'get: firstName'、'get: lastName' 三次（getter 内部访问也走代理）；不传只打印一次（内部访问绕过代理，门卫没看见）。Vue3 里就是依赖收集漏掉 → 改了不更新。

同时指出：get trap 里 Reflect.get 应永远带 receiver（习惯问题，无 getter 场景不影响运行）。

### 第二轮代码修改

学生提交（原文）：

```js
new Proxy(user, {
    get(target, key) {
        if (key === 'name') {
            return Reflect.get(target, key).slice(0, -1).padEnd(3, "*");
        }
        return Reflect.get(target, key);
    },
    set(target, key, value) {
        if (key === 'age') {
            if (typeof value !== 'number' || value <= 18 || value >= 65) {
                throw new TypeError('age需要是18-65之间的数字');
            }
        }
        return Reflect.set(target, key, value);
    },
    deleteProperty(target, key) {
        return false;
    },
});
```

评判：
- ✅ 默认返回值补上；set 用 if/else 结构放行非 age 属性并返回布尔值；typeof 校验；deleteProperty 参数补全
- ❌ 新 bug：改 typeof 校验时丢失了 Number.isNaN——typeof NaN 是 'number'，NaN <= 18 和 NaN >= 65 都是 false，NaN 能穿过校验被赋值。正确应为 `typeof value !== 'number' || Number.isNaN(value) || value <= 18 || value >= 65`
- ❌ get trap 内 Reflect.get 未传 receiver（规范习惯，本场景无 getter 不影响运行）

### 第二轮笔记修改评判

- ✅ apply/construct 补上："函数专属：apply 拦 proxyFn() 调用，construct 拦 new proxyFn()，target 为函数时才有"
- ✅ Vue3 链路补上核心注释："get 收集依赖，把当前正在读的属性登记；set 触发更新，通知所有登记的内容重新读取"；语法错误修复（分号改逗号）
- ✅ 对比完全纠正："Object.defineProperty 拦截单个属性，不能拦截新增的属性，能拦截的操作是2种；Proxy 拦截整个对象，能拦截新增属性，13种；能力差异：defineProperty 拦不了新增属性、拦不了数组索引，只能拦 2 种操作，做不出完整的响应式"
- ❌ Reflect 第三点写反一个字："receiver为target时，Reflect.set会再次触发set"——应为"receiver 为代理对象时"（receiver 传 target 不会触发 set trap，传代理才会递归）
- ❌ 13 种 trap 只列了 7 个，未按三组列全（getOwnPropertyDescriptor/defineProperty/getPrototypeOf/setPrototypeOf/isExtensible/preventExtensions 未列）
- ❌ 第四部分 receiver 描述含糊："需要传递target时就用receiver"表述混乱；未按要求补写 getter 例子

### 第四部分不确定点最终解答（全部给出）

1. receiver 何时有用：target 属性是 getter/setter 时，Reflect.get(target, key, receiver) 把 getter 内部 this 修正为 receiver（代理对象），内部属性访问继续走代理，依赖收集不漏
2. Object.keys(proxy) vs for...in：Object.keys 只返回自有可枚举属性；for...in 遍历整条原型链可枚举属性。ownKeys 拦的是取键的第一步，Object.keys 之后还会过滤不可枚举。ownKeys 返回数组必须是 string/symbol 键，且必须包含 target 所有不可配置的自有属性，否则抛 TypeError
3. Proxy.revocable：创建 { proxy, revoke }，revoke() 后代理上任何操作抛 TypeError。场景：对象交给第三方库用完即回收、权限过期
4. 为何不能代理原始类型：new Proxy(1, ...) 直接 TypeError，Proxy 只接受对象。Vue3 ref() 把原始值包成 { value: 1 } 再代理，所以要用 .value
5. === 和 instanceof：proxy !== target 正确；但不是 Object.create 创建，是引擎内部 exotic object。instanceof 走原型链（getPrototypeOf 转发），proxy instanceof 某类与 target 一致（true），学生猜的 false 是错的
6. 必选 trap：没有"必选"，但有不变量约束（ownKeys 必须含所有不可配置键、getOwnPropertyDescriptor 不能谎报不可配置属性等），违反直接抛 TypeError。"增删改查"是答非所问
