# 1.20 事件循环机制

## 第一部分：一句话说清楚

> 提示语：用一句白话给一个完全不懂的人解释"事件循环"是什么。可以想象你在给家里长辈解释"银行排队叫号"或"餐厅后厨"。
Javascript是单线程的，一次只能执行一件事，但是浏览器和node存在很多异步任务（网络请求，用户交互，定时器）；
需要一个机制来协调“同步任务”和“异步任务”之间的执行顺序，这个机制就是事件循环；

举例子：厨师一次只能做一件事，所以当洗菜，切菜，炖汤一起出现的时候，厨师先洗菜，然后安排灶台去炖汤（1小时），此时不会等待1小时，而是继续完成切菜任务，等所有的同步事情完成了，等待炖汤的回调放进队列之后，厨师再取出来执行；

## 第二部分：核心原理（含事件循环原理图）

> 提示语：用 ASCII 图画出事件循环的完整流程。图中至少要出现：调用栈、宏任务队列、微任务队列、渲染时机这四个要素，并用箭头标出它们的先后顺序。
>
> 然后用自己的话解释：一段代码从浏览器拿到手到全部执行完毕，走了哪些流程？每个宏任务执行完之后，会先发生什么、再发生什么？

1、同步任务逐行执行完毕；
2、执行微任务列表中的所有微任务，包括微任务执行期间产生的新的微任务；
3、取一个宏任务进行执行；
4、回到第2步，继续循环；

调用栈 -> 执行第一个宏任务；执行完之后，再从微任务队列中取出所有的微任务进行执行；
 ｜ 执行完1个宏任务之后；
微任务队列 -> 一次清空全部，队列中有：Promise.then/catch/finally，queueMicroTask(() => {})，nextTick(() => {})
 ｜
浏览器可能请求API，处理用户交互，渲染DOM，更新DOM；
 ｜
宏任务队列 -> 按照注册顺序取出1个宏任务执行，队列中有：setTimeout/setInterval，事件监听回调
 ｜
回到调用栈，取下一个任务，循环；

## 第三部分：微任务 vs 宏任务的区别

> 提示语：列一个对比表，至少覆盖这几点：分别有哪些（各举 2-3 个）、谁的优先级高、执行时机差在哪、为什么会有"清空 vs 取一个"的差别。
>
> 再回答一个问题：为什么 Promise.then 的回调一定比 setTimeout 的回调先执行？用事件循环的流程解释，不许只回答"因为微任务优先级高"。

微任务：
1、Promise.then/catch/finally；
2、queueMicroTask(() => {})；
3、await 后面的代码；

宏任务：
1、setTimeout/setInterval；
2、事件监听回调；

微任务优先级高，执行时机是微任务列表中清空所有的微任务和新产生的微任务后，取一个宏任务执行；

Promise.then不一定会比setTimeout的回调先执行，如果这个Promise是放在setTimeout中执行的话，就会比setTimeout回调慢了；

## 第四部分：我的理解中不确定的部分

> 提示语：诚实写出你没完全搞懂的点。给你几个常见疑问参考（有别的疑问也可以写）：
> - await 后面的代码属于什么任务？是微任务吗？
    是微任务，异步任务的同步写法，但是await右侧的表达式是同步执行的，下一行开始的代码责备包装成微任务进入微任务队列排队；
> - 为什么 Vue 的 nextTick 要放在微任务里？放宏任务里会怎样？
    回调在渲染之前执行，所以用户看到画面时，DOM已经是最新的；放到宏任务之后，会导致界面上的内容闪烁；
> - setTimeout(fn, 0) 真的是 0 毫秒后执行吗？最短间隔是多少？
    setTimeout(fn, 0) 的 0 只是"计时器 0 毫秒后到期，把回调扔进宏任务队列"，定时器只保证不早于，不保证准时。
> - 为什么说 JS 是单线程的，却能"同时"处理定时器、网络请求和点击事件？
    因为JS不会执行这些任务，而是注册回调后交给相关的API进行执行，等他们执行完放到任务队列中，才从中获取回调来执行；
>
> 没有不确定的也要写"暂时没有"，但必须是认真想过之后。
    为什么会有"清空 vs 取一个"的差别？
     - 因为微任务是宏任务的收尾工作，一个宏任务跑完，就必须把挂起的所有微任务都执行完，此时这个宏任务才算结束；才能继续下一个宏任务；
