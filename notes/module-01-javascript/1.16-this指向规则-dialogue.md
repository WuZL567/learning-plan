## 一、教学过程

### 为什么需要它

你写过 Vue 组件吧？在 `methods` 里用 `this.xxx` 访问 data，在 Composition API 里用 `this` 却拿不到东西——这两个 `this` 为什么不一样？你在回调函数里 `console.log(this)` 发现是 `undefined`，在事件处理函数里又是 DOM 元素。

`this` 是 JS 里最容易被面试官下套的地方。8 道输出题，错一道就尴尬了。因为面试官知道：**this 指向不清的人，遇到复杂异步场景和闭包陷阱大概率会写出 bug**。

### 一句话说清楚

**this 不是在定义时决定的，而是在函数被调用时决定的——谁调用了函数，this 就指向谁（new 除外）。**

### 核心原理

```js
const vm = {
  name: '我的组件',
  show() { console.log(this?.name) }
}

// 1. 默认绑定：直接调用 → this = undefined（严格模式）或 window
const fn = vm.show
fn()  // undefined / window.name

// 2. 隐式绑定：对象调用 → this = 调用者
vm.show()  // '我的组件'

// 3. 显式绑定：call/apply/bind → this = 你指定的值
const obj2 = { name: '另一个对象' }
vm.show.call(obj2)  // '另一个对象'

// 4. new 绑定：new 调用 → this = 新创建的空对象
function Component(name) { this.name = name }
const c = new Component('构造的')

// 5. 箭头函数：没有自己的 this → 继承外层作用域的 this
const arrow = () => console.log(this?.name)
```

**优先级从高到低：new > 显式(bind/call/apply) > 隐式(对象调用) > 默认(直接调用)。箭头函数不参与优先级，它根本没有自己的 this。**

| 绑定类型 | 规则 | 口诀 |
|---------|------|------|
| new 绑定 | `this` = 新创建的对象 | new 的就是我 |
| 显式绑定 | `this` = call/apply/bind 的第一个参数 | 我点你就是你 |
| 隐式绑定 | `this` = 调用方法的对象（`.`左边那个） | 谁点就是谁 |
| 默认绑定 | `this` = undefined(严格模式) / window | 裸奔就是全局 |
| 箭头函数 | `this` = 定义时外层作用域的 this | 我没有自己的 this |

## 二、验收过程

### 第一轮：8 道输出题

**第 1 题：**
```js
const obj = {
  name: 'obj',
  getName() { return this.name }
}
const fn = obj.getName
console.log(fn())
```

- 学生回答："undefined，因为虽然定义fn是obj.getName，但是调用的时候this才会生效，所以这里并没有指明this指向，所以是全局的this；"
- 评判：输出结果正确。但"全局的 this"说法不准确——严格模式下直接调用 this 是 undefined，不是 window。ES Module 和 class 默认严格模式，实际是 undefined.name → undefined（非严格模式才是 window.name → 空字符串）。

**第 2 题：**
```js
const obj = {
  name: '外层',
  inner: {
    name: '内层',
    getName() { return this.name }
  }
}
console.log(obj.inner.getName())
```

- 学生回答："内层，这里调用getName函数的是inner，符合隐式绑定。"
- 评判：✅ 正确。`.`左边是 obj.inner，this = obj.inner。

**第 3 题：**
```js
console.log(obj.getName.call(obj2))
console.log(obj.getName.apply(obj2))
console.log(obj.getName.bind(obj2)())
```

- 学生回答："三个都输出 obj2，call，apply，bind的第一个参数就是修改的this指向"
- 评判：✅ 正确。显式绑定三兄弟都指向 obj2。call/apply 立即执行，bind 返回新函数需再调用。

**第 4 题：**
```js
function Person(name) { this.name = name }
const p = {}
const bound = Person.bind(p)
bound('张三')
const p2 = new bound('李四')
console.log(p.name)
console.log(p2.name)
```

- 学生回答："都打印李四，这题考察优先级，new绑定的优先级高于显式绑定"
- 评判：❌ 两问全错。优先级说对了，但忽略了 `bound('张三')` 是普通调用、bind 正常生效 → p.name = '张三'。`new bound('李四')` 才触发 new 优先 → p2.name = '李四'，p 不受影响。
- 正确答案：先输出 '张三'，再输出 '李四'。关键点：new 优先于 bind，但 bind 绑的对象不是"废了"，普通调用时仍然生效，两条路各走各的。

**第 5 题：**
```js
const obj = {
  name: 'obj',
  fn() {
    console.log(this.name)
    setTimeout(function() {
      console.log(this.name)
    }, 0)
  }
}
obj.fn()
```

- 学生回答："首先输出obj，因为obj调用fn时是隐式绑定，调用的是obj的对象，所以fn中先输出obj；然后输出undefined，因为setTimeout中没有用箭头函数，这里fn中没有name属性，所以setTimeout中打印this.name时是undefined"
- 评判：⚠️ 两个输出结果都对，但第二问推理错。"fn中没有name属性"不是原因。真正原因：setTimeout 回调是普通函数，由定时器内部直接调用，默认绑定 → 严格模式 this = undefined → TypeError（或非严格 window.name = ''）。

**第 6 题：**
```js
const obj = {
  name: 'obj',
  fn() {
    console.log(this.name)
    setTimeout(() => {
      console.log(this.name)
    }, 0)
  }
}
obj.fn()
```

- 学生回答："两个都打印obj，第一个打印和第五题一样的原因；第二个打印obj则是因为setTimeout中用了箭头函数，this绑定的是外层作用域的this，所以这里fn的外层是obj对象，所以能获取到this.obj"
- 评判：⚠️ 结果对，表述有误。箭头函数找的是**外层函数作用域的 this**，不是"外层对象"。fn 被 obj 调用时 this = obj，箭头函数继承 fn 的 this。若改为 `const fn2 = obj.fn; fn2()`，两次都输出 undefined——因为 fn 的 this 变了，箭头函数跟着变。

**第 7 题（经典面试题）：**
```js
const length = 10
function fn() {
  console.log(this.length)
}
const obj = {
  length: 5,
  method(fn) {
    fn()
    arguments[0]()
  }
}
obj.method(fn, 1, 2, 3)
```

- 学生回答："10，这是词法作用域，代码编写的时候就定义好了作用域，所以这里fn调用就是获取了10"
- 评判：❌ 完全错，且只答了第一个输出。第一问：const 声明的变量不挂 window，浏览器 window.length 是 iframe 数量（默认 0），Node 严格模式直接 TypeError。第二问：arguments[0]() 等价 arguments.fn()，隐式绑定 this = arguments，arguments.length = 参数个数 = 4。
- 正确答案：第一次输出 0（浏览器）/ TypeError（Node），第二次输出 4。

**第 8 题：**
```js
class Button {
  constructor(name) { this.name = name }
  click() { console.log(this.name) }
  arrowClick = () => { console.log(this.name) }
}
const btn = new Button('提交按钮')
const { click, arrowClick } = btn
click()
arrowClick()
```

- 学生回答："提交按钮，undefined，因为arrowClick是箭头函数，所以没有this，而全局下也没有name属性"
- 评判：❌ 两问正好全反。click 是普通方法，class 严格模式，解构后直接调用 this = undefined → undefined/TypeError。arrowClick 是 class field 箭头函数，等号赋值发生在 constructor 执行时，当时的 this 就是实例，箭头函数永久捕获 → '提交按钮'。用箭头函数定义 class 方法等于自动 bind。
- 正确答案：第一次 undefined（或 TypeError），第二次 '提交按钮'。

**第一轮评分：5.5 / 10 → 补一个点**
- 概念理解 -0.5："箭头函数没有 this"说法不准确，应为"继承外层 this"
- 代码正确性 -1.5：第 4 题两问全错、第 7 题全错、第 8 题方向反
- 边界处理 -2：4、7、8 三道边界题全错，严格模式与非严格模式区别没体现
- 表达清晰度 -0.5：笔记过于简略

### 补课：三个核心认知

**认知一：this 不是"没有"，是"从哪拿"。** 普通函数像服务员，谁来餐厅就给谁服务（看调用者）；箭头函数像贴身保镖，只听命于雇主（外层函数），谁来叫都不理。

**认知二：完整判断流程。**
```
函数被调用
  ↓
是用 new 调的吗？ → YES → this = 新创建的对象
  ↓ NO
是 call/apply/bind 显式绑定的吗？ → YES → this = 指定的对象
  ↓ NO
是 obj.xxx() 这种形式调的吗？ → YES → this = . 左边的对象
  ↓ NO
是箭头函数吗？ → YES → this = 定义时外层作用域的 this
  ↓ NO
严格模式？ → YES → this = undefined
  ↓ NO
this = window
```
第 4 题详解：`bound('张三')` → 不是 new 调用 → bind 生效 → p.name = '张三'。`new bound('李四')` → new 调用 → new 优先 → p2.name = '李四'，p 不受影响。**bind 后的函数不是"永远指向 p"，而是"new 调用时 new 优先，其他调用时 bind 生效"。**

**认知三：this 丢失只发生在普通函数上。** 解构赋值只把函数引用拿出来，this 信息丢失。解决方法：bind / 箭头函数包一层 / class field 箭头函数。

**第 7 题详解：** const 不挂 window；arguments[0]() 等价 arguments.fn()，this = arguments 对象，arguments.length = 4。

### 第二轮：笔记验收 → 7 / 10 → 补一个点

- 概念理解 -1：class field vs constructor bind 答错。学生说"constructor 中的 bind 是调用时确定的"——错，bind 在 constructor 里执行时就锁死了，两者都是构造时确定。真正区别：class field 箭头函数只存在实例上、原型上没有；bind 是原型上有原始方法、实例上有绑定后的副本；子类能否 super 调用不同。
- 边界处理 -1.5：第三部分基本空白，必用场景只写 1 个且模糊，禁用场景 2 个全没写。
- 表达清晰度 -0.5：第二部分只抄流程图没写 Vue 真实例子。
- 答对的三个判断（肯定）：new 和 bind 各走各路 ✅、箭头函数 call 不能改 this ✅、口诀总结 ✅。

### 第三轮：笔记补交验收

学生笔记最终内容要点：
- 一句话说清楚：普通函数调用时指定、谁调用指向谁；箭头函数定义时决定、继承外层 this ✅
- 判断流程图三处空白全部填对（箭头函数→外层作用域 this；严格模式→undefined；非严格→window）✅
- 必用场景 1：class 普通函数里 setTimeout/setInterval 必须用箭头函数 ✅
- 必用场景 2：class 被 new 之后解构内部函数，箭头函数在定义时保存 this ✅
- 禁用场景 1：Vue Options API methods 不能用箭头函数，会去外层作用域找 this 导致拿不到组件实例 ✅
- 禁用场景 2：仍空白 ❌
- 不确定部分 4 问：new/bind ✅、箭头函数 call 不能改 ✅、class field vs bind "效果一样，constructor 中通过 bind 绑定 this 是通过原型链来找 this"（结论对，解释不准）、口诀 ✅
- 新增提问："Vue options API 的 methods 中使用箭头函数，使用 this 时是不是用的全局 this 呢？"——导师解答：在 ES Module（严格模式）中顶层 this 是 undefined，所以箭头函数继承的是 undefined，不是 window；在非严格 script 中才是 window。Vue 内部会把 methods 绑定到组件实例，但箭头函数无法被重新绑定，所以拿不到 vm。

**扣分项：**
1. 概念理解 -0.5：class field vs bind 说"通过原型链来找 this"不准。正确区别：class field 箭头函数只存在实例上（原型上没有）；constructor bind 是原型上有原始方法 + 实例上多一份绑定副本。两者效果一样（都是构造时锁定 this），区别在原型链结构。
2. 边界处理 -0.5：禁用场景只写了 Vue Options API 一个，第二个缺失。参考例子：DOM 事件回调里需要 this 指向触发元素时（addEventListener 的 handler 里用 this.classList），用箭头函数就拿不到元素了。
3. 表达清晰度 -0.5：个别表述绕（"会来到普通函数这里继承"、"通过原型链来找 this"）。

**改进建议：**
- 面试讲 this 时先背口诀再举例：new 的就是我 > 我点你就是你 > 谁点就是谁 > 裸奔就是全局 > 箭头函数继承外层。
