# 1.6 显式类型转换（Number / String / Boolean / parseInt）

## 一、一句话说清楚

> 用一句白话解释什么是显式类型转换，以及它和隐式类型转换的本质区别。

显式类型转换就是使用函数强制将值的类型转成目标类型，和隐式类型转换的本质区别是：一个是js引擎猜测的类型处理，一个是用户主动干预的类型处理；


## 二、核心原理

> 用你自己的话，分别解释 Number()、String()、Boolean()、parseInt() / parseFloat() 的转换规则。可以用对比表、类比或图解。重点要覆盖各函数的边界行为（空字符串、空格、null、undefined、非数字字符串等）。

### Number() 的转换规则

将值按照严格数字规则进行转换成数字，例如：
Number("0") => 0
Number(true) => 1
Number(false) => 0
Number(null) => 0
Number(undefined) => NaN
Number("abc") => NaN
Number('12a') => NaN
Number("") => 0
Number(" ") => 0

### String() 的转换规则

将值按照toString函数来转成字符串类型，例如：
String(0) => "0"
String(true) => "true"
String(false) => "false"
// null和undefined没有toString函数，但是String会特殊处理它们
String(null) => "null"
String(undefined) => "undefined"

### Boolean() 的转换规则

将值进行布尔类型转换，除了 false，""，0，null，undefined，NaN 是 falsy，其它都是truthy，包括[]，{}，"0"，" "；
Boolean("") => false
Boolean(" ") => true

### parseInt() 和 parseFloat() 的转换规则

这两个是将字符串从前到后读取提取数字，parseInt是整数，parseFloat包含浮点数；
和Number的区别在于：
Number("123ccc") => NaN，而parseInt("123ccc") => 123
Number("")和Number("  ")都 => 0，而parseInt("")和parseInt("  ")都 => NaN

### 四个函数的核心差异总结
Number 和 paresInt 之间处理字符串时，Number是判断这个是不是可以转成数字，而paresInt则是从字符串首位开始读取，直到不是数字的地方截取，例如parseInt("223dd")会获取223的数字，而Number则返回NaN；

parseInt支持radix参数，parseInt(string, radix)中，radix指定处理的进制，0表示没传，默认用10进制；

["1","2","3"].map(parseInt)为什么输出[1,NaN,NaN]，因为["1","2","3"].map(parseInt)中parseInt当做了callback，map函数传入了三个参数分别是item，index和原数组，但是parseInt只支持2个参数，忽略第三个参数之后，前面item作为string但是index做为了radix，也就是进制，所以等效于parseInt("1", 0)，parseInt("2", 1)，parseInt("3", 2)，0表示不传，所以默认是10进制，所以打印1，而进制没有1，所以parseInt("2", 1)是NaN，而parseInt("3", 2)中，有2进制，但是2进制没有3这种数字，所以也是NaN；

Number()处理对象时，需要先拆分对象，先执行valueOf函数获取值，如果返回自身则再执行toString获取值，再拿不到就抛出TypeError的错误，所以Number([]) => 0，Number({}) => NaN；

## 三、与隐式类型转换的关系

> 学完1.5隐式转换后再学1.6显式转换，它们是什么关系？什么场景下你不能依赖隐式转换而必须用显式转换？举一个你在实际项目中遇到过的例子。
显式转换是主动要求指定值的类型，而不是由JS引擎猜测决定；
在将DOM组件中的数据下发到后端API接口时，需要主动处理字符串为后端接口参数所需要的类型。
