## 教学过程

### 技术点：继承方式（1.13 | P0 | 能讲清面试）

### 为什么需要它

你在 Vue 项目里写组件，BaseList.vue 封装了分页、搜索、loading 这些通用逻辑，UserList.vue 和 OrderList.vue 想要复用这套逻辑。你有两个选择：用 mixins（Vue2 时代的方案）或者用组合式 API 的 composables（Vue3 的方案）。

JavaScript 的继承也是干同一件事——让一个对象/构造函数拿到另一个对象/构造函数的属性和方法。只不过 JS 的继承不是通过 class（那是语法糖），而是通过原型链。面试官问继承，他真正想问的是：你理解原型链的运作机制吗？你能讲清楚各种继承方案之间的权衡吗？

### 一句话说清楚

JS 继承就是让子"类"的实例能沿着原型链往上找，访问到父"类"的方法和属性，五种实现方式各有各的 trade-off。

### 核心原理

| 继承方式 | 类比 | 核心做法 |
|---------|------|---------|
| 原型链继承 | 直接把学霸的作业本借过来看 | `Child.prototype = new Parent()` |
| 借用构造函数 | 抄学霸的答案到自己的卷子上 | `Parent.call(this, ...args)` |
| 组合继承 | 既借作业本看，又抄到自己卷子上 | 上面两者结合 |
| 寄生组合继承 | 借学霸的作业本复印件看，抄答案到自己卷子 | `Object.create(Parent.prototype)` + `Parent.call(this)` |
| class extends | 老师统一发了标准答题卡 | ES6 语法糖，底层还是寄生组合 |

寄生组合继承代码：
```js
function Child(name) {
    Parent.call(this, name);  // 偷属性
}
Child.prototype = Object.create(Parent.prototype);  // 偷方法
Child.prototype.constructor = Child;  // 修正 constructor
```

## 验收过程

### 第一轮提交（6.5分，补一个点）

**学生提交的核心内容：**

学生用五种方式实现了 Dog 继承 Animal，但存在以下问题：
1. 寄生组合继承的 Dog4 构造函数是空的，缺了 `Animal.call(this, name)`
2. 原型链继承的缺点写成了"继承了父级的静态属性"，实际上应该是"引用类型共享问题 + 无法传参"
3. 第四部分写"暂时还没有"，但实际上存在上述问题

**第一次三层追问：**

**追问一（白话复述）：** "用30秒解释寄生组合继承到底做了什么？为什么它叫寄生+组合？"

学生回答："寄生组合继承，通过call调用父函数来获取父类属性，通过使用Object.create基于父类原型创建子类的原型对象获取父类的共享方法；寄生是指子类原型上constructor原本是指向父类的，现在手动指向自身，组合是指组合继承的方式"

评判：call+Object.create 核心理解正确。但"寄生"的解释不够准确——寄生是指 Object.create(Animal.prototype) 创建干净副本，避免像组合继承那样 new Animal() 产生冗余实例属性。不是 constructor 修正。

**追问二（对比理解）：** "寄生组合继承和 ES6 class extends 有哪些细微差别？super(name) 在 class 里具体做了什么？"

学生回答："super(name)具体实现：Object.setPrototypeOf(Animal.prototype)"

评判：**完全错误**。super(name) 调用的是父类构造函数，等价于 `Animal.call(this, name)`。Object.setPrototypeOf 是 extends 关键字在类声明时做的事（设置静态属性继承 `Child.__proto__ = Parent`）。super 和 extends 是两件事。

**追问三（场景应用）：** "用寄生组合继承写出 UserComponent 继承 BaseComponent 的代码"

学生代码：
```js
function UserComponent(loading, error) {
    BaseComponent.call(this, loading, error);
}
UserComponent.prototype = Object.create(BaseComponent.prototype);
UserComponent.prototype.constructor = UserComponent;
```
评判：代码结构完全正确 ✅

**第一轮评分：7/10，补一个点**

- 概念理解 2/4：super() 理解完全错误(-1)，原型链继承缺"无法传参"(-0.5)，寄生解释偏差(-0.5)
- 代码正确性 3/3：概念类给满分
- 边界处理 1.5/2：HTML注释不规范(-0.5)
- 表达清晰度 0.5/1：prototype描述"对象仓库"不精确(-0.5)

### 第二轮提交（9分，通过）

**学生修正内容：**
1. 原型链继承补上了"无法传参"缺点
2. super() 和 extends 拆开解释，三步拆解准确：
   - Dog5.prototype = Object.create(Animal.prototype) → 原型方法继承
   - Object.setPrototypeOf(Dog5, Animal) → 静态属性继承
   - Dog5.prototype.constructor = Dog5 → constructor修正
   - super(name) → 等价于 Animal.call(this, name)
3. "寄生"解释修正为 Object.create 创建空对象寄生，避免 new 冗余实例属性
4. HTML注释改为JS注释

**三层追问回答（第二轮补充）：**

追问一修正："寄生是指基于父类原型通过Object.create来创建一个空的对象来寄生，不像组合继承那样使用new来产生冗余的实例属性"

追问二修正："super(name)具体实现：Animal.call(this, name); extends具体实现：三步..."

评判：全部正确 ✅
