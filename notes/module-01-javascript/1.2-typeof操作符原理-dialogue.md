# 对话记录：typeof 操作符原理与边界情况

**日期**：2026-08-07

## 一、教了什么

typeof 本质上不是"判断类型"，而是读取 JS 引擎在值前面加的二进制类型标记位。null 的二进制全是 0，低位恰好是对象标记 000，所以 typeof null 返回 "object"——这是 JS 诞生时的设计缺陷。typeof 能准确判断基本类型（除 null）和 function，但对所有引用类型统一返回 "object"。要区分数组、Date、Map 等需要用 Object.prototype.toString.call() 读取内部 [[class]] 属性。typeof 还有一个特殊的安全机制：对未声明的变量不会报 ReferenceError，而是返回 "undefined"。

## 二、答了什么

学生对 typeof 的核心理解准确：本质是读二进制标记位，null 因全零被误判为 object。能正确对比 typeof 和 Object.prototype.toString 的适用场景和性能差异。代码实现简洁正确，用三段逻辑（null 优先 → typeof 基本类型 → toString 引用类型）覆盖了全部 18 种类型。第四部分诚实列出了不理解的点，包括 NaN 为什么是 number、document.all 的浏览器差异、数组/对象区分不了的原因。
