# 对话记录：1.12 原型与原型链

日期：2026-08-11

---

## 我教了什么

1. 用"模具 + 共享工具箱 + 爸爸链"的类比讲清了 `prototype` 和 `__proto__` 的区别——prototype 只有构造函数有，是共享工具箱；`__proto__` 所有对象都有，是指向共享工具箱的指针。
2. 详细拆解了 Function / Function.prototype / Function.__proto__ 的三角关系，解释了"鸡生蛋蛋生鸡"的设计原因——所有函数的 `__proto__` 都指向 `Function.prototype`，Function 自己也不例外。
3. 用代码对比了手动寄生组合继承和 class extends 的等价关系，指出 class extends 多做了静态属性继承（`Dog.__proto__ = Animal`）这件事。
4. 回答了学生 5 个深度追问：如何判断构造函数、为什么 __proto__ 指向 prototype 而不是构造函数、Function.__proto__ 为什么不是 Object.prototype、constructor 的作用、super 的参数传递机制。

## 他答了什么

核心理解：
- 原型是存放共享函数和属性的"库"，原型链是通过 `__proto__` 逐级查找的路径
- 构造函数之间的原型链关系写对了：Array/Object/Function 的 `__proto__` 都指向 `Function.prototype`
- class extends 和手动继承的对比，指出了三点差异：super vs call、Object.create vs extends、静态属性继承

追问表现：
- 主动提出 5 个深层次问题，说明在主动建模型而非死记硬背
- 对"为什么 p1.__proto__ 不指向 Person"、"Function 为什么指向自己"等问题有疑惑，经过讲解后理解

不足之处：
- 原型链图只画了构造函数链，缺少实例链（p1 → Person.prototype → Object.prototype → null）
- 未能清晰区分"构造函数的原型链"和"实例的原型链"是两条不同的链

- 分数：8/10
