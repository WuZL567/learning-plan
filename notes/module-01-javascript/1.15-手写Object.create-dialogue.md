## 一、教学过程

### 为什么需要它

你在 1.13 学了寄生组合继承，里面最关键的一步就是 `Object.create(Parent.prototype)`。它创建一个新对象，并且把新对象的原型指向你指定的对象，而不调用构造函数——这就是区别。

你可能会想："我直接用 `new` 不行吗？"不行。`new` 会调用构造函数，构造函数里可能有副作用（比如发请求、操作DOM），你只想继承原型上的方法，不想执行构造函数。而且构造函数可能还需要传参，你连参数都没有。这就是为什么需要 `Object.create`——它只做"建对象+指定原型"这一件事，干净利落。

你在 1.14 刚手写完 `new`，现在手写 `Object.create` 是天然的知识配对。面试官经常把这两个放一起问，让你对比它们的区别。

### 一句话说清楚

`Object.create(proto)` 就是：造一个空对象，把它的 `__proto__` 指向你传进来的 `proto`，然后返回。

### 核心原理

`Object.create` 本质就是做两件事：
1. 创建一个空函数
2. 把函数的 prototype 指向传入的对象
3. `new` 这个函数，返回实例

用你熟悉的 Vue 来类比：Vue3 的 `reactive` 创建响应式对象时内部也有类似的"基于某个原型创建新对象"的操作。Vue 源码里也用 `Object.create(null)` 来创建字典对象，避免原型链污染。

```
function myCreate(proto) {
    function F() {}      // 空函数，构造函数里啥也不干
    F.prototype = proto;  // 把这个空函数的原型指向你传的对象
    return new F();       // new 一个实例，实例的 __proto__ 就是 proto
}
```

**Object.create(null) 陷阱**：`Foo.prototype = null` 后 `new Foo()`，引擎发现 `Foo.prototype` 不是对象，自动回退到 `Object.prototype` 作为原型。所以处理 null 需要走另一条路——不是把这个 null 挂到 prototype 上，而是直接操作 `__proto__` 或者用 `Object.setPrototypeOf`。

### propertiesObject 讲解

`Object.create` 的第二个参数 `propertiesObject`，本质就是**在创建对象的同时，通过属性描述符定义自有属性**。它和 `Object.defineProperties` 的第二个参数格式一模一样。

属性描述符有两种：
- 数据描述符：value, writable, enumerable, configurable
- 存取描述符：get, set, enumerable, configurable

两种不能混用。

实现方式：`if (propertiesObject !== undefined) { Object.defineProperties(obj, propertiesObject); }`

### 练习任务

在 `src/module-01-javascript/1.15-手写Object.create/myObjectCreate.js` 中实现 `myObjectCreate` 函数，支持 proto 参数和可选的 propertiesObject 参数，处理 proto=null 边界和类型校验。

## 二、验收过程

### 第一轮验收（2026-08-12）

**提交代码核心内容**：
```js
function myObjectCreate(proto, propertiesObject) {
    const Foo = function () { };
    Foo.prototype = proto;
    return new Foo();
}
```

**测试结果**：
| 测试 | 结果 |
|------|------|
| proto=对象 | ✅ |
| proto=null | ❌ 原型回退到 Object.prototype |
| proto=123 | ❌ 未抛 TypeError |
| propertiesObject | ❌ 完全未实现 |

**评分**：2.5/10 —— 重学

**主要问题**：
- proto=null 时 `new Foo()` 引擎回退到 Object.prototype，原生应该返回 null 原型对象
- 未做类型校验
- propertiesObject 完全未处理
- 注释与代码不符（注释写了"判断 null"但代码没判断）

**学生疑问**：propertiesObject 是什么？不理解。

**解答**：用"买房"类比——只传 proto 是买毛坯房，传 propertiesObject 是买房+装修交付。格式和 `Object.defineProperties` 第二个参数一样，包含 value/writable/enumerable/configurable 等属性描述符。实现只需一行 `Object.defineProperties(obj, propertiesObject)`。

### 第二轮验收（2026-08-12）

**提交代码核心内容**：
```js
function myObjectCreate(proto, propertiesObject) {
    if (typeof proto !== 'object' && proto !== null) throw new TypeError("必须是对象或null");
    if (proto === null) {
        const newObj = {};
        newObj.__proto__ = null;
        if (propertiesObject !== undefined) {
            Object.defineProperties(newObj, propertiesObject);
        }
        return newObj;
    }
    const Foo = function () { };
    Foo.prototype = proto;
    return new Foo();
}
```

**测试结果**：
| 测试 | 结果 |
|------|------|
| proto=对象 | ✅ |
| proto=null | ✅ |
| proto 不合法→TypeError | ✅ |
| proto=null + propertiesObject | ✅ |
| **proto=对象 + propertiesObject** | ❌ y 为 undefined |

**评分**：6.5/10 —— 补一个点

**主要问题**：propertiesObject 只在 null 分支处理了，对象分支（new Foo()）忘记调 defineProperties。建议合并两个分支，defineProperties 只写一次。

### 第三轮验收（2026-08-12）

**提交代码核心内容**：
```js
function myObjectCreate(proto, propertiesObject) {
    if (typeof proto !== 'object' && proto !== null) throw new TypeError("必须是对象或null");
    let newObj;
    if (proto === null) {
        newObj = {};
        newObj.__proto__ = null;
    } else {
        const Foo = function () { };
        Foo.prototype = proto;
        newObj = new Foo();
    }
    if (propertiesObject !== undefined) {
        Object.defineProperties(newObj, propertiesObject);
    }
    return newObj;
}
```

**测试结果**：20/20 全部通过，含基础功能、null 分支、5 种类型校验、propertiesObject、writable:false、与原生对比。

## 四、薄弱点记录

本技术点经过 2 次打回后通过，薄弱点：
1. 第一版未理解 `new Foo()` 处理 null 原型的回退机制
2. 第一版不了解 propertiesObject（属性描述符）的概念
3. 第二版合并 defineProperties 时遗漏了对象分支

建议后续回顾时关注原型操作的本质（prototype vs `__proto__` vs setPrototypeOf 的区别）。
