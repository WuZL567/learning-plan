# 1.3 instanceof 操作符原理与手写实现

## 一、一句话说清楚
（这里用一句白话解释 instanceof 到底在判断什么，不要抄文档）

在判断对象是否存在于构造函数的原型链上，而不是单纯判断这个对象是什么类型的；

## 二、核心原理
（这里用类比或图解或伪代码，讲清楚 instanceof 沿着原型链查找的完整过程。可以画出 arr instanceof Array 和 arr instanceof Object 两条链路的查找路径）

arr instanceof Array 就是从 arr.__proto__ 一直向上找，是否找得到 Array.prototype，arr.__proto__ → Array.prototype，判断 arr.__proto__ === Array.prototype;
arr instanceof Object 则是从 arr.__proto__ 找到 Array.prototype，再继续找到 Object.prototype，arr.__proto__ → Array.prototype → Array.prototype.__proto__ → Object.prototype，判断 arr.__proto__ === Object.prototype;

## 三、instanceof vs typeof vs Object.prototype.toString.call
（这里写三者的对比：各自适用什么场景、各自的局限是什么。可以用表格）
instanceof 适合沿着对象的原型链查找，是不是属于某一个构造函数的原型上，以此来找到对象所属于哪一个引用类型；
typeof 适合查找数据的原始类型；
而 Object.prototype.toString.call 则适合通过原型链和函数调用来查询引用类型数据的类型；

## 四、我的理解中不确定的部分
（诚实写出还没完全搞懂的点。比如：为什么原始值 instanceof Number 返回 false？Object.create(null) 创建的对象 instanceof Object 为什么是 false？原型链被动态修改后 instanceof 结果会变吗？）

1、是因为 123 是原始值（primitive），根本没有原型链。只有 new Number(123) 才是对象，才有 __proto__。
2、null 是基本类型，它创建的对象 __proto__ 直接是 null，原型链断了，到不了 Object.prototype；
3、会。如果你改了 Constructor.prototype，已创建的旧实例的 __proto__ 还指向旧 prototype，新的 instanceof 判断会失败。但如果直接改实例的 __proto__（不推荐），instanceof 结果也会跟着变。
