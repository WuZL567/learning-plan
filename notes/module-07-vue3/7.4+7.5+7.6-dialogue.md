## 验收过程

### 学生提交的笔记核心内容

**7.4 ref原理：**
- 一句话：ref是对象包装器，通过.value的getter/setter收集依赖和触发更新；基本类型包一层成对象可以用Proxy监听
- 包装机制：增加value属性，通过value的getter/setter实现收集依赖和触发更新；ref包装对象时内部增加get/set的handle
- ref vs reactive：数据类型（ref是基本数据类型，reactive是对象类型）、访问方式（ref通过.value，reactive直接访问）、解构行为（reactive解构丢失响应式，用toRef/toRefs解决）
- 不确定点：模板为什么不用写.value、reactive对象里的ref为什么自动脱ref、toRef和toRefs的区别

**7.5 computed原理：**
- 一句话：computed是支持缓存的响应式getter，依赖数据不变返回缓存值，变化时才重新计算
- 缓存机制：首次访问收集依赖，下次访问查看依赖是否变化，未变化返回缓存值；依赖变化后重新计算；dirty用true/false表示数据是否失效
- computed vs watch：用途（computed简单计算返回新值，watch执行复杂逻辑）、返回值（computed返回计算值，watch不返回）、执行时机（computed访问时执行，watch监听参数变化时执行）
- 不确定点：computed能写setter吗、懒执行的意思、依赖没变为什么还能触发视图更新

**7.6 watch原理：**
- 一句话：watch是监听指定值变化并执行回调的机制，支持拿到新旧值、配置深度监听和立即执行
- 三种监听方式：ref(() => xxx.value)、reactive(() => xxx)、getter(xxx)；deep深度监听对象深层数据变化，immediate立即执行
- watch vs watchEffect：依赖收集（watch显式指定，watchEffect自动收集）、新旧值（watch有，watchEffect无）、执行时机（watch默认懒执行可设immediate，watchEffect立即执行）
- 不确定点：为什么watch reactive对象需要deep:true、watch多个数据源怎么写、watch的返回值

✅ 正确

---

**第二层：对比理解**

导师：ref vs reactive，数据类型上有什么区别？
学生：ref是基本数据类型，reactive是对象类型
⚠️ 不够准确
**正确答案：** ref可以包装任意类型（基本类型和对象类型），reactive只能包装对象/数组。ref包装对象时内部会调用reactive

导师：watch监听reactive对象为什么需要deep:true？
学生：因为对象可能存在深度的层次，需要deep参数来深度监听
✅ 正确，补充：默认情况下watch只监听reactive对象的引用变化（整个对象被替换），不监听内部属性变化，deep:true才递归监听所有嵌套属性

导师：watch的三种数据源怎么写？
学生：ref: () => xxx.value; reactive: () => xxx; getter: xxx
❌ 错误
**正确答案：**
- 监听ref：直接传`xxx`（不用包getter函数），或者`() => xxx.value`
- 监听reactive对象的某个属性：`() => state.count`（必须用getter函数）
- 监听reactive整个对象：直接传`state`，但默认是深度监听（隐式deep:true）

**第三层：场景应用**

导师：computed能写setter吗？怎么写？
学生：以前好像可以用setter，现在应该也可以
⚠️ 不够具体
**正确答案：** 可以写setter，语法是：
```js
const fullName = computed({
  get: () => `${firstName.value} ${lastName.value}`,
  set: (val) => {
    const [first, last] = val.split(' ')
    firstName.value = first
    lastName.value = last
  }
})
```
但实际工程中很少用，因为computed的语义是"计算"而不是"修改"

导师：watch监听多个数据源怎么写？
学生：写数组形式
✅ 正确，补充代码：
```js
watch([source1, source2], ([new1, new2], [old1, old2]) => {
  // 回调接收两个数组
})
```

导师：watch的返回值是干什么的？
学生：没有返回值吧，是回调函数的返回值吧
❌ 错误
**正确答案：** watch返回一个**停止监听的函数**，调用它可以手动停止监听
```js
const stopWatch = watch(source, callback)
// 某个时机停止监听
stopWatch()
```
这在组件卸载前或条件性监听时很有用

导师：模板里为什么不用写.value？
学生：模板自动解构不需要写
✅ 正确，更准确的说法是"模板编译器自动添加.value"

导师：toRef和toRefs的区别？
学生：toRef转换单个属性：const nameOnly = toRef(state, "name")，toRefs转换整个对象：const { name: nameRef, age: ageRef } = toRefs(state)
✅ 正确

## 验收结论

**评分：8.5分**
**判定：通过✅**

**扣分项：**
1. ref vs reactive数据类型理解不准确（-0.5分）：ref不只能包装基本类型，这是高频误区
2. watch三种数据源写法错误（-0.5分）：ref直接传变量，reactive对象的属性必须用getter
3. watch返回值理解错误（-0.5分）：返回停止函数是常见用法，必须掌握

**需要补充的知识点：**

1. **computed的懒执行：** 即使依赖变化了，如果没人访问computed，它也不会重新计算。只有访问时发现dirty=true才会计算

2. **ref包装对象的内部实现：**
   ```js
   function ref(value) {
     return isObject(value) 
       ? reactive({ value })  // 对象类型调用reactive
       : new RefImpl(value)   // 基本类型用RefImpl包装
   }
   ```

3. **watch vs watchEffect的默认执行时机：**
   - watch默认懒执行（需要immediate:true立即执行）
   - watchEffect默认立即执行

4. **reactive对象里的ref为什么自动脱ref：** reactive的Proxy在get handler里检测到返回值是ref类型，就自动返回`.value`
