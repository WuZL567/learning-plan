## 一句话说清楚

（用一句大白话解释computed是什么，和普通函数有什么本质区别？）

computed是支持缓存的响应式getter，依赖数据不变时返回缓存值，依赖数据变化时才重新计算并更新缓存值；

## 核心要点1：computed的缓存机制

（讲清楚computed怎么实现缓存的？什么时候返回缓存值？什么时候重新计算？dirty标记是干什么的？）

首次访问时会收集依赖，然后下次访问时会查看是否依赖数据发生变化，未变化就返回缓存值；
等到依赖数据发生变化后，就会重新计算；dirty用true和false表示数据是否失效，true时下次需要重新计算数据；

## 核心要点2：computed vs watch的区别

（从用途、返回值、执行时机三个角度对比，什么时候用computed，什么时候用watch？）

用途：computed一般在依赖数据的基础上，简单计算场景下使用，直接返回计算后的新值；watch一般是会通过监听一个变量，然后执行一段相关的逻辑函数，不会返回东西；
返回：computed会返回计算后的新值；watch是不会返回值，就执行回调函数；
执行时机：computed访问这个变量时就会执行；watch是监听的参数变化时就执行回调函数；
在简单计算后获取新的数据的时候用computed，在数据变化后需要执行复杂逻辑的用watch；

## 我的理解中不确定的部分

（诚实写出你没完全搞懂的点，比如：computed能写setter吗？computed的懒执行是什么意思？computed依赖的数据没变，为什么还能触发视图更新？）
1、可以写setter，语法是：
  const fullName = computed({
    get: () => `${firstName.value} ${lastName.value}`,
    set: (val) => {
      const [first, last] = val.split(' ')
      firstName.value = first
      lastName.value = last
    } 
  });
2、就是说定义的时候不执行里面的逻辑，后面访问变量时才计算逻辑；即使依赖变化了，如果没人访问computed，它也不会重新计算。只有访问时发现dirty=true才会计算。
3、还是会返回值，返回的是缓存的值；
