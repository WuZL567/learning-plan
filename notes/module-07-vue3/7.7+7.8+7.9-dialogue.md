## 第三层追问：场景应用

**问题 7**：watchEffect 的清理函数怎么用？场景 - 用户快速切换标签页，每次切换都要发请求获取数据。但用户切太快，上一个请求还没返回就切到下一个了。你怎么用 watchEffect 的清理函数取消上一个未完成的请求？

**学生回答**：不知道。

**评判**：❌ 不会用清理函数。

**正确答案**：
```javascript
watchEffect((onCleanup) => {
  const controller = new AbortController();
  
  // 发请求
  fetch('/api/data', { signal: controller.signal });
  
  // 清理函数：下次执行前会先调用这里
  onCleanup(() => {
    controller.abort(); // 取消上一个请求
  });
});
```

核心思路：watchEffect 的回调参数 `onCleanup` 是个函数，你在里面注册清理逻辑。每次 watchEffect 重新执行前，会先调用上次注册的清理函数。

**问题 8**：从你写 `<template><div>{{ count }}</div></template>` 到浏览器显示出来，中间经历了哪些步骤？虚拟 DOM 在哪个环节出现？

**学生回答**：代码转成虚拟 DOM 的 JS 对象，然后浏览器读取渲染。

**评判**：⚠️ 不完整，缺少编译和 Diff 两个关键步骤。

**正确答案**：
1. **模板编译**：`<template>` → render 函数（编译时）
2. **执行 render 函数**：生成虚拟 DOM（VNode 树）
3. **Diff 对比**：新旧 VNode 树对比，找出差异
4. **打补丁（patch）**：把差异应用到真实 DOM

虚拟 DOM 在第 2 步出现，Diff 在第 3 步发挥作用。

---

**问题 9**：Diff 算法为什么能从 O(n³) 优化到 O(n)？Vue 做了哪两个假设把复杂度降下来的？

**学生回答**：假设同层级不相同，就变化了；假设两端不同，就是变化了。

**评判**：⚠️ 理解有偏差，混淆了"假设"和"优化手段"。

**正确答案**：

传统树 diff 是 O(n³) 因为：
- 遍历树 A 的每个节点：O(n)
- 遍历树 B 的每个节点找匹配：O(n)
- 找到后计算编辑距离（插入/删除/移动）：O(n)

**Vue 做的两个假设优化到 O(n)**：
1. **只做同层比较，不跨层级**
   - 跨层移动在实际开发中极少，直接删除重建成本可接受
   - 复杂度从 O(n²) 降到 O(n)

2. **利用 key 快速判断节点是否相同**
   - 不用遍历整棵树找匹配，直接通过 key 定位
   - 双端对比 + key 映射表，避免暴力遍历

"双端对比"是优化手段，不是假设。
