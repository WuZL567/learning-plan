## 一句话说清楚

（用一句大白话解释Composition API是什么，和Options API有什么本质区别）

Composition API是函数式的组件逻辑组织方式，用setup函数代替options对象，把相关逻辑整合聚在一块，方便复用和维护；

## 核心要点1：setup函数的作用

（讲清楚setup函数什么时候执行？返回什么？可以访问this吗？为什么说它替代了beforeCreate/created？）

它的生命周期在 beforeCreate 之后 created 之前；返回一个对象；不可以访问this；因为生命周期恰好在这个范围内；

## 核心要点2：Composition API的三大优势

（从逻辑复用、类型推断、代码组织三个角度，用自己的话讲清楚为什么Composition API比Options API更好）

逻辑复用：支持抽成useXxx的类似Hook函数，不需要再Mixin；
类型推断：更好地支持TypeScript；
代码组织：按照功能逻辑拆分和组织，相关代码放在一起，更加清晰好维护；

## 我的理解中不确定的部分

（诚实写出你没完全搞懂的点，比如：setup和script setup有什么区别？ref和reactive选哪个？Composition API能和Options API混用吗？）

1、setup()函数需要手动return，且有props/context参数；<script setup>是编译时语法糖，自动return所有顶层变量，支持顶层await；
2、优先用ref；
3、好像可以，我之前做的项目需要从Options API迁移成Composition API，中间过渡就是两者共存的；
