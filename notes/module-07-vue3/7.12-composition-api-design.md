# 7.12 Composition API 设计思想

## 一句话说清楚

（这里用你自己的话，一句话解释 Composition API 是什么）
它是将一个功能中的响应式状态，逻辑，副作用都写在一个setup函数中，按功能组织代码；

## 核心要点一：三大优势

（这里写 Composition API 相比 Options API 的三大优势，每个优势用一句话 + 一个例子说明）
1、composition API按照功能组织代码，更清晰：
export default {
    setup() {
        // 功能1
        const count = ref(0);
        const doubleCount = computed(() => count.value * 2);
        const incrementCount = (num: number) => {
            return count.value + num;
        }

        // 功能2
        const user = ref({
            name: 'zhangsan',
            age: 20,
        })

        // 生命周期
        onMounted(() => {
            count.value = 10;
        });

        return {
            count,
            doubleCount,
            incrementCount,
            user,
        };
    }
}

export default {
    data() {
        return {
            count: 1,
            user: {
                name: 'zhangsan',
                age: 20,
            }
        };
    },
    computed: {
        doubleCount() {
            return this.count * 2;
        }
    },
    methods: {
        incrementCount(num) {
            return count.value + num;
        }
    },
    mounted() {
        this.count = 10;
    }
}

2、Composition API的逻辑复用方式更优雅；
options API都是用mixin，导致命名冲突，来源不清晰，composition API用普通函数，可以任意组合，也可以用hook；

3、Composition API的类型推导更友好；
setup返回的都是显式声明，TypeScript推导更精确；

## 核心要点二：什么时候用 Composition API

（这里写你理解的使用场景：什么项目适合用？小项目需要用吗？）
任何项目都可以用Composition API；

## 我不确定的部分

（这里诚实写出你没完全搞懂的点，比如"setup 函数的返回值如果不写 return 会怎样"、"Composition API 和 Hooks 有什么区别"等）
1、不写return就无法暴露内部的变量和函数到外部去，无法给别的地方调用；
2、我觉得没什么区别，都是普通函数，并且都暴露一些函数和变量给外部使用和复用；
