## 教学过程

### 为什么需要它

HTTP 是明文传输的，就像寄明信片，邮递员（中间人）能看到内容。HTTPS = HTTP + TLS，就是在 HTTP 下面加了一层加密保护层。TLS 握手就是双方"商量用哪把钥匙开锁"的过程。

### 一句话说清楚

TLS 握手就是客户端和服务端在传数据之前，先用非对称加密安全地协商出一把对称加密的钥匙（会话密钥），后面所有数据都用这把钥匙加密传输。

### 核心原理

**TLS 握手 4 步：**

1. **ClientHello**：客户端发送"你好"，包含：随机数 A（明文）、支持的加密套件列表、TLS 版本
2. **ServerHello**：服务端回应，包含：随机数 B（明文）、选定的加密套件、数字证书（含公钥）、ServerHello Done
3. **客户端验证 + 生成预主密钥**：客户端验证证书是否由可信 CA 签发、是否过期、域名是否匹配。验证通过后生成随机数 C（预主密钥），用证书里的公钥加密 C，发送给服务端
4. **双方计算会话密钥**：客户端和服务端都用 A + B + C 计算出相同的会话密钥（Session Key）。之后所有数据都用这把会话密钥做对称加密

**为什么混合加密：**

- 纯非对称加密：安全但慢，RSA 加解密比 AES 慢 1000 倍
- 纯对称加密：快但密钥传输不安全，怎么把钥匙安全地给对方？
- 混合加密：用非对称加密安全交换对称密钥（握手阶段），用对称密钥加密海量数据（传输阶段）。就像用保险箱寄一把普通锁的钥匙，收到后用普通锁锁门

**证书的作用：**

- 解决"公钥到底是谁的"问题
- 没有证书：中间人可以劫持通信，把自己的公钥发给客户端，客户端用假公钥加密，中间人用自己的私钥解密就能看到明文
- 有证书：证书由受信任的 CA（证书颁发机构）签发，包含域名、公钥、有效期、CA 的数字签名。客户端验证证书 = 确认公钥属于真正的服务器。中间人无法伪造 CA 签名，攻击失效

## 验收过程

### 学生提交的笔记核心内容

**一句话说清楚：**
> HTTPS=HTTP+TLS，TLS握手是为了在服务端和客户端传输数据之前先生成仅双方知道的会话密钥，然后通过这个密钥来加密数据传输

**TLS握手4步：**
> 第一步：客户端发送随机数A + 支持的加密套件列表给服务端
> 第二步：服务端发送随机数B + 选中的加密套件 + 含有公钥的证书给客户端
> 第三步：客户端验证证书，生成随机数C，用公钥加密C发送给服务端
> 第四步：客户端和服务端用A+B+C计算出同一把会话密钥，之后传输数据都用这个密钥加密数据

**混合加密：**
> 纯非对称加密速度比较慢，纯对称加密安全性不够；混合加密时，交换密钥使用非对称加密传输，保证私钥安全，海量数据传输使用对称加密，提升速度

**证书作用：**
> 没有证书，客户端就没法验证服务端的来源合法性，也没法知道公钥是谁的，也就没法加密随机数C去发送给服务端

**不确定的点：**
> 1、不确定ECDHE和RSA版是什么区别
> 2、因为有三次传输操作，要确保每一步都不会出错，每一步都是准确的
> 3、使用了混合加密，不是纯非对称加密和纯对称加密，既保证安全性又保证性能
> 4、什么是中间人攻击？

**TLS握手4步：** ✅ 正确，缺少 ServerHello Done 细节，但核心流程理解准确

- 第2点理解有偏差：三个随机数的目的不是"确保不出错"，而是**增加熵（随机性）**，防止被预测
- 其他不确定点都是合理的疑问，解答如下：

### 针对不确定点的解答

**1. ECDHE 和 RSA 版差别：**
- RSA 版：客户端生成预主密钥，用服务端公钥加密发送。没有前向保密——私钥泄露后历史通信全解密
- ECDHE 版：双方各自生成临时密钥对，用椭圆曲线 Diffie-Hellman 算法协商预主密钥。私钥是临时的，用完就扔，即使长期私钥泄露也解不开历史通信。现代 HTTPS 基本都用 ECDHE

**2. 三个随机数为什么不能只用一个：**
- 客户端随机数：明文传输（可被截获）
- 服务端随机数：明文传输（可被截获）
- 预主密钥：非对称加密传输（中间人看不到）
- 三个随机数来自不同机器、不同时间、不同生成方式，组合起来的随机性远大于单个。即使前两个被截获，没有第三个也推不出会话密钥

**3. TLS 1.3 为什么快：**
- 握手从 2-RTT 变成 1-RTT
- 支持 0-RTT 恢复（访问过的网站可以直接带数据发）
- 砍掉不安全算法（RSA 密钥交换、CBC 模式），只保留 ECDHE + AEAD

**4. 什么是中间人攻击：**
- 想象你给朋友寄信，邮递员偷偷拆开看，还模仿你朋友笔迹回信给你
- 没有证书时：中间人劫持通信，把自己的公钥发给客户端，用假公钥加密数据，中间人用自己的私钥解密看明文
- 有证书时：客户端验证证书（CA 签发 + 域名匹配），中间人无法伪造 CA 签名，攻击失效
