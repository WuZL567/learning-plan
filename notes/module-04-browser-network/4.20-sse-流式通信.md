# 4.20 SSE 原理与API

## 一句话说清楚
SSE（Server-Sent Events）是基于 HTTP 的服务器单向推送技术，服务器保持长连接持续推送数据，浏览器通过 `EventSource` API 接收，适合 AI 流式输出、实时通知等场景。

## 核心要点一：SSE 的工作原理
**核心机制：**

1. **基于 HTTP 协议的长连接**：客户端发起一个 GET 请求，服务器返回 `Content-Type: text/event-stream`，连接保持打开状态不断开。

2. **服务器持续推送数据**：服务器有数据就推送，格式是 `data: xxx\n\n`（两个换行符表示一条消息结束）。

3. **浏览器通过 `EventSource` API 接收**：
   ```javascript
   const eventSource = new EventSource('http://localhost:3000/sse');
   eventSource.onmessage = (event) => {
     console.log('收到消息:', event.data);
   };
   ```

4. **断线自动重连机制**：浏览器内置重连逻辑，默认 3 秒后自动发起新请求，重连时会发送 `Last-Event-ID` 请求头告诉服务器上次收到的消息 ID。

**对比理解：**
- **短轮询**：前端每隔几秒问一次"有新消息吗？"（主动拉取，浪费资源）
- **SSE**：前端订阅后，服务器有消息就推送（被动接收，高效）
- **WebSocket**：双向通道，前端和后端都能主动发消息（更复杂，适合聊天室）

## 核心要点二：SSE 与 WebSocket 的区别
**完整对比表：**

| 维度 | SSE | WebSocket |
|------|-----|-----------|
| 通信方向 | 单向（服务器→客户端） | 双向（客户端↔服务器） |
| 协议 | 基于 HTTP（复用现有协议） | 独立协议（ws:// 或 wss://） |
| 连接建立 | 普通 HTTP 请求 | HTTP 握手后升级为 WebSocket |
| 自动重连 | 浏览器内置（默认 3 秒） | 需要手动实现 |
| 消息格式 | 纯文本（`data: xxx\n\n`） | 二进制或文本 |
| 浏览器兼容性 | 好（除了 IE 全部支持） | 好 |
| 实现复杂度 | 简单（浏览器原生支持） | 较复杂（需要处理重连、心跳） |
| 适用场景 | AI 流式输出、实时通知、股票行情 | 聊天室、协同编辑、多人游戏 |

**重点：AI 问答为什么用 SSE 不用 WebSocket？**

1. **单向通信够用**：AI 输出时只需要服务器推送给前端，不需要前端频繁发消息。
2. **更简单**：浏览器原生 `EventSource` API，自动重连，省心。
3. **更轻量**：复用 HTTP 协议，不需要额外的 WebSocket 服务器。

WebSocket 适合需要双向实时通信的场景，比如聊天室（你发消息别人也发消息）。

## 我的理解中不确定的部分
**已解答的疑问：**

1. **SSE 的消息格式是什么样的？`data:` 和 `event:` 是什么意思？**  
   标准格式：`data: 消息内容\n\n`（两个换行符表示消息结束）
   ```
   data: 这是第一条消息\n\n
   data: 这是第二条消息\n\n
   ```
   高级用法：
   - 多行消息：`data: 第一行\ndata: 第二行\n\n`
   - 自定义事件：`event: customEvent\ndata: 消息内容\n\n`（前端用 `addEventListener('customEvent')` 监听）
   - 消息 ID：`id: 123\ndata: 消息内容\n\n`（用于断线重连时告诉服务器上次收到哪条）

2. **如果服务器断开连接，`EventSource` 会一直重连吗？有重连次数限制吗？**  
   浏览器会无限重连，默认 3 秒间隔。服务器可以通过返回 `retry: 5000\n\n` 设置重连间隔（单位毫秒）。如果不想重连，前端调用 `eventSource.close()` 关闭连接。

3. **SSE 能跨域吗？需要 CORS 配置吗？**  
   SSE 也受同源策略限制。跨域时需要后端配置 CORS 响应头：
   ```javascript
   res.setHeader('Access-Control-Allow-Origin', '*');
   ```

4. **AI 流式输出为什么用 SSE 不用 WebSocket？**  
   因为 AI 输出是单向的（服务器推送给前端），不需要前端频繁发消息。SSE 更简单，浏览器原生支持，自动重连，比 WebSocket 轻量。WebSocket 适合双向实时通信（如聊天室）。
