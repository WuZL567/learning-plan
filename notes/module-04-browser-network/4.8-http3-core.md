# 4.8 HTTP/3 核心特性

## 一句话说清楚

<!-- 用一句白话解释 HTTP/3 是什么，解决了什么问题 -->
HTTP/3 是 HTTP/2 的应用层 + QUIC传输层，核心是每个流独立重传，解决TCP层的队头阻塞；

## 三个要点

### 要点1：TCP 队头阻塞问题

<!-- HTTP/2 虽然有应用层多路复用，但 TCP 层的队头阻塞是什么？用高速公路的比喻解释 -->
TCP阻塞就是TCP层出现一个TCP包丢了的时候，所有的流都会阻塞，等待TCP恢复，因为要依赖TCP来保证顺序交付；

### 要点2：QUIC 协议原理

<!-- QUIC 基于 UDP，怎么保证可靠性？流独立重传是什么意思？ -->
UDP 本身不可靠（不保证顺序、不保证送达），QUIC 在 UDP 之上**自己实现了可靠性**：序号、确认、重传、流控，相当于把 TCP 的活自己干了，但做到了"每条流独立"。

流独立重传：一个包丢了只阻塞对应的那个流，其他的流不受影响。

### 要点3：0RTT 握手

<!-- 为什么 HTTP/3 首次连接只要 1RTT，后续可以 0RTT？和 TCP+TLS 的 2-3RTT 对比 -->
QUIC 内置 TLS 1.3，握手和加密合并为一步。

- 首次连接 1RTT：QUIC 握手时同时完成密钥交换，只需一个往返就能建立连接（TCP+TLS 需要 2-3RTT）
- 后续连接 0RTT：客户端缓存了上次的密钥，下次连接时直接带上加密数据发出去，不用等服务端确认，真正零延迟

## 不确定的点

<!-- 诚实写出没完全搞懂的点，这比假装全懂更有价值 -->
1. QUIC 在 UDP 上自己实现可靠性，具体是怎么做到的？（序号、确认、重传这些机制的细节）
2. Connection ID 具体是什么格式？服务端怎么通过它识别同一个连接？
3. 0RTT 有什么安全风险？（重放攻击？）
