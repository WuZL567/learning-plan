# 4.13 协商缓存详解

## 一句话说清楚
（用一句白话解释协商缓存是什么，比如"协商缓存就是..."）
协商缓存就是客户端用ETag或Last-Modified问服务端，资源是否发生了变化，如果未变化，则返回304，复用本地缓存，如果发生变化，则返回200和新的资源；

## 核心要点一：两组对比字段
（写清楚 Last-Modified/If-Modified-Since 和 ETag/If-None-Match 的工作流程，以及哪个优先级更高、为什么）
Last-Modified/If-Modified-Since：
1、服务器首次返回Last-Modified；
2、浏览器再次请求时带上If-Modified-Since；
3、服务器对比这两个时间，变化了就返回200和新资源，没变化则返回304；

ETag/If-None-Match：
1、服务器首次返回ETag，带上了一个表示资源的哈希值；
2、浏览器再次请求时带上If-None-Match，带上资源的哈希值；
3、服务器对比这两个哈希值，变化了就返回200和新资源，没变化则返回304；

ETag优先级更高，因为精确度更高，哈希值精度高于秒级时间；

## 核心要点二：协商缓存和强缓存的配合链路
（写清楚强缓存过期后如何触发协商缓存，以及 304 和 200 的区别。可以画个简单的决策流程图：请求 → 强缓存判断 → 协商缓存判断 → 重新下载）
1、强缓存有效期内 -> 直接用本地缓存，不发请求；
2、强缓存过期后 -> 触发协商请求，发请求询问服务器；
3、链路：有强缓存 -> 强缓存有效期 -> 直接不发请求，使用本地缓存；
                -> 强缓存不在有效期 -> 协商缓存，发请求询问服务器 -> 服务器判断资源是否变化 -> 有变化 -> 返回200+新资源
                                                                                  -> 无变化 -> 返回304
## 我的理解中不确定的部分
（诚实写出你不太确定的点，比如"ETag 的哈希值是怎么生成的""为什么 ETag 比 Last-Modified 精确""304 响应有没有响应体"）
1、ETag的哈希值是通过资源内容生成的；
2、因为ETag是用哈希值，而Last-Modified用的是秒级时间差；
3、304没有响应体；
