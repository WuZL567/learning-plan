# 4.12-强缓存

## 一句话说清楚

> 用一句话解释强缓存是什么（提示：浏览器在有效期内会不会发请求？）
强缓存就是在有效期内，直接使用本地缓存，不下发请求。

## 两个核心要点

### 要点1：Cache-Control 的常见指令及区别

> 这里写 max-age、no-cache、no-store 三个指令的区别（提示：max-age 多久内不发请求？no-cache 是不缓存吗？no-store 呢？）
max-age: 3600 => 表示在 3600秒之内，不需要请求，直接用缓存；
no-cache => 不是不使用缓存，而是先问服务器是否资源发生了变化，变化了就请求获取新资源，未变化就使用本地缓存（协商缓存）；
no-store => 直接不使用缓存，无论有没有缓存都直接从服务器请求获取资源；

### 要点2：Expires 和 Cache-Control 的区别及优先级

> 这里写 Expires 和 Cache-Control 的区别（提示：一个是绝对时间一个是相对时间，哪个优先级高？为什么 Cache-Control 更好？）
Cache-Control：是相对时间，比如max-age：3600；、
Expires：是绝对时间，依赖客户端时间判断，Expires设置的具体日期时间是否过期；
如果两者都存在，Cache-Control的优先级 大于 Expires；
为什么Cache-Control更好，因为依赖客户端时间会有问题，如果客户端时间不准确，则会导致Expires的设置失效；

## 我的理解中不确定的部分

> 诚实写出没完全搞懂的点，比如：
> - no-cache 和 no-store 具体什么场景用？
no-cache可以用到一些不常更新的数据上，比如说某个物品的地理位置，只有物品的位置发生变化时，才需要请求更新；
no-store可以用到经常需要更新的数据上，比如说实时价格，实时库存等这些；

> - max-age=0 和 no-cache 有什么区别？
max-age=0表示立即过期，表示缓存立即过期，但会走协商缓存（问服务器是否变化）；
no-cache则是协商缓存，服务端数据更新了就请求，否则用缓存即可；
所以 max-age=0 ≈ no-cache（基本等价，都是协商缓存）

> - 强缓存和协商缓存的优先级关系是什么？
强缓存优先级更高，浏览器先看强缓存（Cache-Control/Expires），如果强缓存有效就直接用，不发请求；如果强缓存过期或设置了 no-cache，才走协商缓存（ETag/Last-Modified）
