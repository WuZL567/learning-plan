# 4.2 DNS域名解析流程

## 一句话说清楚

（用一句白话解释 DNS 是干什么的，输入 URL 后它做了什么。参考：查号台/通讯录类比。）

用来查询域名背后对应的服务器IP地址的，输入URL后，它会先从浏览器缓存查找，没有就查询操作系统的缓存hosts文件，没有找到就去根服务器上找，没找到就去.com查找，没有找到就继续去完整服务器上查找；

## 三个要点

### 要点一：完整解析链路

画出（或文字描述）访问 www.baidu.com 时的完整链路，从第一层到最后一步，每层都要写出来。

提示：浏览器缓存 → ？ → ？ → ？ → 权威服务器。想不起来先按顺序写，写错没关系，重点是写出每一层。

浏览器缓存->操作系统缓存文件（hosts）->根服务器（.）->域名服务器（.com）->完整服务器（baidu.com）返回IP；

### 要点二：递归查询 vs 迭代查询

用你自己的话说清楚：哪一段是递归？哪一段是迭代？为什么根服务器不直接告诉 IP？

提示：想象你（浏览器）和本地 DNS 的关系是一种"我帮你负责到底"，本地 DNS 和各层服务器之间是另一种"我给你指路，你自己去"。

客户到本地DNS就是递归查询，会负责到底查询最终答案；
从本地DNS到权威服务器是迭代查询，只会指路，一层层递归指路；

### 要点三：缓存与 TTL

DNS 为什么到处都有缓存？TTL 是什么意思？如果某台服务器换 IP 了，为什么用户访问还是老 IP？

提示：联系前端里 CDN 缓存、浏览器缓存的思路来类比。

因为本地DNS到权威服务器之间，每一层都只会指路，缓存的是每一层查到的结果；
TTL是每一层的有效期时间，所以换了IP之后，老用户还是访问的旧IP，这是因为未过期导致的；
