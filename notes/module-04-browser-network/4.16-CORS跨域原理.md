# 4.16 CORS 跨域原理

## 一句话说清楚
（用一句白话解释 CORS 跨域是什么，比如"CORS 跨域就是浏览器限制不同源的网页访问资源"）
跨域CORS是浏览器不支持不同源的网页访问资源，同源的意思是（相同协议 && 相同域名 && 相同端口），三者其一不满足就是不同源；

## 核心要点一：同源策略三要素 + 简单请求 vs 复杂请求
（写清楚同源策略的三要素：协议+域名+端口。举 2-3 个例子说明哪些情况算跨域。然后写清楚简单请求和复杂请求的判断条件，比如 GET/POST + text/plain 是简单请求，PUT/DELETE 或 application/json 是复杂请求）
1、协议相同：https://a.com 和 http://a.com 不是同源，因为一个是https协议，一个是http协议；
2、域名相同：https://a.com 和 https://b.com 不是同源，因为一个域名是a.com，一个是b.com；
3、端口相同：https://a.com:443 和 https://a.com:4430 不是同源，因为一个端口是443，一个是4430；

简单请求（不需要预检，直接发）：
 - 方法是GET，POST，HEAD；
 - Content-Type 不是 application/json；
 - 没有自定义请求头（Authorization）；
复杂请求（需要先发OPTIONS预检）：
 - 方法是PUT，DELETE，PATCH；
 - Content-Type 是 application/json；
 - 有自定义请求头；

## 核心要点二：预检请求（OPTIONS）完整流程
（写清楚复杂请求的预检流程：浏览器先发 OPTIONS 询问权限 → 服务器返回 Access-Control-Allow-* 响应头 → 浏览器收到许可后发真正的请求。重点写清楚 Access-Control-Allow-Origin、Access-Control-Allow-Methods、Access-Control-Max-Age 这几个响应头的作用）
1、浏览器发送OPTIONS预检请求给服务器，询问权限；
2、服务器返回响应头 Access-Control-Allow-*；
 - Access-Control-Allow-Origin：允许的源；
 - Access-Control-Allow-Credentials：是否允许带Cookie；
 - Access-Control-Allow-Methods：允许的请求方法；
 - Access-Control-Max-Age：预检结果有效期；
3、浏览器收到这些响应头之后，发送真正的请求；
