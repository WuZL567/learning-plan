## 一、教学过程

（冲刺模式教学，压缩到 2-3 分钟阅读量）

### 为什么需要它

你天天写接口调 `https://api.example.com`，浏览器怎么知道这个"名字"对应哪台服务器的 IP？网络世界里机器只认 IP 地址（比如 `110.242.68.66`），人记不住数字才发明了域名。**DNS 就是把域名翻译成 IP 的"查号台"**——这是面试开场第一问（"输入 URL 后发生了什么"）的第一步，答不出这一步后面全卡住。而且它和前端强相关：缓存、TTL、CDN 加速全是它的概念，理解了 DNS，缓存那几题（4.12-4.14）会好讲很多。

### 一句话说清楚

DNS 是互联网的通讯录：你报出名字（域名），它查出电话号码（IP），而且全程有缓存，查过一次就记下来。

### 核心原理

**链路**（以访问 www.baidu.com 为例）：

```
浏览器缓存 → 操作系统缓存(hosts文件) → 本地DNS服务器(LDNS)
    ↓ 本地DNS也没有
根服务器(.) "去问 .com 的服务器"
    ↓
顶级域名服务器(.com) "去问 baidu.com 的权威服务器"
    ↓
权威服务器(baidu.com) 查表 → 返回 IP
    ↓
本地DNS记下结果(缓存)，返回给浏览器
```

**递归 vs 迭代**（面试必考）：
- **递归**：你→本地 DNS。你只问一次，本地 DNS"负责到底"，问完把最终答案给你。你不用管中间问了几个人。
- **迭代**：本地 DNS→根→顶级→权威。根服务器不给答案，只"指路"："我不认识 baidu，你去问管 .com 的"，一层层指下去，本地 DNS 自己跑完全程。

**缓存与 TTL**：每一层查到结果都会存一份，配一个有效期 TTL（比如 300 秒）。所以换 IP 后老用户还访问旧 IP，就是因为各级缓存没过期。这跟你清 CDN 缓存、强缓存 max-age 是同一个思路。

## 二、验收过程

### 学生笔记核心内容

**一句话说清楚**："用来查询域名背后对应的服务器IP地址的，输入URL后，它会先从浏览器缓存查找，没有就查询操作系统的缓存hosts文件，没有找到就去根服务器上找，没找到就去.com查找，没有找到就继续去完整服务器上查找。"

**要点一（链路）**："浏览器缓存->操作系统缓存文件（hosts）->根服务器（.）->域名服务器（.com）->完整服务器（baidu.com）返回IP"

**要点二（递归/迭代）**："客户到本地DNS就是递归查询，会负责到底查询最终答案；从本地DNS到权威服务器是迭代查询，只会指路，一层层递归指路。"

**要点三（缓存与TTL）**："因为本地DNS到权威服务器之间，每一层都只会指路，缓存的是每一层查到的结果；TTL是每一层的有效期时间，所以换了IP之后，老用户还是访问的旧IP，这是因为未过期导致的。"

**不确定的点**：1、不知道；2、不知道；3、不知道。

### 初步审阅指出的问题

1. **链路漏掉了本地DNS服务器（LDNS）这一层**：学生写的是"浏览器缓存 → 操作系统缓存 → 根服务器"，跳过了本地DNS。而本地DNS是整个解析的"主力"（浏览器把查询委托给它，它负责到底）。漏掉它导致"递归 vs 迭代"的起点悬空。
2. **术语错误**：".com"那层应叫**顶级域名服务器（TLD）**，最后返回 IP 的应叫**权威服务器**（学生写成"域名服务器""完整服务器"）。

### 三层追问完整问答记录

**追问一（白话复述）**：用 30 秒白话讲一遍：输入 www.baidu.com 后，DNS 到底做了什么？重点说：浏览器缓存和 hosts 文件都没命中之后，下一个出场的是谁？它在什么情况下才去问根服务器？

**学生回答**："DNS就是从浏览器缓存开始查询，没有就查操作系统缓存文件（hosts文件），没有就查本地DNS服务器，如果还没找到，说明本地DNS中未找到，所以开始查找服务器：先查找根服务，它会指路去查顶级域名服务器.com，然后顶级域名服务器又会指路去查权威服务器（baidu.com），最终查到IP返回。"

**评判**：✅ 通过。链路完整：浏览器缓存 → hosts → 本地DNS → 根 → 顶级(.com) → 权威 → 返回 IP。上次漏掉本地DNS的问题已修正，能口述全流程了。

**追问二（对比理解）**：递归查询和迭代查询的区别，用你自己的生活场景打比方？另外，全世界所有解析请求的第一站都是根服务器，为什么根服务器反而最轻松——它为什么不直接告诉你 IP？

**学生回答**："递归查询就是会递归查找，最终返回一个结果给你；而迭代查询就是会逐层逐层的查询，每一层只会指路下一层去哪查，不会告诉结果；不知道；"

**评判**：递归/迭代概念 ✅（意思对：递归是负责到底返回最终结果，迭代是每层只指路）。但"根服务器为什么不直接给 IP" ❌ 没答上。

**正确答案**：根服务器不存任何具体域名的 IP——它的"数据库"里只有 13 个顶级域名服务器的地址。而且它刻意只指路不干活：全世界每个新域名的第一次解析都会经过它，如果它真去查每个域名，负载会爆掉。所以它把自己降级成"导航台"，把流量分发给下一层，自己永远轻载。权威服务器才是真正持有 `baidu.com → IP` 这张表的"产权登记处"。

**追问三（场景应用）**：假设你们公司的接口域名要换新 IP（比如 CDN 迁移），改动生效后，老用户是立刻访问到新 IP 吗？不是的话，是什么拖慢了生效速度？如果你想让切换"尽量快"，部署前你会做什么？

**学生回答**："不是立刻访问到新的IP，得等到TTL有效期过了之后在访问才是新的IP，或者强制刷新TTL就可以立即访问了"

**评判**：核心方向 ⚠️ 半对。"等 TTL 过期"是对的。但"强制刷新 TTL 就能立即访问"不准确——你只能清掉**自己这端**的缓存（浏览器、OS、路由器），**ISP 本地DNS 的缓存你管不着**，只能等它过期。

**正确答案（工程实践）**：部署新 IP 前**提前降 TTL**：提前 24-48 小时把 TTL 从 86400 秒降到 60 秒，让各级缓存的旧记录快速失效，等差不多都过期了再切换 IP，用户几乎无感知——和前端发布时用协商缓存、灰度切流量的思路一样。
