# 4.7 HTTP/2 核心特性

## 一句话说清楚

（用一句白话解释 HTTP/2 是什么、解决什么问题）

HTTP/2是为了解决HTTP/1.1三大问题的HTTP版本，解决队头阻塞，头部重复发送等；

## 三个要点

### 要点1：多路复用

（为什么 HTTP/1.1 有队头阻塞？HTTP/2 怎么用帧和流解决的？）
因为HTTP/1.1是串行模式，前面的响应返回才可以继续下发下一个请求，HTTP/1.1 要并发只能开多个连接；
HTTP/2在一个 TCP 连接上，把数据拆成帧，每个帧标记属于哪个流，多个流的数据可以并发发送，最终按照流来分拣；

### 要点2：头部压缩

（HPACK 怎么压缩 Header？静态表、动态表、霍夫曼编码分别起什么作用？）
维护一个静态表，存放常见Header名称和值的映射；
维护一个动态表，存放已经出现过在本次连接中的Header；
使用霍夫曼编码压缩Header；

### 要点3：服务端推送

（服务端推送的场景是什么？和客户端自己请求有什么区别？）
客户端请求index.html，服务端主动将对应的JS和CSS都推送过来，不需要客户端再请求；

## 不确定的点

（诚实写出没完全搞懂的点）

HTTP/2 虽然在应用层解决了队头阻塞，但 TCP 层仍然有队头阻塞。
原因：TCP 是字节流协议，所有流的数据混在同一个 TCP 连接里。如果中间有一个 TCP 包丢了，整个连接的所有流都得停下来等重传——即使丢的那个包跟其他流没关系。
HTTP/3 用 QUIC 协议（基于 UDP） 解决了这个问题：每个流完全独立，一个流丢包不影响其他流。
HTTP/2:  流A、流B、流C 都在一个TCP连接里 → TCP丢包 → 全部阻塞
HTTP/3:  流A、流B、流C 各自独立的UDP连接 → A丢包 → B和C继续
