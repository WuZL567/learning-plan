# 对话记录：4.7 HTTP/2 核心特性

日期：2026-09-01

## 教学过程

### 为什么需要它

HTTP/1.1 有三个大问题：队头阻塞（一个请求卡住，后面全排队）、每个连接一次只能处理一个请求（浏览器开 6 个连接也只能同时 6 个）、头部重复发送（每次请求都带一堆 Cookie 和 Header）。HTTP/2 就是来解决这三个问题的。

### 一句话说清楚

HTTP/2 的核心是**多路复用**：一个 TCP 连接上可以同时发多个请求，互不阻塞，像高速公路上多辆车并行。

### 核心原理

**1. 多路复用（Multiplexing）**

HTTP/1.1 的问题：请求排队，必须等前一个响应完才能发下一个。

HTTP/1.1:
请求A → 响应A → 请求B → 响应B → 请求C → 响应C（串行）

HTTP/2:
请求A ──→ ┐
请求B ──→ ├──→ 响应A、B、C 混合返回（并行）
请求C ──→ ┘

HTTP/2 把数据拆成**帧（Frame）**，每个帧标记属于哪个**流（Stream）**，多个流的数据帧在同一个连接上交错发送，接收端根据标记重新组装。就像高速公路，不同车（帧）可以并行，到了目的地再按车牌（流ID）分拣。

**2. 头部压缩（HPACK）**

HTTP/1.1 每次请求都重复发送完整的 Header（Cookie、User-Agent 等），浪费带宽。

HTTP/2 用 HPACK 算法：
- 维护一个**静态表**（常见 Header 名称和值的预定义映射）
- 维护一个**动态表**（本次连接中出现过的 Header）
- 用**霍夫曼编码**压缩 Header 值

效果：第一次请求 Header 可能 800B，后续相同 Header 只需发几个字节的索引。

**3. 服务端推送（Server Push）**

客户端请求 `index.html`，服务端可以主动把 `style.css`、`main.js` 也推过去，省去客户端解析 HTML 后再发请求的往返时间。

客户端: GET /index.html
服务端: 响应 index.html
服务端: 推送 style.css（客户端还没请求）
服务端: 推送 main.js（客户端还没请求）

**4. 二进制分帧层**

HTTP/1.1 是纯文本协议（人能直接读）。HTTP/2 在应用层和传输层之间加了一个**二进制分帧层**，所有数据都转成二进制帧，解析更快、更紧凑。

### 学生提交的笔记核心内容

**一句话说清楚：**
HTTP/2是为了解决HTTP/1.1三大问题的HTTP版本，解决队头阻塞，头部重复发送等；

**要点1：多路复用**
因为HTTP/1.1是串行模式，前面的响应返回才可以继续下发下一个请求；
HTTP/2则把数据拆成帧，每个帧标记属于哪个流，多个流的数据可以并发发送，最终按照流来分拣；

**要点2：头部压缩**
维护一个静态表，存放常见Header名称和值的映射；
维护一个动态表，存放已经出现过在本次连接中的Header；
使用霍夫曼编码压缩Header；

**要点3：服务端推送**
客户端请求index.html，服务端主动将对应的JS和CSS都推送过来，不需要客户端再请求；

### 追问记录

**第一层追问（白话复述）：** 用 30 秒解释 HTTP/2 的多路复用到底是什么？

**学生回答：** 将数据拆成帧，每个帧标记属于哪一个流，多个流的数据并发发送，最后按照流的ID来分拣结果；

**评判：** 基本对，但漏了一个关键前提——"一个 TCP 连接"。HTTP/2 的核心是：在一个 TCP 连接上，用多个流并发传输。HTTP/1.1 要并发只能开多个连接（浏览器默认开 6 个）。

**第二层追问（对比理解）：** HTTP/2 解决了队头阻塞，为什么还需要 HTTP/3？

**学生回答：** 不知道；

**评判：** 这是面试高频考点，必须懂。HTTP/2 虽然在应用层解决了队头阻塞，但 TCP 层仍然有队头阻塞。原因：TCP 是字节流协议，所有流的数据混在同一个 TCP 连接里。如果中间有一个 TCP 包丢了，整个连接的所有流都得停下来等重传——即使丢的那个包跟其他流没关系。HTTP/3 用 QUIC 协议（基于 UDP）解决了这个问题：每个流完全独立，一个流丢包不影响其他流。

**第三层追问（场景应用）：** 如果一个页面有 100 个请求，HTTP/1.1 和 HTTP/2 分别会怎么处理？

**学生回答：** HTTP/1.1会一个个的串行请求，HTTP/2则会并发，按照允许的并发大小来安排。

**评判：** 部分正确，但HTTP/1.1 不是完全串行的。HTTP/1.1 浏览器会开 6-8 个 TCP 连接并行处理，但每个连接内是串行的。HTTP/2 是一个连接内并发，效率更高。
