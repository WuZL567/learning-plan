日期：2026-09-03

## 教学过程

### 为什么需要它

HTTP/2 虽然解决了应用层的队头阻塞，但底层用的还是 TCP。TCP 有个硬伤：**一个 TCP 连接里，只要丢了一个包，整个连接的所有数据流都得等这个包重传完才能继续**。就像高速公路上一个车道坏了，所有车道都得停下来等修好。

HTTP/3 的出现就是为了解决这个 TCP 层的队头阻塞问题。它直接换了底层传输协议，从 TCP 换成了 **QUIC（基于 UDP）**。

### 一句话说清楚

HTTP/3 把传输层从 TCP 换成了 QUIC（基于 UDP），彻底解决了 TCP 的队头阻塞问题，还内置了 TLS 1.3 加密，连接建立更快。

### 核心原理

**HTTP/2 vs HTTP/3 的本质差异：**

```
HTTP/2 协议栈：
应用层：HTTP/2（多路复用）
传输层：TCP（单个包丢失→整个连接阻塞）
加密层：TLS 1.2/1.3

HTTP/3 协议栈：
应用层：HTTP/3
传输层：QUIC（基于UDP，内置TLS 1.3）
```

**QUIC 解决的三个核心问题：**

1. **彻底解决队头阻塞**：QUIC 把每个 HTTP 流独立管理，流 A 丢包不影响流 B。就像把一条大高速改成多条独立小路，一条路堵了不影响其他路。

2. **0-RTT 连接恢复**：第一次连接后，客户端会保存服务器的配置。下次直接发送加密数据，不需要握手。就像你办了 VIP 卡，下次来直接进门不用再登记。

3. **连接迁移**：你从 WiFi 切换到 4G，TCP 连接会断（因为 IP 变了）。QUIC 用连接 ID 标识连接，IP 变了连接不断。就像你的会员卡号不会因为你换了手机号就失效。

**类比理解：**

- HTTP/1.1：一条车道，车一辆一辆排队过
- HTTP/2：一条宽车道，多辆车并排跑（应用层多路复用），但底层还是一条路，一个坑就全堵
- HTTP/3：多条独立车道（QUIC 的独立流），一条路堵了其他路继续跑

**第二层追问：对比理解**

问：HTTP/2 和 HTTP/3 的传输层差异是什么？

学生回答：HTTP/2 的 TCP 只有一条，会在 TCP 出现问题时阻塞所有的流。

评判：⚠️ 理解有偏差（得 1 分，满分 2.5 分）
- ✅ 说对了 HTTP/2 的问题：TCP 层一个包丢失会阻塞所有流
- ❌ 但没说清楚 HTTP/3 的传输层是什么：**QUIC 是基于 UDP 的**，这是关键差异
- ❌ "QUIC 是按照 TCP 实现的传输方式"这句话不准确。QUIC 不是 TCP 实现的，它是**基于 UDP**，自己在应用层实现了可靠传输、拥塞控制等功能

正确答案：
- HTTP/2：应用层 HTTP/2 + 传输层 TCP + TLS
- HTTP/3：应用层 HTTP/3 + 传输层 QUIC（**基于 UDP**，内置 TLS 1.3）
- 核心差异：**TCP 是单一字节流，一个包丢失全阻塞；QUIC 基于 UDP，多个独立流，丢包只影响单个流**

**第三层追问：场景应用**

问：在什么场景下 HTTP/3 的优势最明显？

学生回答：网络切换时连接不会中断，因为使用连接 ID。

评判：✅ 部分正确（得 1.5 分，满分 2.5 分）
- ✅ 连接迁移场景答对了（移动端从 WiFi 切 4G）
- ❌ 但漏了另一个重要场景：**弱网环境高丢包率**。这是 HTTP/3 最大的优势场景
- ❌ 还漏了 0-RTT 连接恢复的场景：频繁建立连接的场景（如 API 请求）

正确答案：
1. **弱网环境（高丢包率）**：比如地铁、电梯、移动网络信号差的地方，HTTP/3 的独立流机制让丢包影响最小化
2. **移动端网络切换**：WiFi ↔ 4G/5G 切换时，HTTP/3 的连接迁移让连接不中断
3. **频繁建立连接的场景**：0-RTT 让第二次连接几乎无延迟

**关于"不确定的部分"**

学生写的不确定点解答：
1. QUIC 丢包怎么办？答：丢包后重新请求（❌ 不准确）
2. 0-RTT 连接恢复具体是怎么做到的？答：使用连接 ID（❌ 这是连接迁移的原理）
3. 连接 ID 是怎么生成的？答：每个流都有独立编号以此生成（❌ 这是流编号不是连接 ID）

正确解答：
1. **QUIC 丢包处理**：QUIC 自己实现了可靠传输机制，有确认应答（ACK）、超时重传、流量控制，和 TCP 类似，但是**每个流独立重传**，不会阻塞其他流
2. **0-RTT 原理**：第一次连接后，服务器给客户端一个"会话票据（Session Ticket）"，客户端下次连接直接用这个票据加密发送数据，不需要握手
3. **连接 ID 生成**：服务器在连接建立时生成一个随机的连接 ID（类似 UUID），客户端和服务器都记住这个 ID。IP 变了，只要连接 ID 对得上，连接就能继续
