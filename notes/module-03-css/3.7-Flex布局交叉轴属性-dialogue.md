# 对话记录：3.7 Flex 布局交叉轴属性

日期：2026-08-20

## 一、教学过程

### 为什么需要它

做前端 5 年，垂直居中早写吐了。但面试问"交叉轴"时，很多人栽在同一个坑里：**`align-items` 和 `align-content` 都管垂直方向，到底什么时候用哪个？** 答不上来。

这个坑在真实工作中天天踩——列表项高度不一时要 `align-items: flex-start`，多行卡片墙要 `align-content: space-between`，单个元素想特立独行要 `align-self`。三个属性管同一根轴，分不清就把布局做成玄学。

3.6 学完主轴（`justify-content`），交叉轴就是它的"另一半"。Flex 的精髓就一句话：**主轴定方向，交叉轴定位置**。只会一半，面试官一问交叉轴就露馅。

### 一句话说清楚

交叉轴就是"与主轴垂直的那根轴"，`align-items` 管单行内的对齐，`align-content` 管多行整体的分布，`align-self` 管单个元素搞特殊。

### 核心原理

**第一步：确定交叉轴在哪。** 交叉轴的方向由 `flex-direction` 决定：

| flex-direction | 主轴方向 | 交叉轴方向 |
|---|---|---|
| row（默认） | 水平 → | 垂直 ↓ |
| column | 垂直 ↓ | 水平 → |

**第二步：分清三个属性各管什么。**

```
align-items    → 管"行内"对齐     —— 像队列里每个人站齐（单行时管全部）
align-content  → 管"行与行"分布   —— 像多支队列怎么排布（必须多行才生效）
align-self     → 管"单个人"站队   —— 队里某个人想单独靠边站
```

**第三步：记住 `align-items` 的 5 个取值，尤其是 stretch 和 baseline：**

- `flex-start` / `flex-end` / `center`：沿交叉轴顶/底/中
- `stretch`（默认值）：item 拉伸填满容器高度——但 item 自身设了高度就拉伸不了
- `baseline`：按 item 第一行文字的基线对齐——两个 item 字号不同时，`flex-start` 按盒子顶对齐，`baseline` 按文字基线对齐，效果分道扬镳

**最容易搞混的一对：** `align-items: center` 管一行内 3 个 item 的垂直居中；`align-content: center` 管 wrap 成多行后，这 3 行整体在容器里怎么分布。单行时 `align-content` 完全没效果。

- 底部两条区别注释：

  - "baseline 处理位置的依据是 item 的第一行文本的位置，与文本内容有关系；flex-start 是基于 item 容器位置；如果不设置字体大小，默认浏览器字体大小下，它和 flex-start 的效果一致"

### 追问与评判

**追问 1：main9 的 align-content: baseline 是什么效果？**

评判：发现概念错误。`baseline` 不是 flex 布局中 `align-content` 的有效取值（align-content 只接受 flex-start / flex-end / center / space-between / space-around / stretch / space-evenly）。`baseline` 属于 align-items / align-self 家族，因为 baseline 对齐的是行内元素的基线，而 align-content 对齐的是行（flex line）整体，行没有基线可对齐。浏览器将无效声明按初始值处理，main9 实际渲染是默认效果（stretch 的表现），学生看到的不是 baseline 效果。

**追问 2：main4 的 stretch 真的拉伸了吗？**

评判：main4 的 item 全部设了固定高度（20/30/50px），此时 stretch 拉不动 item，实际效果等同 flex-start。学生没有观察到这一点。stretch 只在 item 未设交叉轴方向尺寸时才生效。
