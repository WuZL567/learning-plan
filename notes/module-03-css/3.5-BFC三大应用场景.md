# 3.5 BFC 三大应用场景

## 第一部分：一句话说清楚

用一句白话讲出 BFC 的三大应用场景是什么。这里写"BFC 的三大应用场景是……"，一句话讲完，不要展开。要能让你 30 秒内讲给面试官听。

（提示：三大场景分别是"包住浮动解决什么"、"两栏布局防止什么"、"margin 塌陷阻断什么"。一句话里把三个场景都点到。）

1、父元素没设置高度，子元素设置float，导致父元素高度塌陷 - 给父元素创建BFC，解决父元素高度塌陷；
2、相邻兄弟元素，左边元素设置float，右边元素覆盖到左边元素 - 给右边元素创建BFC，解决兄弟元素覆盖；
3、父元素无margin，子元素设置margin，导致父元素位置偏移 - 给父元素创建BFC，解决父元素无margin偏移；

## 第二部分：核心原理

用类比或图解讲清楚。这里写三大场景，每个场景按固定结构写：

### 场景一：包住浮动，解决父元素高度塌陷

1. 现象描述：什么情况下会出现高度塌陷？（父元素有什么特点？子元素做了什么？父元素塌陷后视觉上是什么样？）
父元素无高度样式，无BFC；子元素设置float脱离文档流；父元素高度塌陷导致背景缩成一条线；

2. 手写代码：写一个父元素包浮动子元素、父元素建 BFC 前后的对比代码（HTML + CSS，各写一遍：不建 BFC 塌陷的版本 / 建 BFC 撑开的版本）。
// 创建BFC之前，父元素高度坍塌
<div class="parent">
    <div class="child"></div>
</div>
.parent {
    .child {
        width: 20px;
        height: 20px;
        float: left;
    }
}

// 创建BFC之后，父元素高度正常
<div class="parent">
    <div class="child"></div>
</div>
.parent {
    display: flow-root;
    .child {
        width: 20px;
        height: 20px;
        float: left;
    }
}

3. 为什么有效：用箭头或字符画标出"BFC 计算高度时把内部浮动元素算进去了"这个过程。

───────────────────────── 父元素parent
┌───────┐
│ child │←float: left
│ 20×20 │
└───────┘

// 父元素创建BFC后
┌───────────────────────┐
│ 父元素 parent 高度 20   │
│ ┌───────┐             │
│ │ child │←float: left │
│ │ 20×20 │             │

└───────────────────────┘

### 场景二：自适应两栏布局，防止被浮动元素覆盖

1. 现象描述：左右两栏布局，左栏 float 后，右栏为什么会被左栏压住/重叠？（提示：右栏是普通块级元素，块级元素会怎么和浮动元素相处？）
因为左栏是浮动元素，右栏是普通块级元素，所以这两者相邻会叠加；

2. 手写代码：写一个经典两栏布局——左栏固定宽度 float: left，右栏不设宽度，建 BFC 后自动占满剩余空间。附上不建 BFC 时右栏被压住的对比版本。
// 没有创建右栏BFC，左栏覆盖右栏
<div class="parent">
    <div class="left"></div>
    <div class="right"></div>
</div>
.parent {
    .left {
        width: 20px;
        height: 20px;
        float: left;
    }
    .right {
        height: 20px;
    }
}

// 创建右栏BFC，左栏不再覆盖右栏
<div class="parent">
    <div class="left"></div>
    <div class="right"></div>
</div>
.parent {
    .left {
        width: 20px;
        height: 20px;
        float: left;
    }
    .right {
        display: flow-root;
        height: 20px;
    }
}

3. 为什么有效：为什么右栏建 BFC 后就不会和左栏重叠了？（提示：BFC 之间互不侵犯；右栏从"普通块级元素"变成了什么？）
右栏创建BFC之后不与浮动元素重叠，会自动计算剩余空间为宽度；
为什么不能给父元素创建BFC来解决呢？因为父元素创建BFC后，右栏还是普通块级元素，和左栏的浮动元素还是会叠加，所以必须给右栏创建BFC来解决；

### 场景三：阻断 margin 塌陷穿透

1. 现象描述：子元素设 margin-top，为什么顶的不是自己而是父元素？（提示：父子之间 margin 合并了；谁是最外层？）
因为子元素和父元素之间的margin合并，导致作用点外移，视觉上父元素位置偏移；

2. 手写代码：写一个子元素 margin-top 顶飞父元素的代码，再写父元素建 BFC 后 margin 生效在正确位置的版本。
// 没有BFC，父元素位置向下偏移20px；
<div class="parent">
    <div class="child"></div>
</div>
.parent {
    .child {
        width: 20px;
        height: 20px;
        margin-top: 20px;
    }
}

// 创建BFC，父元素位置正常，子元素上外边距20px，撑起父元素高度为40px；
<div class="parent">
    <div class="child"></div>
</div>
.parent {
    display: flow-root;
    .child {
        width: 20px;
        height: 20px;
        margin-top: 20px;
    }
}

3. 为什么有效：为什么 BFC 能阻止 margin 合并？（提示：合并的前提是"在同一个格式化上下文里"，BFC 把内部和外部切开了；注意兄弟之间的 margin 合并 BFC 管不管——想清楚再写。）
因为创建了BFC之后，它们之间的影响就隔绝了，所以不会在不同BFC之间互相影响；
但是兄弟之间的margin还说会合并，即使创建BFC也一样合并；

## 第三部分：和 XX 的区别或关系

这里写以下对比：

1. 三大场景的共同点：三个场景用的都是"建 BFC"这个动作，它们本质上是同一个原理吗？是哪个原理？为什么说"切的位置不一样"？
是一个原理，创建BFC后，内部样式不会影响到外部的样式；
给不同元素创建BFC，隔绝的位置不一致，有的是父子元素之间，有的是兄弟元素之间；

2. BFC 和 `clear: both`（清除浮动）的区别：清浮动和建 BFC 都能解决高度塌陷，它们解决的方式有什么不同？`clear: both` 是靠什么解决的？BFC 是靠什么解决的？（提示：clear 是"下游自救"，BFC 是"上游圈地"，想想哪个更干净）
clear: both是在浮动元素后的元素或者伪元素上clear，让它换行避开浮动从而撑起父元素；
BFC：父元素把浮动元素包进高度计算中；

3. 三大场景里建的 BFC 各用什么触发条件最合适？写一下你的选择，比如场景一用 `overflow: hidden` 还是 `display: flow-root`？场景二给右栏建 BFC 该用哪个？场景三用哪个？为什么？（提示：想想这些触发条件各自的副作用）
场景一和场景三可以用overflow: hidden或者display: flow-root；场景二则是overflow: hidden；
因为overflow:hidden 会裁剪溢出内容，而flow-root无副作用但是需要考虑浏览器兼容性；

4. 两栏布局中，右栏"建 BFC"和右栏"设 margin-left: 左栏宽度"有什么区别？各有什么优缺点？
有区别，如果左栏宽度变化，后续还得确保没有遗漏右侧的margin-left同时修改；而BFC是将左栏宽度带入计算，计算规则变化，所以不需要单独设置左边距；

## 第四部分：我的理解中不确定的部分

诚实写出没完全搞懂的点。这里写：

1. 你在实际项目里遇到过这三个场景中的哪一个？当时是怎么解决的？用了 BFC 吗？
很少，基本写flex布局；

2. 场景二里，如果右栏不仅想要 BFC 隔离，还想要固定宽度（比如 300px），布局会怎么变？BFC 自适应还会生效吗？
布局不需要变化，BFC的自适应宽度是auto时生效，如果设置固定宽度，则会生效固定宽度；

3. 其他你拿不准的细节（比如：BFC 包住浮动后，浮动元素的高度超长会不会溢出 BFC？三个场景能叠加在同一个元素上吗？）
BFC 有 height/max-height 限制时，浮动内容会溢出或被裁剪；能叠加；
