# 对话记录：3.3 盒模型（标准盒模型 vs IE盒模型）

日期：2026-08-19

## 一、教学过程

**技术点**：3.3 盒模型（标准盒模型 vs IE盒模型），P0，能讲清面试。

### 为什么需要它

盒模型是 CSS 里最底层的地基，但它恰恰是面试最爱挖坑的地方——不是问你知不知道，而是连环追问：**"width 到底管的是哪一段？"** 这一问就能筛掉一批答"width 就是宽度"的候选人。

你写了 5 年 Vue，肯定遇到过这类 bug：给 input 设了 `width: 100%`，结果把父容器撑爆了；或者两个 `width: 50%` 的 div 并排却换行了。这些十有八九都是盒模型在捣乱。面试官问盒模型，其实就是在问**你有没有真的被它坑过、并且搞明白了坑在哪**。

### 一句话说清楚

盒模型是描述一个元素在页面上实际占多大地方的规则，而**标准盒模型和 IE 盒模型的唯一分歧点，就是 width 这个属性到底包不包含 padding 和 border**。

### 核心原理

把元素想成一个快递箱子：

- **标准盒模型（content-box）**：`width` 只管箱子里的**货物**。实际占位 = width + padding（泡沫） + border（纸板厚度）。
- **IE 盒模型（border-box）**：`width` 管**整个箱子**（货物 + 泡沫 + 纸板）。总占位就是 width，泡沫和纸板从里面扣。

举个数：

```css
div {
  width: 100px;
  padding: 20px;
  border: 5px solid #000;
}
```

- `box-sizing: content-box`（默认）：实际宽度 = 100 + 20×2 + 5×2 = **150px**
- `box-sizing: border-box`：实际宽度 = **100px**（content 只剩 100 - 40 - 10 = 50px）

现代项目几乎统一用 `border-box` 全局 reset，就是因为"设多少占多少"符合直觉，改 padding 不会撑爆布局：

```css
* { box-sizing: border-box; }
```

面试的加分点在于说得完整：默认值是 content-box、border-box 下 content 会被压缩、还有 margin 不属于盒模型本身但会影响元素在页面里的总占位。

### 第一层追问（白话复述）

**导师**：用你自己的话，30 秒讲清楚：盒模型是什么？面试官问你 content-box 和 border-box 的区别，你第一句话怎么说？

**学生**：盒模型就是来判断一个元素占位大小的规则，就是说这个元素的width包括哪些部分内容；content-box中，width就是content的宽度，不包括padding+border的宽度；border-box中，width就是content+padding+border的宽度。

**评判**：✅ 通过。核心准确，两次表述都对了（这次没有笔记里的错误）。补充点：答 content-box 时最好把"实际占位"说全——content-box 下 width 只代表 content 宽，元素实际占位是 width + padding + border，这正是它撑爆布局的原因。面试回答要多一个"实际占位多大"的维度。

### 第二层追问（对比理解）

**导师**：1. margin 在两种盒模型下有区别吗？margin 算不算盒模型的一部分？2. 追加：子元素的 margin 会怎么影响父容器？例：

```html
<div style="background: red;">   <!-- 父容器，没设高度 -->
  <div style="margin-top: 50px;">子元素</div>
</div>
```

父容器这个红色区域，你觉得子元素的 margin-top 会被包含进去吗？为什么？

**学生**：没有区别，不算盒模型的部分；会影响父容器，例子中的子元素的margin-top会撑开父容器的高度，具体原因我不知道，是不是定位的原因。

**评判**：⚠️ 第一个对（两种盒模型下 margin 都一样，不算盒模型的一部分），第二个答反了——子元素 margin-top **不会撑开**父容器，反而发生 **margin 塌陷（margin 折叠）**，margin 直接"穿出"父容器把父容器往下推。

**正确解答**：父容器像一间房子，子元素是房里的桌子。桌子的 margin-top 像桌子往墙上撞——墙不会被撞高，桌子只会把自己推离墙。如果房子四壁很薄（父容器没有 padding、border、高度），桌子这一撞直接穿墙，把整间房子往后推。CSS 术语：**垂直方向的 margin 会折叠**，子元素 margin-top 和父元素自身 margin-top 合并取较大值。实际效果：红色区域高度只包住子元素本身，50px 的 margin 在红色区域外面，把整个红块往下推了 50px。

修复方法：① 父容器加 `overflow: hidden`（创建 BFC，margin 不穿出去）；② 父容器改 flex/grid 布局（flex 容器内 margin 不折叠）。这衔接下一个技术点 3.4 BFC 触发条件。

### 第三层追问（场景应用）

**导师**（模拟面试）：
> 你写过一个搜索框吗？代码是这样的：
> ```css
> .search-input {
>   width: 100%;
>   padding: 10px;
> }
> ```
> 它把父容器撑爆了。你现在打开 DevTools，怎么一步步排查？**原因**是什么？**改成什么**能修好？

**学生**：首先看input有没有默认盒模型的样式，如果没有则写入盒模型box-sizing为border-box来看是否问题解决，解决后看是否需要全局设置这些基本元素的box-sizing为border-box；也可以先去掉padding的样式，看是否恢复正常，如果是则是盒模型的问题，处理方式同上。

**评判**：✅ 通过。定位方向对（input 默认 content-box，width:100% 是相对父容器 content 宽度，padding 加在外面 100%+20px 当然超了）；二分法排查（去掉 padding 看是否恢复）是 DevTools 经典手法，加分；修复方案对，还想到全局 reset。
