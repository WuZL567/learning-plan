# 3.4 BFC 触发条件

## 第一部分：一句话说清楚

用一句白话解释 BFC 是什么。这里写"BFC 是……"，一句话讲完，不要展开。要能让你 30 秒内讲给面试官听。

BFC叫块级格式化上下文，就是在BFC的元素内，元素内部和元素外部不会互相影响；

## 第二部分：核心原理

用类比或图解讲清楚。这里写：

1. 默写 BFC 的触发条件，**至少 5 种以上**，每条写清楚具体写法。用表格或列表整理。

（提示：从 html 根元素、float、position、display、overflow 这几大类去想，每一类"不是默认值"就能触发。display 类有多个值，能写几个写几个。）

html：根元素自带BFC；
float: left;
position: absolute/fixed;
display: flex/inline-flex/grid/flow-root;
overflow: hidden/auto/scroll;

2. 用你自己的类比讲一下：为什么 BFC 内部的东西不会影响外部？（提示：想想"小国家的海关"——浮动分子出不了国、邻国的人进不来、国内的风波传不出去。你用自己的话复述，不要抄。）
就像是一层房子的一间卧室，你再怎么修改你的房间布局效果，都不会影响整层房子；

3. 画一个图解：一个 div 内部有一个 float 的子元素，父 div 建了 BFC 后，高度塌陷问题为什么就解决了？用字符画或箭头标出来。
父元素不是BFC时，子元素float会浮动，脱离父元素文本流，也就不在父元素内了；
而创建父元素为BFC之后，BFC 计算自身高度时会把内部的浮动子元素算进去（BFC 包住内部浮动），所以父元素高度被撑开。浮动元素从头到尾都是浮动的，变的是父元素的计算规则；

## 第三部分：和 XX 的区别或关系

这里写以下对比：

1. BFC 和"父元素高度塌陷"的关系：float 子元素为什么会让父元素高度为 0？父元素建 BFC 后为什么就好了？
因为子元素浮动会脱离父元素文本流，父元素内不存在子元素，所以父元素就高度塌陷，导致高度为0；
而父元素创建BFC之后，BFC 计算自身高度时会把内部的浮动子元素算进去（BFC 包住内部浮动），所以父元素高度被撑开。浮动元素从头到尾都是浮动的，变的是父元素的计算规则；

2. `overflow: hidden` 到底是"触发 BFC"还是"裁剪内容"？如果一个元素同时想滚动又要建 BFC，该用什么？（提示：overflow 是手段，不是目的；想想 overflow: auto 和 overflow: hidden 的区别）
既触发了BFC又裁剪内容；
可以继续用overflow: auto或者overflow: scroll；只要不是overflow: visible；

3. BFC 和 IFC、FFC、GFC 的关系：你知道这几类格式化上下文是什么吗？flex 容器算不算 BFC？
BFC：块级格式化上下文（block）；
IFC：行内格式化上下文（inline）；
FFC：flex格式化上下文（flex）；
GFC：grid格式化上下文（grid）；
flex容器算FFC；

4. 对比"用 overflow: hidden 建 BFC"和"用 display: flow-root 建 BFC"：flow-root 有什么优势？为什么它是专门为建 BFC 设计的属性？
我猜测应该是这个display: flow-root不会有其他的功能，是纯粹的创建BFC的样式，所以你还可以用overflow的其他属性来使用。

## 第四部分：我的理解中不确定的部分

诚实写出没完全搞懂的点。这里写：

1. 你在实际项目里有没有遇到过 BFC 相关的 bug？当时是怎么定位到的？用了哪个触发条件解决的？
很少有，毕竟写业务时大部分是flex布局；

2. 有没有想过：position: relative 算不算 BFC 触发条件？为什么不算？（想不通就写下来，我来解答）
不算。因为relative的元素仍在文档流中，布局环境没变化，触发BFC的position是absolute和fixed，脱离文档流，所以还在文档流的元素不算触发BFC；

3. 其他你拿不准的细节（比如 display: flex 容器内部的 float 会怎样、BFC 会不会被嵌套、两个 BFC 相邻会怎样）。
flex布局中float不会生效；
BFC可以嵌套；
两个BFC相邻时，外边距margin依旧合并；

没有不确定的点也要至少写一个"测试验证想法"（比如"我想验证 overflow: hidden 和 overflow: auto 是否都能包住浮动"），写了才能验证你的理解。
