### 3.11-3.13 教学（合并）

为什么需要它：面试必考"水平垂直居中"多方案，旧浏览器兼容 + 面试变体 + 参照物理解。

一句话说清楚：父元素 relative，子元素 absolute + top/left:50% + translate(-50%,-50%)——先用 50% 把左上角移到容器中心，再退回自身一半。

核心原理：两个 50% 参照物不同——top/left 百分比参照父容器，translate 百分比参照子元素自身。类比：站在操场正中央（绝对定位），再后退半个身位（transform）。不用 margin 负值法的原因：translate 百分比相对自身，子元素尺寸变化不用改代码。

三种方案对比表：
- 方案二（3.11）：absolute + top/left:50% + translate(-50%,-50%)。子元素尺寸随便变，但 transform 创建新层叠上下文。
- 方案三（3.12）：absolute + inset:0 + margin:auto。inset:0 把四边钉在容器边缘，剩余空间被 margin:auto 平分。子元素必须有确定尺寸。
- 方案四（3.13）：grid + place-items:center。place-items = align-items + justify-items 简写。最简洁，老浏览器兼容差。

### 3.14 教学

为什么需要它：5 年前端必遇到样式被覆盖的 bug；面试 80% 考算优先级。

一句话说清楚：四位计数 (内联, ID, 类·属性·伪类, 类型·伪元素)，逐位比较，先大先赢，不进位。

核心原理：官衔类比——内联是皇帝、ID 是局长、类/伪类是科长、类型/伪元素是科员，10 个科员打不过 1 个局长。规则：逐位比较；:not() 本身 0 权重括号内照计；!important 凌驾一切包括内联。

## 二、验收过程

### 3.11-3.13 首次验收（评分 7.5，打回）

学生提交：三个方案代码全部跑通居中。方案二注释质量高（参照物讲清、容器不设 position 的边界答对）。

扣分项：
1. 方案三 margin:auto 机制理解错误（-1.5）：学生注释写"margin 是基于自身的外边距，也就是和父级的距离"——错误。margin:auto 是自动平分剩余空间，不是固定距离。且学生自己注释标注"inset为0表示什么？"（诚实但未答出必答问题）。
2. 方案四缺简写说明（-0.5）：未说明 place-items = align-items + justify-items。
3. inset:0 作用未讲清（-0.5）。

修改要求：
- inset:0 = top:0; right:0; bottom:0; left:0 简写，四边钉在容器边缘
- margin:auto 平分剩余空间（容器尺寸−子元素尺寸，上下左右各一半）
- 与普通文档流区别：普通文档流水平方向有剩余空间可平分（margin:0 auto 水平居中），垂直方向高度被内容撑满无剩余空间，所以垂直不居中；absolute+inset:0 制造了垂直剩余空间
- 方案四注释补简写关系

### 3.11-3.13 二次验收（评分 9，通过）

修改确认：inset:0 注释正确 ✅；margin:auto"自动平分剩余空间" ✅；place-items 简写关系 ✅。

剩余小瑕疵（不计扣分）：普通文档流对比点没写全（面试被追问要能说出）；方案四用展开写法（align-items+justify-items）而非 place-items 简写本身——面试手写写简写版更利落。

### 3.14 首次验收（评分 7.5，打回）

学生提交笔记。大部分规则对（逐位不进位、!important、:not、通配符、层叠对比），但有硬伤：

扣分项：
1. 四位分类错误（-1.5）：学生把分类写成"内联 → ID → class/元素/伪类 → type/伪元素"——元素选择器不属于第三级。正确：第三级是类·属性·伪类；第四级是类型（div、p）·伪元素（::before）。因分类错导致两个例子全算错：#app .box p 学生算 (0,1,2,0) 实际 (0,1,1,1)；div .nav a:hover 学生算 (0,0,3,0) 实际 (0,0,2,2)。
2. 伪类 vs 伪元素混淆（-0.5）：:hover 是伪类不是伪元素，与 .active 同级（第三级），权重一样大，看层叠顺序。真正差一级的是 ::before/::after。
3. 白话复述偏浅（-0.5）：没说出四位计数、逐位比较核心机制。

修改要求：修正分类、重算两个例子、修正 :hover vs .active 答案。

### 3.14 二次验收（评分 9.8，通过）

修改确认：分类修正 ✅（元素归入第四级）；例子算对 (0,1,1,1) 和 (0,0,2,2) ✅；:hover vs .active 改为"一样大，都是第三级，看加载顺序" ✅；白话复述补上四位计数+逐位比较 ✅。

小提醒（不计扣分）：第 43 行"class/类型[type=xxx]"的"类型"应叫"属性选择器"（[type=xxx] 的正式名称），避免与"类型选择器"混淆。

### 三层追问（3.14，学生书面作答）

1. 白话复述：30 秒讲清 CSS 优先级是什么
   学生答：判断哪些样式生效哪些被覆盖的规则，按四位计数逐位对比。
   评判：✅ 通过。二次提交补齐了核心机制（四位计数、逐位对比）。

2. 对比理解：优先级和层叠是一回事吗？
   学生答：不是一回事。优先级是不同权重之间的优先关系，层叠是相同权重下后加载的覆盖前面的。

   学生答：先注释蓝色样式看红色是否生效，再比较两个选择器的权重；或直接给红色加 !important 验证。
