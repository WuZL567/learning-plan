## 核心策略：5 个套路

1. **Embedding 向量化** → 把文字变成一组数字（向量），语义相近的文字，数字也相近
2. **RAG 检索增强生成** → 先从你的文档里找到相关内容，再让 AI 基于这些内容回答
3. **LangGraph 状态图** → 用"节点+箭头"画出 AI 的工作流程，每个节点做一件事
4. **人工介入** → 在 AI 工作流程中插入"暂停等人确认"的节点
5. **多 Agent 协作** → 多个 AI 各司其职，像一个团队一样协作完成任务

## Demo 1：Embedding 入门 — 把文字变成数字向量

### 学习目标

- 理解什么是 Embedding（向量化）
- 理解"语义相似度"的概念
- 动手把句子变成向量，计算相似度

### 1.1 什么是 Embedding

~~~
Embedding = 把文字变成一组数字（向量）

"宫保鸡丁"  → [0.12, -0.34, 0.56, ..., 0.78]  （1536 个数字）
"鱼香肉丝"  → [0.11, -0.32, 0.54, ..., 0.76]  （语义相近，数字也相近）
"今天天气好" → [0.89, 0.23, -0.67, ..., 0.12]  （语义不同，数字差很远）

核心特性：
  语义相近的文字 → 向量距离近
  语义不同的文字 → 向量距离远

这就是 RAG 的基础：
  1. 把你的文档切成小块，每块变成向量，存起来
  2. 用户提问时，把问题也变成向量
  3. 找到和问题向量最"近"的文档块
  4. 把这些文档块和问题一起发给 AI
~~~

### 1.2 动手实验

创建文件 `demo1_Embedding.py`：

~~~python
# ========== demo1_Embedding.py
# 把文字变成向量，计算语义相似度

from openai import OpenAI
from dotenv import load_dotenv
import os
import numpy as np

load_dotenv()

客户端 = OpenAI(
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL"),
)


def 获取向量(文本: str) -> list[float]:
    """把一段文字变成向量（一组数字）"""
    响应 = 客户端.embeddings.create(
        model="text-embedding-ada-002",  # OpenAI 的 Embedding 模型
        input=文本,
    )
    return 响应.data[0].embedding


def 计算相似度(向量A: list[float], 向量B: list[float]) -> float:
    """计算两个向量的余弦相似度（-1到1，越大越相似）"""
    A = np.array(向量A)
    B = np.array(向量B)
    return float(np.dot(A, B) / (np.linalg.norm(A) * np.linalg.norm(B)))


# ========== 实验1：语义相近的句子，向量也相近
print("=== 实验1：语义相似度 ===\n")

句子们 = [
    "宫保鸡丁是一道川菜",
    "宫保鸡丁的做法",
    "红烧肉怎么做好吃",
    "今天天气真不错",
    "Python 和 JavaScript 哪个好学",
]

向量们 = {}
for 句子 in 句子们:
    向量们[句子] = 获取向量(句子)
    print(f"  \"{句子}\" → 向量维度: {len(向量们[句子])}，前5个数: {[round(x, 4) for x in 向量们[句子][:5]]}")

print("\n=== 相似度矩阵 ===\n")

# 计算每对句子之间的相似度
目标句子 = "宫保鸡丁是一道川菜"
print(f"与 \"{目标句子}\" 的相似度：")
for 句子 in 句子们:
    if 句子 != 目标句子:
        相似度 = 计算相似度(向量们[目标句子], 向量们[句子])
        条 = "⭐" if 相似度 > 0.85 else "  "
        print(f"  {条} {相似度:.4f}  \"{句子}\"")


# ========== 实验2：菜品知识库检索模拟
print("\n\n=== 实验2：模拟 RAG 检索 ===\n")

# 模拟文档库（每个文档块）
文档库 = [
    "宫保鸡丁是经典川菜，主料鸡肉丁和花生，口味麻辣鲜香，价格38元。",
    "鱼香肉丝用猪肉丝、木耳、胡萝卜丝炒制，口味酸甜微辣，价格28元。",
    "麻婆豆腐是四川名菜，用嫩豆腐和牛肉末，麻辣烫鲜嫩，价格22元。",
    "本店营业时间：上午11点到晚上10点，周末提前到10点开门。",
    "停车场在餐厅后面，可容纳50辆车，消费满200元免费停车2小时。",
    "会员制度：消费满500元自动升级银卡会员，享受9折优惠。",
    "红烧肉选用五花肉慢炖2小时，入口即化，甜咸适中，价格45元。",
]

# 把文档块变成向量
文档向量 = [(文, 获取向量(文)) for 文 in 文档库]

# 用户提问
用户问题 = "有什么辣的菜推荐？"
问题向量 = 获取向量(用户问题)

print(f"用户问题: \"{用户问题}\"\n")
print("检索结果（按相似度排序）：")

# 计算问题和每个文档块的相似度
检索结果 = []
for 文档, 向量 in 文档向量:
    相似度 = 计算相似度(问题向量, 向量)
    检索结果.append((相似度, 文档))

# 按相似度降序排列
检索结果.sort(reverse=True)

for 排名, (相似度, 文档) in enumerate(检索结果, 1):
    标记 = "✅ 命中" if 排名 <= 3 else "   "
    print(f"  {标记} [{相似度:.4f}] {文档}")

print("\n→ 取前3条作为上下文，发给 AI 生成回答（这就是 RAG！）")
~~~

### 2.2 实现完整 RAG

创建文件 `demo2_RAG全流程.py`：

~~~python
# ========== demo2_RAG全流程.py
# 完整的 RAG 流程：加载文档 → 切块 → 向量化 → 存入向量库 → 检索 → AI 生成回答

from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_community.vectorstores import Chroma
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import DirectoryLoader, TextLoader
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough
from dotenv import load_dotenv
import os

load_dotenv()


# ========== 第一步：加载文档
print("📁 第一步：加载文档...")

加载器 = DirectoryLoader(
    "知识库/",                    # 文档目录
    glob="**/*.txt",              # 加载所有 .txt 文件
    loader_cls=TextLoader,        # 用文本加载器
    loader_kwargs={"encoding": "utf-8"},
)
文档列表 = 加载器.load()
print(f"  加载了 {len(文档列表)} 个文档")
for 文档 in 文档列表:
    print(f"  - {文档.metadata['source']}: {len(文档.page_content)} 字符")


# ========== 第二步：文本切块
print("\n✂️ 第二步：文本切块...")

切块器 = RecursiveCharacterTextSplitter(
    chunk_size=200,        # 每块最多200个字符
    chunk_overlap=50,      # 相邻块重叠50个字符（保证上下文连贯）
    separators=["\n\n", "\n", "。", "，", " "],  # 切分优先级：先按段落，再按句子
    length_function=len,
)

文档块 = 切块器.split_documents(文档列表)
print(f"  切成了 {len(文档块)} 个文档块")
for i, 块 in enumerate(文档块[:3]):
    print(f"  块{i+1}: {块.page_content[:60]}...")
print(f"  ... 共 {len(文档块)} 块")


# ========== 第三步：向量化 + 存入向量数据库
print("\n🔢 第三步：向量化并存入 ChromaDB...")

Embedding模型 = OpenAIEmbeddings(
    model="text-embedding-ada-002",
)

# 创建向量数据库（会自动调用 Embedding 模型把每个文档块变成向量）
向量库 = Chroma.from_documents(
    documents=文档块,
    embedding=Embedding模型,
    persist_directory="./向量数据库",   # 持久化到本地文件
    collection_name="餐厅知识库",
)
print(f"  ✅ 已存入 {len(文档块)} 个向量")


# ========== 第四步：创建检索器
print("\n🔍 第四步：创建检索器...")

检索器 = 向量库.as_retriever(
    search_type="similarity",   # 相似度检索
    search_kwargs={"k": 3},     # 返回最相似的3个文档块
)
print("  ✅ 检索器创建完成")


# ========== 第五步：构建 RAG 链
print("\n🔗 第五步：构建 RAG 链...")

# 定义 Prompt 模板
RAG提示词 = ChatPromptTemplate.from_template("""
你是"川味小馆"的 AI 助手。请基于以下参考资料回答用户的问题。

## 规则
- 只基于参考资料回答，不要编造信息
- 如果参考资料中没有相关信息，请明确说"抱歉，我没有找到相关信息"
- 回答简洁友好
- 在回答末尾标注信息来源（来自哪个文档）

## 参考资料
{context}

## 用户问题
{question}

## 回答
""")

# 初始化 AI 模型
模型 = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# 格式化文档块为字符串
def 格式化文档(docs):
    return "\n\n".join([f"[来源: {d.metadata['source']}]\n{d.page_content}" for d in docs])

# 构建 RAG 链
RAG链 = (
    {"context": 检索器 | 格式化文档, "question": RunnablePassthrough()}
    | RAG提示词
    | 模型
    | StrOutputParser()
)
print("  ✅ RAG 链构建完成")


# ========== 第六步：提问！
print("\n" + "=" * 60)
print("🤖 RAG 问答系统已就绪！输入问题测试，输入 'q' 退出\n")

while True:
    问题 = input("👤 你的问题: ").strip()
    if 问题.lower() == 'q':
        break
    if not 问题:
        continue

    # 调用 RAG 链
    回答 = RAG链.invoke(问题)
    print(f"\n🤖 AI: {回答}\n")

    # 显示检索到的原文（调试用）
    检索到的文档 = 检索器.invoke(问题)
    print("📎 检索到的参考资料：")
    for i, 文档 in enumerate(检索到的文档, 1):
        print(f"  [{i}] ({文档.metadata['source']}) {文档.page_content[:80]}...")
    print()
~~~

~~~python
# ========== demo3_RAG优化.py
# RAG 优化技巧：重排序 + 引用来源追踪

from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_community.vectorstores import Chroma
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough
from dotenv import load_dotenv
import os
import json

load_dotenv()


# ========== 加载已有的向量数据库（Demo 2 已经创建好的）
Embedding模型 = OpenAIEmbeddings(model="text-embedding-ada-002")

向量库 = Chroma(
    persist_directory="./向量数据库",
    embedding_function=Embedding模型,
    collection_name="餐厅知识库",
)


# ========== 优化1：多重检索 + 重排序
class 带重排序的检索器:
    """
    先用向量检索多一些候选（如 top 10）
    再用 AI 对候选进行重排序，选出真正相关的 top 3
    这样比单纯向量检索更准确
    """

    def __init__(self, 向量数据库, 模型, 候选数=6, 最终数=3):
        self.向量数据库 = 向量数据库
        self.模型 = 模型
        self.候选数 = 候选数
        self.最终数 = 最终数

    def invoke(self, 问题: str):
        # 第一轮：向量检索获取更多候选
        候选文档 = self.向量数据库.similarity_search(问题, k=self.候选数)

        if len(候选文档) <= self.最终数:
            return 候选文档

        # 第二轮：让 AI 重排序（评估每个候选和问题的相关性）
        候选文本 = "\n".join([
            f"[{i+1}] {doc.page_content}"
            for i, doc in enumerate(候选文档)
        ])

        重排提示 = f"""对以下文档片段，按与问题的相关性打分（1-10分）。
只输出JSON数组，格式: [{{"编号": 1, "分数": 8, "原因": "简要原因"}}]

问题: {问题}

文档片段:
{候选文本}"""

        回复 = self.模型.invoke([{"role": "user", "content": 重排提示}])
        分数文本 = 回复.content

        try:
            # 解析 AI 的评分
            import re
            # 尝试提取 JSON
            json_match = re.search(r'$$.*$$', 分数文本, re.DOTALL)
            if json_match:
                评分列表 = json.loads(json_match.group())
                评分列表.sort(key=lambda x: x.get("分数", 0), reverse=True)
                选出的编号 = [项["编号"] - 1 for 项 in 评分列表[:self.最终数]]
                return [候选文档[i] for i in 选出的编号 if i < len(候选文档)]
        except Exception:
            pass

        # 解析失败就用原始向量排序的前 N 个
        return 候选文档[:self.最终数]


# ========== 优化2：引用来源追踪的 RAG
class 带引用的RAG:
    """每次回答都标注信息来源"""

    def __init__(self):
        self.模型 = ChatOpenAI(model="gpt-4o-mini", temperature=0)
        self.检索器 = 带重排序的检索器(向量库, self.模型)

        self.提示词 = ChatPromptTemplate.from_template("""
你是"川味小馆"的 AI 助手。

## 规则
- 严格基于参考资料回答
- 在回答中用 [来源1] [来源2] 标注信息来源
- 如果参考资料中没有相关信息，直接说"抱歉，没有找到相关信息"
- 回答简洁，不超过5句话

## 参考资料
{context}

## 用户问题
{question}

## 回答（请标注来源）
""")

    def 提问(self, 问题: str) -> dict:
        # 1. 检索相关文档
        相关文档 = self.检索器.invoke(问题)

        # 2. 格式化上下文（带编号）
        上下文列表 = []
        for i, 文档 in enumerate(相关文档, 1):
            上下文列表.append(
                f"[来源{i}: {文档.metadata['source']}]\n{文档.page_content}"
            )
        上下文 = "\n\n".join(上下文列表)

        # 3. 让 AI 生成回答
        回复 = self.模型.invoke(
            self.提示词.format_messages(context=上下文, question=问题)
        )

        # 4. 返回结构化结果
        return {
            "问题": 问题,
            "回答": 回复.content,
            "参考资料": [
                {
                    "编号": i+1,
                    "来源": 文档.metadata["source"],
                    "内容": 文档.page_content,
                }
                for i, 文档 in enumerate(相关文档)
            ],
        }


# ========== 测试

    "会员有什么优惠？",
~~~

## Demo 4：LangGraph 入门 — 用状态图编排 AI 工作流

### 学习目标

- 理解 LangGraph 的核心概念：状态、节点、边
- 用状态图实现一个简单的 AI 工作流
- 理解 LangGraph 和 LangChain 的关系

### 4.1 核心概念

~~~
LangGraph = 用"有向图"编排 AI 的工作流程

类比理解：
  LangChain  →  一条流水线（线性的：A → B → C）
  LangGraph  →  一张流程图（可以有分支、循环、条件判断）

核心概念：

1. State（状态）：工作流中传递的数据
   → 类比：流水线上每个工位都能看到的"工作单"
   → 就像一个 dict，在节点之间传递和更新

2. Node（节点）：每个处理步骤
   → 类比：流水线上的每个工位
   → 就是一个函数，接收状态，返回更新后的状态

3. Edge（边）：节点之间的连接
   → 类比：传送带，把产品从一个工位传到下一个
   → 可以是固定连接，也可以是条件分支

4. Conditional Edge（条件边）：根据条件决定走哪条路
   → 类比：质检工位，合格走左边，不合格走右边

图示：
  ┌────────┐     ┌────────┐     ┌────────┐
  │ 开始    │ →  │ 分析    │ →  │ 回答    │
  └────────┘     └────┬───┘     └────────┘
                      │
                 需要工具？
                    ╱  ╲
                  是     否
                  ↓       ↓
            ┌────────┐    │
            │ 调工具  │    │
            └────┬───┘    │
                 ↓        ↓
            ┌────────┐
            │ 综合    │ → 最终回答
            └────────┘
~~~

~~~python
# ========== demo4_LangGraph入门.py
# 用 LangGraph 实现一个简单的 AI 客服工作流

from langgraph.graph import StateGraph, END
from openai import OpenAI
from dotenv import load_dotenv
import os
import json
from typing import TypedDict, Literal

load_dotenv()

客户端 = OpenAI(
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL"),
)


# ========== 第一步：定义状态（State）
# 状态 = 在节点之间传递的数据
# 就像一个"工作单"，每个节点都能读取和修改
class 客服状态(TypedDict):
    用户消息: str           # 用户说的话
    意图: str               # 识别出的意图（点餐/查询/投诉/闲聊）
    工具结果: str           # 工具返回的结果
    回答: str               # AI 最终回答
    步骤记录: list[str]     # 记录经过了哪些步骤（调试用）


# ========== 第二步：定义节点（Node）
# 每个节点就是一个函数，接收状态，返回部分更新

def 意图识别(状态: 客服状态) -> dict:
    """节点1：识别用户意图"""
    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": """分析用户消息的意图，只输出以下之一：
- 点餐：用户想要点菜或下单
- 查询：用户询问菜品、价格、营业时间等信息
- 投诉：用户不满意要投诉
- 闲聊：用户在闲聊"""},
            {"role": "user", "content": 状态["用户消息"]},
        ],
        temperature=0,
    )
    意图 = 回复.choices[0].message.content.strip()
    print(f"  🔍 意图识别: {意图}")

    return {
        "意图": 意图,
        "步骤记录": 状态.get("步骤记录", []) + [f"意图识别: {意图}"],
    }


def 处理点餐(状态: 客服状态) -> dict:
    """节点2a：处理点餐请求"""
    菜品库 = "宫保鸡丁38元、鱼香肉丝28元、麻婆豆腐22元、红烧肉45元、米饭3元"

    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": f"你是餐厅点餐助手。菜单：{菜品库}。帮顾客确认点餐内容和总价。回复简洁。"},
            {"role": "user", "content": 状态["用户消息"]},
        ],
        temperature=0.7,
    )

    return {
        "回答": 回复.choices[0].message.content,
        "步骤记录": 状态.get("步骤记录", []) + ["处理点餐"],
    }


def 处理查询(状态: 客服状态) -> dict:
    """节点2b：处理查询请求（模拟调用知识库）"""
    知识库 = {
        "营业时间": "上午11:00至晚上22:00，周末10:00开门",
        "停车": "后方停车场50车位，消费满200免费停2小时",
        "会员": "银卡9折（满500），金卡8.5折（满2000）",

    # 简单的关键词匹配（实际项目用 RAG）
    找到的信息 = []
    for 关键词, 信息 in 知识库.items():

            找到的信息.append(f"{关键词}：{信息}")

    if not 找到的信息:
        找到的信息 = ["暂无相关信息，请拨打0755-8888-8888咨询"]

    return {
        "工具结果": "\n".join(找到的信息),
        "步骤记录": 状态.get("步骤记录", []) + [f"查询结果: {找到的信息}"],
    }


def 生成查询回答(状态: 客服状态) -> dict:
    """节点2b续：基于查询结果生成回答"""
    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "你是餐厅客服，基于以下信息回答顾客问题，回复简洁：\n" + 状态["工具结果"]},
            {"role": "user", "content": 状态["用户消息"]},
        ],
        temperature=0.7,
    )

    return {
        "回答": 回复.choices[0].message.content,
        "步骤记录": 状态.get("步骤记录", []) + ["生成查询回答"],
    }


def 处理投诉(状态: 客服状态) -> dict:
    """节点2c：处理投诉"""
    return {
        "回答": "非常抱歉给您带来不好的体验！我已经记录了您的反馈，会立即转告经理。请问方便留下您的联系方式吗？我们会尽快给您回复。",
        "步骤记录": 状态.get("步骤记录", []) + ["处理投诉"],
    }


def 处理闲聊(状态: 客服状态) -> dict:
    """节点2d：处理闲聊"""
    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "你是餐厅客服，友好地闲聊，但尽量引导到点餐话题。回复1-2句话。"},
            {"role": "user", "content": 状态["用户消息"]},
        ],
        temperature=0.7,
    )

    return {
        "回答": 回复.choices[0].message.content,
        "步骤记录": 状态.get("步骤记录", []) + ["处理闲聊"],
    }


# ========== 第三步：定义条件边（Conditional Edge）
def 路由到处理节点(状态: 客服状态) -> str:
    """根据意图决定走哪条路"""
    意图 = 状态["意图"]
    if "点餐" in 意图:
        return "处理点餐"
    elif "查询" in 意图:
        return "处理查询"
    elif "投诉" in 意图:
        return "处理投诉"
    else:
        return "处理闲聊"


# ========== 第四步：构建状态图
print("🔧 构建 LangGraph 工作流...\n")

图 = StateGraph(客服状态)

# 添加节点
图.add_node("意图识别", 意图识别)
图.add_node("处理点餐", 处理点餐)
图.add_node("处理查询", 处理查询)
图.add_node("生成查询回答", 生成查询回答)
图.add_node("处理投诉", 处理投诉)
图.add_node("处理闲聊", 处理闲聊)

# 设置入口
图.set_entry_point("意图识别")

# 添加条件边：意图识别 → 根据意图分流
图.add_conditional_edges(
    "意图识别",        # 从哪个节点出发
    路由到处理节点,    # 路由函数
    {
        "处理点餐": "处理点餐",
        "处理查询": "处理查询",
        "处理投诉": "处理投诉",
        "处理闲聊": "处理闲聊",
    },
)

# 查询需要两步：先查知识库，再生成回答
图.add_edge("处理查询", "生成查询回答")

# 所有处理节点都到 END
图.add_edge("处理点餐", END)
图.add_edge("生成查询回答", END)
图.add_edge("处理投诉", END)
图.add_edge("处理闲聊", END)

# 编译
客服工作流 = 图.compile()
print("✅ 工作流构建完成！\n")


# ========== 第五步：运行
测试消息 = [
    "我想点两份宫保鸡丁和一碗米饭",
    "你们几点关门？",

    "今天心情不错",
]

for 消息 in 测试消息:
    print(f"{'='*50}")
    print(f"👤 用户: {消息}")

    结果 = 客服工作流.invoke({
        "用户消息": 消息,
        "意图": "",
        "工具结果": "",
        "回答": "",
        "步骤记录": [],
    })

    print(f"🤖 回答: {结果['回答']}")
    print(f"📝 步骤: {' → '.join(结果['步骤记录'])}")
    print()
~~~

- Node（节点）= 处理函数，接收状态返回更新
- Edge（边）= 节点间的连接，可以是固定或条件分支
- `StateGraph` 构建图 → `add_node` 添加节点 → `add_conditional_edges` 条件分支 → `compile()` 编译

### 5.1 人工介入

创建文件 `demo5_人工介入.py`：

~~~python
# ========== demo5_人工介入.py
# 在 AI 工作流中插入"暂停等人确认"的节点
# 场景：AI 推荐了菜品，需要用户确认才下单

from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver
from openai import OpenAI
from dotenv import load_dotenv
import os
import json
from typing import TypedDict

load_dotenv()

客户端 = OpenAI(
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL"),
)


class 点餐状态(TypedDict):
    用户消息: str
    推荐菜品: str          # AI 推荐的菜品
    用户确认: str          # 用户确认结果（同意/修改/取消）
    最终订单: str          # 最终确认的订单
    步骤: list[str]


def 推荐菜品(状态: 点餐状态) -> dict:
    """节点1：AI 推荐菜品"""
    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "你是餐厅助手，根据顾客需求推荐菜品。菜单：宫保鸡丁38元、鱼香肉丝28元、麻婆豆腐22元、红烧肉45元、米饭3元。推荐2-3道菜并说明理由和总价。"},
            {"role": "user", "content": 状态["用户消息"]},
        ],
        temperature=0.7,
    )

    推荐 = 回复.choices[0].message.content
    print(f"\n🤖 AI 推荐:\n{推荐}")

    return {
        "推荐菜品": 推荐,
        "步骤": ["AI推荐"],
    }


def 等待确认(状态: 点餐状态) -> dict:
    """节点2：人工介入 — 等待用户确认"""
    # 这个节点会暂停工作流，等待外部输入
    # interrupt() 会暂停执行，把当前状态保存下来
    # 等用户确认后，再从这里恢复执行
    print("\n⏸️  等待您确认...")
    print("  输入 '确认' 下单")
    print("  输入 '修改:xxx' 调整")
    print("  输入 '取消' 放弃")

    # 注意：在 LangGraph 中用 interrupt() 实现暂停
    # 这里用简化的模拟方式
    用户输入 = input("\n👤 您的选择: ").strip()

    return {
        "用户确认": 用户输入,
        "步骤": ["等待确认"],
    }


def 处理确认结果(状态: 点餐状态) -> str:
    """条件路由：根据用户确认决定下一步"""
    确认 = 状态["用户确认"]
    if "确认" in 确认:
        return "下单成功"
    elif "修改" in 确认:
        return "重新推荐"
    else:
        return "取消订单"


def 下单成功(状态: 点餐状态) -> dict:
    """节点3a：下单成功"""
    return {
        "最终订单": 状态["推荐菜品"],
        "步骤": ["✅ 下单成功"],
    }


def 重新推荐(状态: 点餐状态) -> dict:
    """节点3b：根据修改意见重新推荐"""
    修改意见 = 状态["用户确认"].replace("修改:", "")

    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "你是餐厅助手，根据修改意见调整推荐。菜单：宫保鸡丁38元、鱼香肉丝28元、麻婆豆腐22元、红烧肉45元、米饭3元。"},
            {"role": "user", "content": f"之前的推荐：{状态['推荐菜品']}\n\n修改意见：{修改意见}"},
        ],
        temperature=0.7,
    )

    新推荐 = 回复.choices[0].message.content
    print(f"\n🤖 调整后的推荐:\n{新推荐}")

    return {
        "推荐菜品": 新推荐,
        "步骤": ["重新推荐"],
    }


def 取消订单(状态: 点餐状态) -> dict:
    """节点3c：取消订单"""
    return {
        "最终订单": "已取消",
        "步骤": ["❌ 取消订单"],
    }


# ========== 构建工作流
图 = StateGraph(点餐状态)

图.add_node("推荐菜品", 推荐菜品)
图.add_node("等待确认", 等待确认)
图.add_node("下单成功", 下单成功)
图.add_node("重新推荐", 重新推荐)
图.add_node("取消订单", 取消订单)

图.set_entry_point("推荐菜品")

# 推荐完 → 等确认
图.add_edge("推荐菜品", "等待确认")

# 确认后 → 条件路由
图.add_conditional_edges(
    "等待确认",
    处理确认结果,
    {
        "下单成功": "下单成功",
        "重新推荐": "重新推荐",
        "取消订单": "取消订单",
    },
)

# 重新推荐后 → 再次等确认（循环！）
图.add_edge("重新推荐", "等待确认")

# 下单和取消 → 结束
图.add_edge("下单成功", END)
图.add_edge("取消订单", END)

# 编译
工作流 = 图.compile()


# ========== 运行
print("🍽️  AI 点餐助手（带人工确认）\n")
用户消息 = input("👤 请问您想吃什么类型的菜？: ")

结果 = 工作流.invoke({
    "用户消息": 用户消息,
    "推荐菜品": "",
    "用户确认": "",
    "最终订单": "",
    "步骤": [],
})

print(f"\n{'='*50}")
print(f"📝 步骤记录: {' → '.join(结果['步骤'])}")
if 结果["最终订单"] != "已取消":
    print(f"✅ 最终订单已确认！")
~~~

### 5.2 带循环的 Agent 工作流

创建文件 `demo5_ReAct循环.py`：

~~~python
# ========== demo5_ReAct循环.py
# 用 LangGraph 实现 ReAct 循环：思考 → 行动 → 观察 → 再思考
# 比 Demo4 文本解析更可靠的实现方式

from langgraph.graph import StateGraph, END
from openai import OpenAI
from dotenv import load_dotenv
import os
import json
from typing import TypedDict

load_dotenv()

客户端 = OpenAI(
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL"),
)


# ========== 状态定义
class Agent状态(TypedDict):
    消息历史: list[dict]    # 对话历史
    工具结果: str           # 工具执行结果
    最终回答: str           # 最终回答
    是否完成: bool          # 是否完成
    迭代次数: int           # 防止无限循环


# ========== 工具定义
菜品库 = {
    "宫保鸡丁": {"价格": 38.5, "辣度": 3},
    "鱼香肉丝": {"价格": 28.0, "辣度": 1},
    "麻婆豆腐": {"价格": 22.0, "辣度": 4},
    "红烧肉":   {"价格": 45.0, "辣度": 0},
    "糖醋排骨": {"价格": 42.0, "辣度": 0},
}

工具定义 = [
    {
        "type": "function",
        "function": {
            "name": "查询菜品",
            "description": "查询菜品价格和辣度",
            "parameters": {
                "type": "object",
                "properties": {"菜品名称": {"type": "string"}},
                "required": ["菜品名称"],
            },
        },
    },
    {
        "type": "function",
        "function": {
            "name": "筛选菜品",
            "description": "按条件筛选菜品",
            "parameters": {
                "type": "object",
                "properties": {
                    "最大辣度": {"type": "integer", "description": "最大辣度0-5"},
                    "最高价格": {"type": "number", "description": "最高价格"},
                },
            },
        },
    },
]

def 执行工具(名称: str, 参数: dict) -> str:
    if 名称 == "查询菜品":
        菜 = 菜品库.get(参数["菜品名称"])
        return json.dumps(菜 or {"错误": "未找到"}, ensure_ascii=False)
    elif 名称 == "筛选菜品":
        结果 = [
            f"{名}(¥{信息['价格']},辣度{信息['辣度']})"
            for 名, 信息 in 菜品库.items()
            if 信息["辣度"] <= 参数.get("最大辣度", 5)
            and 信息["价格"] <= 参数.get("最高价格", 999)
        ]
        return json.dumps(结果, ensure_ascii=False)
    return json.dumps({"错误": "未知工具"})


# ========== 节点函数
def 思考(状态: Agent状态) -> dict:
    """节点：AI 思考，决定下一步"""
    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=状态["消息历史"],
        tools=工具定义,
        tool_choice="auto",
    )

    消息对象 = 回复.choices[0].message

    if 消息对象.tool_calls:
        # AI 决定调用工具
        新历史 = 状态["消息历史"] + [消息对象]
        return {
            "消息历史": 新历史,
            "是否完成": False,
            "迭代次数": 状态["迭代次数"] + 1,
        }
    else:
        # AI 直接给出最终回答
        return {
            "消息历史": 状态["消息历史"] + [消息对象],
            "最终回答": 消息对象.content,
            "是否完成": True,
            "迭代次数": 状态["迭代次数"] + 1,
        }


def 执行工具节点(状态: Agent状态) -> dict:
    """节点：执行 AI 请求的工具"""
    最新消息 = 状态["消息历史"][-1]
    工具结果列表 = []

    for 调用 in 最新消息.tool_calls:
        函数名 = 调用.function.name
        参数 = json.loads(调用.function.arguments)
        结果 = 执行工具(函数名, 参数)
        工具结果列表.append({
            "role": "tool",
            "tool_call_id": 调用.id,
            "content": 结果,
        })
        print(f"  🔧 {函数名}({参数}) → {结果[:60]}")

    return {
        "消息历史": 状态["消息历史"] + 工具结果列表,
    }


def 判断是否完成(状态: Agent状态) -> str:
    """条件路由"""
    if 状态["是否完成"]:
        return "完成"
    if 状态["迭代次数"] >= 5:
        return "完成"  # 防止无限循环
    return "继续"


# ========== 构建工作流
图 = StateGraph(Agent状态)

图.add_node("思考", 思考)
图.add_node("执行工具", 执行工具节点)

图.set_entry_point("思考")

图.add_conditional_edges(
    "思考",
    判断是否完成,
    {"完成": END, "继续": "执行工具"},
)
图.add_edge("执行工具", "思考")  # 循环：执行完工具 → 回到思考

工作流 = 图.compile()


# ========== 运行
问题 = "我想吃辣的菜，预算50以内，帮我算一下点两道菜加一碗米饭多少钱"
print(f"👤 {问题}\n")

结果 = 工作流.invoke({
    "消息历史": [
        {"role": "system", "content": "你是餐厅助手，用工具帮顾客查菜单、推荐菜品、计算价格。"},
        {"role": "user", "content": 问题},
    ],
    "工具结果": "",
    "最终回答": "",
    "是否完成": False,
    "迭代次数": 0,
})

print(f"\n🤖 最终回答: {结果['最终回答']}")
print(f"📊 迭代次数: {结果['迭代次数']}")
~~~

运行：

~~~bash
python3 demo5_ReAct循环.py
# 观察 AI 的多步推理过程：
# 1. 第1轮思考：需要筛选菜品 → 调用筛选工具
# 2. 第2轮思考：知道了菜品列表 → 需要算价格 → 调用计算工具
# 3. 第3轮思考：有足够信息了 → 给出最终回答
~~~

**Demo 5 学完你应该掌握：**
- 人工介入 = 在工作流中插入"暂停等待确认"的节点
- 循环边 = `图.add_edge("B", "A")` 实现 A → B → A 的循环
- 迭代次数限制 = 防止 Agent 无限循环（设置 max_iterations）
- ReAct 在 LangGraph 中的实现比纯文本解析更可靠

## Demo 6：多 Agent 协作 — 分工合作

### 学习目标

- 理解多 Agent 协作的架构模式
- 实现"主管 Agent + 工人 Agent"模式
- 理解 A2A（Agent-to-Agent）协议的概念

### 6.1 A2A 协议

~~~
A2A（Agent-to-Agent）= Agent 之间的通信标准

类比：
  一个餐厅里有多个角色：
    点餐员 Agent → 负责接收顾客点餐
    厨师 Agent   → 负责做菜和出餐时间
    收银 Agent   → 负责结账和优惠
    经理 Agent   → 负责协调以上所有人

  经理 Agent 是"主管"，其他是"工人"
  经理收到顾客问题 → 分配给合适的工人 → 工人返回结果 → 经理汇总回答

A2A 通信方式：
  1. 共享状态：所有 Agent 读写同一个状态对象
  2. 消息传递：Agent 之间发送消息
  3. 任务委派：主管 Agent 创建子任务分配给工人
~~~

### 6.2 实现多 Agent 系统

创建文件 `demo6_多Agent.py`：

~~~python
# ========== demo6_多Agent.py
# 多 Agent 协作系统：主管 Agent + 工人 Agent

from langgraph.graph import StateGraph, END
from openai import OpenAI
from dotenv import load_dotenv
import os
import json
from typing import TypedDict

load_dotenv()

客户端 = OpenAI(
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL"),
)


# ========== 状态定义（所有 Agent 共享）
class 多Agent状态(TypedDict):
    用户消息: str
    分配结果: str          # 主管分配的任务
    菜品信息: str          # 菜品 Agent 的结果
    价格计算: str          # 价格 Agent 的结果
    最终回答: str          # 主管汇总的回答
    步骤记录: list[str]


# ========== 工人 Agent 1：菜品专家
def 菜品专家Agent(状态: 多Agent状态) -> dict:
    """负责查询菜品信息和推荐"""
    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": """你是菜品专家，熟悉所有菜品信息。
菜单：
- 宫保鸡丁：38元，辣度3/5，川菜，鸡肉+花生
- 鱼香肉丝：28元，辣度1/5，川菜，猪肉+木耳
- 麻婆豆腐：22元，辣度4/5，川菜，豆腐+牛肉末
- 红烧肉：45元，辣度0/5，本帮菜，五花肉
- 糖醋排骨：42元，辣度0/5，本帮菜，排骨
- 凉菜拼盘：18元，辣度0/5，凉菜
- 米饭：3元，主食

只输出菜品相关信息，不计算价格。"""},
            {"role": "user", "content": 状态["用户消息"]},
        ],
        temperature=0,
    )

    结果 = 回复.choices[0].message.content
    print(f"  🍳 菜品专家: {结果[:80]}...")

    return {
        "菜品信息": 结果,
        "步骤记录": 状态["步骤记录"] + [f"菜品专家完成"],
    }


# ========== 工人 Agent 2：价格计算师
def 价格计算师Agent(状态: 多Agent状态) -> dict:
    """负责计算价格和优惠"""
    菜品信息 = 状态.get("菜品信息", "")

    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": """你是价格计算师。根据菜品信息计算总价。
价格表：宫保鸡丁38、鱼香肉丝28、麻婆豆腐22、红烧肉45、糖醋排骨42、凉菜拼盘18、米饭3。
优惠：满100减10，满200减30。
只输出计算过程和结果。"""},
            {"role": "user", "content": f"顾客需求：{状态['用户消息']}\n\n菜品信息：{菜品信息}"},
        ],
        temperature=0,
    )

    结果 = 回复.choices[0].message.content
    print(f"  💰 价格计算师: {结果[:80]}...")

    return {
        "价格计算": 结果,
        "步骤记录": 状态["步骤记录"] + ["价格计算师完成"],
    }


# ========== 主管 Agent：任务分配
def 主管分配(状态: 多Agent状态) -> dict:
    """主管分析需求，决定分配什么任务"""
    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": """你是餐厅经理，负责分析顾客需求并分配任务。
输出以下JSON：
{"需要菜品专家": true/false, "需要价格计算": true/false, "任务说明": "简要说明"}"""},
            {"role": "user", "content": 状态["用户消息"]},
        ],
        temperature=0,
    )

    try:
        分配 = json.loads(回复.choices[0].message.content)
    except:
        分配 = {"需要菜品专家": True, "需要价格计算": True, "任务说明": "默认全部执行"}

    print(f"  👔 经理分配: {分配}")

    return {
        "分配结果": json.dumps(分配, ensure_ascii=False),
        "步骤记录": 状态["步骤记录"] + [f"经理分配: {分配['任务说明']}"],
    }


def 判断需要哪些Agent(状态: 多Agent状态) -> list[str]:
    """条件路由：决定执行哪些工人 Agent"""
    分配 = json.loads(状态["分配结果"])
    需要的 = []
    if 分配.get("需要菜品专家"):
        需要的.append("菜品专家")
    if 分配.get("需要价格计算"):
        需要的.append("价格计算师")
    return 需要的 if 需要的 else ["菜品专家"]  # 至少一个


def 主管汇总(状态: 多Agent状态) -> dict:
    """主管汇总所有结果，生成最终回答"""
    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "你是餐厅经理，汇总各专家的信息，给顾客一个简洁友好的回答。不超过3句话。"},

        ],
        temperature=0.7,

        "步骤记录": 状态["步骤记录"] + ["经理汇总完成"],

    if 分配.get("需要价格计算"):
        发送列表.append(Send("价格计算师", 状态))
    return 发送列表 if 发送列表 else [Send("菜品专家", 状态)]

图.add_conditional_edges("主管分配", 分发任务)
图.add_edge("菜品专家", "主管汇总")
图.add_edge("价格计算师", "主管汇总")
图.add_edge("主管汇总", END)

工作流 = 图.compile()
~~~

~~~python
# ========== rag_engine.py

from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_community.vectorstores import Chroma
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import DirectoryLoader, TextLoader
from dotenv import load_dotenv
import os

load_dotenv()


class RAG引擎:
    def __init__(self, 知识库路径: str = "知识库", 向量库路径: str = "./向量数据库"):
        self.Embedding = OpenAIEmbeddings(model="text-embedding-ada-002")
        self.向量库路径 = 向量库路径

        # 检查是否已有向量数据库
        if os.path.exists(向量库路径) and os.listdir(向量库路径):
            self.向量库 = Chroma(
                persist_directory=向量库路径,
                embedding_function=self.Embedding,
                collection_name="知识库",
            )
        else:
            self.向量库 = self._构建向量库(知识库路径)

        self.检索器 = self.向量库.as_retriever(
            search_type="similarity",
            search_kwargs={"k": 3},
        )

    def _构建向量库(self, 路径: str):
        加载器 = DirectoryLoader(路径, glob="**/*.txt", loader_cls=TextLoader)
        文档 = 加载器.load()
        切块器 = RecursiveCharacterTextSplitter(
            chunk_size=300, chunk_overlap=50,
            separators=["\n\n", "\n", "。", "，", " "],
        )
        块 = 切块器.split_documents(文档)
        return Chroma.from_documents(
            块, self.Embedding,
            persist_directory=self.向量库路径,
            collection_name="知识库",
        )

    def 检索(self, 问题: str) -> str:
        文档列表 = self.检索器.invoke(问题)
        return "\n\n".join([
            f"[来源: {d.metadata['source']}]\n{d.page_content}"
            for d in 文档列表
        ])
~~~

~~~python
# ========== agent_graph.py

from langgraph.graph import StateGraph, END
from openai import OpenAI
from dotenv import load_dotenv
import os
import json
from typing import TypedDict
from rag_engine import RAG引擎
from tools import 工具函数映射
from tools_schema import 工具清单

load_dotenv()

客户端 = OpenAI(api_key=os.getenv("OPENAI_API_KEY"), base_url=os.getenv("OPENAI_BASE_URL"))
RAG = RAG引擎()


class AgentState(TypedDict):
    消息历史: list[dict]
    检索上下文: str
    工具执行结果: str
    最终回答: str
    是否完成: bool
    意图: str
    迭代次数: int


def 意图识别(状态: AgentState) -> dict:
    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "判断用户意图：'知识库'（问餐厅/菜品相关）或 '工具'（需要查价格/算钱）或 '闲聊'。只输出一个词。"},
            {"role": "user", "content": 状态["消息历史"][-1]["content"]},
        ],
        temperature=0,
    )
    意图 = 回复.choices[0].message.content.strip()
    return {"意图": 意图, "迭代次数": 0}


def 路由(状态: AgentState) -> str:
    意图 = 状态["意图"]
    if "知识库" in 意图:
        return "RAG检索"
    elif "工具" in 意图:
        return "思考"
    else:
        return "闲聊"


def RAG检索(状态: AgentState) -> dict:
    问题 = 状态["消息历史"][-1]["content"]
    上下文 = RAG.检索(问题)
    return {"检索上下文": 上下文}


def 生成RAG回答(状态: AgentState) -> dict:
    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": f"基于以下资料回答，简洁友好，标注来源：\n{状态['检索上下文']}"},
            *状态["消息历史"],
        ],
        temperature=0.7,
    )
    return {"最终回答": 回复.choices[0].message.content, "是否完成": True}


def 思考(状态: AgentState) -> dict:
    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=状态["消息历史"],
        tools=工具清单,
        tool_choice="auto",
    )
    消息 = 回复.choices[0].message
    if 消息.tool_calls:
        return {"消息历史": 状态["消息历史"] + [消息], "是否完成": False, "迭代次数": 状态["迭代次数"] + 1}
    return {"最终回答": 消息.content, "是否完成": True}


def 执行工具(状态: AgentState) -> dict:
    最新 = 状态["消息历史"][-1]
    结果列表 = []
    for 调用 in 最新.tool_calls:
        名 = 调用.function.name
        参 = json.loads(调用.function.arguments)
        结果 = 工具函数映射[名](**参)
        结果列表.append({"role": "tool", "tool_call_id": 调用.id, "content": json.dumps(结果, ensure_ascii=False)})
    return {"消息历史": 状态["消息历史"] + 结果列表}


def 闲聊(状态: AgentState) -> dict:
    回复 = 客户端.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "system", "content": "友好闲聊，引导到点餐话题。"}] + 状态["消息历史"],
        temperature=0.7,
    )
    return {"最终回答": 回复.choices[0].message.content, "是否完成": True}


def 判断完成(状态: AgentState) -> str:
    if 状态["是否完成"] or 状态["迭代次数"] >= 5:
        return "完成"
    return "继续"


# 构建图
图 = StateGraph(AgentState)
图.add_node("意图识别", 意图识别)
图.add_node("RAG检索", RAG检索)
图.add_node("生成RAG回答", 生成RAG回答)
图.add_node("思考", 思考)
图.add_node("执行工具", 执行工具)
图.add_node("闲聊", 闲聊)

图.set_entry_point("意图识别")
图.add_conditional_edges("意图识别", 路由, {"RAG检索": "RAG检索", "思考": "思考", "闲聊": "闲聊"})
图.add_edge("RAG检索", "生成RAG回答")
图.add_edge("生成RAG回答", END)
图.add_conditional_edges("思考", 判断完成, {"完成": END, "继续": "执行工具"})
图.add_edge("执行工具", "思考")
图.add_edge("闲聊", END)

Agent工作流 = 图.compile()
~~~

## 高频面试题

### Q1：什么是 RAG？和直接用 AI 回答有什么区别？

~~~
RAG = Retrieval-Augmented Generation（检索增强生成）

直接用 AI：
  用户问题 → AI → 回答（靠模型自己的知识，可能过时或不准确）

RAG：
  用户问题 → 检索你的文档 → 找到相关内容 → AI 基于这些内容回答

优势：
  1. 准确性：基于你的真实文档回答，不会编造
  2. 时效性：文档更新了，回答就更新了（不用重新训练模型）
  3. 可溯源：每个回答都能标注信息来源
  4. 成本低：比微调模型便宜得多
~~~

### Q2：RAG 中的切块策略怎么选？

~~~
核心原则：每个块应该是一个完整的信息单元

推荐：RecursiveCharacterTextSplitter
  - chunk_size: 200-500（中文），500-1000（英文）
  - chunk_overlap: 10-20% 的 chunk_size
  - separators: ["\n\n", "\n", "。", "，", " "]

优化技巧：
  1. 重排序：先检索 top 10，再用 AI 精选出 top 3
  2. 混合检索：向量检索 + 关键词检索（BM25）结合
  3. 元数据过滤：按文档类型、时间等预先筛选
~~~

### Q3：LangGraph 和 LangChain 有什么区别？

~~~
LangChain：线性链（Chain）
  A → B → C（适合简单的、线性的流程）

LangGraph：有向图（Graph）
  可以有条件分支、循环、并行、人工介入
  适合复杂的 Agent 工作流

什么时候用什么：
  简单的"检索+回答" → LangChain 就够了
  多步推理、工具调用、条件分支 → LangGraph
  需要人工介入、检查点恢复 → LangGraph
~~~

### Q4：什么是 A2A 协议？

~~~
A2A = Agent-to-Agent Protocol
Google 提出的 Agent 之间通信的标准协议

解决的问题：
  不同平台、不同框架的 Agent 之间如何协作？

核心概念：
  Agent Card：描述 Agent 的能力（类似 MCP 的工具定义）
  Task：Agent 之间的任务委派
  Message：Agent 之间的消息传递

和 MCP 的关系：
  MCP：Agent ↔ 工具（连接数据库、API 等）
  A2A：Agent ↔ Agent（连接其他 AI Agent）
~~~

### Q5：Embedding 模型怎么选？

~~~
OpenAI text-embedding-ada-002：
  - 维度：1536
  - 支持多语言
  - 需要 API 调用（有费用）
  - 推荐用于：需要高质量向量的场景

开源替代：
  - BGE 系列（BAAI）：中文效果好，可本地部署
  - Sentence-Transformers：开源生态丰富
  - M3E（Moka AI）：中文专用

选择建议：
  有预算 → OpenAI ada-002（质量高，省心）
  中文为主 → BGE-large-zh 或 M3E
  需要本地部署 → Sentence-Transformers
~~~

## 终极记忆卡片

1. **Embedding** → 把文字变成向量（数字数组），语义相近 → 向量距离近
2. **RAG 全流程** → 加载文档 → 切块 → 向量化 → 存入向量库 → 检索 → AI 生成回答
3. **切块策略** → RecursiveCharacterTextSplitter，chunk_size 200-500，overlap 10-20%
4. **重排序** → 先多取候选（top 10），AI 精排（top 3），比纯向量检索更准
5. **引用来源** → Prompt 要求标注 + 返回结构化参考资料
6. **LangGraph 状态图** → State（传递数据）+ Node（处理函数）+ Edge（连接）
7. **条件分支** → `add_conditional_edges` 根据状态决定走哪条路
8. **循环** → `add_edge("B", "A")` 实现 A → B → A 循环
9. **人工介入** → 在工作流中插入暂停等待确认的节点
10. **多 Agent** → 主管分配任务 + 工人并行执行 + 主管汇总结果
11. **A2A 协议** → Agent ↔ Agent 的通信标准，MCP 是 Agent ↔ 工具
