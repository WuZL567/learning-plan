# ES6+ 核心特性：从 let/const 到 Proxy 的完整思考路径

## 核心策略：ES6+ 的 5 个套路

~~~
套路1：变量声明的进化      → let / const / var 的区别 + 暂时性死区
套路2：简化代码的语法糖    → 解构 / 展开 / 箭头函数 / 模板字符串
套路3：新的数据结构        → Map / Set / WeakMap / WeakSet / Symbol
套路4：类与继承            → class / extends / super / 静态方法
套路5：元编程与响应式      → Proxy / Reflect（Vue3 响应式原理）
~~~

## 套路一：变量声明的进化（let / const / var）

### var 的问题

~~~
问题1：没有块级作用域 → 变量"泄漏"到外面
问题2：可以重复声明 → 容易覆盖变量
问题3：变量提升 → 在声明前就能用（值是 undefined）
~~~

**手写口诀：var 函数作用域 + 提升 + 可重复声明，let/const 块级作用域 + 不提升 + 不可重复**

### 三者的对比

| | var | let | const |
|---|---|---|---|
| 作用域 | 函数作用域 | 块级作用域 | 块级作用域 |
| 变量提升 | ✅ 提升（值为 undefined） | ✅ 提升但暂时性死区 | ✅ 提升但暂时性死区 |
| 重复声明 | ✅ 可以 | ❌ 报错 | ❌ 报错 |
| 重新赋值 | ✅ 可以 | ✅ 可以 | ❌ 报错 |
| 全局属性 | ✅ 挂到 window | ❌ 不挂 | ❌ 不挂 |

### 测试

~~~javascript
// ========== var 的问题1：没有块级作用域 ==========
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 输出：3, 3, 3 ❌（i 泄漏到外面，循环结束后 i=3）

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 100);
}
// 输出：0, 1, 2 ✅（每次循环都是一个新的 j）

// ========== var 的问题2：可以重复声明 ==========
var a = 1;
var a = 2;  // 不报错，悄悄覆盖了
console.log(a);  // 2

let b = 1;
// let b = 2;  // ❌ SyntaxError: Identifier 'b' has already been declared

// ========== var 的问题3：变量提升 ==========
console.log(c);  // undefined（var 提升了，但值没提升）
var c = 1;

// console.log(d);  // ❌ ReferenceError（暂时性死区）
let d = 1;

// ========== const 的特殊情况 ==========
const e = [1, 2, 3];
e.push(4);       // ✅ 可以修改内容
console.log(e);  // [1, 2, 3, 4]
// e = [];        // ❌ 不能重新赋值（引用不能变）

const f = { 名字: "红烧肉" };
f.价格 = 38;     // ✅ 可以修改属性
// f = {};       // ❌ 不能重新赋值
~~~

### 重点：暂时性死区（TDZ）

~~~javascript
// 暂时性死区：从块开始到 let/const 声明之前的区域
// 在这个区域内访问变量会报错

{
  // ← TDZ 开始
  console.log(x);  // ❌ ReferenceError: Cannot access 'x' before initialization
  // ← TDZ 结束
  let x = 1;
}

// 虽然 let/const 也会提升（JavaScript 引擎知道这个变量存在）
// 但在声明前不能访问（和 var 不同）
~~~

## 闭包

### 什么是闭包？

~~~
闭包 = 函数内部引用了外部作用域的变量，即使外部函数已经执行完毕，
这个变量也不会被销毁（因为被内部函数引用着）。

简单说：函数能"记住"它出生时的环境。
~~~

### 经典面试题：for 循环 + var

~~~javascript
// ========== 问题：var 的循环闭包 ==========
function 生成菜单() {
  var 菜单 = [];
  for (var i = 0; i < 3; i++) {
    菜单.push(function() { return i; });
  }
  return 菜单;
}
var 结果 = 生成菜单();
console.log(结果[0]());  // 3 ❌（期望是 0）
console.log(结果[1]());  // 3 ❌（期望是 1）
console.log(结果[2]());  // 3 ❌（期望是 2）
// 原因：var i 是函数作用域，三个函数共享同一个 i
// 循环结束后 i=3，所以都返回 3

// ========== 解决方案1：用 let ==========
function 生成菜单2() {
  var 菜单 = [];
  for (let i = 0; i < 3; i++) {  // let 有块级作用域
    菜单.push(function() { return i; });
  }
  return 菜单;
}
var 结果2 = 生成菜单2();
console.log(结果2[0]());  // 0 ✅
console.log(结果2[1]());  // 1 ✅
console.log(结果2[2]());  // 2 ✅

// ========== 解决方案2：用 IIFE（ES5 时代） ==========
function 生成菜单3() {
  var 菜单 = [];
  for (var i = 0; i < 3; i++) {
    (function(j) {
      菜单.push(function() { return j; });
    })(i);  // IIFE 创建新的作用域，j 是 i 的副本
  }
  return 菜单;
}

// ========== 解决方案3：用 bind ==========
function 生成菜单4() {
  var 菜单 = [];
  for (var i = 0; i < 3; i++) {
    菜单.push(function(j) { return j; }.bind(null, i));
  }
  return 菜单;
}
~~~

## 套路二：简化代码的语法糖

### 1. 解构赋值

**手写口诀：对象按名取，数组按下标取，支持默认值和重命名**

~~~javascript
// ========== 对象解构 ==========
const 菜品 = { 名字: "红烧肉", 价格: 38, 类型: "热菜" };

const { 名字, 价格 } = 菜品;
console.log(名字);  // "红烧肉"
console.log(价格);  // 38

// 重命名
const { 名字: 菜名 } = 菜品;
console.log(菜名);  // "红烧肉"

// 默认值
const { 名字: n, 评分 = 5 } = 菜品;
console.log(评分);  // 5（菜品没有评分，用默认值）

// 嵌套解构
const 订单 = { 菜品: { 名字: "红烧肉" }, 数量: 2 };
const { 菜品: { 名字: 订单菜品名 } } = 订单;
console.log(订单菜品名);  // "红烧肉"

// ========== 数组解构 ==========
const [第一道, 第二道, 第三道] = ["红烧肉", "麻婆豆腐", "糖醋里脊"];
console.log(第一道);  // "红烧肉"

// 跳过元素
const [, 跳过第一, 第三个] = ["红烧肉", "麻婆豆腐", "糖醋里脊"];
console.log(跳过第一);  // "麻婆豆腐"

// 剩余元素
const [头, ...尾] = ["红烧肉", "麻婆豆腐", "糖醋里脊"];
console.log(头);   // "红烧肉"
console.log(尾);   // ["麻婆豆腐", "糖醋里脊"]

// 默认值
const [甲, 乙 = 10] = [5];
console.log(乙);  // 10

// ========== 交换变量 ==========
let x = 1, y = 2;
[x, y] = [y, x];
console.log(x, y);  // 2, 1

// ========== 函数参数解构 ==========
function 点菜({ 名字, 数量 = 1 }) {
  console.log(`${名字} x${数量}`);
}
点菜({ 名字: "红烧肉" });      // 红烧肉 x1
点菜({ 名字: "红烧肉", 数量: 3 }); // 红烧肉 x3
~~~

### 2. 展开运算符 vs 剩余参数

**手写口诀：展开是"拆开"，剩余是"收集"，同一个 `...` 符号**

~~~javascript
// ========== 展开运算符（拆开数组/对象） ==========
const 热菜 = ["红烧肉", "麻婆豆腐"];
const 凉菜 = ["拍黄瓜"];
const 全部菜 = [...热菜, ...凉菜, "汤"];
console.log(全部菜);  // ["红烧肉", "麻婆豆腐", "拍黄瓜", "汤"]

const 基础 = { 名字: "红烧肉", 价格: 38 };
const 菜品 = { ...基础, 类型: "热菜" };
console.log(菜品);  // { 名字: "红烧肉", 价格: 38, 类型: "热菜" }

// ========== 剩余参数（收集到数组） ==========
function 点菜(第一道, ...其他菜) {
  console.log("第一道：", 第一道);
  console.log("其他：", 其他菜);
}
点菜("红烧肉", "麻婆豆腐", "糖醋里脊");
// 第一道：红烧肉
// 其他：["麻婆豆腐", "糖醋里脊"]
~~~

#### 测试

~~~javascript
// ========== 展开是浅拷贝 ==========
const 原始 = { 名字: "红烧肉", 配料: ["酱油", "糖"] };
const 拷贝 = { ...原始 };
拷贝.配料.push("醋");
console.log(原始.配料);  // ["酱油", "糖", "醋"] ❌（配料被改了！）
// ... 展开只拷贝一层，嵌套对象还是引用

// ========== 深拷贝需要配合其他方法 ==========
const 深拷贝 = JSON.parse(JSON.stringify(原始));
// 或者用 structuredClone（现代浏览器）
const 深拷贝2 = structuredClone(原始);

// ========== 对象展开会覆盖同名属性 ==========
const 默认配置 = { 主题: "白色", 字体: "14px", 语言: "中文" };
const 用户配置 = { 主题: "黑色", 字体: "16px" };
const 最终配置 = { ...默认配置, ...用户配置 };
console.log(最终配置);
// { 主题: "黑色", 字体: "16px", 语言: "中文" }
// 后面的覆盖前面的
~~~

### 3. 箭头函数

**手写口诀：没有自己的 this，没有 arguments，不能 new，不能做构造函数**

~~~javascript
// ========== 基本语法 ==========
const 做菜 = (菜名) => `做了${菜名}`;
// 等价于：const 做菜 = (菜名) => { return `做了${菜名}`; };

// 单参数可省略括号
const 做菜2 = 菜名 => `做了${菜名}`;

// 多参数需要括号
const 做菜3 = (菜名, 份数) => `${菜名} x${份数}`;

// 无参数需要空括号
const 做菜4 = () => "做完了";

// 返回对象需要加括号
const 做菜5 = (菜名) => ({ 名字: 菜名, 做好了: true });
// ↑ 不加括号会被当成函数体的花括号
~~~

### this 指向速查表

| 场景 | this 指向 |
|---|---|
| 普通函数调用 `fn()` | `undefined`（严格模式）/ `globalThis`（非严格模式） |
| 对象方法 `obj.fn()` | `obj` |
| 箭头函数 `() => {}` | 定义时外层的 this（继承，不可改变） |
| `new Foo()` | 新创建的实例对象 |
| `call` / `apply` / `bind` | 第一个参数指定的对象 |
| 事件处理器 `el.onclick = fn` | 触发事件的元素 `el` |

#### 箭头函数 vs 普通函数的 this

~~~javascript
const 店 = {
  名字: "老王饭馆",

  // ========== 普通函数：this = 调用者 ==========
  做菜() {
    console.log("普通方法：", this.名字);  // this = 店

    // 嵌套的普通函数：this = undefined
    function 内部() {
      console.log("内部普通函数：", this.名字);  // undefined
    }
    内部();

    // 嵌套的箭头函数：this = 外层的 this = 店
    const 内部箭头 = () => {
      console.log("内部箭头函数：", this.名字);  // 老王饭馆
    };
    内部箭头();
  },

  // ========== 箭头函数：this = 定义时的外层 this ==========
  做菜箭头: () => {
    console.log("箭头方法：", this.名字);  // undefined（外层 this = 全局/undefined）
  }
};

店.做菜();
// 普通方法：老王饭馆
// 内部普通函数：undefined
// 内部箭头函数：老王饭馆

店.做菜箭头();
// 箭头方法：undefined
~~~

**核心区别：** 普通函数的 this 在调用时确定（谁调用指向谁），箭头函数的 this 在定义时确定（继承外层 this，不可改变）。

#### 测试

~~~javascript
// ========== 箭头函数不能做构造函数 ==========
const Person = (名字) => { this.名字 = 名字; };
// new Person("老王");  // ❌ TypeError: Person is not a constructor

// ========== 箭头函数没有 arguments ==========
const 普通 = function() { console.log(arguments); };
普通(1, 2, 3);  // Arguments(3) [1, 2, 3]

const 箭头 = () => { console.log(typeof arguments); };
// 箭头(1, 2, 3);  // ❌ ReferenceError（或访问外层的 arguments）

// ========== 箭头函数的 this 不能用 call/apply/bind 改变 ==========
const 箭头2 = () => console.log(this);
箭头2.call({ 名字: "试试" });  // 不会改变，this 还是外层的 this

// ========== 箭头函数不适合做对象方法 ==========
const 菜品 = {
  名字: "红烧肉",
  展示: () => console.log(this.名字),  // ❌ this 不是菜品
  展示2() { console.log(this.名字); }  // ✅ this 是菜品
};
菜品.展示();   // undefined
菜品.展示2();  // 红烧肉
~~~

### 4. 模板字符串

~~~javascript
const 名字 = "红烧肉";
const 价格 = 38;

// 普通字符串拼接
console.log(名字 + "的价格是" + 价格 + "元");

// 模板字符串
console.log(`${名字}的价格是${价格}元`);

// 多行字符串
const 菜单 = `
  菜单：
    1. ${名字} - ${价格}元
    2. 麻婆豆腐 - 22元
`;

// 标签模板字符串（高级用法）
function 高亮(strings, ...值们) {
  return strings.reduce((结果, 字符串, i) => {
    return 结果 + 字符串 + (值们[i] ? `<b>${值们[i]}</b>` : '');
  }, '');
}
const html = 高亮`菜品是${名字}，价格是${价格}元`;
console.log(html);  // 菜品是<b>红烧肉</b>，价格是<b>38</b>元
~~~

## 套路三：新的数据结构

### 1. Map

**手写口诀：键可以是任何类型，有 size，用 forEach 遍历**

~~~javascript
const 映射 = new Map();

// set 和 get
映射.set("红烧肉", 38);
映射.set(42, "数字做键");
映射.set(true, "布尔做键");

const 对象键 = { 名字: "老王" };
映射.set(对象键, "对象做键");

console.log(映射.get("红烧肉"));  // 38
console.log(映射.get(42));        // "数字做键"
console.log(映射.get(对象键));    // "对象做键"

// has / delete / size
console.log(映射.has("红烧肉"));  // true
映射.delete(42);
console.log(映射.size);           // 3

// 遍历
映射.forEach((值, 键) => console.log(键, 值));
for (const [键, 值] of 映射) { console.log(键, 值); }
~~~

### 2. Map vs Object

| | Map | Object |
|---|---|---|
| 键的类型 | 任何类型（对象、函数、基本类型） | 只能是字符串或 Symbol |
| 大小 | `map.size` | `Object.keys(obj).length` |
| 遍历 | 直接可遍历（forEach / for...of） | 需要 Object.keys() / entries() |
| 性能 | 频繁增删场景更好 | 频繁读取场景更好 |
| 原型 | 没有原型链污染 | 可能有原型链上的属性 |

~~~javascript
// ========== 用 Map 的场景 ==========
// 1. 键不是字符串
const DOM映射 = new Map();
DOM映射.set(document.querySelector("#菜单"), "菜单组件");

// 2. 需要知道大小
const 缓存 = new Map();
if (缓存.size > 100) 缓存.clear();

// 3. 频繁增删
const 实时数据 = new Map();
实时数据.set("温度", 36.5);
实时数据.delete("温度");

// ========== 用 Object 的场景 ==========
// 1. 简单的键值对
const 配置 = { 主题: "黑色", 字体: "14px" };

// 2. JSON 序列化
JSON.stringify(配置);  // ✅
// JSON.stringify(new Map());  // ❌ 不支持直接序列化
~~~

### 3. Set

**手写口诀：值唯一，自动去重，有 size**

~~~javascript
const 集合 = new Set([1, 2, 3, 2, 1]);
console.log(集合);  // Set(3) {1, 2, 3}  ← 自动去重

// add / has / delete / size
集合.add(4);
集合.add(3);  // 已存在，不添加
console.log(集合.size);    // 4
console.log(集合.has(2));  // true
集合.delete(1);

// 遍历
集合.forEach(值 => console.log(值));
for (const 值 of 集合) { console.log(值); }

// ========== 常见用法 ==========

// 数组去重
const 原始 = [1, 2, 2, 3, 3, 3];
const 去重后 = [...new Set(原始)];
console.log(去重后);  // [1, 2, 3]

// 集合运算
const A = new Set([1, 2, 3]);
const B = new Set([2, 3, 4]);

// 并集
const 并集 = new Set([...A, ...B]);  // {1, 2, 3, 4}

// 交集
const 交集 = new Set([...A].filter(x => B.has(x)));  // {2, 3}

// 差集
const 差集 = new Set([...A].filter(x => !B.has(x)));  // {1}
~~~

### 4. WeakMap / WeakSet

**手写口诀：键必须是对象，不阻止垃圾回收，不能遍历**

~~~javascript
// ========== WeakMap ==========
const 弱映射 = new WeakMap();

const 对象1 = { 名字: "红烧肉" };
const 对象2 = { 名字: "麻婆豆腐" };

弱映射.set(对象1, 38);
弱映射.set(对象2, 22);

console.log(弱映射.get(对象1));  // 38

// 当对象没有其他引用时，WeakMap 里的记录会被自动清除
// 对象1 = null;  → WeakMap 里对象1 的记录会被垃圾回收

// ========== WeakMap 的实际用途：给对象附加私有数据 ==========
const 私有数据 = new WeakMap();

class 餐厅 {
  constructor(名字) {
    私有数据.set(this, { 名字, 密码: "secret" });
  }
  获取名字() {
    return 私有数据.get(this).名字;
  }
}
const 店 = new 餐厅("老王饭馆");
console.log(店.获取名字());  // "老王饭馆"
console.log(店.密码);        // undefined（外部访问不到）

// ========== WeakMap vs Map ==========
// Map 会阻止垃圾回收 → 内存泄漏风险
// WeakMap 不阻止 → 对象没有其他引用时自动清理

// ========== WeakSet ==========
const 弱集合 = new WeakSet();

const 菜品1 = { 名字: "红烧肉" };
const 菜品2 = { 名字: "麻婆豆腐" };

弱集合.add(菜品1);
弱集合.add(菜品2);
console.log(弱集合.has(菜品1));  // true

// 不能遍历（没有 forEach、没有 size）
// for (const x of 弱集合) {}  // ❌ TypeError
~~~

### 5. Symbol

**手写口诀：独一无二的值，永远不会重复，常用于对象的唯一键**

~~~javascript
// ========== 基本用法 ==========
const 唯一键1 = Symbol();
const 唯一键2 = Symbol();
console.log(唯一键1 === 唯一键2);  // false（每个 Symbol 都是唯一的）

// 带描述的 Symbol（方便调试，不影响唯一性）
const 红烧肉 = Symbol("红烧肉");
const 麻婆豆腐 = Symbol("红烧肉");  // 描述相同，但值不同
console.log(红烧肉 === 麻婆豆腐);  // false

// ========== 用 Symbol 做对象的唯一键 ==========
const 状态 = Symbol("状态");
const 菜品 = { 名字: "红烧肉", [状态]: "做好了" };
console.log(菜品[状态]);    // "做好了"
console.log(菜品.状态);     // undefined（用点语法访问不到）
// Symbol 键不会被 for...in 遍历到

// ========== Symbol 的常见用途 ==========

// 1. 防止属性名冲突
const ON_CLICK = Symbol("onClick");
元素[ON_CLICK] = function() { ... };

// 2. 模拟私有属性
const _密码 = Symbol("密码");
class 用户 {
  constructor(密码) { this[_密码] = 密码; }
  验证(输入) { return 输入 === this[_密码]; }
}

// 3. 定义类的特殊行为（内置 Symbol）
class 菜单 {
  [Symbol.iterator]() {
    let i = 0;
    const 菜品们 = ["红烧肉", "麻婆豆腐", "糖醋里脊"];
    return {
      next() {
        return i < 菜品们.length
          ? { value: 菜品们[i++], done: false }
          : { done: true };
      }
    };
  }
}

for (const 菜 of new 菜单()) {
  console.log(菜);  // 红烧肉、麻婆豆腐、糖醋里脊
}

// 4. 全局 Symbol 注册表
const s1 = Symbol.for("红烧肉");  // 全局注册
const s2 = Symbol.for("红烧肉");  // 从全局取
console.log(s1 === s2);  // true（同一个 Symbol）
~~~

## 套路四：类与继承（class）

### class 的本质

~~~
class 是 ES5 原型链继承的语法糖
底层还是原型链，只是写法更简洁
~~~

**手写口诀：class 是语法糖，constructor 是构造函数，方法在 prototype 上，static 是类方法**

~~~javascript
// ========== ES6 class 写法 ==========
class 餐厅 {
  // 构造函数
  constructor(名字, 城市) {
    this.名字 = 名字;   // 实例属性
    this.城市 = 城市;
  }

  // 实例方法（挂在 prototype 上）
  报名() {
    console.log(`欢迎来到${this.名字}，位于${this.城市}`);
  }

  // 静态方法（挂在类本身上，不在 prototype 上）
  static 创建(名字) {
    return new 餐厅(名字, "北京");
  }

  // getter（访问时自动调用）
  get 全名() {
    return `${this.城市}的${this.名字}`;
  }

  // setter（赋值时自动调用）
  set 全名(值) {
    [this.城市, this.名字] = 值.split("的");
  }
}

const 店 = new 餐厅("老王饭馆", "北京");
店.报名();            // 欢迎来到老王饭馆，位于北京
console.log(店.全名);  // 北京的老王饭馆
店.全名 = "上海的新店";
console.log(店.名字);  // 新店

const 新店 = 餐厅.创建("分店");
新店.报名();          // 欢迎来到分店，位于北京
~~~

#### 测试

~~~javascript

console.log(餐厅.prototype.报名 === 店.报名);       // true（方法在 prototype 上）
console.log(店.__proto__ === 餐厅.prototype);       // true
console.log(店.hasOwnProperty("名字"));             // true（实例属性）
console.log(店.hasOwnProperty("报名"));             // false（方法在 prototype 上）

// ========== 静方法不能通过实例调用 ==========
// 店.创建();  // ❌ TypeError（静态方法在类本身上，不在实例上）
餐厅.创建("测试");  // ✅ 通过类调用
~~~

### 原型链核心关系图

~~~
实例 (店)
  ├── __proto__  →  餐厅.prototype
  │                    ├── __proto__  →  Object.prototype
  │                    │                    ├── __proto__  →  null
  │                    │                    ├── toString
  │                    │                    └── hasOwnProperty
  │                    └── constructor  →  餐厅
  └── 自身属性（名字、城市）

餐厅 (构造函数)
  ├── __proto__  →  Function.prototype
  └── prototype  →  餐厅.prototype（上面已画）
~~~

### instanceof 原理

沿着 `__proto__` 链查找，如果找到 `Constructor.prototype` 就返回 `true`。

~~~javascript
function Restaurant(name) { this.name = name; }
Restaurant.prototype.showName = function() { return this.name; };

const r = new Restaurant("老王");

console.log(r.__proto__ === Restaurant.prototype);                // true
console.log(Restaurant.prototype.__proto__ === Object.prototype); // true
console.log(Object.prototype.__proto__ === null);                 // true
console.log(r instanceof Restaurant);  // true（沿着 __proto__ 链找到了 Restaurant.prototype）
console.log(r instanceof Object);      // true（继续往上找到了 Object.prototype）
~~~

**一句话总结：** class 只是让原型链的写法更简洁、更清晰，底层机制完全一样——方法在 prototype 上，实例通过 \_\_proto\_\_ 链访问。

### 继承（extends + super）

**手写口诀：extends 继承，super 调父类，constructor 里必须先 super**

~~~javascript
class 基础餐厅 {
  constructor(名字) {
    this.名字 = 名字;
    this.类型 = "餐厅";
  }
  报名() {
    console.log(`欢迎来到${this.名字}`);
  }
}

class 高级餐厅 extends 基础餐厅 {
  constructor(名字, 星级) {
    super(名字);        // 必须先调 super！
    this.星级 = 星级;   // 然后才能用 this
    this.类型 = "高级餐厅";
  }

  // 重写父类方法
  报名() {
    super.报名();  // 调用父类方法
    console.log(`我们是${this.星级}星级餐厅`);
  }

  // 新增方法
  评级() {
    return `${this.名字}：${this.星级}星`;
  }
}

const 店 = new 高级餐厅("老王饭馆", 5);
店.报名();
// 欢迎来到老王饭馆
// 我们是5星级餐厅
console.log(店.评级());  // 老王饭馆：5星
console.log(店 instanceof 高级餐厅);  // true
console.log(店 instanceof 基础餐厅);  // true
~~~

## 套路五：Proxy / Reflect（元编程）

### Proxy 是什么？

~~~
Proxy = "代理"
在对象外面包一层"拦截器"
任何对这个对象的操作（读取、设置、删除等）都会被拦截

生活比喻：
  原始对象 = 你的银行卡
  Proxy = 银行柜台
  你不能直接操作银行卡里的钱
  所有操作（存钱、取钱、查余额）都要通过柜台
  柜台可以决定：允许、拒绝、或者加一些额外逻辑
~~~

**手写口诀：new Proxy(目标, 处理器)，处理器里写拦截逻辑**

### Proxy 的 13 种拦截操作

~~~
get(target, prop)         → 读取属性
set(target, prop, value)  → 设置属性
has(target, prop)         → in 操作符
deleteProperty(target, prop)  → delete 操作符
apply(target, thisArg, args)  → 函数调用
construct(target, args)   → new 操作符
... 还有 7 种（不常用）
~~~

### 测试

~~~javascript
// ========== 基本用法：get 和 set 拦截 ==========
const 菜品 = { 名字: "红烧肉", 价格: 38 };

const 代理菜品 = new Proxy(菜品, {
  get(目标, 属性) {
    console.log(`读取 ${属性}`);
    return 目标[属性];
  },
  set(目标, 属性, 值) {
    console.log(`设置 ${属性} = ${值}`);
    if (属性 === "价格" && 值 < 0) {
      throw new Error("价格不能为负数");
    }
    目标[属性] = 值;
    return true;
  }
});

console.log(代理菜品.名字);    // 读取 名字 → 红烧肉
代理菜品.价格 = 45;            // 设置 价格 = 45
// 代理菜品.价格 = -10;        // ❌ Error: 价格不能为负数

// ========== has 拦截（in 操作符） ==========
const 代理菜品2 = new Proxy(菜品, {
  has(目标, 属性) {
    if (属性 === "秘密") return false;  // 隐藏"秘密"属性
    return 属性 in 目标;
  }
});

菜品.秘密 = "秘方";
console.log("秘密" in 代理菜品2);  // false（被隐藏了）

// ========== delete 拦截 ==========
const 代理菜品3 = new Proxy(菜品, {
  deleteProperty(目标, 属性) {
    if (属性 === "名字") {
      console.log("不能删除名字！");
      return false;
    }
    delete 目标[属性];
    return true;
  }
});

delete 代理菜品3.名字;  // 不能删除名字！
delete 代理菜品3.价格;  // 正常删除

// ========== 函数代理（apply 拦截） ==========
function 做菜(菜名) {
  return `${菜名}做好了`;
}

const 代理做菜 = new Proxy(做菜, {
  apply(目标, thisArg, 参数们) {
    console.log(`开始做 ${参数们[0]}...`);
    const 结果 = 目标.apply(thisArg, 参数们);
    console.log(结果);
    return 结果;
  }
});

代理做菜("红烧肉");
// 开始做 红烧肉...
// 红烧肉做好了
~~~

### Reflect 是什么？

~~~
Reflect = Proxy 的"搭档"
Proxy 的每个拦截操作，Reflect 都有对应的方法
建议在 Proxy 的处理器里用 Reflect 来执行默认行为
~~~

**手写口诀：Proxy 拦截，Reflect 执行默认行为**

~~~javascript
// ========== 不用 Reflect（直接操作目标对象） ==========
const 代理1 = new Proxy(菜品, {
  get(目标, 属性) {
    return 目标[属性];  // 直接读取目标
  },
  set(目标, 属性, 值) {
    目标[属性] = 值;    // 直接设置目标
    return true;
  }
});

// ========== 用 Reflect（推荐） ==========
const 代理2 = new Proxy(菜品, {
  get(目标, 属性, 代理) {
    console.log(`读取 ${属性}`);
    return Reflect.get(目标, 属性, 代理);  // 用 Reflect 执行默认行为
  },
  set(目标, 属性, 值, 代理) {
    console.log(`设置 ${属性} = ${值}`);
    return Reflect.set(目标, 属性, 值, 代理);
  }
});

// 为什么用 Reflect？
// 1. 行为和原生操作一致（处理了 receiver/this 的问题）
// 2. 返回 boolean（set 返回 true/false，比直接赋值更规范）
// 3. 代码更语义化
~~~

### Vue3 响应式原理（Proxy 的实际应用）

~~~javascript
// ========== 手写简易版 reactive（Vue3 核心思想） ==========
function reactive(对象) {
  return new Proxy(对象, {
    get(目标, 属性, 代理) {
      const 值 = Reflect.get(目标, 属性, 代理);

      // 依赖收集（告诉系统：有人在读这个属性）
      track(目标, 属性);

      // 如果值是对象，递归代理
      if (typeof 值 === "object" && 值 !== null) {
        return reactive(值);
      }

      return 值;
    },
    set(目标, 属性, 值, 代理) {
      const 旧值 = 目标[属性];
      const 结果 = Reflect.set(目标, 属性, 值, 代理);

      // 触发更新（告诉系统：有人在改这个属性）
      if (旧值 !== 值) {
        trigger(目标, 属性);
      }

      return 结果;
    }
  });
}

// 依赖收集和触发更新的简化实现
const 依赖映射 = new Map();

function track(目标, 属性) {
  // 这里简化处理，实际 Vue 用的是 WeakMap + Map + Set
  if (!依赖映射.has(目标)) 依赖映射.set(目标, new Map());
  const 属性映射 = 依赖映射.get(目标);
  if (!属性映射.has(属性)) 属性映射.set(属性, new Set());
}

function trigger(目标, 属性) {
  if (!依赖映射.has(目标)) return;
  const 属性映射 = 依赖映射.get(目标);
  if (!属性映射.has(属性)) return;
  属性映射.get(属性).forEach(fn => fn());
}
~~~

#### 测试

~~~javascript
// ========== 简易 reactive 测试 ==========
const 原始 = { 名字: "红烧肉", 价格: 38 };
const 响应式 = reactive(原始);

console.log(响应式.名字);  // "红烧肉"（get 被拦截，触发了 track）
响应式.价格 = 45;          // （set 被拦截，触发了 trigger）

// 嵌套对象也是响应式的

  热菜: { 名字: "红烧肉", 价格: 38 }
});
console.log(菜单.热菜.名字);  // "红烧肉"（嵌套对象也被代理了）

// ========== Proxy vs Object.defineProperty（Vue2 vs Vue3） ==========
// Object.defineProperty 的问题：
//   1. 不能监听新增属性（需要 Vue.set）
//   2. 不能监听数组下标变化（需要重写数组方法）
//   3. 不能监听属性删除
//   4. 只能劫持已有属性

// Proxy 的优势：
//   1. 可以拦截 13 种操作（包括新增、删除、in 等）
//   2. 数组也能正常监听
//   3. 性能更好（惰性代理，不递归遍历所有属性）
//   4. 代码更简洁
~~~

### Proxy 的实际应用场景

~~~javascript
// ========== 场景1：数据校验 ==========
function 校验(规则) {
  return new Proxy({}, {
    set(目标, 属性, 值) {
      if (规则[属性] && !规则[属性](值)) {
        throw new Error(`${属性} 校验失败：${值}`);
      }
      return Reflect.set(目标, 属性, 值);
    }
  });
}

const 表单 = 校验({
  年龄: v => typeof v === "number" && v >= 0 && v <= 150,
  名字: v => typeof v === "string" && v.length > 0,
});

表单.名字 = "老王";  // ✅
表单.年龄 = 25;       // ✅
// 表单.年龄 = -1;     // ❌ Error: 年龄 校验失败：-1
// 表单.名字 = "";     // ❌ Error: 名字 校验失败：

// ========== 场景2：访问日志 ==========
function 带日志(对象) {
  return new Proxy(对象, {
    get(目标, 属性) {
      console.log(`[GET] ${String(属性)}`);
      return Reflect.get(目标, 属性);
    },
    set(目标, 属性, 值) {
      console.log(`[SET] ${String(属性)} = ${值}`);
      return Reflect.set(目标, 属性, 值);
    }
  });
}

const 调试菜品 = 带日志({ 名字: "红烧肉" });
调试菜品.名字;          // [GET] 名字
调试菜品.价格 = 38;     // [SET] 价格 = 38

// ========== 场景3：默认值（类似 Python 的 defaultdict） ==========
function 默认值(默认工厂) {
  return new Proxy({}, {
    get(目标, 属性) {
      if (!(属性 in 目标)) {
        Reflect.set(目标, 属性, 默认工厂());
      }
      return Reflect.get(目标, 属性);
    }
  });
}

const 计数器 = 默认值(() => 0);
计数器.红烧肉++;
计数器.红烧肉++;
计数器.麻婆豆腐++;
console.log(计数器.红烧肉);   // 2
console.log(计数器.麻婆豆腐); // 1

// ========== 场景4：负索引数组（Python 风格） ==========
function 负索引数组(...元素) {
  return new Proxy(元素, {
    get(目标, 属性) {
      const 索引 = Number(属性);
      if (Number.isInteger(索引) && 索引 < 0) {
        return 目标[目标.length + 索引];
      }
      return Reflect.get(目标, 属性);
    }
  });
}

const 列表 = 负索引数组("红烧肉", "麻婆豆腐", "糖醋里脊");
console.log(列表[-1]);  // 糖醋里脊（最后一个）
console.log(列表[-2]);  // 麻婆豆腐（倒数第二个）

## 终极记忆卡片

~~~
套路1：变量声明
  var → 函数作用域 + 提升 + 可重复（淘汰）
  let → 块级作用域 + 暂时性死区 + 可重新赋值
  const → 块级作用域 + 暂时性死区 + 不可重新赋值（引用不能变，内容可以变）

闭包
  函数"记住"出生时的环境，外部函数执行完后变量不销毁
  for + var 问题 → 三种方案：let / IIFE / bind

this 指向
  普通函数 → 调用时确定（谁调用指向谁）
  箭头函数 → 定义时确定（继承外层 this，不可改变）
  new → 新创建的实例
  call/apply/bind → 第一个参数

套路2：语法糖
  解构 → 对象按名取，数组按下标取，支持默认值和重命名
  展开 → ... 拆开数组/对象（浅拷贝）
  箭头函数 → 没有自己的 this，没有 arguments，不能 new
  模板字符串 → `${}` 插值，支持多行

套路3：数据结构
  Map → 键可以是任何类型，有 size，可遍历
  Set → 值唯一，自动去重
  WeakMap → 键必须是对象，不阻止垃圾回收，不能遍历
  Symbol → 独一无二的值，用于唯一键和私有属性

套路4：类与继承
  class → 语法糖，constructor + 实例方法 + 静态方法
  原型链 → 实例.__proto__ → 构造函数.prototype → Object.prototype → null
  instanceof → 沿 __proto__ 链查找 Constructor.prototype
  extends → 继承，constructor 里必须先 super
  getter/setter → 访问/赋值时自动调用

套路5：Proxy/Reflect
  Proxy → 拦截对象操作（get/set/has/delete 等）
  Reflect → 执行默认行为（Proxy 的搭档）
  Vue3 → 用 Proxy 实现响应式（替代 Vue2 的 Object.defineProperty）
~~~
