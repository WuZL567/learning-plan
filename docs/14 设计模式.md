# 设计模式：前端 7 大高频设计模式 + 实战

## 学习路线图

~~~
模式1: 单例模式 → 全局只有一个实例（5分钟）
  ↓
模式2: 发布订阅模式 → EventBus / 自定义事件（10分钟）
  ↓
模式3: 观察者模式 → Vue 响应式的底层原理（10分钟）
  ↓
模式4: 策略模式 → 消除 if-else 地狱（10分钟）
  ↓
模式5: 代理模式 → ES6 Proxy / 请求缓存（10分钟）
  ↓
模式6: 工厂模式 → 根据参数创建不同对象（10分钟）
  ↓
模式7: 装饰器模式 → 不修改原代码增强功能（10分钟）
  ↓
综合实战: 在 Vue3 项目中的实际应用（20分钟）
~~~

---

## 核心策略：7 个模式一句话概括

1. **单例模式** → 全局只创建一个实例，所有人用同一个
2. **发布订阅** → 发布者和订阅者互不认识，通过事件中心通信
3. **观察者模式** → 被观察者变了，自动通知所有观察者
4. **策略模式** → 把不同的算法封装成函数，用配置替代 if-else
5. **代理模式** → 不直接访问目标对象，通过代理间接访问
6. **工厂模式** → 传入参数，返回对应的实例
7. **装饰器模式** → 不修改原函数，给它"穿上一层外衣"增加功能

## 模式一：单例模式 — 全局唯一

### 概念讲解

~~~
单例模式 = 整个应用中，某个类只有一个实例

类比：公司只有一个 CEO，不管多少人去找 CEO，找到的都是同一个人

前端场景：
  - 全局状态管理（Vuex/Pinia 的 store）
  - 全局弹窗（Dialog）→ 不管触发几次，页面上只有一个弹窗
  - 数据库连接池 → 只创建一个连接池
  - 浏览器的 window 对象就是天然的单例
~~~

### 手写口诀

**用闭包保存实例，第一次创建后直接返回**

### 代码实现

~~~javascript
// ========== 最简单的单例：闭包 + 变量
const 创建单例 = (创建函数) => {
  let 实例 = null;
  return (...参数) => {
    if (!实例) {
      实例 = 创建函数(...参数);  // 第一次才创建
    }
    return 实例;                // 之后直接返回
  };
};

// ========== 使用示例：全局弹窗管理器
class 弹窗管理器 {
  constructor() {
    this.弹窗列表 = [];
    console.log("弹窗管理器被创建了");  // 应该只打印一次
  }

  显示(消息) {
    this.弹窗列表.push(消息);
    console.log(`显示弹窗: ${消息}，当前共 ${this.弹窗列表.length} 个`);
  }

  关闭所有() {
    this.弹窗列表 = [];
    console.log("所有弹窗已关闭");
  }
}

// 包装成单例
const 获取弹窗管理器 = 创建单例(() => new 弹窗管理器());

// ========== 测试
const 管理器1 = 获取弹窗管理器();
const 管理器2 = 获取弹窗管理器();

console.log(管理器1 === 管理器2);  // 输出 ✅ true（是同一个实例）

管理器1.show = 管理器1.显示;     // 修正方法调用
管理器1.显示("欢迎光临");
管理器2.显示("今日特价");         // 管理器2 就是管理器1，所以能看到之前的弹窗
// 输出 ✅ 显示弹窗: 欢迎光临，当前共 1 个
// 输出 ✅ 显示弹窗: 今日特价，当前共 2 个
~~~

### 前端中的真实应用

~~~javascript
// ========== Vue3 中的 Pinia store 就是单例
// defineStore 只会创建一次，组件中多次 useStore 拿到的是同一个
// const useUserStore = defineStore('user', { ... })
// 组件A: const store = useUserStore()  ← 同一个实例
// 组件B: const store = useUserStore()  ← 同一个实例

// ========== 全局 Loading 单例（React 示例）
class LoadingManager {
  static 实例 = null;    // 静态属性存实例

  static 获取实例() {
    if (!LoadingManager.实例) {
      LoadingManager.实例 = new LoadingManager();
    }
    return LoadingManager.实例;
  }

  constructor() {
    this.加载中 = false;
    this.请求计数 = 0;   // 多个并发请求共享计数
  }

  开始() {
    this.请求计数++;
    this.加载中 = true;
  }

  结束() {
    this.请求计数--;
    if (this.请求计数 <= 0) {
      this.请求计数 = 0;
      this.加载中 = false;
    }
  }
}

const loading = LoadingManager.获取实例();
// 请求拦截器中：loading.开始()
// 响应拦截器中：loading.结束()
// 组件中读取：loading.加载中 控制 Loading 遮罩显示
~~~

## 模式二：发布订阅模式 — EventBus

### 概念讲解

~~~
发布订阅 = 发布者和订阅者通过"事件中心"通信，双方互不认识

类比：电台广播
  电台（发布者）在 FM99.5 频道播出节目
  听众（订阅者）调到 FM99.5 就能听到
  电台不知道有多少人在听，听众不知道电台在哪里

vs 观察者模式的区别：
  发布订阅：发布者 → 事件中心 → 订阅者（解耦更彻底）
  观察者模式：被观察者直接持有观察者列表（耦合更紧）
~~~

### 手写口诀

**事件名映射回调数组，on 存起来，emit 遍历执行，off 过滤删除**

### 代码实现

~~~javascript
class EventBus {
  constructor() {
    this.事件映射 = new Map();  // 事件名 → [回调1, 回调2, ...]
  }

  // 订阅（监听）
  on(事件名, 回调) {
    if (!this.事件映射.has(事件名)) {
      this.事件映射.set(事件名, []);
    }
    this.事件映射.get(事件名).push(回调);
  }

  // 发布（触发）
  emit(事件名, ...参数) {
    const 回调列表 = this.事件映射.get(事件名) || [];
    回调列表.forEach(回调 => 回调(...参数));
  }

  // 取消订阅
  off(事件名, 回调) {
    const 回调列表 = this.事件映射.get(事件名) || [];
    this.事件映射.set(
      事件名,
      回调列表.filter(fn => fn !== 回调 && fn._原始回调 !== 回调)
    );
  }

  // 只订阅一次
  once(事件名, 回调) {
    const 包装函数 = (...参数) => {
      回调(...参数);
      this.off(事件名, 包装函数);  // 执行一次后自动取消
    };
    包装函数._原始回调 = 回调;  // 用于 off 时匹配
    this.on(事件名, 包装函数);
  }
}

// ========== 测试
const 事件中心 = new EventBus();

// 订阅
const 处理订单 = (数据) => console.log(`收到订单: ${JSON.stringify(数据)}`);
事件中心.on("新订单", 处理订单);

// 发布
事件中心.emit("新订单", { 菜品: "宫保鸡丁", 数量: 2 });
// 输出 ✅ 收到订单: {"菜品":"宫保鸡丁","数量":2}

// once 测试
事件中心.once("系统通知", (消息) => console.log(`通知: ${消息}`));
事件中心.emit("系统通知", "打烊了");
// 输出 ✅ 通知: 打烊了
事件中心.emit("系统通知", "又一条");  // 不会触发，因为 once 已自动取消

// 取消订阅
事件中心.off("新订单", 处理订单);
事件中心.emit("新订单", { 菜品: "鱼香肉丝" });  // 不会触发
~~~

### 前端中的真实应用

## 模式三：观察者模式 — Vue 响应式原理

### 概念讲解

~~~
观察者模式 = 被观察者（Subject）维护一个观察者列表
             当自身状态改变时，自动通知所有观察者

类比：老师（被观察者）通知学生（观察者）"下课了"
  老师直接知道有哪些学生，直接通知
  不需要通过事件中心（这是和发布订阅的区别）

前端场景：
  - Vue 2 的响应式：data 是被观察者，watcher/computed 是观察者
  - Vue 3 的 Proxy 响应式
  - React 的 useState 触发 re-render
~~~

### 手写口诀

**被观察者存观察者列表，set 时通知所有观察者更新**

### 代码实现

~~~javascript
// ========== 被观察者（Subject）
class 被观察者 {
  constructor(初始值) {
    this._值 = 初始值;
    this.观察者列表 = [];
  }

  get 值() {
    return this._值;
  }

  set 值(新值) {
    if (this._值 !== 新值) {
      this._值 = 新值;
      this.通知();  // 值变了，通知所有观察者
    }
  }

  添加观察者(观察者) {
    this.观察者列表.push(观察者);
  }

  移除观察者(观察者) {
    this.观察者列表 = this.观察者列表.filter(obs => obs !== 观察者);
  }

  通知() {
    this.观察者列表.forEach(观察者 => 观察者.更新(this._值));
  }
}

// ========== 观察者（Observer）
class 观察者 {
  constructor(名称, 回调) {
    this.名称 = 名称;
    this.回调 = 回调;
  }

  更新(新值) {
    this.回调(新值);
  }
}

// ========== 测试
const 菜品价格 = new 被观察者(38.5);

// 创建观察者
const 价格标签 = new 观察者("价格标签", (新值) => {
  console.log(`价格标签更新: ¥${新值}`);
});

const 购物车 = new 观察者("购物车", (新值) => {
  console.log(`购物车重新计算小计: ¥${新值}`);
});

// 注册观察者
菜品价格.添加观察者(价格标签);
菜品价格.添加观察者(购物车);

// 修改价格 → 自动通知所有观察者
菜品价格.值 = 42.0;
// 输出 ✅ 价格标签更新: ¥42
// 输出 ✅ 购物车重新计算小计: ¥42

菜品价格.值 = 35.0;
// 输出 ✅ 价格标签更新: ¥35
// 输出 ✅ 购物车重新计算小计: ¥35

// 价格没变，不触发通知
菜品价格.值 = 35.0;
// 无输出
~~~

### Vue3 响应式的简化原理

~~~javascript
// ========== Vue3 的 reactive() 简化原理
// 真实实现更复杂（track/trigger/Effect 等），这里展示核心思想

function 简化reactive(初始对象) {
  const 观察者列表 = [];

  return new Proxy(初始对象, {
    get(目标, 属性) {
      // 实际 Vue 在这里做"依赖收集"（track）
      return 目标[属性];
    },
    set(目标, 属性, 新值) {
      const 旧值 = 目标[属性];
      目标[属性] = 新值;

      if (旧值 !== 新值) {
        // 实际 Vue 在这里做"触发更新"（trigger）
        观察者列表.forEach(fn => fn(属性, 新值, 旧值));
      }
      return true;
    },
  });
}

// 这就是为什么 Vue3 能自动追踪数据变化并更新视图
// getter 中收集依赖（谁用了这个数据）
// setter 中触发更新（数据变了，通知用了它的组件重新渲染）
~~~

## 模式四：策略模式 — 消灭 if-else

### 概念讲解

~~~
策略模式 = 把不同的算法/行为封装成独立的"策略"
           用配置（查表）替代 if-else 分支

类比：餐厅收银台
  if-else 写法：如果是会员打8折，如果是银卡打9折，如果是金卡打8.5折...
  策略模式：直接查表 { 会员: 0.8, 银卡: 0.9, 金卡: 0.85 }

优势：
  1. 消灭 if-else / switch 地狱
  2. 新增策略不需要修改原有代码（开闭原则）
  3. 每个策略独立，方便测试
~~~

### 手写口诀

**策略装进 Map，key 是条件，value 是函数，查表执行**

### 代码实现

~~~javascript
// ========== 反面教材：if-else 地狱
function 计算折扣_反面(会员类型, 价格) {
  if (会员类型 === "普通") {
    return 价格;
  } else if (会员类型 === "银卡") {
    return 价格 * 0.9;
  } else if (会员类型 === "金卡") {
    return 价格 * 0.85;
  } else if (会员类型 === "钻石") {
    return 价格 * 0.8;
  } else if (会员类型 === "员工") {
    return 价格 * 0.5;
  }
  // 新增会员类型就要继续加 else if... 越来越长
}

// ========== 策略模式：用 Map 查表
const 折扣策略 = {
  "普通": (价格) => 价格,
  "银卡": (价格) => 价格 * 0.9,
  "金卡": (价格) => 价格 * 0.85,
  "钻石": (价格) => 价格 * 0.8,
  "员工": (价格) => 价格 * 0.5,
};

function 计算折扣(会员类型, 价格) {
  const 策略 = 折扣策略[会员类型];
  if (!策略) throw new Error(`未知会员类型: ${会员类型}`);
  return 策略(价格);
}

// 新增会员类型？加一行就行：
折扣策略["年卡"] = (价格) => 价格 * 0.7;

// ========== 测试
console.log(计算折扣("普通", 100));  // 输出 ✅ 100
console.log(计算折扣("银卡", 100));  // 输出 ✅ 90
console.log(计算折扣("金卡", 100));  // 输出 ✅ 85
console.log(计算折扣("年卡", 100));  // 输出 ✅ 70
~~~

### 实战：表单校验策略

~~~javascript
// ========== 表单校验（前端最常用策略模式的场景）
const 校验策略 = {
  必填: (值) => {
    if (!值 || (typeof 值 === "string" && !值.trim())) {
      return "此项为必填";
    }
    return null;
  },

  手机号: (值) => {
    if (!/^1[3-9]\d{9}$/.test(值)) {
      return "手机号格式不正确";
    }
    return null;
  },

  邮箱: (值) => {
    if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(值)) {
      return "邮箱格式不正确";
    }
    return null;
  },

  最小长度: (最小值) => (值) => {
    if (值.length < 最小值) {
      return `最少 ${最小值} 个字符`;
    }
    return null;
  },

  数值范围: (最小, 最大) => (值) => {
    const 数字 = Number(值);
    if (isNaN(数字) || 数字 < 最小 || 数字 > 最大) {
      return `必须在 ${最小} 到 ${最大} 之间`;
    }
    return null;
  },
};

// 校验函数
function 校验表单(表单数据, 校验规则) {
  const 错误 = {};

  for (const [字段名, 规则列表] of Object.entries(校验规则)) {
    for (const 规则 of 规则列表) {
      const 校验函数 = typeof 规则 === "string"
        ? 校验策略[规则]
        : 规则;  // 支持直接传函数

      const 错误信息 = 校验函数(表单数据[字段名]);
      if (错误信息) {
        错误[字段名] = 错误信息;
        break;  // 每个字段只报第一个错误
      }
    }
  }

  return Object.keys(错误).length === 0 ? null : 错误;
}

// ========== 测试
const 表单 = { 用户名: "", 手机号: "123", 邮箱: "abc@def.com" };
const 规则 = {
  用户名: ["必填", 校验策略.最小长度(2)],
  手机号: ["必填", "手机号"],
  邮箱: ["邮箱"],
};

console.log(校验表单(表单, 规则));
// 输出 ✅ { 用户名: "此项为必填", 手机号: "手机号格式不正确" }
~~~

## 模式五：代理模式 — ES6 Proxy

### 概念讲解

~~~
代理模式 = 不直接访问目标对象，通过代理间接访问
           代理可以在访问前后插入额外逻辑

类比：明星的经纪人
  粉丝不能直接找明星 → 通过经纪人（代理）预约
  经纪人会做各种检查（有没有档期、安全审查等）

前端场景：
  - ES6 Proxy → Vue3 响应式的核心
  - 图片懒加载 → 先用占位图（代理），滚动到可视区域才加载真实图片
  - 请求缓存 → 代理拦截重复请求，直接返回缓存
  - 防抖节流 → 代理拦截频繁调用
~~~

### 手写口诀

**Proxy 创建代理，get/set/apply 拦截操作，前后插入自定义逻辑**

### 代码实现

~~~javascript
// ========== ES6 Proxy 基础
const 菜品 = {
  名称: "宫保鸡丁",
  价格: 38.5,
  秘密配方: "祖传秘方",
};

const 安全代理 = new Proxy(菜品, {
  get(目标, 属性) {
    if (属性 === "秘密配方") {
      console.log("⚠️ 尝试访问机密信息，已拦截");
      return "无权查看";
    }
    console.log(`📖 读取 ${属性}: ${目标[属性]}`);
    return 目标[属性];
  },

  set(目标, 属性, 新值) {
    if (属性 === "价格") {
      if (新值 < 0) {
        console.log("❌ 价格不能为负数");
        return false;
      }
      if (新值 > 1000) {
        console.log("❌ 价格不能超过1000");
        return false;
      }
    }
    console.log(`✏️ 修改 ${属性}: ${目标[属性]} → ${新值}`);
    目标[属性] = 新值;
    return true;
  },
});

// ========== 测试
console.log(安全代理.名称);        // 输出 ✅ 📖 读取 名称: 宫保鸡丁
安全代理.价格 = 42;                // 输出 ✅ ✏️ 修改 价格: 38.5 → 42
安全代理.价格 = -5;                // 输出 ✅ ❌ 价格不能为负数
console.log(安全代理.秘密配方);    // 输出 ✅ ⚠️ 尝试访问机密信息... 无权查看
~~~

### 实战：请求缓存代理

~~~javascript
// ========== 请求缓存代理（实际项目常用）
function 创建缓存代理(请求函数, 过期时间 = 60000) {
  const 缓存 = new Map();

  return async (...参数) => {
    const 缓存键 = JSON.stringify(参数);

    // 检查缓存
    if (缓存.has(缓存键)) {
      const { 数据, 时间 } = 缓存.get(缓存键);
      if (Date.now() - 时间 < 过期时间) {
        console.log(`🎯 命中缓存: ${缓存键}`);
        return 数据;
      }
      缓存.delete(缓存键);  // 过期了
    }

    // 缓存未命中，发请求
    console.log(`🌐 发起请求: ${缓存键}`);
    const 数据 = await 请求函数(...参数);
    缓存.set(缓存键, { 数据, 时间: Date.now() });
    return 数据;
  };
}

// ========== 测试
let 请求次数 = 0;
async function 查询菜品(菜品名) {
  请求次数++;
  // 模拟网络请求
  return { 名称: 菜品名, 价格: 38.5, 请求序号: 请求次数 };
}

const 缓存查询 = 创建缓存代理(查询菜品, 5000);

(async () => {
  const 结果1 = await 缓存查询("宫保鸡丁");
  console.log(结果1);  // 输出 ✅ {名称: "宫保鸡丁", 请求序号: 1}（发了请求）

  const 结果2 = await 缓存查询("宫保鸡丁");
  console.log(结果2);  // 输出 ✅ {名称: "宫保鸡丁", 请求序号: 1}（缓存命中，序号还是1）

  const 结果3 = await 缓存查询("鱼香肉丝");
  console.log(结果3);  // 输出 ✅ {名称: "鱼香肉丝", 请求序号: 2}（不同的菜，发了新请求）

  console.log(`总请求次数: ${请求次数}`);  // 输出 ✅ 总请求次数: 2（第二次被缓存拦截了）
})();

## 模式六：工厂模式 — 批量创建对象

### 概念讲解

~~~
工厂模式 = 不直接 new 对象，而是调用工厂函数，由工厂决定创建什么

类比：餐厅后厨
  顾客说"要一份川菜" → 后厨（工厂）决定做什么菜
  顾客不需要知道怎么做，只需要告诉工厂要什么

前端场景：
  - axios.create() → 创建不同配置的 axios 实例
  - React.createElement() → 根据类型创建不同的虚拟 DOM
  - 数据库连接工厂 → 根据环境创建 MySQL/PostgreSQL/SQLite 连接
~~~

### 手写口诀

**工厂函数接收类型参数，switch/Map 查表，返回对应实例**

### 代码实现

## 模式七：装饰器模式 — 不改原代码增强功能

### 概念讲解

~~~
装饰器模式 = 不修改原函数/对象，给它"套一层"增加新功能

类比：给手机戴手机壳
  手机本身不变，手机壳增加了防摔、支架等功能
  可以叠多个壳（多个装饰器）

前端场景：
  - 高阶组件（HOC）= React 的装饰器
  - composable = Vue3 的装饰器
  - AOP（面向切面编程）：日志、性能监控、权限检查
  - TypeScript 装饰器
~~~

### 手写口诀

**新函数包住原函数，前插入逻辑 → 调原函数 → 后插入逻辑**

### 代码实现

~~~javascript
// ========== 函数装饰器：给函数加"前后钩子"
function 装饰(原函数, { 前置, 后置, 错误处理 }) {
  return async function 装饰后的函数(...参数) {
    if (前置) await 前置(...参数);

    try {
      const 结果 = await 原函数(...参数);
      if (后置) await 后置(结果, ...参数);
      return 结果;
    } catch (错误) {
      if (错误处理) await 错误处理(错误, ...参数);
      else throw 错误;
    }
  };
}

// ========== 使用示例
async function 查询菜品(菜品名) {
  console.log(`  查询: ${菜品名}`);
  if (菜品名 === "不存在的菜") throw new Error("菜品不存在");
  return { 名称: 菜品名, 价格: 38.5 };
}

const 增强查询 = 装饰(查询菜品, {
  前置: (...参数) => {
    console.log(`⏱️ 请求开始: ${参数[0]}`);
    参数._开始时间 = Date.now();
  },
  后置: (结果) => {
    console.log(`✅ 请求成功: ${JSON.stringify(结果)}`);
  },
  错误处理: (错误) => {
    console.log(`❌ 请求失败: ${错误.message}`);
  },
});

// ========== 测试
(async () => {
  await 增强查询("宫保鸡丁");
  // 输出:
  // ⏱️ 请求开始: 宫保鸡丁
  //   查询: 宫保鸡丁
  // ✅ 请求成功: {"名称":"宫保鸡丁","价格":38.5}

  await 增强查询("不存在的菜");
  // 输出:
  // ⏱️ 请求开始: 不存在的菜
  //   查询: 不存在的菜
  // ❌ 请求失败: 菜品不存在
})();
~~~

~~~javascript
// ========== 计时装饰器
function 计时装饰器(函数名) {
  return (原函数) => {
    return async function (...参数) {
      const 开始 = performance.now();
      const 结果 = await 原函数(...参数);
      const 耗时 = (performance.now() - 开始).toFixed(2);
      console.log(`⏱️ ${函数名} 耗时: ${耗时}ms`);
      return 结果;
    };
  };
}

// ========== 重试装饰器
function 重试装饰器(最大次数 = 3, 延迟 = 1000) {
  return (原函数) => {
    return async function (...参数) {
      for (let 次数 = 1; 次数 <= 最大次数; 次数++) {
        try {
          return await 原函数(...参数);
        } catch (错误) {
          console.log(`  第 ${次数} 次重试...`);
          if (次数 === 最大次数) throw 错误;
          await new Promise(r => setTimeout(r, 延迟));
        }
      }
    };
  };
}

// ========== 叠加使用（多个装饰器套娃）
let 请求函数 = async (url) => {
  // 模拟偶尔失败
  if (Math.random() < 0.5) throw new Error("网络错误");
  return { url, data: "ok" };
};

请求函数 = 重试装饰器(3, 500)(请求函数);  // 先套重试
请求函数 = 计时装饰器("API请求")(请求函数); // 再套计时

// 调用时自动：计时 → 重试 → 原函数 → 重试结束后打印耗时
~~~

    }
  };

## 高频面试题

### Q1：观察者模式和发布订阅模式有什么区别？

~~~
观察者模式：
  被观察者 → 直接持有 → 观察者列表
  耦合紧：被观察者知道观察者的存在

发布订阅模式：
  发布者 → 事件中心 → 订阅者
  耦合松：发布者和订阅者互不认识

类比：
  观察者 = 微信群（群主直接@所有人）
  发布订阅 = 广播电台（电台不知道谁在听）

Vue 用的哪种？
  Vue 2 的 EventBus → 发布订阅
  Vue 2 的 Watcher/Dep → 观察者
  Vue 3 的 reactive → 观察者（effect + track/trigger）
~~~

### Q2：你在项目中用过哪些设计模式？

~~~
1. 单例模式 → 全局状态管理（Pinia store）、全局弹窗
2. 发布订阅 → 组件间通信（mitt）、自定义事件系统
3. 策略模式 → 表单校验规则、折扣计算、路由守卫
4. 代理模式 → Vue3 Proxy 响应式、请求缓存
5. 工厂模式 → axios.create()、API 配置
6. 装饰器模式 → HOC（React）、composable（Vue3）、日志/计时

面试时挑 2-3 个展开讲，结合具体项目场景
~~~

### Q3：策略模式和工厂模式的区别？

~~~
策略模式：重点是"选择算法"
  → 我已经知道要做什么，只是做法不同
  → 例：打几折、用什么校验规则

工厂模式：重点是"创建对象"
  → 我不知道要创建什么，由参数决定
  → 例：创建川菜还是粤菜、创建哪种 API 实例

两者经常一起用：工厂创建对象 + 策略决定行为
~~~

### Q4：Vue3 的 Proxy 和 Vue2 的 defineProperty 有什么区别？（代理模式）

~~~
Vue2 Object.defineProperty：
  逐个属性劫持 → 不能监听新增/删除属性
  不能监听数组下标 → 要重写数组方法（push/pop 等）

Vue3 Proxy：
  代理整个对象 → 能监听所有操作
  惰性代理 → 只在访问时才递归代理子对象
  支持 Map/Set 等集合类型

本质就是代理模式：Proxy 是"代理人"，所有对对象的操作都先经过它
~~~

1. **单例** → 全局只一个实例，闭包存实例或 static 属性
