## 套路一：闭包保存状态（bind / 防抖 / 节流）

这三道题的共同核心：**函数内部用一个变量记住某个状态，这个变量因为闭包不会被销毁。**

### 1. bind

**要记住的逻辑链：**
~~~
我要什么？→ 一个新函数，this 绑死了，参数预设了，还要支持 new 调用
怎么实现？→ 闭包保存三样东西：原函数、this指向、预设参数
new 调用时怎么办？→ 判断 this 是否是新创建的对象，是就用新对象，不是就用绑定的
原型链怎么办？→ 用 Object.create 让 new 出来的实例正确继承原函数的 prototype
~~~

**手写口诀：闭包存原函数，返回新函数，里面判断 new 再 apply，外面接好原型链**

~~~javascript
Function.prototype.myBind = function(this指向, ...预设参数) {
  const 原函数 = this;  // 口诀1：存原函数

  function 绑定函数(...新参数) {  // 口诀2：返回新函数
    // 口诀3：判断是不是 new 调用
    //   普通调用：this instanceof 绑定函数 → false → 用绑定的 this指向
    //   new 调用：this instanceof 绑定函数 → true → 用新创建的对象 this
    const 实际this = this instanceof 绑定函数 ? this : this指向;
    return 原函数.apply(实际this, [...预设参数, ...新参数]);  // 口诀4：apply 一下
  }

  // 口诀5：接好原型链（让 new 出来的实例能访问原函数的 prototype 方法）
  if (原函数.prototype) {
    绑定函数.prototype = Object.create(原函数.prototype);
  }

  return 绑定函数;
};
~~~

**记住这句话：`bind = 闭包存三样 + 判断 new + apply 一下 + Object.create 接原型链`**

**关键点逐行理解：**

~~~javascript
// 1. 为什么用 apply 不用 call？
原函数.apply(实际this, [...预设参数, ...新参数]);
// 用 apply 是因为要合并两个数组（预设参数 + 新参数）
// 也可以写成：原函数.call(实际this, ...预设参数, ...新参数)

// 2. this instanceof 绑定函数 是怎么判断的？
// 普通调用：绑定函数()     → this = undefined → false → 用绑定的 this指向
// new 调用：new 绑定函数() → this = {}（新对象）→ true → 用新对象

// 3. 为什么用 Object.create 而不是直接赋值？
// ❌ 绑定函数.prototype = 原函数.prototype
//    修改绑定函数的 prototype 会影响原函数（同一个引用）
// ✅ 绑定函数.prototype = Object.create(原函数.prototype)
//    创建新对象，__proto__ 指向原函数.prototype，互不影响
~~~

#### 测试

~~~javascript
// ========== 基本绑定 this ==========
function 点菜(菜1, 菜2) {
  console.log(`${this.店名}做了${菜1}和${菜2}`);
}

const 老王饭馆 = { 店名: "老王饭馆" };
const 老王做菜 = 点菜.myBind(老王饭馆, "红烧肉");
老王做菜("麻婆豆腐");
// 老王饭馆做了红烧肉和麻婆豆腐 ✅

// ========== 预设参数 ==========
const 老王做红烧肉 = 点菜.myBind(老王饭馆, "红烧肉");
老王做红烧肉("麻婆豆腐");  // 老王饭馆做了红烧肉和麻婆豆腐 ✅
老王做红烧肉("糖醋里脊");  // 老王饭馆做了红烧肉和糖醋里脊 ✅

// ========== 支持 new 调用 ==========
function 餐厅(名字, 城市) {
  this.名字 = 名字;
  this.城市 = 城市;
}
餐厅.prototype.报名 = function() {
  console.log(`欢迎来到${this.名字}，位于${this.城市}`);
};

const 绑定餐厅 = 餐厅.myBind({ 名字: "假对象" }, "老王饭馆");
const 店 = new 绑定餐厅("北京");
console.log(店.名字);              // "老王饭馆" ✅（预设参数生效）
console.log(店.城市);              // "北京" ✅（新传的参数生效）
店.报名();                         // "欢迎来到老王饭馆，位于北京" ✅
console.log(店 instanceof 餐厅);   // true ✅（原型链正确）
console.log(Object.getPrototypeOf(店) !== 餐厅.prototype);  // true ✅（是副本不是原对象）
~~~

#### 面试追问

~~~
Q：为什么用 apply 不用 call？
A：需要合并两个数组（预设参数 + 新参数），apply 接收数组形式的参数。

Q：为什么用 Object.create 而不是直接 boundFn.prototype = originFn.prototype？
A：直接赋值是引用，修改 boundFn.prototype 上的方法会影响原函数。
   Object.create 创建新对象，__proto__ 指向原函数.prototype，互不影响。

Q：this instanceof boundFn 怎么判断的？
A：new 调用时 this 是新创建的对象，是 boundFn 的实例，所以 instanceof 返回 true。
   普通调用时 this 不是 boundFn 的实例，返回 false。
~~~

### 2. 防抖

**要记住的逻辑链：**
~~~
我要什么？→ 用户停止操作 N 毫秒后才执行（延迟模式）
           或者 第一次触发立即执行，之后 N 毫秒内忽略（立即模式）
怎么实现？→ 闭包存定时器，通过定时器是否为 null 判断是否在冷却期
~~~

**手写口诀：闭包存定时器，延迟模式等停了才执行，立即模式第一次就执行然后冷却**

#### 两种模式的区别

~~~
延迟执行（立即执行 = false）：
  触发 → 等等... → 停了300ms → 执行
  比喻：顾客疯狂按门铃，等他停了才开门

立即执行（立即执行 = true）：
  触发 → 立即执行 → 然后300ms内忽略所有触发
  比喻：顾客第一次按门铃立刻开门，之后再按都不理，等300ms才重新响应

什么时候用哪个？
  搜索框输入 → 延迟执行（等用户打完字再搜）
  按钮提交   → 立即执行（第一次点击就提交，防止重复点击）
  窗口 resize → 延迟执行（等用户停了再计算布局）
~~~

#### 完整版（支持立即执行）

**核心思路：一个 setTimeout 覆盖两种模式。setTimeout 始终存在但不一定执行回调，立即执行放在 setTimeout 外面。**

~~~javascript
function debounce(回调, 延迟, 立即执行 = false) {
  let 定时器 = null;

  return function(...参数) {
    const 是否立即 = 立即执行 && 定时器 === null;  // 立即模式 + 不在冷却期

    clearTimeout(定时器);

    // 一个 setTimeout 覆盖两种模式
    定时器 = setTimeout(() => {
      定时器 = null;                    // 冷却结束
      if (!立即执行) 回调.apply(this, 参数);  // 延迟模式才执行回调，立即模式跳过
    }, 延迟);

    if (是否立即) 回调.apply(this, 参数);     // 立即模式：第一次触发立即执行
  };
}
~~~

#### 测试

~~~javascript
// ========== 延迟模式 ==========
const 搜索 = debounce((词) => console.log(`搜索：${词}`), 300);
搜索("红"); 搜索("红烧"); 搜索("红烧肉");
// 300ms 后只输出一次：搜索：红烧肉 ✅

// ========== 立即模式 ==========
const 提交 = debounce((数据) => console.log(`提交：${数据}`), 2000, true);
提交("订单1");  // 立即输出：提交：订单1 ✅
提交("订单2");  // 冷却中，忽略 ✅
提交("订单3");  // 冷却中，忽略 ✅
// 2秒后冷却结束
提交("订单4");  // 立即输出：提交：订单4 ✅
~~~

#### 最终口诀

~~~
防抖完整版 = 闭包存定时器 + 一个 setTimeout 覆盖两种模式

  clearTimeout → setTimeout（始终存在）
    延迟模式：300ms后执行回调
    立即模式：300ms后只清空定时器（不执行回调）

  立即执行（放在 setTimeout 外面）：
    定时器为null + 立即模式 → 立即执行回调

一行话总结：
  setTimeout 内部控制"延迟模式的回调"
  setTimeout 外部控制"立即模式的回调"
  用一个 const 是否立即 = 立即执行 && 定时器 === null 统一判断
~~~

#### 面试追问

~~~
Q：防抖和节流的区别？
A：防抖是"停了才执行"（你一直触发就一直不执行），节流是"每隔 N 毫秒最多执行一次"（你一直触发也会每隔 N ms 执行一次）。

Q：立即执行模式的场景？
A：按钮提交防重复点击（第一次点击立即提交，之后忽略）。

Q：为什么清除定时器后再设置？
A：确保每次触发都重置等待时间，这样才能实现"停止 N 毫秒后才执行"的效果。
~~~

### 3. 节流

**要记住的逻辑链：**
~~~
我要什么？→ 每隔 N 毫秒最多执行一次
怎么实现？→ 记录上次执行时间，当前时间减去上次时间够了才执行
用什么保存上次时间？→ 闭包
~~~

**手写口诀：闭包存上次时间，间隔够了才执行**

~~~javascript
function throttle(回调, 间隔) {
  let 上次时间 = 0;  // 口诀1：闭包存上次时间

  return function(...参数) {  // 口诀2：返回新函数
    const 现在 = Date.now();
    if (现在 - 上次时间 >= 间隔) {  // 口诀3：间隔够了吗？
      上次时间 = 现在;  // 够了就更新时间
      回调.apply(this, 参数);  // 然后执行
    }
  };
}
~~~

**记住这一句话：`节流 = 闭包存时间戳 + 差值够了才执行`**

#### 测试

~~~javascript
// ========== 基本测试 ==========
let 次数 = 0;
const 节流函数 = throttle(() => {
  次数++;
  console.log(`执行第${次数}次`);
}, 300);

// 快速连续调用5次
节流函数();  // 执行第1次 ✅（第一次立即执行，因为 上次时间=0，差值一定>=间隔）
节流函数();  // 忽略（300ms内）
节流函数();  // 忽略（300ms内）
节流函数();  // 忽略（300ms内）
节流函数();  // 忽略（300ms内）

// ========== 模拟时间间隔测试 ==========
const 滚动处理 = throttle((位置) => {
  console.log(`处理滚动到 ${位置}`);
}, 1000);

滚动处理(100);   // 处理滚动到 100 ✅（首次立即执行）
// ... 等待1200ms ...
滚动处理(500);   // 处理滚动到 500 ✅（间隔够了）
滚动处理(600);   // 忽略（1000ms内）
~~~

#### 面试追问

~~~
Q：和 debounce 的区别？
A：debounce 重置计时（你一直触发就一直不执行），throttle 按固定间隔执行（你一直触发也会每隔 N ms 执行一次）。

Q：首次为什么立即执行？
A：因为初始值上次时间 = 0，Date.now() - 0 一定 >= 间隔，所以第一次调用立即执行。
~~~

### 三个对比记忆

| | bind | 防抖 | 节流 |
|---|---|---|---|
| 闭包存什么 | 原函数 + this + 预设参数 | 定时器 ID | 上次执行时间 |
| 返回什么 | 新函数 | 新函数 | 新函数 |
| 核心操作 | apply 一下 | clearTimeout + setTimeout | Date.now() 判断间隔 |

## 套路二：计数器模式（Promise.all / Promise.race / 并发控制）

这三道题的共同核心：**用一个数字（计数器）跟踪"完成了几个"或"正在执行几个"。**

### 4. Promise.all

**要记住的逻辑链：**
~~~
我要什么？→ 全部成功才 resolve，有一个失败就 reject
怎么实现？→ 计数器 +1，够了就 resolve
怎么保证顺序？→ 按索引存结果，不按完成顺序
~~~

**手写口诀：计数器 + 索引存结果 + 全部完成才 resolve**

~~~javascript
function promiseAll(数组) {
  return new Promise((resolve, reject) => {
    const 结果们 = [];     // 口诀1：结果数组
    let 完成数 = 0;        // 口诀2：计数器

    if (数组.length === 0) return resolve([]);

    数组.forEach((项, 索引) => {
      Promise.resolve(项).then(
        值 => {
          结果们[索引] = 值;        // 口诀3：按索引存（保证顺序）
          if (++完成数 === 数组.length) {  // 口诀4：全完成了？
            resolve(结果们);
          }
        },
        原因 => reject(原因)  // 口诀5：有一个失败就 reject
      );
    });
  });
}
~~~

**记住这一句话：`Promise.all = 计数器 + 索引存结果 + 全完成 resolve，任一失败 reject`**

#### 测试

~~~javascript
// ========== 全部成功 ==========
promiseAll([
  Promise.resolve("红烧肉"),
  Promise.resolve("麻婆豆腐"),
  Promise.resolve("糖醋里脊")
]).then(结果 => console.log(结果));
// ["红烧肉", "麻婆豆腐", "糖醋里脊"] ✅（顺序和传入一致）

// ========== 有一个失败 ==========
promiseAll([
  Promise.resolve("红烧肉"),
  Promise.reject(new Error("麻婆豆腐做砸了")),
  Promise.resolve("糖醋里脊")
]).then(结果 => console.log(结果))
  .catch(错误 => console.log(错误.message));
// 麻婆豆腐做砸了 ✅（立即 reject，不等其他的）

// ========== 空数组 ==========
promiseAll([]).then(结果 => console.log(结果));
// [] ✅

// ========== 不同完成时间（顺序仍然正确） ==========
function 延时(ms, 值) {
  return new Promise(r => setTimeout(() => r(值), ms));
}
promiseAll([延时(300, "慢菜"), 延时(100, "快菜"), 延时(200, "中菜")])
  .then(结果 => console.log(结果));
// ["慢菜", "快菜", "中菜"] ✅（按传入顺序，不是完成顺序）
~~~

#### 面试追问

~~~
Q：如何保证结果顺序？
A：用索引存结果（results[index] = value），不按完成顺序存储，按传入顺序排列。

Q：有一个失败时，其他成功的怎么办？
A：直接 reject，不等其他的。成功的会被忽略（Promise 的状态只能变一次）。
~~~

### 5. Promise.race

**要记住的逻辑链：**
~~~
我要什么？→ 谁先完成（成功或失败）就用谁的结果
怎么实现？→ 每个都注册 .then(resolve, reject)，第一个完成的就生效
~~~

**手写口诀：每个都 then，传同一个 resolve 和 reject**

~~~javascript
function promiseRace(数组) {
  return new Promise((resolve, reject) => {
    数组.forEach(项 => {
      Promise.resolve(项).then(resolve, reject);  // 就这一行
    });
  });
}
~~~

**记住这一句话：`Promise.race = 遍历数组，每个都 .then(resolve, reject)`**

#### 测试

~~~javascript
// ========== 谁快用谁（成功） ==========
function 延时(ms, 值) {
  return new Promise(r => setTimeout(() => r(值), ms));
}

promiseRace([延时(300, "慢菜"), 延时(100, "快菜"), 延时(200, "中菜")])
  .then(结果 => console.log(结果));
// 快菜 ✅（100ms 的最快）

// ========== 谁快用谁（失败） ==========
promiseRace([延时(300, "慢菜"), Promise.reject(new Error("快速失败"))])
  .then(结果 => console.log(结果))
  .catch(错误 => console.log(错误.message));
// 快速失败 ✅（reject 比 resolve 快）

// ========== 空数组 ==========
promiseRace([]).then(结果 => console.log(结果));
// 永远 pending（没有东西可以 resolve 或 reject）

// ========== 实际用途：请求超时 ==========
const 请求 = 延时(5000, "数据");
const 超时 = new Promise((_, reject) => setTimeout(() => reject(new Error("超时")), 2000));

promiseRace([请求, 超时])
  .then(数据 => console.log(数据))
  .catch(错误 => console.log(错误.message));
// 超时 ✅（2000ms 的超时比 5000ms 的请求快）
~~~

#### 面试追问

~~~
Q：Promise.race 空数组会怎样？
A：永远 pending。因为没有任何 Promise 可以 resolve 或 reject，返回的 Promise 永远不会改变状态。

Q：race 的实际用途？
A：请求超时控制（race 一个正常请求和一个超时 Promise）。
~~~

### 6. 并发控制

**要记住的逻辑链：**
~~~
我要什么？→ 最多同时 N 个任务，做完了再从队列里取下一个
怎么实现？→ 计数器跟踪正在执行的数量 + 一个等待队列
满了怎么办？→ await 一个 Promise，把 resolve 存到队列里
完成了怎么办？→ 计数器 -1，从队列里取一个 resolve 执行
~~~

**手写口诀：计数器 + 等待队列 + 满了就 await，完了就 shift**

~~~javascript
class 并发控制器 {
  constructor(最大并发数) {
    this.最大并发数 = 最大并发数;
    this.正在执行数 = 0;       // 口诀1：计数器
    this.等待队列 = [];         // 口诀2：等待队列
  }

  async 添加任务(异步任务) {
    if (this.正在执行数 >= this.最大并发数) {  // 口诀3：满了？
      await new Promise(resolve => this.等待队列.push(resolve));  // 排队等
    }

    this.正在执行数++;  // 口诀4：计数器 +1
    try {
      return await 异步任务();
    } finally {
      this.正在执行数--;  // 口诀5：计数器 -1
      if (this.等待队列.length > 0) {
        this.等待队列.shift()();  // 口诀6：唤醒下一个
      }
    }
  }
}
~~~

**记住这一句话：`并发控制 = 计数器 + 队列 + 满了 await 排队 + 完了 shift 唤醒`**

#### 测试

~~~javascript
const 控制器 = new 并发控制器(2);  // 最多同时2个

let 当前并发 = 0;
let 最大并发记录 = 0;

function 做菜(菜名, 耗时) {
  return () => new Promise(resolve => {
    当前并发++;
    最大并发记录 = Math.max(最大并发记录, 当前并发);
    console.log(`开始做${菜名}（并发：${当前并发}）`);
    setTimeout(() => {
      当前并发--;
      console.log(`✅ ${菜名}做好了`);
      resolve(菜名);
    }, 耗时);
  });
}

// 提交4个任务，但最多同时2个
const 任务们 = [
  控制器.添加任务(做菜("红烧肉", 500)),
  控制器.添加任务(做菜("麻婆豆腐", 300)),
  控制器.添加任务(做菜("糖醋里脊", 200)),
  控制器.添加任务(做菜("宫保鸡丁", 400)),
];

Promise.all(任务们).then(结果们 => {
  console.log("全部完成：", 结果们);
  console.log("最大并发记录：", 最大并发记录);  // 2 ✅（没有超过并发限制）
});
// 输出顺序：
// 开始做红烧肉（并发：1）
// 开始做麻婆豆腐（并发：2）
// （300ms后）✅ 麻婆豆腐做好了 → 开始做糖醋里脊（并发：2）
// （200ms后）✅ 糖醋里脊做好了 → 开始做宫保鸡丁（并发：2）
// （400ms后）✅ 红烧肉做好了
// （400ms后）✅ 宫保鸡丁做好了
// 全部完成：["红烧肉", "麻婆豆腐", "糖醋里脊", "宫保鸡丁"]
// 最大并发记录：2 ✅
~~~

#### 面试追问

~~~
Q：为什么用 await + Promise 而不是回调？
A：await 能让代码在"满了"的时候暂停，等有空位再继续，代码更清晰。

Q：finally 的作用？
A：无论任务成功还是失败，都要把计数器减1并唤醒下一个，确保不会卡死。
~~~

### 三个对比记忆

| | Promise.all | Promise.race | 并发控制 |
|---|---|---|---|
| 核心机制 | 计数器 | 无（谁快用谁） | 计数器 + 队列 |
| 成功条件 | 全部成功 | 第一个完成 | 每个都执行 |
| 失败条件 | 有一个失败 | 第一个失败 | 捕获每个的错误 |
| 口诀 | 索引存结果 | 每个都 then | 满了 await，完了 shift |

## 套路三：状态机（Promise）

### 7. Promise

**要记住的逻辑链：**
~~~
核心是什么？→ 一个有三种状态的对象
三种状态？→ pending → fulfilled / rejected（只能变一次）
.then 做什么？→ 如果已经完成就立即执行回调，如果还在 pending 就存起来
链式调用怎么做？→ .then 返回一个新的 Promise
~~~

**手写步骤（先记住骨架，再填肉）：**

~~~javascript
// 第1步：三个常量
const PENDING = "pending";
const FULFILLED = "fulfilled";
const REJECTED = "rejected";

// 第2步：类骨架
class myPromise {
  constructor(执行器) {
    // 状态
    this.状态 = PENDING;
    this.值 = undefined;
    this.原因 = undefined;
    // 回调队列
    this.成功队列 = [];
    this.失败队列 = [];

    // resolve 函数
    const resolve = (值) => {
      if (this.状态 !== PENDING) return;  // 状态只能变一次
      this.状态 = FULFILLED;
      this.值 = 值;
      this.成功队列.forEach(fn => fn(值));  // 通知所有等待的回调
    };

    // reject 函数
    const reject = (原因) => {
      if (this.状态 !== PENDING) return;
      this.状态 = REJECTED;
      this.原因 = 原因;
      this.失败队列.forEach(fn => fn(原因));
    };

    // 执行执行器
    try { 执行器(resolve, reject); } catch (e) { reject(e); }
  }

  // 第3步：then 方法
  then(onFulfilled, onRejected) {
    // 值穿透：没传回调就透传
    onFulfilled = typeof onFulfilled === "function" ? onFulfilled : v => v;
    onRejected = typeof onRejected === "function" ? onRejected : e => { throw e; };

    // 返回新 Promise（链式调用的关键）
    const p2 = new myPromise((resolve, reject) => {
      const 处理 = (回调, 值) => {
        queueMicrotask(() => {  // 异步执行（微任务）
          try {
            const r = 回调(值);
            if (r === p2) throw new TypeError("循环引用");
            r instanceof myPromise ? r.then(resolve, reject) : resolve(r);
          } catch (e) { reject(e); }
        });
      };

      if (this.状态 === FULFILLED) 处理(onFulfilled, this.值);
      else if (this.状态 === REJECTED) 处理(onRejected, this.原因);
      else {
        this.成功队列.push(v => 处理(onFulfilled, v));
        this.失败队列.push(e => 处理(onRejected, e));
      }
    });

    return p2;
  }

  // 第4步：catch 和 finally
  catch(fn) { return this.then(null, fn); }

  finally(fn) {
    return this.then(
      v => myPromise.resolve(fn()).then(() => v),
      e => myPromise.resolve(fn()).then(() => { throw e; })
    );
  }

  // 第5步：静态方法
  static resolve(v) { return v instanceof myPromise ? v : new myPromise(r => r(v)); }
  static reject(e)  { return new myPromise((_, r) => r(e)); }
}
~~~

**背诵口诀：**
~~~
Promise = 状态机（pending/fulfilled/rejected）+ 回调队列 + 链式调用

constructor：
  1. 初始化状态为 pending
  2. 定义 resolve：状态变 fulfilled，通知成功队列
  3. 定义 reject：状态变 rejected，通知失败队列
  4. 执行执行器，try...catch

then：
  1. 值穿透处理
  2. 返回新 Promise
  3. 根据当前状态决定：立即执行 or 存入队列
  4. 微任务异步执行
  5. 回调返回值如果是 Promise 就等待，否则直接 resolve
~~~

#### 测试

~~~javascript
// ========== 基本 resolve ==========
new myPromise(resolve => resolve("红烧肉做好了"))
  .then(v => console.log(v));
// 红烧肉做好了 ✅

// ========== 基本 reject ==========
new myPromise((_, reject) => reject(new Error("做砸了")))
  .then(v => console.log(v))
  .catch(e => console.log(e.message));
// 做砸了 ✅

// ========== 链式调用 ==========
new myPromise(r => r("红烧肉"))
  .then(v => { console.log(v); return "麻婆豆腐"; })
  .then(v => { console.log(v); return "糖醋里脊"; })
  .then(v => console.log(v));
// 红烧肉 ✅
// 麻婆豆腐 ✅
// 糖醋里脊 ✅

// ========== then 返回 Promise ==========
new myPromise(r => r("开始"))
  .then(v => {
    console.log(v);
    return new myPromise(r => setTimeout(() => r("异步结果"), 100));
  })
  .then(v => console.log(v));
// 开始 ✅
// （100ms后）异步结果 ✅

// ========== 值穿透 ==========
new myPromise(r => r("穿透测试"))
  .then()         // 不传回调，值穿透
  .then()
  .then(v => console.log(v));
// 穿透测试 ✅

// ========== 状态只能变一次 ==========
new myPromise(r => {
  r("第一次");
  r("第二次");  // 被忽略
  // reject("失败");  // 也被忽略
}).then(v => console.log(v));
// 第一次 ✅（只触发一次）

// ========== 执行器抛错 ==========
new myPromise(() => { throw new Error("执行器出错"); })
  .then(v => console.log(v))
  .catch(e => console.log(e.message));
// 执行器出错 ✅
~~~

#### 面试追问

~~~
Q：then 为什么返回新 Promise？
A：实现链式调用。每个 .then 返回一个新 Promise，这样可以继续 .then。

Q：为什么用 queueMicrotask 而不是 setTimeout？
A：微任务优先级高于宏任务，确保回调尽快执行。Promise 规范要求异步执行但要尽快。

Q：值穿透是什么？
A：.then() 不传回调时，值直接传给下一个 .then。原理是默认回调 v => v，原样返回。
~~~

## 套路四：递归/遍历（深拷贝 / reduce / 类型判断）

### 8. 深拷贝

**要记住的逻辑链：**
~~~
核心问题？→ 对象可能嵌套任意层，可能有循环引用
怎么递归？→ 遍历每个属性，如果是对象就递归调用自己
循环引用怎么办？→ 用 WeakMap 记录「原始→拷贝」的映射，下次遇到直接返回
特殊类型怎么办？→ Date/RegExp/Map/Set 各自单独处理
~~~

**手写口诀：先判基本类型，再查 WeakMap，再处理特殊类型，最后递归普通对象**

~~~javascript
function deepClone(对象, 引用映射 = new WeakMap()) {
  // 口诀1：基本类型直接返回
  if (对象 === null || typeof 对象 !== "object") return 对象;

  // 口诀2：循环引用查 WeakMap
  if (引用映射.has(对象)) return 引用映射.get(对象);

  // 口诀3：特殊类型单独处理
  if (对象 instanceof Date)   return new Date(对象);
  if (对象 instanceof RegExp) return new RegExp(对象.source, 对象.flags);
  if (对象 instanceof Map) {
    const 拷贝 = new Map();
    引用映射.set(对象, 拷贝);
    对象.forEach((值, 键) => 拷贝.set(deepClone(键, 引用映射), deepClone(值, 引用映射)));
    return 拷贝;
  }
  if (对象 instanceof Set) {
    const 拷贝 = new Set();
    引用映射.set(对象, 拷贝);
    对象.forEach(值 => 拷贝.add(deepClone(值, 引用映射)));
    return 拷贝;
  }

  // 口诀4：普通对象/数组，先存 WeakMap 再递归
  const 拷贝 = Array.isArray(对象) ? [] : {};
  引用映射.set(对象, 拷贝);  // 先存！防止循环引用

  for (const 键 of Reflect.ownKeys(对象)) {
    拷贝[键] = deepClone(对象[键], 引用映射);  // 递归
  }

  return 拷贝;
}
~~~

// ========== 普通对象（深拷贝后互不影响） ==========

#### 面试追问

~~~
Q：为什么用 WeakMap 而不是 Map？
A：WeakMap 的键是弱引用，不阻止垃圾回收。当原始对象没有其他引用时，WeakMap 里的记录也会自动清除，避免内存泄漏。

Q：为什么用 Reflect.ownKeys 而不是 Object.keys？
A：Reflect.ownKeys 能拷贝 Symbol 键和不可枚举属性。Object.keys 只能拷贝可枚举的字符串键。

Q：JSON.parse(JSON.stringify(obj)) 有什么问题？
A：丢失 undefined/函数/Symbol、不能处理循环引用、不能处理 Date/RegExp/Map/Set。
~~~

### 9. reduce

**要记住的逻辑链：**
~~~
reduce 做什么？→ 从左到右遍历数组，用累加器把数组浓缩成一个值
两个关键？→ 1. 有没有传初始值  2. 从第几个开始遍历
~~~

**手写口诀：有初始值从 0 开始，没有就用第一个元素从 1 开始**

~~~javascript
Array.prototype.myReduce = function(回调, 初始值) {
  let 累加器;
  let 起始索引;

  if (初始值 !== undefined) {
    累加器 = 初始值;    // 口诀1：有初始值
    起始索引 = 0;       // 从第 0 个开始
  } else {
    if (this.length === 0) throw new TypeError("空数组没有初始值");
    累加器 = this[0];   // 口诀2：没有初始值就用第一个
    起始索引 = 1;       // 从第 1 个开始
  }

  for (let i = 起始索引; i < this.length; i++) {
    // 跳过稀疏数组的空位
    if (i in this) {
      累加器 = 回调(累加器, this[i], i, this);  // 口诀3：每次更新累加器
    }
  }

  return 累加器;  // 口诀4：返回累加器
};
~~~

#### 测试

### 10. 类型判断

**要记住的逻辑链：**
~~~
typeof 的问题？→ null 返回 "object"，数组/Date/RegExp 都返回 "object"
最佳方案？→ Object.prototype.toString.call(值) 返回 "[object 类型名]"
怎么提取类型名？→ slice(8, -1) 截取中间部分
~~~

**手写口诀：null 单独判，基本类型用 typeof，其他用 toString**

~~~javascript
function typeOf(值) {
  if (值 === null) return "null";           // 口诀1：null 单独判
  if (Array.isArray(值)) return "array";    // 口诀2：数组单独判

  const t = typeof 值;
  if (t !== "object" && t !== "function") return t;  // 口诀3：基本类型用 typeof

  return Object.prototype.toString.call(值)  // 口诀4：其他用 toString
    .slice(8, -1)
    .toLowerCase();
}
~~~

Q：typeof null 返回什么？

## 套路五：映射表（EventEmitter / LRU）

### 11. EventEmitter

**要记住的逻辑链：**
~~~
核心数据结构？→ { 事件名: [回调1, 回调2, ...] }
on 做什么？→ 往数组里 push 回调
emit 做什么？→ 找到数组，forEach 执行每个回调
off 做什么？→ 从数组里 filter 掉某个回调
once 做什么？→ 包装一层，执行一次后自动 off
~~~

**手写口诀：事件名映射到回调数组，on push，emit forEach，off filter，once 包装**

~~~javascript
class EventEmitter {
  constructor() {
    this.事件映射 = {};  // 口诀1：映射表
  }

  on(事件名, 回调) {
    (this.事件映射[事件名] ||= []).push(回调);  // 口诀2：push
    return this;
  }

  off(事件名, 回调) {
    if (!this.事件映射[事件名]) return this;
    this.事件映射[事件名] = this.事件映射[事件名].filter(cb => cb !== 回调);  // 口诀3：filter
    return this;
  }

  once(事件名, 回调) {
    const 包装 = (...args) => { 回调(...args); this.off(事件名, 包装); };  // 口诀4：包装
    return this.on(事件名, 包装);
  }

  emit(事件名, ...参数) {
    if (!this.事件映射[事件名]) return false;
    this.事件映射[事件名].forEach(cb => cb(...参数));  // 口诀5：forEach
    return true;
  }
}
~~~

#### 测试

~~~javascript

广播.on("菜做好了", (菜名) => console.log(`上菜：${菜名}`));

// 结账：记录红烧肉 ✅

// 结账：记录麻婆豆腐 ✅

// ========== off（取消订阅） ==========
const 通知结账 = (菜名) => console.log(`结账：记录${菜名}`);
广播.off("菜做好了", 通知结账);  // 移除的不是同一个引用，没效果
// 用同一个引用才能移除

// ========== off 用同一个引用 ==========
function 通知(菜名) { console.log(`通知：${菜名}`); }
广播.on("新菜", 通知);
广播.emit("新菜", "糖醋里脊");  // 通知：糖醋里脊 ✅
广播.off("新菜", 通知);
广播.emit("新菜", "宫保鸡丁");  // 没有输出 ✅（已被移除）

// ========== once（只触发一次） ==========
广播.once("打烊", () => console.log("打烊了"));
广播.emit("打烊");  // 打烊了 ✅
广播.emit("打烊");  // 没有输出 ✅（once 已自动取消）

// ========== emit 不存在的事件 ==========
const 结果 = 广播.emit("不存在的事件");
console.log(结果);  // false ✅

// ========== emit 存在的事件 ==========
广播.on("测试", () => {});
const 结果2 = 广播.emit("测试");
console.log(结果2);  // true ✅

// ========== 链式调用 ==========
广播.on("链式", () => {}).on("链式", () => {});
console.log(广播.事件映射["链式"].length);  // 2 ✅
~~~

#### 面试追问

~~~
Q：off 为什么要比较 _original？
A：once 注册的回调是一个包装函数，用户 off 时传的是原始回调。需要通过 _original 属性匹配到包装函数才能正确移除。

Q：emit 返回值的意义？
A：返回 true 表示事件有监听器在处理，返回 false 表示没有监听器。可以用来判断事件是否被消费。
~~~

### 12. LRU

**要记住的逻辑链：**
~~~
核心数据结构？→ Map（利用 Map 的插入顺序特性）
get 做什么？→ 没有返回 -1，有就删掉再重新插入（移到最新位置）
put 做什么？→ 有就先删，再插入，超出容量就删 Map 的第一个（最久没用的）
~~~

**手写口诀：get 删了重插，put 有就先删再插，满了删第一个**

~~~javascript
class LRUCache {
  constructor(容量) {
    this.容量 = 容量;
    this.缓存 = new Map();  // 口诀1：用 Map
  }

  get(键) {
    if (!this.缓存.has(键)) return -1;  // 口诀2：没有返回 -1

    const 值 = this.缓存.get(键);
    this.缓存.delete(键);    // 口诀3：删掉
    this.缓存.set(键, 值);   // 口诀4：重新插入（移到最新）
    return 值;
  }

  put(键, 值) {
    if (this.缓存.has(键)) {
      this.缓存.delete(键);  // 口诀5：有就先删
    }

    this.缓存.set(键, 值);   // 口诀6：插入

    if (this.缓存.size > this.容量) {  // 口诀7：满了？
      this.缓存.delete(this.缓存.keys().next().value);  // 删第一个（最久没用的）
    }
  }
}
~~~

#### 测试

~~~javascript
const 缓存 = new LRUCache(3);

// ========== 基本 put + get ==========
缓存.put("红烧肉", 38);
缓存.put("麻婆豆腐", 22);
缓存.put("糖醋里脊", 45);
console.log(缓存.get("红烧肉"));   // 38 ✅
console.log(缓存.get("麻婆豆腐")); // 22 ✅

// ========== get 会更新"最近使用" ==========
console.log(缓存.get("红烧肉"));   // 38 ✅（红烧肉被移到最新）

// ========== 超出容量，删除最久没用的 ==========
缓存.put("宫保鸡丁", 35);          // 超出容量
// 当前缓存顺序：糖醋里脊（最久）→ 麻婆豆腐 → 红烧肉（最新）
console.log(缓存.get("麻婆豆腐"));  // 22 ✅（还在）
console.log(缓存.get("糖醋里脊"));  // -1 ✅（已被删除）
console.log(缓存.get("红烧肉"));    // 38 ✅（还在）

// ========== 覆盖已有键 ==========
缓存.put("红烧肉", 99);            // 红烧肉已存在，先删再插
console.log(缓存.get("红烧肉"));    // 99 ✅（值更新了）

// ========== get 不存在的键 ==========
console.log(缓存.get("不存在"));    // -1 ✅

// ========== 容量为1 ==========
const 小缓存 = new LRUCache(1);
小缓存.put("a", 1);
小缓存.put("b", 2);  // 超出容量，删掉 a
console.log(小缓存.get("a"));  // -1 ✅
console.log(小缓存.get("b"));  // 2 ✅
~~~

#### 面试追问

~~~
Q：为什么用 Map 而不是 Object？
A：Map 有 size 属性、有插入顺序保证、键可以是任意类型。Object 的键是字符串，遍历顺序不完全可靠。

Q：get 为什么要 delete 再 set？
A：Map 的遍历顺序是插入顺序。delete + set 把这个键移到了最新位置，这样 keys().next().value 取到的就是最久没用的。

Q：LRU 和 LFU 的区别？
A：LRU（Least Recently Used）是"最近最少使用"，看最后一次使用时间。LFU（Least Frequently Used）是"最不经常使用"，看使用频率。
~~~

## 13. call / apply

**要记住的逻辑链：**
~~~
call 做什么？→ 临时把函数挂到目标对象上执行
步骤？→ 挂上去 → 执行 → 删掉
apply 区别？→ 参数是数组
~~~

**手写口诀：给目标对象挂个临时方法（用 Symbol 防冲突），执行，删掉**

~~~javascript
Function.prototype.myCall = function(this指向, ...参数们) {
  this指向 = this指向 == null ? globalThis : Object(this指向);

  const 唯一键 = Symbol();             // 口诀1：Symbol 防冲突
  this指向[唯一键] = this;             // 口诀2：挂上去

  const 结果 = this指向[唯一键](...参数们);  // 口诀3：执行

  delete this指向[唯一键];             // 口诀4：删掉
  return 结果;
};

Function.prototype.myApply = function(this指向, 参数数组) {
  this指向 = this指向 == null ? globalThis : Object(this指向);

  const 唯一键 = Symbol();
  this指向[唯一键] = this;

  const 结果 = 参数数组
    ? this指向[唯一键](...参数数组)   // 唯一区别：展开数组
    : this指向[唯一键]();

  delete this指向[唯一键];
  return 结果;
};
~~~

#### 测试

~~~javascript
// ========== 基本 call ==========
function 点菜(菜1, 菜2) {
  return `${this.店名}做了${菜1}和${菜2}`;
}
const 老王饭馆 = { 店名: "老王饭馆" };
console.log(点菜.myCall(老王饭馆, "红烧肉", "麻婆豆腐"));
// 老王饭馆做了红烧肉和麻婆豆腐 ✅

// ========== 基本 apply ==========
console.log(点菜.myApply(老王饭馆, ["红烧肉", "麻婆豆腐"]));
// 老王饭馆做了红烧肉和麻婆豆腐 ✅

// ========== call 不会污染目标对象 ==========
console.log(Object.keys(老王饭馆));  // ["店名"] ✅（没有临时属性残留）

// ========== this 指向 null 时 ==========
console.log(点菜.myCall(null, "红烧肉", "麻婆豆腐"));
// undefined做了红烧肉和麻婆豆腐 ✅（this 指向 globalThis）

// ========== this 指向基本类型 ==========
function 获取this类型() { return typeof this; }
console.log(获取this类型.myCall(42));    // "object" ✅（Number 对象）
console.log(获取this类型.myCall("abc")); // "object" ✅（String 对象）

// ========== 返回值 ==========
function 计算(甲, 乙) { return 甲 + 乙; }
console.log(计算.myCall(null, 3, 5));   // 8 ✅
console.log(计算.myApply(null, [3, 5])); // 8 ✅

// ========== apply 无参数 ==========
function 零参数() { return "无参"; }
console.log(零参数.myApply(null));      // "无参" ✅
console.log(零参数.myApply(null, undefined)); // "无参" ✅
~~~

#### 面试追问

~~~
Q：this 指向 null 时怎么办？
A：指向 globalThis（浏览器中是 window，Node.js 中是 global）。

Q：this 指向基本类型时怎么办？
A：用 Object() 包装为对象（42 → Number 对象，"abc" → String 对象）。

Q：为什么用 Symbol 而不是普通字符串做临时键？
A：防止覆盖目标对象上已有的属性。Symbol 是唯一的，不会和已有属性冲突。
~~~

## 附录一：事件循环（Event Loop）

### 为什么需要事件循环？

~~~
JavaScript 是单线程的 → 一次只能做一件事
但浏览器/Node.js 有大量异步操作（网络请求、定时器、用户交互）
→ 需要一个机制来协调"同步代码"和"异步代码"的执行顺序
→ 这个机制就是事件循环
~~~

**手写口诀：同步先跑完，微任务插队，宏任务排队**

### 任务队列的分类

| 类型 | 包含 |
|---|---|
| 同步任务 | 直接执行的代码，一行一行来 |
| 微任务（microtask） | `Promise.then` / `catch` / `finally`、`queueMicrotask`、`await` 后面的代码、`MutationObserver` |
| 宏任务（macrotask） | `setTimeout` / `setInterval`、`requestAnimationFrame`、事件监听器回调、I/O、`MessageChannel` |

### 执行顺序规则

~~~
1. 执行所有同步代码（主线程栈）
2. 清空微任务队列（所有微任务，包括执行微任务时新产生的微任务）
3. 取一个宏任务执行
4. 回到第 2 步，循环
~~~

**记住这句话：`一轮事件循环 = 同步 → 所有微任务 → 一个宏任务`**

### 经典面试题

~~~javascript
async function async1() {
  console.log("async1 start");
  await async2();
  console.log("async1 end");  // 微任务
}
async function async2() {
  console.log("async2");
}

console.log("script start");
setTimeout(() => console.log("setTimeout"), 0);
async1();
new Promise(resolve => {
  console.log("promise1");
  resolve();
}).then(() => console.log("promise2"));
console.log("script end");
~~~

**答案：**

~~~
script start
async1 start
async2
promise1
script end
async1 end
promise2
setTimeout
~~~

**逐步分析：**

~~~
第1轮事件循环：

  同步阶段：
    → 输出 "script start"
    → 注册 setTimeout（放入宏任务队列）
    → 调用 async1()
      → 输出 "async1 start"
      → await async2() → 输出 "async2"
      → await 把后面的 "async1 end" 切成微任务
    → new Promise 的执行器是同步的 → 输出 "promise1"
    → resolve() → 注册 .then 回调（放入微任务队列）
    → 输出 "script end"

  清空微任务：
    → 执行 async1 的 await 后续 → 输出 "async1 end"
    → 执行 Promise.then → 输出 "promise2"

  取宏任务：
    → 执行 setTimeout 回调 → 输出 "setTimeout"
~~~

### 微任务优先级

~~~javascript
Promise.resolve().then(() => {
  console.log("微任务1");
  Promise.resolve().then(() => console.log("微任务1-1"));
}).then(() => console.log("微任务1-2"));

Promise.resolve().then(() => console.log("微任务2"));

// 输出：
// 微任务1
// 微任务2
// 微任务1-1
// 微任务1-2

// 为什么 1-2 在 1-1 之后？
// 因为 1-2 依赖 1 的回调执行完才能进入队列
// 而 1-1 是 1 的回调内部同步注册的微任务
~~~

## 附录二：this 指向

### 速查表

| 场景 | this 指向 |
|---|---|
| 普通函数调用 `fn()` | `undefined`（严格模式）/ `globalThis`（非严格模式） |
| 对象方法 `obj.fn()` | `obj` |
| 箭头函数 `() => {}` | 定义时外层的 this（继承，不可改变） |
| `new Foo()` | 新创建的实例对象 |
| `call` / `apply` / `bind` | 第一个参数指定的对象 |
| 事件处理器 `el.onclick = fn` | 触发事件的元素 `el` |

### 经典面试题

~~~javascript
const obj = {
  name: "餐厅",

  cook() {
    console.log(this.name);  // "餐厅"（this = obj）

    function inner() {
      console.log(this.name);  // undefined（普通函数，this 丢失）
    }
    inner();

    const arrow = () => {
      console.log(this.name);  // "餐厅"（箭头函数继承外层 this）
    };
    arrow();
  },

  cookArrow: () => {
    console.log(this.name);  // undefined（箭头函数，外层 this 是全局/undefined）
  }
};

obj.cook();      // "餐厅" → undefined → "餐厅"
obj.cookArrow(); // undefined
~~~

**核心区别：** 普通函数的 this 在调用时确定（谁调用指向谁），箭头函数的 this 在定义时确定（继承外层 this，不可改变）。

### 箭头函数的限制

~~~javascript
const Person = (name) => { this.name = name; };
// new Person("老王");  // ❌ TypeError: Person is not a constructor

// 箭头函数没有自己的 this、arguments、prototype
// 不能用 call/apply/bind 改变 this
// 不能作为构造函数使用 new
~~~

## 附录三：闭包

### 什么是闭包？

~~~
闭包 = 函数内部引用了外部作用域的变量，即使外部函数已经执行完毕，
这个变量也不会被销毁（因为被内部函数引用着）。

简单说：函数能"记住"它出生时的环境。
~~~

### 经典面试题：for 循环 + var

~~~javascript
// ========== 问题 ==========
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 输出：3, 3, 3 ❌
// 原因：var 是函数作用域，三个回调共享同一个 i，循环结束后 i=3

// ========== 解决方案1：用 let ==========
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 输出：0, 1, 2 ✅
// 原因：let 有块级作用域，每次循环创建一个新的 i

// ========== 解决方案2：IIFE（ES5 时代方案） ==========
for (var i = 0; i < 3; i++) {
  (function(j) {
    setTimeout(() => console.log(j), 100);
  })(i);  // j 是 i 的副本
}
// 输出：0, 1, 2 ✅

// ========== 解决方案3：bind ==========
for (var i = 0; i < 3; i++) {
  setTimeout(((j) => console.log(j)).bind(null, i), 100);
}
// 输出：0, 1, 2 ✅
~~~

**为什么 var 会出问题？** var 是函数作用域，循环中只有一个 i，三个 setTimeout 回调共享同一个 i。循环结束时 i 变成 3，回调执行时读到的都是 3。

**let 为什么能解决？** let 是块级作用域，每次循环都会创建一个新的 i，三个回调各自有自己的 i。

## 附录四：原型链

### 核心关系图

~~~
实例 (r)
  ├── __proto__  →  Foo.prototype
  │                    ├── __proto__  →  Object.prototype
  │                    │                    ├── __proto__  →  null
  │                    │                    ├── toString
  │                    │                    └── hasOwnProperty
  │                    └── constructor  →  Foo
  └── 自身属性

Foo (构造函数)
  ├── __proto__  →  Function.prototype
  └── prototype  →  Foo.prototype（上面已画）
~~~

### instanceof 原理

沿着 `__proto__` 链查找，如果找到 `Constructor.prototype` 就返回 `true`。

~~~javascript
function Restaurant(name) { this.name = name; }
Restaurant.prototype.showName = function() { return this.name; };

const r = new Restaurant("老王");

console.log(r.__proto__ === Restaurant.prototype);                // true
console.log(Restaurant.prototype.__proto__ === Object.prototype); // true
console.log(Object.prototype.__proto__ === null);                 // true
console.log(r instanceof Restaurant);  // true（沿着 __proto__ 链找到了 Restaurant.prototype）
console.log(r instanceof Object);      // true（继续往上找到了 Object.prototype）
~~~

### class 的本质就是原型链的语法糖

~~~javascript
class Restaurant {
  constructor(name) { this.name = name; }
  showName() { return this.name; }
}

// 等价于
function Restaurant(name) { this.name = name; }
Restaurant.prototype.showName = function() { return this.name; };

// 验证
console.log(typeof Restaurant);                         // "function"
console.log(Restaurant.prototype.showName === r.showName); // true（方法在 prototype 上）
~~~

**一句话总结：** class 只是让原型链的写法更简洁、更清晰，底层机制完全一样——方法在 prototype 上，实例通过 \_\_proto\_\_ 链访问。
