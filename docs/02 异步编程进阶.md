# 异步编程进阶：从 Promise 到 async/await 的完整思考路径

## 核心策略：异步编程的 3 层理解

异步编程进阶可以归为 3 个层次，掌握后遇到任何异步场景都能应对。

~~~
层次1：事件循环（理解代码为什么那样执行）→ 事件循环 / 微任务 / 宏任务
层次2：Promise 高级用法（解决实际异步问题）→ 错误处理 / 超时 / 重试 / 并发策略
层次3：async/await 原理（理解语法糖背后是什么）→ Generator / 自动执行器
~~~

---

## 层次一：事件循环（Event Loop）

### 为什么需要事件循环？

~~~
JavaScript 是单线程的 → 一次只能做一件事
但浏览器/Node.js 有大量异步操作（网络请求、定时器、用户交互）
→ 需要一个机制来协调"同步代码"和"异步代码"的执行顺序
→ 这个机制就是事件循环
~~~

**手写口诀：同步先跑完，微任务插队，宏任务排队**

### 任务队列的分类

~~~
同步任务（主线程）：
  代码直接执行，一行一行来

微任务（microtask queue）：
  queueMicrotask(() => { ... })
  Promise.then / catch / finally
  await 后面的代码
  MutationObserver

宏任务（macrotask queue）：
  setTimeout / setInterval
  requestAnimationFrame
  事件监听器回调（click、input 等）
  I/O（Node.js）
  MessageChannel
~~~

### 执行顺序规则

~~~
1. 执行所有同步代码（主线程栈）
2. 清空微任务队列（所有微任务，包括执行微任务时新产生的微任务）
3. 取一个宏任务执行
4. 回到第 2 步，循环
~~~

**记住这句话：`一轮事件循环 = 同步 → 所有微任务 → 一个宏任务`**

### 测试

~~~javascript
console.log("1. 同步");

setTimeout(() => console.log("2. 宏任务"), 0);

Promise.resolve().then(() => {
  console.log("3. 微任务");
  Promise.resolve().then(() => console.log("4. 微任务中的微任务"));
}).then(() => console.log("5. 链式微任务"));

queueMicrotask(() => console.log("6. queueMicrotask"));

console.log("7. 同步");

// 输出顺序：
// 1. 同步
// 7. 同步
// 3. 微任务
// 6. queueMicrotask
// 4. 微任务中的微任务
// 5. 链式微任务
// 2. 宏任务
~~~

#### 分析过程

~~~
// 第1轮事件循环：
//   同步：输出 1、注册 setTimeout、注册 Promise.then、注册 queueMicrotask、输出 7
//   微任务：
//     → 执行 Promise.then 回调：输出 3，内部又产生新微任务（输出 4）
//     → 执行 queueMicrotask 回调：输出 6
//     → 执行链式 .then 回调：输出 5（3 的回调产生的）
//     → 执行微任务中的微任务：输出 4
//     ← 3 的回调里产生的微任务（4）在当前轮微任务队列中就会被执行
//   宏任务：取出 setTimeout → 输出 2
~~~

### await 的微任务特性

~~~javascript
async function 做菜() {
  console.log("A. 开始做菜");
  await Promise.resolve();
  console.log("B. 做好了");  // 这一行是微任务
  await Promise.resolve();
  console.log("C. 上菜了");  // 这一行也是微任务
}

console.log("1. 同步");
做菜();
console.log("2. 同步");

// 输出：
// 1. 同步
// A. 开始做菜
// 2. 同步
// B. 做好了
// C. 上菜了
~~~

**await 把后面的代码"切"成了微任务。**

### 常见面试题

~~~javascript
// ========== 题目1 ==========
async function async1() {
  console.log("async1 start");
  await async2();
  console.log("async1 end");  // 微任务
}

async function async2() {
  console.log("async2");
}

console.log("script start");
setTimeout(() => console.log("setTimeout"), 0);
async1();
new Promise(resolve => {
  console.log("promise1");
  resolve();
}).then(() => console.log("promise2"));
console.log("script end");

// 输出：
// script start
// async1 start
// async2
// promise1
// script end
// async1 end
// promise2
// setTimeout
~~~

**逐步分析：**

~~~
第1轮事件循环：

  同步阶段：
    → 输出 "script start"
    → 注册 setTimeout 回调（放入宏任务队列）
    → 调用 async1()
      → 输出 "async1 start"
      → await async2() → 输出 "async2"
      → await 把后面的 "async1 end" 切成微任务
    → new Promise 的执行器是同步的 → 输出 "promise1"
    → resolve() → 注册 .then 回调（放入微任务队列）
    → 输出 "script end"

  清空微任务队列（按注册顺序）：
    → 执行 async1 的 await 后续 → 输出 "async1 end"
    → 执行 Promise.then 回调 → 输出 "promise2"

  取宏任务：
    → 执行 setTimeout 回调 → 输出 "setTimeout"
~~~

~~~javascript
// ========== 题目2：微任务的优先级 ==========
Promise.resolve().then(() => {
  console.log("微任务1");
  Promise.resolve().then(() => console.log("微任务1-1"));
}).then(() => console.log("微任务1-2"));

Promise.resolve().then(() => console.log("微任务2"));

// 输出：
// 微任务1
// 微任务2
// 微任务1-1
// 微任务1-2

// 为什么 1-2 在 1-1 之后？
// 因为 1-2 依赖 1 的回调执行完才能进入队列
// 而 1-1 是 1 的回调内部同步注册的微任务
~~~

## 层次二：Promise 高级用法

### 1. 错误处理最佳实践

**手写口诀：顶层 async/await + try/catch，链式用 .catch，不要混用**

~~~javascript
// ========== 方式1：async/await + try/catch（推荐） ==========
async function 做菜() {
  try {
    const 数据 = await fetch("/api/菜品");
    const 结果 = await 数据.json();
    console.log(结果);
  } catch (错误) {
    console.log("出错了：", 错误);
  } finally {
    console.log("清理资源");
  }
}

// ========== 方式2：链式 .catch ==========
fetch("/api/菜品")
  .then(r => r.json())
  .then(数据 => console.log(数据))
  .catch(错误 => console.log("出错了：", 错误));

// ========== 方式3：在 async 函数中直接 catch ==========
async function 做菜() {
  const 数据 = await fetch("/api/菜品").catch(错误 => {
    console.log("出错了：", 错误);
    return null;  // 返回默认值，继续执行
  });
  if (!数据) return;
  const 结果 = await 数据.json();
}
~~~

#### 测试

~~~javascript
// ========== try/catch 能捕获 await 的错误 ==========
async function 测试1() {
  try {
    await Promise.reject(new Error("做砸了"));
  } catch (错误) {
    console.log(错误.message);  // 做砸了 ✅
  }
}

// ========== .catch 不要和 try/catch 混用 ==========
async function 测试2() {
  try {
    await Promise.reject(new Error("做砸了")).catch(e => {
      console.log("catch 处理了：", e.message);  // catch 处理了：做砸了
      // 这里 catch 了，try/catch 就捕获不到了
    });
  } catch (错误) {
    console.log("这里不会执行");  // 不会执行 ❌
  }
}

// ========== 错误向上传播 ==========
async function 内部() {
  throw new Error("内部错误");
}

async function 外部() {
  try {
    await 内部();
  } catch (错误) {
    console.log(错误.message);  // 内部错误 ✅（内部 throw 的错误被外部 catch 捕获）
  }
}
~~~

### 2. 请求超时控制

**手写口诀：Promise.race 比速度，请求 vs 超时**

~~~javascript
function 带超时的请求(url, 超时毫秒 = 5000) {
  const 请求 = fetch(url);
  const 超时 = new Promise((_, reject) => {
    setTimeout(() => reject(new Error(`请求超时：${超时毫秒}ms`)), 超时毫秒);
  });

  return Promise.race([请求, 超时]);
}
~~~

#### 测试

~~~javascript
// ========== 正常请求（比超时快） ==========
带超时的请求("/api/菜品", 5000)
  .then(r => r.json())
  .then(数据 => console.log(数据));

// ========== 请求超时 ==========
带超时的请求("/api/慢接口", 1000)
  .catch(错误 => console.log(错误.message));  // 请求超时：1000ms ✅
~~~

### 3. 请求重试机制

**手写口诀：for 循环 + try/catch，成功就 return，失败就继续**

~~~javascript
async function 带重试的请求(url, 最大重试次数 = 3) {
  for (let 当前次数 = 0; 当前次数 <= 最大重试次数; 当前次数++) {
    try {
      const 响应 = await fetch(url);
      return await 响应.json();  // 成功就返回
    } catch (错误) {
      console.log(`第${当前次数 + 1}次请求失败：${错误.message}`);
      if (当前次数 === 最大重试次数) {
        throw 错误;  // 最后一次也失败了，抛出错误
      }
      // 指数退避：等待时间翻倍
      await new Promise(r => setTimeout(r, 1000 * Math.pow(2, 当前次数)));
    }
  }
}
~~~

#### 测试

~~~javascript
// ========== 第1次就成功 ==========
带重试的请求("/api/菜品")
  .then(数据 => console.log(数据));

// ========== 前2次失败，第3次成功 ==========
带重试的请求("/api/flaky", 3)
  .then(数据 => console.log(数据));

// ========== 全部失败 ==========
带重试的请求("/api/永远失败", 2)
  .catch(错误 => console.log("最终失败：", 错误.message));
~~~

### 4. 并发策略对比

**手写口诀：**
~~~
Promise.all        → 全成功才成功，一失败就失败
Promise.allSettled → 全做完再报告，永不 reject
Promise.race       → 谁快用谁（不管成功失败）
Promise.any        → 谁先成功用谁，全失败才失败
~~~

~~~javascript
function 延时(ms, 值, 是否失败 = false) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      是否失败 ? reject(new Error(值)) : resolve(值);
    }, ms);
  });
}
~~~

#### 测试

~~~javascript
// ========== Promise.allSettled（等全部完成） ==========
Promise.allSettled([
  延时(100, "红烧肉"),
  延时(200, "做砸了", true),
  延时(300, "糖醋里脊")
]).then(结果们 => {
  console.log(结果们);
  // [
  //   { status: "fulfilled", value: "红烧肉" },
  //   { status: "rejected", reason: Error("做砸了") },
  //   { status: "fulfilled", value: "糖醋里脊" }
  // ]
  // ✅ 全部返回，不会因为一个失败就 reject
});

// ========== Promise.any（第一个成功） ==========
Promise.any([
  延时(300, "慢菜失败", true),
  延时(100, "快菜成功"),
  延时(200, "中菜成功")
]).then(结果 => console.log(结果));
// 快菜成功 ✅（第一个成功的，忽略失败的）

// ========== Promise.any 全部失败 ==========
Promise.any([
  延时(100, "失败1", true),
  延时(200, "失败2", true),
  延时(300, "失败3", true)
]).catch(错误 => {
  console.log(错误.errors);  // [Error("失败1"), Error("失败2"), Error("失败3")]
  // AggregateError ✅
});

// ========== 四种并发策略对比 ==========
const 任务们 = [
  延时(300, "慢菜"),
  延时(100, "快菜"),
  延时(200, "中菜"),
  延时(150, "失败菜", true),
];

Promise.all(任务们).then(结果 => console.log("all:", 结果));
// reject（有一个失败就失败）

Promise.allSettled(任务们).then(结果 => console.log("allSettled:", 结果));
// 全部返回（4个结果）

Promise.race(任务们).then(结果 => console.log("race:", 结果));
// 快菜（谁快用谁，不管成功失败）—— 但"失败菜"(150ms)比"快菜"(100ms)慢

Promise.any(任务们).then(结果 => console.log("any:", 结果));
// 快菜（第一个成功的，跳过失败的）
~~~

### 5. 实际场景：多个请求的组合

~~~javascript
// ========== 场景1：串行（一个接一个） ==========
async function 串行请求() {
  const 菜品 = await fetch("/api/菜品").then(r => r.json());
  const 评价 = await fetch(`/api/评价/${菜品.id}`).then(r => r.json());
  // 第2个请求依赖第1个的结果 → 必须串行
  return { 菜品, 评价 };
}

// ========== 场景2：并行（同时发） ==========
async function 并行请求() {
  const [菜品, 评价, 推荐] = await Promise.all([
    fetch("/api/菜品").then(r => r.json()),
    fetch("/api/评价").then(r => r.json()),
    fetch("/api/推荐").then(r => r.json()),
  ]);
  // 三个请求互不依赖 → 并行更快
  return { 菜品, 评价, 推荐 };
}

// ========== 场景3：并行但允许部分失败 ==========
async function 宽容并行请求() {
  const 结果们 = await Promise.allSettled([
    fetch("/api/菜品").then(r => r.json()),
    fetch("/api/评价").then(r => r.json()),
    fetch("/api/推荐").then(r => r.json()),
  ]);

  const 成功的 = 结果们
    .filter(r => r.status === "fulfilled")
    .map(r => r.value);

  const 失败的 = 结果们
    .filter(r => r.status === "rejected")
    .map(r => r.reason);

  console.log("成功的：", 成功的);
  console.log("失败的：", 失败的);
}
~~~

## 层次三：async/await 的原理

### async/await 是什么的语法糖？

~~~
async/await = Generator + 自动执行器

Generator 是 ES6 提供的一种"可以暂停和恢复"的函数
async/await 让你不用手动写执行器，语法更简洁
~~~

### 先理解 Generator（生成器）

**手写口诀：function* 定义，yield 暂停，next() 恢复**

~~~javascript
function* 做菜流程() {
  console.log("开始做菜");
  yield "洗菜";           // 暂停，返回"洗菜"
  console.log("菜洗好了");
  yield "切菜";           // 暂停，返回"切菜"
  console.log("菜切好了");
  yield "炒菜";           // 暂停，返回"炒菜"
  console.log("菜炒好了");
  return "红烧肉";        // 结束
}

const 流程 = 做菜流程();

console.log(流程.next());  // { value: "洗菜", done: false }
console.log(流程.next());  // { value: "切菜", done: false }
console.log(流程.next());  // { value: "炒菜", done: false }
console.log(流程.next());  // { value: "红烧肉", done: true }
~~~

#### yield 可以传值

~~~javascript
function* 计算器() {
  const 甲 = yield "输入第一个数";
  const 乙 = yield "输入第二个数";
  return 甲 + 乙;
}

const 计 = 计算器();
console.log(计.next());           // { value: "输入第一个数", done: false }
console.log(计.next(10));         // { value: "输入第二个数", done: false }（甲 = 10）
console.log(计.next(20));         // { value: 30, done: true }（乙 = 20，返回 10+20）
~~~

### Generator + Promise = async/await

~~~javascript
// ========== Generator + 手动执行器 ==========

function* 做菜() {
  const 菜品 = yield fetch("/api/菜品").then(r => r.json());
  const 评价 = yield fetch(`/api/评价/${菜品.id}`).then(r => r.json());
  return { 菜品, 评价 };
}

// 手动执行器（自动执行 Generator）
function 自动执行器(生成器函数) {
  const 生成器 = 生成器函数();

  function 下一步(上一次的值) {
    const 结果 = 生成器.next(上一次的值);  // 恢复执行

    if (结果.done) return Promise.resolve(结果.value);  // 结束了

    return Promise.resolve(结果.value)  // 确保是 Promise
      .then(值 => 下一步(值));            // 递归执行下一步
  }

  return 下一步();
}

// 使用：
自动执行器(做菜).then(结果 => console.log(结果));

// ========== 等价的 async/await ==========

async function 做菜2() {
  const 菜品 = await fetch("/api/菜品").then(r => r.json());
  const 评价 = await fetch(`/api/评价/${菜品.id}`).then(r => r.json());
  return { 菜品, 评价 };
}

做菜2().then(结果 => console.log(结果));
~~~

#### 测试

~~~javascript
// ========== Generator 版本 ==========
function* fetch菜品() {
  const 响应 = yield fetch("/api/菜品");
  const 数据 = yield 响应.json();
  console.log(数据);
}

自动执行器(fetch菜品);

// ========== async/await 版本（完全等价） ==========
async function fetch菜品2() {
  const 响应 = await fetch("/api/菜品");
  const 数据 = await 响应.json();
  console.log(数据);
}

fetch菜品2();

// 两种写法效果完全一样
// async/await 就是 Generator + 自动执行器的语法糖
~~~

### 自动执行器的原理

~~~
自动执行器做的事情：
  1. 调用生成器，拿到生成器对象
  2. 调用 next()，拿到 yield 后面的值（一个 Promise）
  3. 等 Promise 完成后，把结果传给下一次 next()
  4. 重复 2-3，直到 done === true

就像一个"自动喂饭机"：
  生成器说"我要等这个 Promise"（yield）
  执行器说"好的，我帮你等"（.then）
  Promise 好了，执行器把结果"喂"给生成器（next(结果)）
  生成器继续执行，直到下一个 yield 或 return
~~~

### 手写自动执行器（完整版）

~~~javascript
function 自动执行器(生成器函数, ...参数) {
  return new Promise((resolve, reject) => {
    const 生成器 = 生成器函数(...参数);

    function 下一步(方法, 上一次的值) {
      let 结果;
      try {
        结果 = 生成器[方法](上一次的值);  // next(value) 或 throw(error)
      } catch (错误) {
        return reject(错误);
      }

      if (结果.done) return resolve(结果.value);

      Promise.resolve(结果.value).then(
        值 => 下一步("next", 值),       // 成功 → next(值)
        错误 => 下一步("throw", 错误)    // 失败 → throw(错误)
      );
    }

    下一步("next");  // 启动执行器
  });
}
~~~

~~~

## 终极记忆卡片

~~~
层次1：事件循环
  同步先跑完 → 微任务全部清空 → 一个宏任务 → 循环
  await 后面的代码 = 微任务
  Promise.then = 微任务
  setTimeout = 宏任务

层次2：Promise 高级用法
  超时控制  → Promise.race([请求, 超时Promise])
  请求重试  → for循环 + try/catch + 指数退避
  错误处理  → async/await + try/catch（推荐）
  并发策略  → all(全成功) / allSettled(全完成) / race(谁快) / any(第一个成功)

层次3：async/await 原理
  async/await = Generator + 自动执行器
  Generator = function* + yield + next()
  自动执行器 = 递归调用 next()，每次等 Promise 完成后喂结果
